# Concurrent writes and the outbox

Spec: `pnpm spec k.sync`, `std.offline`, `std.conflicts`.

**Concurrent writes:** `transaction(store, name, schema, fn, { concurrent: 'rebase' | 'reject' })`; `'reject'` is the default. A write carries `base` (the head its writer read); when `base` is not the head, `'rebase'` applies it to the current state (use it when the payload holds no value the writer read: a fresh id, a flip), `'reject'` answers 409 `keel.conflict` with `data.head`. Pass `base` to `tx` with the input's `write`; a repeated write `key` commits nothing again.

**Outbox (`@keel/std-offline`):** `outbox('todos.outbox', endpoints, { module: 'api' })` (module level or in a scope) sends through `service({ module })`, so `output` and `errors` describe the route's `ok` value and err's `error`; endpoint bodies hold `write: Write` (`{ key, base, owner }`) and the action checks it first: `const w = writeFor(input.write, ownerOf(caller)); if (!w.ok) return err(w.error)` (`ownerOf` is the module's own function from `caller` to the signed-in user's id, `''` for no one; an app with no sign-in passes `''`), then passes `{ meta, ...w.value }` to `tx`. A write of another owner is 400 `offline.owner`, nothing saved, and its entry is `failed` and never posted again; an action that skips `writeFor` commits a write of any owner. `send(ctx, outbox, 'addTodo', { params, body }, { base: view.get('head'), owner })` resolves `sent | queued | conflict | failed`; `owner` is the signed-in user's id, else `''`. A request with no user gets 400 `offline.signin` from `writeFor`: the flush pauses with entries `queued` until `send` or `drain` names that owner again, and `owner: ''` holds other owners' entries rather than failing them. `drain(ctx, outbox, { owner })` in a scope flushes that owner's entries on reconnect; another owner's entry, or a stored one with an `origin` or no `owner`, is `failed` with `offline.owner` and never posted. `resolve(ctx, outbox, key, 'mine' | 'theirs')` settles a `conflict` or `failed` entry: `'mine'` resolves the re-send's `OutboxResult` (`false` for no such entry), `'theirs'` `true`. A rejected `ctx.storage` write leaves the entry `failed` with `offline.storage`. E2651 an `s.secret` in an endpoint body; E2652 an `events: true` endpoint. One module-level outbox used from several ctxs keeps each ctx's entries apart; ending `drain`'s scope drops its pending retry.

**Races (`@keel/std-conflicts`):** `races(snapshot, stores)` over a stored server store, or `findRaces(group, { user, serve, stores })` over a replayed session group, reports a rebased write whose order changes the result (E2701): make that transaction `'reject'`, or stop its payload carrying a value read from a stale copy.
