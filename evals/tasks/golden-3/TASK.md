# Golden app 3 (volunteer shifts, compliance)

Build this project, `golden-3`: volunteer shift sign-up for a food bank. Anyone signs up for a shift with their name, email, phone and access needs, sees their own sign-ups and cancels them; an organizer sees the roster with contact details and marks attendance. Every page is rendered by one `node` deployable, so the nonce policy covers every document, and personal data reaches every sink. The project exists in the current directory (`keel scaffold project`, installed); you are a developer who has only what a Keel user has. Read `AGENTS.md` first: it names the skills in `.claude/skills/` (`keel`, then `keel-server`, `keel-client`, `keel-compliance`, `keel-testing`). Retrieve exact API text with `keel docs` (the map), `keel docs <id>` (a section), `keel docs --for <code>` and `keel explain <code>`; each package's README is in `node_modules/@keel/<name>/`. Use only kernel and stdlib APIs; invent nothing. Read the `keel-compliance` skill first: it says what Keel enforces and what the app declares. Edit only files in this project. A `@keel/*` package the app needs goes into `package.json` at `^0.0.0` and `pnpm install` resolves it from the local kit. Replace the scaffold's `app` module. If the docs leave an API you need unspecified, stop and report `blocked: <section> <question>`; invent nothing.

## Topology and package
- `topology.ts` default export: `web` (`adapter: 'node'`, modules `shifts` and `sessions`). No `client` deployable.
- `tokens.ts`: `export const tokens = brandTokens` (`@keel/ui/brand`). Every color pair that holds text passes 4.5:1 (k.a11y); use the brand's tokens as they are.
- `package.json` depends on `@keel/std-text` and `@keel/std-sessions` beside the packages the scaffold lists (add `@keel/std-headless` or others only when used). Scripts: `check` (`tsc --noEmit && keel check --quiet`), `test` (`keel test`, so `reports/a11y.json` is written), `build` (`keel build`), `dev` (`keel dev`), `web` (`node --experimental-webstorage --localstorage-file=.web.storage --disable-warning=ExperimentalWarning dist/web/server.mjs`).

## Data (`modules/shifts`, each schema in its own `*.schema.ts`)
- `Shift { id: s.string(), title: line({ max: 80 }), when: line({ max: 80 }), slots: s.int({ min: 1, max: 50 }) }`.
- `Signup { id: s.id('Signup'), shiftId: s.string(), name: line({ max: 80 }).pii('name'), email: Email.pii('contact'), phone: line({ max: 32 }).pii('contact').optional(), needs: para({ max: 500 }).pii('special').optional(), owner: s.string().pii('identifier'), attended: s.boolean() }`. `owner` is the caller hash of whoever signed up.
- `SignupDraft { name, email, phone?, needs? }`: the same four fields, marks included. `Attendance { attended: s.boolean() }`.
- `Board { shifts: Shift[], signups: Signup[] }`; `ShiftParams { shiftId: s.string() }`; `SignupParams { signupId: s.id('Signup') }`.
- No `.pii()` field in a route's `params` or `search` (E1111). Every field that holds a person's data is marked: the redaction in sessions, the input mask and the log scrub follow the marks, and an unmarked copy is not redacted.

## Server state
- `board.ts`: `boardStores(ctx)` returns store `shifts.board` (`Board`) and its bound transactions. Initial state: no sign-ups and three shifts: `s1` `Sorting donations`, `Saturday 9:00 to 12:00`, 4 slots; `s2` `Packing boxes`, `Saturday 13:00 to 16:00`, 4 slots; `s3` `Delivery helpers`, `Sunday 10:00 to 14:00`, 2 slots.
- `invariant` beside the store: sign-up ids unique; every `signup.shiftId` names a shift; no shift holds more sign-ups than its `slots`.
- Pure transactions, one per file, payloads with every value they need: `shifts.signUp` (a whole `Signup`; an unknown or full shift leaves the state unchanged), `shifts.cancel` (`{ id, owner }`; removes the sign-up only when `owner` matches), `shifts.markAttended` (`{ id, attended }`).
- Organizers: the guard `organizer` (`organizer.guard.ts`, `guard({ redirect: 'shifts.index' }, fn)`) admits a caller whose hash is in the JSON array stored under `ctx.storage` key `shifts.organizers` (absent or unparseable: nobody). On a `node` deployable guards run on the server, so the list never reaches a browser. The two organizer actions check the same list (`isOrganizer.ts`) and answer `keel.denied` otherwise.

## Routes (`modules/shifts/routes.ts`; every page in layout `shifts.shell`; loaders and actions declare `stores: boardStores`)
- Layout `shifts.shell` (`AppShell`): `Box as="nav"` `shifts.nav` labelled `Main` with Links `shifts.home` (`Shifts`, to `shifts.index`) and `shifts.mineLink` (`My sign-ups`, to `shifts.mine`); `Box as="main"` `shifts.main` holding the page. On a page (`pageOrigin()` defined, as golden-1's), it calls `record(ctx, { upload: new URL('/sessions', origin) })`.
- `shifts.index` `/`, title `Volunteer shifts · Food bank`: Heading (level 1) `shifts.title` `Volunteer shifts`; per shift Link `shifts.link.<id>` (its title), Text `shifts.when.<id>`, Text `shifts.open.<id>` (`<n> of <slots> places open`).
- `shifts.show` `/shifts/:shiftId`, title `<title> · Food bank`: Heading (level 1) `shifts.show.title` (the shift's title), Text `shifts.show.when`, Text `shifts.show.open`. While places are open, a Form `form(SignupDraft, { id: 'shifts.join' })` posting to this route: Input `name` (label `Name`, `autocomplete="name"`), Input `email` (`type="email"`, label `Email`, `autocomplete="email"`), Input `phone` (`type="tel"`, label `Phone (optional)`, `autocomplete="tel"`), TextArea `needs` (label `Access needs (optional)`, `autocomplete="off"`), submit Button `shifts.join.submit` `Sign up`, in that order. A full shift shows Text `shifts.show.full` `This shift is full` and no Form. Action `signUp`: mints the id with `ctx.random.id('Signup')`, `owner` the caller, `attended: false`; a full shift is `err` `keel.conflict`; success is `ok(routes.href('shifts.mine'))`. Unknown shift: the loader's `err` `keel.notFound`; errorElement `ShiftError` shows Heading `shifts.error` `Not found`.
- `shifts.mine` `/mine`, title `My sign-ups · Food bank`: Heading (level 1) `shifts.mine.title` `My sign-ups`; per sign-up whose `owner` is the caller, Text `shifts.mine.shift.<id>` (`<title>, <when>`) and Link `shifts.mine.cancel.<id>` (`Cancel <title>`, to `shifts.signup`); none: Text `shifts.mine.empty` `You have no sign-ups yet`.
- `shifts.signup` `/mine/:signupId`, title `Cancel sign-up · Food bank`: the caller's own sign-up only (another's id, or an unknown one, is `keel.notFound`, so `ShiftError`): Heading (level 1) `shifts.signup.title` `Cancel your sign-up`, Text `shifts.signup.shift` (`<title>, <when>`), a Form posting to this route with submit Button `shifts.cancel` `Cancel sign-up`. Action `cancel` (input `s.object({})`): owner only, else `keel.notFound`; success `ok(routes.href('shifts.mine'))`.
- `shifts.roster` `/roster`, guard `organizer`, title `Roster · Food bank`: Heading (level 1) `shifts.roster.title` `Roster`; per shift Heading (level 2) `shifts.roster.shift.<shiftId>` (its title) and per sign-up Text `shifts.roster.name.<id>`, `shifts.roster.email.<id>`, `shifts.roster.phone.<id>` (or `No phone`), `shifts.roster.needs.<id>` (or `None given`), `shifts.roster.attended.<id>` (`Attended` or `Not yet`) and Link `shifts.roster.mark.<id>` (`Attendance for <name>`, to `shifts.attend`).
- `shifts.attend` `/roster/:signupId`, guard `organizer`, title `Attendance · Food bank`: Heading (level 1) `shifts.attend.title` `Attendance`, Text `shifts.attend.who` (`<name>, <shift title>`), a Form `form(Attendance, { id: 'shifts.attend', initial })` with Checkbox `attended` (label `Attended`) and submit Button `shifts.attend.save` `Save`. Action `markAttended`: organizer only (`keel.denied`), unknown id `keel.notFound`, success `ok(routes.href('shifts.roster'))`.
- Copy is literal English (`lang` `en`); no other origin anywhere: no absolute `http(s)` literal in `src`, `action`, `Image src`, `ctx.net.fetch` or `service({ base })` (E1570, E1571), no inline script or style, no `style` attribute (the policy blocks them; docs/COMPLIANCE.md).

## Tests (`@keel/testing` only; ids only)
- `board.test.ts`: `properties()` on the three transactions (a factory store in an isolated scope, as the k.testing slice line shows); the invariant.
- `routes.test.ts`: a `renderRoute` test for each of the six pages (with `caller`, and a sim ctx whose storage holds the board and, for the roster pages, `shifts.organizers`): these renders make the page's accessibility claims (the `keel-compliance` skill).
