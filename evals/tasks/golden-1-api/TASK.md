## Behavior (UI unchanged)
- `/` (`todos.index`): lists with open-todo counts; a Form adding a list.
- `/lists/:listId` (`todos.list`, search `filter`: `all|active|done`, optional): filtered todos, filter links, a Checkbox per todo toggling done, a Form adding a todo, `Suggestions` (`resource`, `Match` on loading, error message, ready titles).
- `/lists/:listId/todos/:todoId/edit` (`todos.edit`): Form editing a todo; success navigates to `todos.list`. Guard `editable` (`guard({ redirect: 'todos.index' }, fn)`, held as `guard: editable`) denies when `ctx.storage` `todos.readOnly` is `"1"`, redirecting to `todos.index`.
- Unknown `listId`/`todoId`: loader returns `err` `keel.notFound`; `ListError` renders.
- Layout `todos.shell` (`AppShell`): `main`, home Link, Undo Button (disabled when nothing can be undone), the board's live status `todos.live` (`Live`, `Connecting`, `Offline`, `No access`), and the outbox panel.

## Multi-user behavior
- Every open page stays current: after any user's save, each page re-reads the board with no input of its own (its `todos.view` log gains one `todos.hydrate`).
- Writes (add list, add todo, toggle, edit) go through an outbox. Offline (`ctx.net.online()` false) a write waits, in order, and the page still opens from the board as last served; on reconnect the outbox sends each write once, with its original key.
- Each write names the head of the board its page last read (`base`). Add list, add todo and toggle apply over newer writes (`'rebase'`); an edit carries both fields as the editor read them, so a stale edit is refused (`'reject'`, 409 `keel.conflict` with the head).
- `OutboxPanel` (`aside` `todos.outbox`, label `Outbox`, shown while the outbox holds a write) lists each write in order (`todos.outbox.entry.<key>`, its state `todos.outbox.state.<key>`: `Waiting to send`, `Sending`, `Someone changed this board first`, `Not saved`). A refused write has `todos.outbox.mine.<key>` (`Keep mine`: send it again over the newer board) and `todos.outbox.theirs.<key>` (`Keep theirs`: drop it); a failed one has `todos.outbox.theirs.<key>` (`Dismiss`). A Form's failed write leaves the outbox and its error goes to the Form.

## Architecture
- `api` owns the board as server state (k.server, RFC 0044): `board.ts` makes store `api.board` (`Board { lists, todos }`, initially empty) with an `invariant` beside it (ids unique, every `todo.listId` names a list); each transaction file exports a factory binding `api.addList|addTodo|toggleTodo|editTodo` to a board (pure; new ids arrive in the payload, minted with `ctx.random.id`; unknown or duplicate id leaves state unchanged); `boardStores.ts` returns the board and its bound transactions. Every api loader and action declares `stores: boardStores` and records `tx` meta `{ caller }`.
- Routes, one per path, actions by verb; responses are the k.server runtime `Result` JSON body:
  - `api.lists`: `/api/lists`, GET loader returns `{ lists, todos, canUndo }`; POST creates a list (`ListDraft`).
  - `api.listTodos`: POST `/api/lists/:listId/todos` (`TodoDraft`; unknown list is `keel.notFound`).
  - `api.todo`: POST `/api/todos/:todoId` (edit; a duplicate title in the list is `keel.fields { title }`).
  - `api.todoToggle`: POST `/api/todos/:todoId/toggle`.
  - `api.undo`: POST `/api/undo` (`undoWhere` this caller's last entry; nothing of the caller's is a no-op); `canUndo` is true when the log's last entry is the caller's.
  - `api.suggestions`: GET `/api/suggestions` (fixed titles).
  - `api.boardEvents`: the board channel's event stream, `channelRoute(boardChannel, { id: 'api.boardEvents', stores: boardStores, member: () => true })` in `boardEvents.server.ts` (the board is public), listed as `{ api: true, path, loader }` with its `actions` (std.channels).
- Realtime (k.sync, std.channels, std.offline): `api.addList`, `api.addTodo` and `api.toggleTodo` declare `{ concurrent: 'rebase' }`; `api.editTodo` keeps the default `'reject'`. The four write actions take `write: Write` (`@keel/std-offline`) in their input (`ListWrite`, `TodoWrite`, `ToggleWrite` schemas) and call `tx(t, payload, { meta: { caller }, ...input.write })`. `BoardView` gains `head` (`board.head()` in `loadBoard`). `boardChannel.ts` in `api` (a client-safe file, since `todos` depends on `api`): `channel('api.board', { path: '/api/board/events', params: s.object({}) })`, no message. `api` deps `@keel/std-channels`, `@keel/std-offline`; capabilities add `clock`, `net`, `observe`.
- No hand-written server: `keel build` writes `dist/api/server.mjs` (k.topology Build) and the `web` client as static files in `dist/web/`; because `web` has `host: 'api'` the same build copies the client into `dist/api/`, so `GET /` on `server.mjs` is the app (k.hosting); script `api` runs it with `KEEL_DATABASE_URL=file://$PWD/.api.sqlite`. `vite.config.ts` is `defineConfig({ plugins: [keel()] })`: `keel dev` serves every deployable on one origin. `api/module.ts` lists the schemas `todos` and `digest` import in `public.exports` and every route the clients call (`api.lists`, `api.listTodos`, `api.todo`, `api.todoToggle`, `api.undo`, `api.suggestions`) in `public.routes`.
- `digest` (deps `api`, `@keel/std-jobs`, `@keel/std-schedules`; capabilities `clock`, `random`, `storage`, `net`; std.jobs, std.schedules, k.topology Runners):
  - `Digest.schema.ts` `{ open: s.int({ min: 0 }), done: s.int({ min: 0 }), at: s.number() }`, kept in `ctx.storage` key `digest.latest` (`LATEST_KEY`, `readLatest`: zero counts at 0 before the first count or when unparseable; `writeLatest`).
  - Job `digest.recount` (`recount.server.ts`, input `RecountInput` `{}`): reads `GET /api/lists` through `boardApi = service({ module: 'api', schema: board })` (`board.service.ts`, output `BoardView`), counts open and done todos, writes them with `at` the `ctx.clock` time; the api's error is its `err`.
  - `jobs.server.ts` `queue({ 'digest.recount': recount })`; `schedules.server.ts` `digest.hourly` (`0 * * * *`, `UTC`, job `digest.recount`, input `{}`); `runners.server.ts` `[jobs, schedules]`.
  - Routes: `digest.show` `GET /digest` (`loadDigest`), `digest.refresh` `POST /digest/refresh` (`refresh`: `jobs.enqueue(ctx, 'digest.recount', input)`), `digest.feed` `GET /digest/feed` (`feedDigest`, a live loader: the stored digest, then each different one, read every 1,000 ms of `ctx.clock`). All three are API routes (`api: true`, no component).
- Splitting `digest` into its own `node` deployable edits `topology.ts` alone (`api: { modules: ['api'] }`, `digest: { modules: ['digest'] }`).
- `todos` (deps `api`): `@keel/services` clients through `service({ module: 'api', schema })`, no origin: `todos` (`lists`, `undo`) and `suggestions` (`Suggestions` calls it with its `ctx`, never `ctx.net.fetch`); a view store `todos.view` changed only by one transaction `todos.hydrate` (replaces the state); loaders re-read the board (`GET /api/lists`) and hydrate, then pick by id (`refreshView`; offline, the board as last served).
  - Writes: `boardOutbox = outbox('todos.outbox', boardWrites)` (std.offline; declared inside a module-lifetime `scope(...).run`), over `boardWrites` (the four writes, bodies with `write`; the outbox calls the api by origin, so `output` is the whole answer `WriteAnswer` `{ ok: true, value }`, and `errors` are `409: s.json()` and `422: WriteRefusal` `{ ok: false, error }`). Route actions and `TodoRow` call `send(ctx, boardOutbox, origin, endpoint, input, { base: view.get('head') })`; an action's origin is its `url`'s, a component's `pageOrigin()` (the page's `location.origin`, undefined off a page). `formAnswer` turns a result into the action's answer: `ok(null)` unless `failed`, which leaves the outbox and goes to the Form (a 422's `keel.fields` to its fields).
  - `AppShell` (`uses = [hydrate]`) on a page calls `live(ctx, origin, boardChannel, {}, { read: (c) => todosApi.lists({}, c), hydrate })` and `drain(ctx, boardOutbox)`, shows the status in `todos.live`, and renders `OutboxPanel`. Undo posts through `todos` and re-reads.
