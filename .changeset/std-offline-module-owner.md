The outbox sends through its module's service: `outbox(id, api, { module, limit, maxBytes })` requires `module`, and answers are read as `service({ module })` reads them, an undeclared 409 as JSON. `send(ctx, outbox, endpoint, input, { base, owner })` takes no origin, and each entry holds an `owner` in place of an `origin`. `drain(ctx, outbox, { owner })` posts only that owner's entries; every other owner's entry becomes `failed` with `offline.owner` and is never posted. `Write` requires `owner`, and a flush sends each entry's owner in `body.write`. The new `writeFor(write, owner)` gives an action the `{ key, base }` to pass to `tx` when the write was queued under the owner of its caller, else an `offline.owner` err the server answers 400 with nothing saved; the outbox reads that answer as the entry `failed` with `offline.owner` and never posts it again.

Migration: drop the origin argument of `send`, pass `owner` (the signed-in user's id, else `""`) to `send` and `{ owner }` to `drain`, give `outbox` the `module` that serves the endpoints, and declare each endpoint's `output` and `errors` as the route's `ok` value and its err's `error`, not the whole k.server answer. In each action behind an outbox endpoint, replace `...input.write` with `const w = writeFor(input.write, owner); if (!w.ok) return err(w.error);` and `...w.value`, `owner` being the id of the user the caller is signed in as (`""` with no sign-in). Deploy the server first: a client that sends no `owner` is refused 422 `keel.fields` and its entry is `failed`. An entry stored with an `origin` or without an `owner` loads `failed` with `offline.owner` and is never sent; `resolve(..., 'theirs')` removes it.
