`keel check`, `keel build`, `keel test` and `keel dev` judge the tree, never the derived files on disk: each takes the derivation of the tree it runs over and rewrites each `.keel/` view and deploy file whose bytes differ (`ok check 217 files, 2 refreshed, 0 errors`; W1018 when one cannot be written). A run with `--frozen`, `CI` set or `KEEL_FROZEN=1` writes nothing and reports a differing view as E1005. `routes.json` and `surface.json` come from one evaluation, cached in `node_modules/.cache/keel/derived/` while every file it loaded or read through `node:fs`, every `process.env` name it read and every symbolic link on the path to a file it loaded or read, and every `node_modules/<name>` entry, resolves as before; the evaluation sees `process` by any name (`globalThis`, `global`, `createRequire`, `process.getBuiltinModule`), a file read by a descriptor it opened and a `.json` file required by a computed name, records every lookup of its resolver and of its own `require`, a path found absent too, so creating it re-evaluates, and refuses with E1050 what it cannot see, its message starting with what it refused: a call into `node:child_process`, `cluster`, `worker_threads`, `vm` or a network built-in, a `.node` addon, a code file named at run time (a computed `import()` too), Node's own loader (`node:module`'s `_load`, `process.mainModule`, `import.meta.resolve`), `Function` and `eval`; each module's `import.meta` is its own, and the evaluation's `console` writes nowhere; `keel dev` refreshes on a change to any of those files, a lone contract edit included; `keel check --base <file>` never rewrites that file; the json summary's `counts` hold `refreshed`, `evaluated` and `cached`. `surface.json` is version 3 with no `sources`; `--base` reads versions 2 and 3. Only `surface.json` and the deploy files are committed; a scaffolded `.gitignore` lists the other views. `keel pack --frozen` replaces `keel pack --check`. W1005 is reserved and never reported.
