`simulate` runs each scenario in the run's async context (Node only; `@keel/ctx` imports no Node module) and drives the run's clock while the scenario is pending: on each turn where no work of the run is pending (an asynchronous resource other than a promise made outside held work and not destroyed by a garbage collection, which the drive runs when a pending set it has not collected with stays unchanged for a turn; held work until it is delivered, in start order once no thread-pool request of the run is pending; a harness call not stalled on `ctx.net`) the clock goes to the next deadline or offline window edge, up to the horizon, so a scenario awaits a job's effect, a statement or a delayed request directly and real durations decide nothing. `run()` waits to the horizon, `run(ms)` to exactly `ms` on, `run(0)` drains at the current time, `horizon: 0` leaves the clock to the scenario. A capability's sim factory gets `hold(label, start)` for work that answers through something made outside the run; std-postgres holds its engine boot and each PGlite call. A harness call under `simulate` resolves on a drive turn where nothing else of the run is pending. `keel test` starts test processes with `UV_THREADPOOL_SIZE=1`. The law check is on by default when `KEEL_TEST` is `1` (`law: false` or `law: true` overrides): each passing run is replayed after the last, in run order, within the run's budget, a replay the budget stops failing nothing, and `simulate` resolves `{ seed, runs, checked }`; a failing run is replayed twice; the trace ends with each storage key the run wrote and each live store's snapshot, a `resource` event's id written as the run's own count, and a difference is E1729. The drive moves the clock inside the run's context, so offline-edge and `observe` callbacks make tracked work. E1727 (the scenario waits on nothing the run can move) and E1728 (held work waits on the sim clock, the run's real-time budget spent with work in flight (`budget` ms, else the test's timeout less a tenth from the test's start, else 300,000 ms; the run is not shrunk or replayed), or work of the run still pending when the budget is spent after the scenario resolved: the drive waits for it, moving no clock) reach the operator as E1704 with the shrunk `SimRun`; `keel explain` gains E1727, E1728 and E1729.
