# Accessibility target

WCAG 2.2 AA, enforced structurally: base elements require labels at the type level (`Box` as `nav` or `aside` requires `label`); headless primitives ship keyboard and focus behavior (`@keel/std-headless` widgets follow the WAI-ARIA Authoring Practices 1.2 patterns, std.headless and std.options state each key, and a closed dialog returns focus to its trigger); contrast computed from tokens at build (E1804 in `keel check`, with `contrastTable` from `@keel/ui`); motion honors reduced-motion; tests assert on the a11y tree. `keel check` is static and reports a blank literal `label` on a base element, a namespace import and character references such as `&#32;` and `&nbsp;` included (E1802), text below the contrast minimum (E1804), and a reversed `direction` over focusable base elements (E1820); `@keel/testing` `render` runs axe-core's WCAG 2.2 A and AA rules plus `landmark-unique`, checks contrast from the tokens, checks with tokens that no reversed `direction`, at any breakpoint, sits over two or more elements of one focus order (E1820 again, so a `direction` computed at run time is checked and WCAG 1.3.2 and 2.4.3 earn `example` from a passing `renderRoute` run), and compares roles and names with `a11y.json` (E1702, E1703), and fails a `data-k-pii` control without `autocomplete` (E1821) and, after a `fire` or `settle()`, a `role="status"` region inserted already holding text, which a screen reader does not announce (E1826; `Text role` makes a line of copy a `status` or `alert` region, rendered from the first render). Status messages (4.1.3) stay a person's check; the a11y tree a test reads carries `rowindex` and `rowcount` from `aria-rowindex` and `aria-rowcount`, and a `th` with `scope="row"` reads as `rowheader`; `@keel/testing/a11y` writes each check to `reports/a11y.json` and maps a rule to its WCAG criteria (`criteriaOf`).

The platform's focus indicator stays: the style vocabulary has no `outline`, and the brand guide defines no focus style. The repo's biome config turns `a11y/useSemanticElements` off, since base elements and `role` on `Text` carry the semantics the rule would ask for.
