# Accessibility target

WCAG 2.2 AA, enforced structurally: base elements require labels at the type level (`Box` as `nav` or `aside` requires `label`); headless primitives ship keyboard and focus behavior (`@keel/std-headless` widgets follow the WAI-ARIA Authoring Practices 1.2 patterns, std.headless and std.options state each key, and a closed dialog returns focus to the element focused before it); contrast computed from tokens at build (E1804 in `keel check`, with `contrastTable` from `@keel/ui`); motion honors reduced-motion; tests assert on the a11y tree. `keel check` is static and reports a blank literal `label` on a base element, a namespace import and character references such as `&#32;` and `&nbsp;` included (E1802), text below the contrast minimum (E1804), and a reversed `direction` over focusable base elements (E1820); `@keel/testing` `render` runs axe-core's WCAG 2.2 A and AA rules plus `landmark-unique`, checks contrast from the tokens, and compares roles and names with `a11y.json` (E1702, E1703), and fails a `data-k-pii` control without `autocomplete` (E1821); `@keel/testing/a11y` writes each check to `reports/a11y.json` and maps a rule to its WCAG criteria (`criteriaOf`).
