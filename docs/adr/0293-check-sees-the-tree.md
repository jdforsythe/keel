# ADR-0293: k.derived: check sees the project as it is (RFC 0255)

**Status:** accepted (orchestrator, 2026-11-26), to be confirmed by the operator.

**Context.** `keel check`, `keel test`, `keel ledger` and dev's inspect document read `.keel/` files that only `keel build` and the Vite plugin write, so an edit is judged against the last build. Reproduced on `apps/household`: a page, route, contract, store or `topology.ts` edit is a wrong E1005 ("run keel build"); a dependency upgrade that breaks stored states, or a tree with no `surface.json`, passes `keel check --base` although `keel build` then shows E1563; a read-only `.keel/` makes `keel test` run no test; `keel check` beside `keel dev` disagrees with what dev serves. The guide and the `keel` skill tell people and agents to build before every check.

**Decision.**
- A derived file (the `.keel/` artifacts, `surface.json`, the deploy files) is never read from disk to judge, test or serve: each reader takes the derivation of the tree it runs over. The files are views.
- Every run that is not frozen rewrites each view whose bytes differ, by atomic rename, with no lock, skipping a write whose inputs changed during the run; the language server writes none. One trailer count, `refreshed`; a view that cannot be written is W1018.
- Frozen (`--frozen`, `CI` set, or `KEEL_FROZEN=1`): nothing is written, a differing view is E1005.
- `routes.json` and `surface.json` come from one evaluation, cached in `node_modules/.cache/keel/derived/` keyed by every file it loaded and every question it asked, under the type cache's rule.
- Every build-time evaluation runs in the evaluator (k.evaluator): one Node child per bundle, started with Node's permission model and no file right but its own bundle, code from strings off, zero-filled buffers, an empty working folder and an environment built from nothing. Its global object is prepared in place from one allowlist; its views hold none of Node's objects and answer by asking the command over an inherited pipe, and the command's answers are the cache's inputs and probes. The command ends it at its result; no result in 30 s, or an unsettled top-level await, is E1048, and any other early end E1049. Diagnostics cross as records and are placed by the command. It is the evaluator RFC 0251 specifies, built once here.
- `surface.json` is version 3 with no `sources`; k.compat's normal form is removed. Only `surface.json` and the deploy files are committed. W1005 is reserved.

**Alternatives.** A watcher daemon (needs starting; an agent's shell has none); "build first" documented (today's state, a rule to remember, wrong greens stay); a warning instead of E1005 (keeps every wrong green); re-derive with no cache (0.3 to 0.7 s per check); a digest written into each view (public, so forgeable, and it changes committed files on every dependency bump); no views at all (people and tools read them); for the evaluation, a `node:vm` context or a worker thread (each shares the command's permission model, so an unrecorded read succeeds), one kept evaluator with a realm per evaluation (the same gap), and a membrane over every returned object (a longer list in the realm it guards).

**Consequences.** Edit, `keel check`, done, for a person and an agent; the skill line telling agents to build first goes. CI derives the surface it compares, so a breaking dependency bump fails E1563. Pull requests stop conflicting on compiled views and on `surface.json`'s source hashes. `keel check` writes inside `.keel/` and `deploy/`, never a source. The evaluation shares nothing with the command that starts it, so a dev server's globals, an earlier evaluation's writes and a leftover timer cannot change or hold a run; the views evaluated inside the command's process, the proxy over its global object and the marks in message text are withdrawn after three review rounds broke the cache's guarantee through them. Each evaluation costs one process start (33 to 37 ms measured); a warm check starts one, for `tokens.ts`. Node 22.13 becomes the floor. RFC 0251 adds its `prerender` kind and grants to the same `evaluate`, and this lane no longer waits for it. Not held: the clock and random values; facts Node gives without a file to code that gets past a view, for which no route is known; Windows is unverified. k.derived's clauses state the cost as counted work (no evaluation when nothing changed, one after a loaded file changes), read from the json summary's `counts`; durations are documentation only. `keel pack --check` becomes `--frozen`.
