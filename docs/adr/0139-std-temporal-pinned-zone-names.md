# ADR-0139: `TimeZone` names come from a pinned IANA list and are kept as written (RFC 0117)

**Status:** accepted (orchestrator under the owner's standing leave, 2026-11-17).

**Context.** `TimeZone` required a name that `Intl.DateTimeFormat` reports back unchanged. V8 reports `Asia/Kolkata` as `Asia/Calcutta`, so current names failed on Node while Firefox and Safari accepted them; `gen` indexed into `Intl.supportedValuesOf`, so one seed gave different zones on different hosts.

**Decision.**
- D1: a `TimeZone` is `UTC` or a Zone or Link name of the package's pinned IANA tz database release, spelled exactly as there (case-sensitive); it is kept as written. `parse` reads only that list, never the host's `Intl`.
- D2: `gen` draws from that release's Zone names, so seeded runs repeat on every host.
- D3: the list lives in `packages/std-temporal/src/internal/zoneNames.ts`, generated by `tooling/generate.mjs` from `tooling/tzdata.source.zi` (the name lines of tz release 2026f). `generate.mjs --check` fails when the file differs from the source. A new IANA release replaces the source and ships with a changeset.
- D4: where a zone is used, `plainDateOf` and `formatInstant` throw `RangeError` for a pinned zone the host's `Intl` lacks (a Boundary shows `keel.unexpected`); std.schedules `schedule` throws E2551 for such a zone.

**Alternatives.**
- Any name `Intl` accepts, no list: several texts per zone, and `gen` still follows the host.
- Canonicalising in `parse`: not a format type, and hosts disagree.
- Zone names only: values written on Node (`Asia/Calcutta`) would fail.
- `parse` also asking the host's `Intl`: a client with older tz data refuses a value the server stored, and `gen` draws names it refuses.
- `plainDateOf` and `formatInstant` returning a `Result` with `temporal.unknownZone`, or falling back to `UTC`: two signature changes for a rare host, or a time shown hours off with no sign of it.

**Consequences.**
- One value text per name on every host; Node accepts current names.
- A value decodes on every host; a host with older tz data fails only where it formats or converts that zone.
- `@keel/std-temporal` carries the list in its client entry: 4,949 bytes gzip against a 5 kB budget.
