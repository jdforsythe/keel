# ADR-0028: The service declaration file is `<M>Api.schema.ts` (RFC 0039)

**Status:** accepted
**Context.** k.services put the endpoint declaration `<M>Api` in `modules/<m>/api.schema.ts`, and `@keel/services/openapi` generated it there. k.check E1752 (principle 3) requires a file's name to equal its one export, so every generated service tree failed `keel check`. The k.scaffold clause 1 service case was skipped, and k.scaffold could not flip (backlog 0108, rfc:0036 Remaining 2).
**Decision.** The declaration lives in `modules/<m>/<M>Api.schema.ts` and exports `<M>Api`. `api.ts` keeps exporting `api` and imports `./<M>Api.schema.ts`. `openapi()` keeps its `{ schema, service }` result, and only the import inside `service` changes. `scaffold service` derives the file name from the module id (`<Pascal(id)>Api`), the same rule k.services uses for the export name. E1752 is unchanged. Scaffold conformance runs the real `keel scaffold service --openapi` and then `keel check` + `keel test`, and replays the printed `--dry-run` for `transaction` and `service`. k.scaffold is `conformance-covered`.
**Alternatives.** An E1752 exemption for `api.schema.ts`: a second naming rule in check. One file per operation: more files, and the declaration still needs a name. Parsing the export name out of the generated text in scaffold: this couples scaffold to services' output format.
**Consequences.** Client call sites (`import { api } from './api.ts'`) are unchanged. Existing `api.schema.ts` files must be renamed by hand, and E1752 points at them. `codemod rename` treats `routes.href("id", ...)` (RFC 0041) like the free `href`, because route ids are rewritten as whole tokens in every string literal.
