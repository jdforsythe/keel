# ADR-0214: a channel follows changes an app data commit names (RFC 0192)

**Status:** accepted (orchestrator, D98).

**Context.** std.channels sends `saved` after a server store save, and app data in Postgres (k.data, std.postgres) is no store, so `apps/household` keeps a counter store that each write action bumps after its commit. A forgotten bump leaves pages stale, two concurrent bumps make a committed write answer 409, and a bump reaches only the streams in its own process, so a second replica's streams hear nothing.

**Decision.** A write names the channel it changes inside its transaction: `t.changed(channel, params)` on a std-postgres transaction (or the database object, as its own transaction) is `pg_notify('keel_changes', ...)`, delivered after commit, once per channel and params, never for a rollback. Each process holds one `LISTEN` connection per URL; PGlite and sim deliver in process, sim in step order with no timer. `channelRoute(..., { follows: [db], stores? })` follows any capability whose object has `follow(channel, key, on)`; a followed change is `{ kind: 'changed' }` to each member stream of that channel and params, after `member` runs again, and `live` re-reads on it. Events carry no capability, params or row. A lost listening connection ends its streams as a drop, and the reopen's `reset` re-reads. Store `saved` and `message` stay in the serving process.

**Alternatives.** The documented counter store (keeps the 409 on committed writes and the per-process reach); a separate topic declaration (a second name for the channel and a params mapping); channels following a table (Keel-installed triggers in the app's database, no row-to-params mapping); a kernel signal primitive (a publish and subscribe surface in the kernel, raised outside the data transaction, still without a cross-replica transport); a broker in std-channels (an extra service, raised after the commit).

**Consequences.** The kernel and the channel declaration do not change. std.postgres gains `changed`, `follow`, one listening connection per URL per process and E2460 (params failing the channel's schema, or a payload over 7,900 bytes). std.channels gains `follows`, the `changed` event, and `stores` becomes optional. The household deletes `changeStores.ts` and `Changes.schema.ts`; its actions lose `stores` and the bump. Cross-replica delivery of store saves remains for a later RFC.
