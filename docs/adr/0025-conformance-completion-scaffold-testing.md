# ADR-0025: Conformance completion for k.scaffold and k.testing (RFC 0036)

**Status:** accepted
**Context.** The freeze review left three partial k.scaffold clauses: the check after every generator was a proxy (relative imports resolve) that skipped `transaction` and `service`, the dry run compared edit sets instead of the printed diff, and `turbo.json` was compared with itself. In k.testing, the `fire` resource test was capped at 24 microtask hops because the harness stopped after 32 quiet hops, and the harness restored stores from `snapshot()`, which drops log `meta` (rfc:0028, backlog 0104). Twelve scaffold headers used `// Clause:` (W1706), so the ledger counted none of the seven clauses. Backlog 0061.
**Decision.** Scaffold conformance runs the real `keel` binary (`packages/cli/src/bin.ts`, run by node from source) as a child process. It runs on the generated tree, written to a temp directory whose `node_modules` links the workspace packages. `keel check` and `keel test` must both be clean, and the test count must cover every generated test file. The dry run is replayed by applying the printed unified diffs and comparing them byte for byte with the files the real run writes. `turbo.json` is compared with a task graph that the test computes from the module manifests. `@keel/scaffold` gains `transaction` and a `service` placement op. The cli converts the OpenAPI document with `@keel/services/openapi`, because scaffold cannot import services. A file whose first line is a generated marker is read-only to every operation (E1005). Generated projects set `test.environment: "happy-dom"` in `vite.config.ts`. In the harness, a `settle` round whose hops saw no change waits one `node:timers` `setImmediate` turn, so the microtask queue drains first. A loop that keeps writing never reaches that wait and still ends in "fire did not settle". Snapshots taken for restore keep `meta`.
**Alternatives.** Draining on every round: a microtask loop that never ends would starve the turn and hang the run instead of failing. Importing `@keel/cli` or `@keel/testing` from scaffold conformance: S0003, a later package in deps order. Running only `@keel/check` in-process: `keel test` stays unasserted. Raising `ROUND_HOPS`: still a finite cutoff below an arbitrary chain. A global `setImmediate`: a test that fakes timers would hang the harness. A scaffold-side OpenAPI converter: two generators for one format (principle 1).
**Consequences.** The suite needs no build, but each `keel` call adds about 1 s, so each generator case takes 2-3 s. Under Stryker these cases run the repository's unmutated cli. Only the tree they check comes from the mutated scaffold. The cli must route `scaffold transaction` and `scaffold service --openapi` (today they are `PENDING`, and `scaffoldInput` no longer type-checks against the wider `Op`). Rung promotion through `keel ledger` belongs in cli conformance, because testing may not import cli.
