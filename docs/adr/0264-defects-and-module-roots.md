# ADR-0264: k.errors and k.reactive: `defect`, `attempt`'s `expect`, module roots (RFC 0242)

**Status:** accepted (orchestrator, 2026-11-26), for the operator to confirm.

**Context.** The stdlib on the library format is held to the app's rules, and its packages met E1451 (no `throw`), E1452 (no `catch` but `attempt`) and E1207 (no detached scope) by wrapping each site in `unsafe(`: 19 of the main line's 33 calls and 26 of `lane-std-formats`' 41. The kernel had no sanctioned way to raise a bug, no catch that hands back what was thrown, and never named the root scope a module's top level already gets.

**Decision.**
- `defect(message, code?): never` and `isDefect(x, code?)` in `@keel/schema`: the one way code held to the rules raises an unexpected failure. An `Error` named `Defect`, message `<code> <message>`, `code` non-enumerable; it goes where any throw goes, with nothing added. E1455 holds a given code to a literal `E` and four digits.
- `attempt(fn, expect)`: `expect` maps a thrown value it recognizes to a `KeelError` (the `err`); `undefined` throws the very value on; a defect never reaches `expect`.
- `try`/`finally` without `catch` is the cleanup form, no E1452.
- An `unsafe(` range lifts neither E1451 nor E1452; E1451's message names `defect`.
- A module root is a scope made while no scope runs; state kept for a module's life lives in one, entered later with `run`. E1207 is judged in every file but a kernel package's own, `unsafe(` ranges and libraries included.
- R1013 (`keel review`, medium): a `defect` on a `Result`'s `err` branch.

- After review: a type predicate claiming a signature or a type parameter is E1762 outside `unsafe(`; key guards (`isStore`, `isTransaction`, `isSchema`, `isDefect`) are none; R1015 lists the rest. E1452 also refuses control leaving a `finally`. A module root is only the scope the compiler runs a module's top-level statement in; any other ownerless `scope` is the E1208 defect, and check reports `scope` and primitive calls after an `await`. A failure a caller could handle is a value: std.postgres' `postgres.database { sqlstate }`, its E2461 defect for the rest, `follow`'s `lost`. R1013 reads flow. The defect mark is `Symbol.for('keel.defect')`; `expect` never sees a wrapped defect. E1451, E1452, E1455 and E1207 resolve callees by symbol; E1451 adds `Promise.reject`, E1452 `.then(f, g)`, `allSettled`, `any`. No new section: the key sits in k.errors, callee resolution and E1762 in k.unsafe.
- Second review: a test's root is `scope(fn, { detached: true })` (test code is not app code, so E1207 does not judge it) or a harness that owns what it makes; the kernel's entry points make roots as kernel code; a script reaches Keel state through them. No test file is compiled, so its top level has no module root. structure-lint reports S0020 and S0019.

- Third review (D21 to D40; where they differ from a line above, they replace it). The wall test is the acceptance test: ordinary code ported by the first offered fix, else the edit the message names, ends correct, as fix chains in conformance (k.fixes). A failure is a `KeelError` in a `Result` (error type bounded, optional `cause`, `causedBy` and `in`) or it is thrown. `attempt(fn, expect)` with `expect` required: a value is `ok`, a returned `Result` is itself, a defect passes unseen, any other throw is `expect`'s to claim or pass on; `err` takes a `KeelError` only (E1458). Throwing built-ins are E1457 bare; `S.parseJson` is the total form. A fix is offered only when its output compiles in place, behaves as before and leaves nothing behind: E1451 for a thrown `KeelError` where the return type takes it, E1452 for cleanup-and-rethrow to `try`/`finally` with a flag, E1455 for a missing `cause`, nothing else. Module state on a server: a write to a node a module root owns, or making one there, while a request is served is the defect E1256, by owner and not by maker; check reports a `set` on a module signal and a write to plain module state (E1260) in server code. Identity is the kernel's record in the realm, never a key; made values are frozen, copies are refused (E1515), and the server reads schemas from the maker's record. E1762 accepts five proofs and reports every other body. `Secret` has no statics (E1764). A production log holds a thrown value's class, known code, keyed fingerprint, site and causes, never its text; `KEEL_LOG_THROWN` opens at most 24 hours of text (E1596). A `defect` message is a literal with values in `data`. On PGlite the driver refuses a `statement_timeout` by its value after every statement; class `08` is split between `keel.unreachable`, `postgres.database` and E2461. The guarantee is stated in layers (k.errors Layers).
- Breaking review (D41 to D56; where they differ from a line above, they replace it). Code that runs other code and must survive its throws calls `supervise(ctx, id, fn, failed)` (`@keel/ctx`): every throw, a defect among them, is reported once as a throw and the call gives `err(failed)`, a value made before the work runs; kernel packages and libraries may call it, review lists each call (R1018), app code may not (E1461). An `expect` is a function check can read; it claims only where a test of the thrown value selects the branch (E1452) and carries a number, a boolean or a closed code out of it, never text (E1460). A `KeelError` is made by `make` only, with a literal message, `keelError` holding the kernel's codes (E1458, E1460). `ok` refuses a `Result` in check's type pass and at run time (E1459), not in its TypeScript type. Identity is held in a binding of the maker's package under no key; a realm holds one copy of each kernel package, a second being E1765 at evaluation, check and build; the `keel.` registered symbols are the kernel's (E1766). A coded refusal at start prints its own code, message and `see` and exits 1, and E1577 is for what Keel did not raise; inside the `KEEL_LOG_THROWN` window E1577's one record holds the scrubbed text. E1260 and `processSlot` leave k.shared until built: the spec says a request's write to plain module state is refused by nothing. Three new sections: k.supervise, k.expect, k.realm.

**Alternatives.** After the breaking review: a total `expect` for supervisors (it never sees a defect, and app code would write it in disguise); `supervise` in app code (the shortest way past E1452); a `supervise` whose failure is a function of the thrown value (a second catch); keeping the realm record under a registered symbol (the forgery's door) or a `WeakSet` per copy with no check for a second copy (silent disagreement); a parameter type on `ok` that refuses a `Result` (it refuses every generic caller); stripping an error's `message` from production responses (pages show it to people; a literal already carries no value); describing E1260 before it is built. Earlier: Leave the wrappers as `unsafe` (the count measures package count, not escapes); `invariant(cond)` beside `defect` (two ways); a second catch returning the raw value (unserializable, two catches); a required code now (ten std sections need codes first); a `moduleScope()` export or `detached` for libraries (a second way, or the escape E1207 exists to refuse).

**Consequences.** After the third review: about 150 one-argument `attempt` calls and about 40 interpolated `defect` messages are rewritten; the `unsafe` count goes from 33 to 30 on this lane and then moves by what E1762's five proofs report in the kernel's `src/`; RFC 0245 gives up its two `catch` fixes for k.fixes; E1260 waits for RFC 0251's `processSlot`; six sections are added and none is over its limit. Before it: For the three patterns `unsafe` falls to 14 on the main line, 15 with `lane-std-formats`, `axeSync`'s cast counted again. E1762 adds the predicates no key guard replaces: at least 2 by reading (testing `isStateOf`, std-channels `holds`), and whatever its first run finds among the kernel's predicates; each was a cast the count never held. No owner survives an `await`; code after one uses a captured scope's `run`. std.db keeps defects behind k.persist's rejecting storage contract until a later RFC. No stdlib package or library can detach a scope or throw inside `unsafe`. A third-party library raises, catches and keeps module state with public exports only. Kernel packages keep their own throws. k.errors, k.check and k.escapes read `implemented` until their new clauses are covered. After the breaking review: the stdlib's supervisors move to `supervise`; about 45 hand-written kernel errors become `keelError` calls; a project that resolves a kernel package twice fails check until deduped; the three wall-test patterns wait for a re-base of the keel skill's token target, which this lane does not raise.
