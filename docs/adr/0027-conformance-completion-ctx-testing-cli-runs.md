# ADR-0027: Conformance completion for k.ctx and k.testing through real `keel` runs (RFC 0038)

**Status:** accepted
**Context.** k.ctx "`keel test` runs under sim by default" was asserted only for its environment half (`KEEL_TEST=1` makes `createCtx` sim, rfc:0032). k.testing clauses 8 and 9 were asserted through the `ledger` and `ledgerDiff` engines, not a `keel ledger` run (rfc:0036). Both are proxies under the strict verdict (task 0034 D1). The k.ctx Conformance paragraph was prose, so the ledger had no k.ctx clause items. The ledger's unsafe count missed `unsafe<T>(...)`. Backlog 0107.
**Decision.** cli conformance owns the CLI halves. It spawns `node packages/cli/src/bin.ts` over temp projects under the OS tmpdir, never under the repository. Their `node_modules` links `@keel/*` and the toolchain. The child env drops `VITEST*` and every `KEEL_*`. The `keel test` case pairs with a control: plain vitest on the same project must see a real ctx, so the test fails if `keel test` stops setting the contract. A test observes the ctx through a registered probe capability and the clock, net and random of `createCtx({})`. The committed ledger in the `--diff` cases is the file `keel ledger --write` produced. k.ctx Conformance has one bullet per clause. `unsafe<T>(...)` counts as an unsafe use.
**Alternatives.** In-process `run()`: `keel test` would mutate the runner's own env, and the control run could not be separated. Spawning from ctx or testing conformance: deps order (S0003). Hand-written ledger files: the stored file would not be what the command emits.
**Consequences.** k.ctx and k.testing are `conformance-covered`. Each spawned `keel` call costs about 1 s, so the three files take about 5 s. `keel ledger` ranks from test sources and does not execute them. "Passing" is established by the `keel test` run over the same tree, which CI runs before the ledger. k.ctx#1-5 hold `none` in the ledger until the ctx suite's headers quote their clauses.
