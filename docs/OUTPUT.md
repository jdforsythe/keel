# Output contract

Every `keel` command and every `pnpm` script has one data model and three renderings. The agent-facing rendering is the default.

**Mode.** `--format=compact|json|pretty`. Default `compact` when stdout is not a TTY or `KEEL_AGENT=1`; `pretty` on a human terminal; `json` for tooling. A built server (`node server.mjs`) takes no flags: `KEEL_FORMAT=json` sets its mode.

**Diagnostic shape** (check, test, build, bench, audit, session):

```
E1042 src/cart/add.tsx:14:7 write to state not owned by this component
  fix: -  cart.items.push(item)
       +  tx.cart.addItem({ item })
```

Fields: `code` (stable, one letter and four digits, never renumbered) · `path:line:col` · `message` one line of at most 89 characters (UTF-16 code units; a longer one keeps 86, or 85 rather than split a surrogate pair, then `...`; k.check Diagnostics), the same in every format · optional `fix` as a unified diff hunk · optional `see` (spec section id) · optional `detail`, lines a failure prints below its head, each indented two spaces (an e2e test's `server:`, `screenshot:` and `trace:` lines, k.e2e-page). The code is the key to `keel explain E1042` and `keel docs --for E1042`. Compact and pretty print `see` as `see: keel docs <id>`; json keeps the id.

**Compact rules**
- Passing tests, successful builds, clean files are silent. One trailer line: `ok 412 tests, 0 failed, 3 skipped (1.8s)` from a `pnpm` script; `keel` commands print the same line without the timing. A tooling script's trailer is `ok <name> <count> <unit>, ... (1.8s)` (`ok check 81 tasks (29.1s)`), and a script with a line of its own prints it whole (`ok voice-lint 2911 files`). A failed run ends on one `fail <name>` trailer (`fail build`) and prints no `ok` line.
- Group by code, cap at 5 per code, then `... +17 more E1042 (keel check --code E1042)`; a tooling script prints `(--code E1042)`.
- Stack traces: app frames only, max 5, relative paths.
- Test failures: compact diff of serialized state, never two dumps.
- No progress bars, spinners, colors, banners, timestamps in compact or json.
- Relative paths. No ANSI.
- Every command accepts `--quiet` (trailer only) and `--limit N`.
- `--verbose` exists; skills say to use it only with a stated reason.

**JSON.** NDJSON: `{"kind":"diag","code":"E1042","path":…,"line":…,"col":…,"message":…,"fix":…,"see":…}` per line, then `{"kind":"summary",…}`. Other commands emit their own record kinds (`ledger`, `property`, `example`, `docs.area`, `docs.entry`, `docs.section`, `docs.skill`, `docs.cite`, `docs.code`, `docs.term`, `docs.hit`, `explain.text`, `inspect.section`, `inspect.store`, `scaffold.edit`, `quickfix`, `invalid`, `unparsable`, `session`, `session.issue`, `conflicts.race`, `report.tally`, `review`, `mutate.run`, `ledger.mutation`, `session.monitor`, `csp`, `evidence`); warnings are `diag` records with a `W` code (W1005, W1556, W1557, W1706). With `--limit N` json caps too; otherwise json is uncapped.

`session` (std.sessions): `{ kind, id, fingerprint, route, events, inputs, error, file }`; compact `7f3a9c01d2e4 orders.show 42 events orders.locked`, `ok` for no error, ` -> <file>` when one was written. `session.issue` (`keel-session-action`): `{ kind, fingerprint, action, issue }`, `action` one of `created`, `updated`, `commented`; compact `7f3a9c01d2e4 created #12`.

`ledger.mutation` (k.ledger): `{ kind, file, score, survived, fresh }`, one per mutation claim of `keel ledger`, `score` in percent; compact `src/store.ts 84.2% 3 survived`, with ` stale` after it when `fresh` is false.

`csp` (k.security): `{ kind, directive, blocked, route }`, one per accepted policy report, `blocked` one of `inline`, `eval`, `trusted-types` or the blocked URL's origin, `route` a route id or `-`; past 100 reports in 60 s the window's end writes `{ kind, dropped }`.

`review` (k.review): `{ kind, code, path, line, col, message, protection, opt, danger, novelty, loud, id, reason? }`, one per finding; compact `R1053 modules/a/x.ts:4:9 critical new module specifier computed at run time`.

`evidence` (k.evidence): `{ kind, dir, at, keyId, files }`, one per verified bundle; compact `ok evidence evidence/2026-11-10 6 files key 3f2a9c01d2e4b5a6`.

`session.monitor` (std.monitor): `{ kind, origin, transactions, runs, file }`; compact `ok session monitor 12 transactions, 340 runs -> .keel/monitored.json`.

`report.tally` (std.report): `{ kind, id, rows }`, `rows` of `{ key, n }` by `n` descending, then `key`; one per tally section `keel report` reads; compact `orders.status paid=3 open=1`, `orders.status 0` without rows, then `ok report 1 tallies`.

`conflicts.race` (std.conflicts): `{ kind, code, path, store, entry, against, reason }`, `code` E2701 (a race) or W2702 (an unchecked entry), `path` the file the analysis read; compact `E2701 <file>:1:1 race api.editTodo #6 over api.editTodo #4, api.addTodo #5 on api.board`, or `W2702 <file>:1:1 unchecked api.editTodo #6 on api.board (folded)`.

**Server log.** A built server (`node server.mjs`) and `keel dev` write one record per line through the app's `log` sink, in compact or json. A `req` record is `GET /orders/7 orders.show 200 12ms` (method, path, route id omitted when none matched, status, time) or `{"kind":"req","method":…,"path":…,"route":…,"status":…,"ms":…}`; a `diag` record is `E1554 <message>` or `{"kind":"diag","code":…,"message":…,"see":…}` with `frames` (at most 5 app positions) for a throw; `csp` records are above. Each record is one line of at most 8,192 characters plus a `req` record's route id (k.serverlog): a control character, U+2028, U+2029 or `…` in a written value is `\u` and four hex digits, and a message or path past 2,048 characters, or a frame or method past 256, ends in `…+<n>`, `n` the characters left out, so `…` in a record always marks a cut. A value marked `.pii()` or a revealed `Secret` is `[pii]` or `[secret]` in every record of its request, the `req` path included (`GET [secret] app.reset 200 4ms`). When the sink's `write` throws on the last `diag`, stderr gets the one fixed line `keel.unexpected log write threw, records lost (once per process)`, once per process, holding no value. That record follows `KEEL_FORMAT` as the log does: under json it is the `diag` object `{"kind":"diag","code":"keel.unexpected",…}`.

**Budgets, enforced in CI** (`tooling/budgets.json`): `keel check` (the real checker, compact) on a copy of golden app 1 with 10 injected errors <= 600 tokens; `keel explain` <= 300, MCP `tools/list` <= 2,050 tokens; `keel test` with 3 failures <= 400 tokens; the spec map <= 400 (`pnpm spec`), each area <= 500 (`pnpm spec <area>`) and each `spec/` section <= 3,100 tokens, so map, area and section fit principle 8's 4,000. Installed docs (k.docs): `keel docs` <= 900, each `keel docs <area>` <= 500 and `keel docs --for E1451` <= 400 tokens, compact, in a project with every package installed; each packed section's text <= 3,100 and each skill's <= 3,700; the `AGENTS.md` Keel block <= 600. Package size (`size` entries, every package; `platform: "node"` for node-only ones): the package's own code bundled by esbuild from `src/index.ts` (a subpath entry from `src/<sub>/index.ts` or `src/<sub>.ts`), minified, dependencies external, gzipped. A size entry is the package entry's own code, bundled minified with dependencies external, then gzipped; a `browser` entry loads each server-only file (`*.server.*`, `*.guard.*`) as the stub the compiler's browser build loads (`browserStub`, `tooling/size.mjs`), so code no browser receives is not counted, and a `node` entry counts it.

**Tooling codes.** Each `pnpm` script owns a code prefix (`T` is a failed test from `keel test` and the test reporter; T0002: temp folders a run's tests or the code they ran left in its temp root, `tooling/test-tmp-global.ts`): `B` budgets, `D` docs-freshness, docs-pack and docs-check (D0001: a doc with more than 50 commits to its subject since it was verified; W0014: a doc with no `subject:` line, aged on all of `docs/`; D0002: a spec section no package owns in `tooling/docs-owners.json`; D0003: a section two packages own; D0004: an owner that is not a package; D0005: `docs-pack` run where there is no package to pack; W0013: an owner entry naming no section; D0019: a spec section in no area or in two; D0020: an area file no map row names, a map row with no area file, or an area row naming no section; D0021: in a section title, an area title or a `holds` outside backticks, a word on `tooling/titles.json`'s `clipped` list (the message gives the words to use), a word mixing letters and digits or holding two capitals that is neither a diagnostic code nor on its `names` list, or a `holds` over 90 characters; docs-check over the published skills in `packages/cli/skills`: D0006: a `ts` or `tsx` fence that does not type-check; D0007: more than two `ts fragment` fences; D0008: an `import { ... } from '@keel/...'` naming a package or export that does not exist; D0009: a cited diagnostic code in neither the explain catalog nor a spec section, or a range holding none; D0010: a cited section id with no spec file; D0011: a repo-only path or command; D0012: size over the target or `name`/`description` frontmatter missing; D0013: `.claude/skills/<name>/` differs from the published skill (`node tooling/docs-check.mjs --write` rewrites the copies); D0014: a fence importing a relative path no other fence of the skill provides; docs-check over the scaffold's `AGENTS.md` and `CLAUDE.md` templates, rendered with the published skills: D0015: a cited diagnostic code in neither the explain catalog nor a spec section, or a range holding none; D0016: a cited section id with no spec file; D0017: a repo-only path or command, `.claude/skills/` allowed; D0018: the `AGENTS.md` Keel block over `docs.agents`; the voice lint covers the rendered templates), `E` spec, turbo, handoff and mutate plumbing (E0016: a `--shard` that is not `i/N`, or given with `--mutate`; W0015: a shard that wrote no report to merge), `F` format-check, `H` hygiene (H0001: a home-directory path in a tracked file, `/Users/<name>` or `/home/<name>` but `/home/runner`; H0002: operator speech quoted under `docs/` or `tasks/`; H0003: a licence other than UNLICENSED in a package.json, the root without it, or a LICENSE not stating all rights reserved; H0004: a `packages/*` package not `"private": true`; H0005: a personal word or email listed by hash in `tooling/hygiene.refuse.json`; H0006: with `--launch`, the placeholder security address in `SECURITY.md`), `M` mutate (M0002: a `mutation-justified.json` entry that matches no survivor of its package's report; M0003: a malformed entry; W0016: a package with that file and no report), `O` orphans, `S` structure-lint (S0010: a writing `pnpm evidence:report` while a spec section, unit manifest or test file differs from HEAD; S0011: the committed ledger file differs from what `keel ledger` produces from the tree; S0012: a file in a `packages/std-*` package's `src/` or `unsafe/` names a kernel `internal` entry (import, re-export, `import()`, `require()`) that `tooling/deps.json` `internal` does not list for that package (k.parity); S0009: a runtime entry of a `packages/std-*` package, any `exports` key but `./tools`, a key under it and `./module`, reaches `@keel/cli`, `@keel/check`, `vite`, `vitest`, `typescript` or `oxc-*`; the diagnostic sits at the importing file and names the chain from the entry; S0015: a fast-check `assert`, `check`, `sample` or `statistics` call with no `seed` in its options and no seeded top-level `configureGlobal`, in a package file (conformance included), a tooling or eval file or an app's or example's test file; S0016: a time of 100 ms or more written as a number in test code (a package's tests and conformance, tooling's tests and smokes, an app's or example's test files) at a `timeout` property outside a vitest call's options, `AbortSignal.timeout`, a time-named variable or default, or a `Date.now() +` deadline, not through `testTime` or `fixedTime`, a conformance file's listed in `tooling/hard-times-conformance.json`); S0018: a `mkdtemp` or `mkdtempSync` call in a package's, tooling's, app's or example's test files, not through `tempDir`; S0017: a test that runs `properties`, `simulate` or fast-check's `assert` and declares no options, in an app's, example's or library's folder whose vitest config is not `keelConfig`, so vitest's flat 5 s default bounds it, conformance-guard and generate, `V` voice-lint (V0003); `W` and `I` codes are advisory and never fail the run. `R` codes are `keel review` findings (k.escapes): their exit follows their loudness (k.review), never their letter.

**Internal rule.** Keel's own scripts, runners, and hooks obey this contract from task 0001.
