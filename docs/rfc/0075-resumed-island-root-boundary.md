# RFC 0075: a resumed island has the app root's Boundary; intrinsic calls keep their import

Status: accepted (ADR-0064, 2026-11-09), amended the same day after review and red team (backlog 0278-0280). Found by the S1 exit drill. Applies WORKFLOW RFC default 1 (a stdlib need that exposes a kernel gap is met by a kernel change, not a workaround), default 2 (one way) and, for `data.at`, default 4 (privacy by default). It restores the k.errors sentence "the app root has a default one" for server-rendered pages, where the app root is the set of resumed islands, and makes it explicit for `resume`. No app-facing API changes.

## Problem
1. **Resumed islands had no root catcher.** `resumeIsland` created the island owner with no catcher, so a throw from a binding or event handler reached `report` with no Boundary and was rethrown: an uncaught page error. Nothing reported it to the ctx, so no observer, and no session recorder, saw it. `mount` wraps its tree in a root Boundary that reports and renders `<pre data-k-error>`; `resume` did not, although k.errors says the app root has a default Boundary.
2. **`data.at` of a handler throw was often empty.** `on(target: Element, …)` (k.ui base elements) took `target.id` at registration, before the element's id is set, so a handler's throw had `data.at` `""` under `mount` and `resume` alike. The session fingerprint hashes `data.at`, so every handler error on a page shared one fingerprint.
3. **The compiler stripped referenced intrinsic imports.** `lowerFile` removed any `@keel/runtime-dom` import made only of intrinsics, even when the file called them as functions, so a plain `.ts` module calling `If(...)` or `Boundary(...)` failed in the browser with "If is not defined".

## Proposal
### 1. The island root Boundary (k.errors)
Each island `resume` resumes gets the root Boundary `mount` gives its tree (`internal/rootCatcher.ts`), installed as the island owner's catcher and, as `mount`'s `renderUnit` does, as the `onError` of the island's scope on both the claim and the client re-render path, so an `effect` or `computed` created in the island component that throws on a later `signal.set` is caught too (`data.at` the stamp at the island's place, 2b; the review found it escaping `set` unreported, backlog 0278). It is armed once the island's claim succeeds: until then a throw passes through as before, so a claim that throws stays a mismatch (E1253) and the island re-renders on the client. On the client re-render path the catcher is armed before rendering, so a throw there renders the fallback in place of the server element instead of escaping `resume`. Once armed, the first throw:
- becomes `keel.unexpected` with `data.at` (`toUnexpected`, as a Boundary does);
- is reported to the ctx as an `error` event (k.ctx Observers), so the ctx keeps it for a late observer (RFC 0074);
- tears the island down (owner, scope, delegation root) and replaces its nodes (the server element, the client-rendered element, or every node of a client-rendered fragment) with the root fallback `<pre data-k-error="<at>">` holding the message, the same node `mount`'s root Boundary renders;
- disposes its own state signal, which lives in a detached scope of its own so it outlives the scope `resume` runs in.
Later throws under the same island are ignored. When the client re-render throws, the island's queued pre-resume events are dropped (`eventQueue.resume(el, null)` removes them before the fallback replaces `el`). Other islands have their own owners and catchers and keep working. Every resume entry goes through `resumeIsland`: ui-only island roots, islands with eager children (the E1253 client re-render path), and node and static deployables alike. `mount` is unchanged and still calls `onError`; `resume` has no `onError` option.

### 2. `data.at` of a handler throw
Decision (default 4; backlog 0280): `data.at` of a handler throw is only ever an id the compiler wrote, never an element's runtime `id`. Sessions never redact `data.at`, upload it verbatim and hash it into the fingerprint, and `<li id={user.email}>` would put app data there. A handler's throw carries the id `on` registered it under (a compiled `on("<id>", …)` names the element's literal or derived id), else the `data-k` of its element or of the nearest ancestor with a non-empty one (`internal/stampOf.ts`), else `""`. `on(element, …)` (k.ui base elements) registers `""`, so its throw resolves the stamp when it throws. A k.ui base element with a literal `id` is compiler-known (ids.json lists it), so the compiler stamps it: a JSX tag `<Button id="cart.buy">` and a source call `Button({ id: "cart.buy", … })` (an `@keel/ui` base element import, object literal argument, string literal `id`) are both emitted as `stamp("cart.buy", Button)(props)`, which sets the built element's `data-k` to the id when the element is bound (it already has `data-k`, so no new island). An `id` from an expression is never stamped. Without the stamp, a base element's handler error would lose the literal id it had before this RFC (`on` read `target.id`), which the follow-up review measured on golden-1 and apps/sessions. Delegated dispatch and non-bubbling listeners resolve it the same way, under `mount` and `resume` alike. `data-k` is the compiler's stamp: the `attr` op binds nothing for it, so a bound `data-k={…}` cannot carry app data into `data.at`. Binding throws keep the id their op passes.

### 2a. A computed's throw surfaces in its reader (k.reactive)
Found by the live S1 drill: the same click on apps/sessions `ops.home.limits` reported `data.at` `"ops.home"` after `resume` (fingerprint 1a9e17423979) and `""` in replay under `mount` (90b8fb7c0acb), so E2004 and no issue. The click's write makes the computed that a `text` binding reads throw. `refresh` verified the effect's Check sources before running it, so the computed threw outside the binding's own catch and reached the nearest scope `onError`: the island scope's (`data.at` the island id) or `mount`'s root unit (`data.at` the mount host's id, `""` in the harness). Neither is "the element id where the throw surfaced". Decision (second amendment after review and red team, backlog 0284-0286): a computed keeps a throw as its outcome until a source changes. It runs once per commit (the check that pulls it and every reader see one evaluation), each reader's `get()` throws the kept error, a read without a source change does not rerun it, and a throw or the first value after one always counts as a change, without consulting `equals`. A binding then reports its own element (`ops.home.limits.list`) on every path, and a reader that saw the throw reruns when the computed recovers, also to the value it had before the throw (the first version rethrew from the check and reran the computed in every reader, and the equality cutoff hid a recovery to the old value: readers, chains, `resource` fetchers and store `select` stayed on the error). A computed with no source read before its throw keeps the error, as a computed with no sources keeps its value.

### 2b. `data.at` of a throw at no element (k.errors)
An island component's own top-level `effect` or `computed` throw reached the island scope's `onError` with `data.at` the island id after `resume`, while under `mount` and replay it reached the root unit's with the mount element's id (`""` in the harness): such a session never reproduced (E2004, backlog 0285). Decision: a throw at no element of its own (the root component's effect, computed or render) has `data.at` the `data-k` stamp at the root's place, by one rule on both paths: `mount` passes `stampOf(el)` as its root Boundary's `at` (an optional `root` argument of the `boundary` op), and `resumeIsland` uses `stampOf` of the island's parent for its scope `onError` and a failed client re-render. k.errors says `data.at` is the element id where the throw surfaced; such a throw surfaced at no element, so the value is the root's place, which is compiler-known (only a `data-k` stamp counts) and the same however the page was rendered. The island id was rejected: `mount` has no island, and a route id is in the fingerprint already.

### 3. Intrinsic calls keep their import (k.component)
Decision: supported. Intrinsics are runtime functions (`If` is the `cond` op wrapper), and a file without JSX has no other way to use them; k.ui base elements are already called as functions in plain `.ts` modules (apps/sessions `Home`). JSX stays the way in `.tsx`, where the compiler lowers the tags to ops. The compiler removes a `@keel/runtime-dom` import only when every binding it imports is an intrinsic used solely as a JSX tag (`a.identsByName` has no value reference to it); a binding called, passed as a value or named in a parameter or destructuring default keeps the import. For the defaults, `analyze` records as bindings only the names a pattern declares (`patternIdents`), not whole patterns, so a default (`function P({ pick = If })`, `const { pick = If } = o`) and a computed key are reads (the red team found such an import stripped, backlog 0279). E1251 (`noRuntimeOpImport`) is unchanged: it forbids `@keel/runtime-dom/ops`, and intrinsics come from `@keel/runtime-dom`, which app code may import (k.runtime API).

## Alternatives
- **Wrap each island in a `boundary` op at resume.** The op claims a `<!--[-->` region the server does not emit around an island root, so every island would mismatch.
- **Report but do not render a fallback.** Leaves a dead island looking live, and differs from `mount`.
- **`data.at` from the runtime `id` (item 2).** Specific fingerprints for every element, but app data (an email in `id={…}`) reaches sessions, uploads and fingerprints unredacted; default 4 rules it out.
- **Mark ids set by a binding and skip them.** The claim path sees server-rendered runtime ids before any binding runs, and k.ui base elements set `id` directly; the `data-k` stamp needs no tracking.
- **Arm the catcher before the claim.** A binding throwing during the claim would render the fallback instead of re-rendering the island on the client (E1253), changing mismatch recovery.
- **Forbid intrinsic calls with a check rule (item 3).** A plain `.ts` module would lose conditionals and Boundaries altogether, while base elements are called as functions there; it would be the more restrictive one way for no gain.

## Spec diff
- **k.errors** (922 -> 1,383 printed). **Boundaries**: "the app root has a default one" becomes "the app root has a default one, for a `mount` tree and for each island `resume` resumes: it catches what any Boundary catches, reports the error to the ctx (k.ctx `error`) and renders `<pre data-k-error=\"<at>\">` with the message in place of that tree or island (a throw while `resume` claims an island is a mismatch, k.runtime E1253). An `effect` or `computed` of an island's own component has `data.at` the island's id. A handler's throw has `data.at` an id the compiler wrote: the id `on` registered it under, else the `data-k` of its element or of the nearest ancestor with a non-empty one (the compiler stamps a bound template element's id, and a bound k.ui base element's literal `id`), else `\"\"`; an `id` set at runtime never is, and the `attr` op never sets `data-k`." **Conformance**: "After `resume`, an island whose handler throws reports one `keel.unexpected` with that element's id as `data.at` to an observer and renders the root fallback in place of the island; the page's other islands keep handling events; under `mount` the same throw reports the same error." · "After `resume`, an `effect` created in an island's component that throws on a later `signal.set` reports one `keel.unexpected` with the island's id as `data.at` and renders the root fallback in place of the island, also for an island re-rendered on the client after a mismatch; the other islands keep handling events." · "A handler registered with `on(element, …)` on an element whose `id` is set at runtime throws with `data.at` the `data-k` of its nearest ancestor that has one, else `\"\"`; `attr(el, \"data-k\", …)` sets nothing." · "In a compiled module, a throwing `onClick` on a k.ui base element with a literal `id` (a `.tsx` tag or a `.ts` call `Button({ id: \"…\" })`) reports that id as `data.at`; with `id={expr}` and no stamped ancestor it reports `\"\"`; on a plain element it reports the element's compiler id."
- **k.component** (663 -> 788). **Control flow**: "A file without JSX calls them as functions with the same props (`If({ when, children: () => node })`); the compiler removes a `@keel/runtime-dom` import only when every binding it imports is used solely as a JSX tag." **Conformance**: "A plain `.ts` module calling `If` and `Boundary` imported from `@keel/runtime-dom`, or naming `If` only as a parameter or destructuring default, compiles with that import kept and renders the chosen branch; a `.tsx` module using them only as tags compiles with the import removed."
- **k.reactive** (936 -> 1,118). **API**: "A computed's throw surfaces in the computation reading it: the computed runs once per commit and keeps the error, each reader's `get()` throws it until a source changes, and its first value after a throw counts as a change." **Conformance**: "An effect reading a computed that throws after a later write gets that throw from its own `get()`, where a `try` around the read catches it; no `onError` receives it." · "A computed that threw and then returns its value from before the throw reruns its readers (also with `equals`, through a computed chain, and for a `resource` fetcher reading it)." · "A throwing computed runs at most once per commit however many readers and dependent computeds read it, and every reader's `get()` throws that one error."
- **k.errors** (1,484 printed). "An `effect` or `computed` of an island's own component has `data.at` the island's id" becomes "A throw at no element of its own (the root component's own `effect`, `computed` or render) has `data.at` the `data-k` at the root's place (the `mount` element, the island's parent), else `\"\"`." The island-effect clause expects `data.at` `\"\"`, and the clause "The same component and the same click report the same `data.at` under `mount` and after `resume`, for a handler's throw, for a binding's throw (the element the binding writes) and for the component's own `effect` throw (`\"\"`), when the handler's write makes the computed they read throw." is added.
- k.runtime is unchanged (1,493), so nothing is trimmed.

## Migration
None. An app whose resumed island threw got an uncaught page error before and gets the root fallback and an `error` event now. No golden app test depends on an uncaught resume error.

## Size
`@keel/runtime-dom` (root entry, the budgeted one) 4,066 B gzip, up from 4,062 B before this RFC, within 6 kB. `resume` lives in `./ops` (7,389 B, up from 7,286 B), which has no budget of its own. `@keel/compiler` 26,332 B, up from 25,966 B, within 26 kB (26,624 B). `@keel/reactive` 2,133 B, up from 2,098 B, within 4 kB.

## Known limits
- A throw during an island's claim is still a mismatch, not an error: the island re-renders on the client, and a throw there renders the fallback.
- A resumed island has no `onError` hook; observers on the ctx see its errors.
- A handler on a k.ui base element with no literal `id` and no stamped ancestor has `data.at` `""`; such handler errors on one page share a fingerprint.
- Binding and structural ops still take `data.at` from the element's `id` when they bind (`idOf`); an `id` bound from app data on the same element, or rendered by the server before the claim, can reach `data.at` of a binding throw there.
