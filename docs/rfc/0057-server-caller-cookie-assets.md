# RFC 0057: signed `__Host-` caller cookie and hardened asset serving

Status: accepted (ADR-0046)

## Problem
- **Red team L3 (backlog 0134).** `callerOf` accepted any well-formed `keel-caller` value. A host on a sibling subdomain can set `keel-caller=<known>; Domain=example.com`. The victim's writes then carry a caller the attacker knows, and the attacker can undo them (session fixation). Any value a client invents also became a caller. That includes a raw token read from a pre-0054 snapshot's `meta.caller`, which still names the browser that owns it.
- **Red team L5 (backlog 0136).** `loadAssets` served every file under `assets/` with `Cache-Control: public, max-age=31536000, immutable`, hashed or not. A file without a content hash, once cached, cannot be replaced for a year. Responses had no `X-Content-Type-Options: nosniff`. `readdir(..., { recursive: true })` follows symlinked directories, and `readFile` follows file symlinks, so a link under `assets/` served whatever it pointed at. A manifest `file` such as `../x.js` was read from outside the build too.

## Proposal
1. **`__Host-` on https.** When the app is secure, the cookie is `__Host-keel-caller`, set `Path=/; HttpOnly; SameSite=Lax; Secure` with no `Domain`. Browsers accept a `__Host-` cookie only from the exact host, over https, so no sibling can plant it. The server then reads only that name. A plain `keel-caller` sent to a secure app counts as no cookie. Over http (dev) the name stays `keel-caller`, without `Secure`.
2. **Secure detection: `createApp({ secure })`, default the request URL's scheme.** `x-forwarded-proto` is not read. Without a proxy, any client can send it, and the server cannot tell whether a proxy sits in front. The deployer knows. Behind a TLS-terminating proxy, pass `secure: true`. The default stays correct for direct https and for local http.
3. **Signed tokens: `createApp({ secret })`.** The cookie value is `token.mac`. `token` is `ctx.random.id("Caller")`, as before. `mac` is base64url HMAC-SHA-256 of the token under `secret`. A value counts only when its token is well-formed and its `mac` matches (`timingSafeEqual`). Anything else is ignored, and the request is cookieless: a write mints a fresh caller and a read gets `""`. `caller` is the base64url SHA-256 of the whole cookie value. That keeps the RFC 0054 property: a stored id cannot be sent back as a cookie. Without `secret`, `createApp` draws 32 random bytes. Callers then reset on restart and differ between instances. Production should pass a stable secret of at least 32 random bytes, the same in every instance. Node's `crypto` stays one lazy import at `createApp`, so per-request work is synchronous (RFC 0054 proposal 4).
4. **Hashed means named and hashed.** A built file is `immutable` only when the Vite manifest names it (any chunk's `file`, `css` or `assets`) and its name ends `-<hash>.<ext>`, with a hash of at least 8 characters from `[A-Za-z0-9_-]` (Vite's `[name]-[hash]`). Any other file under `assets/` is `no-cache`. The browser revalidates it on every use, and a deploy that replaces it is seen at once. Both conditions are needed. A file can be named by the manifest yet unhashed (a user's `entryFileNames`), or hash-like yet unknown to the build.
5. **`nosniff` on every asset response.** Built files and the dev `/@keel/entry.ts` answer `X-Content-Type-Options: nosniff`.
6. **No escape from `assets/`.** `loadAssets` takes the real path of `dist/<name>/assets` once. It walks real directories only (`withFileTypes`; a symlinked directory is never descended). It reads a file, or a file symlink, only when that file's real path lies inside that root. The entry must be one of those files. A manifest entry outside `assets/`, or one escaping it with `..`, is E1555 `entry ... is missing`. A symlinked build directory (a release link) still works, because the root is resolved first.
7. **Request paths never reach the filesystem (confirmed).** Files are read once at startup into a map keyed by URL path. A request is a map lookup on `URL.pathname`, which has already normalized `..`, `%2e%2e` and `%2E%2E` segments. `..%2f` stays one segment and matches no key. Tests now pin this.

**Threat scope.** THREAT-MODEL's adversary is the web attacker. The caller is a per-browser undo scope, not authentication (RFC 0044).
- **Closed:** cookie planting from a sibling host on https (`__Host-`); forged or invented values; replay of pre-0054 raw tokens (unsigned, so ignored); an unhashed asset pinned in caches for a year; content sniffing of assets; a symlink or a `..` entry serving files outside the build.
- **Residual:** over plain http, or on https without `secure` behind a proxy, a sibling host can still plant a cookie, and the attacker could obtain a validly signed one first. The server cannot tell, so production must be https or pass `secure: true`. Anyone holding the cookie is that caller, as before. A leaked `secret` lets its holder mint new callers but not reach existing ones, because ids hash 122-bit random tokens. Each instance without a shared `secret` re-mints callers, which fails closed: undo by caller refuses others' entries.

## Amendment (red team, backlog 0159, 0161)
- **Short secrets (0159).** `createApp({ secret })` accepted any length. An empty key's HMAC is public, so anyone could sign caller cookies. A `secret` under 32 bytes (UTF-8) now rejects at startup with E1556 (`E1556 secret: ...`, a coded error like E1555). E1556 is named in k.server Server state, not in Rules, because Rules codes need a `keel explain` entry and a `fixture-per-code` listing in `packages/check`, which this change does not touch. The follow-up moves E1556 to Rules with both. When the E1555 production gate holds (`mode` production, `NODE_ENV` neither `development` nor `test`) and no `secret` is given, `createApp` writes one `W1556` `diag` to `log` at startup: callers reset on restart and differ per instance.
- **Hash rule (0161).** `-[\w-]{8,}` called `island-checkout.js` hashed. A file is now `immutable` only when the manifest names it and its name ends in `-<h>.<ext>`. `h` is Vite's `[hash]`, exactly 8 base64url characters that are not all lowercase letters, or a hex run of 8 or more. The 0.07% of real hashes that are 8 lowercase letters are served `no-cache`, which is safe. A user's `entryFileNames` producing unhashed names such as `app-mainView.js` is still misread, a residual risk that only custom naming can trigger.
- **Encoded paths (0161).** Files are keyed by their decoded path, and `servedEntry` decodes `url.pathname` with `decodeURIComponent` before the lookup. A malformed escape matches no file and takes the request flow (404). `café-….png` and `my logo-….svg` serve at their percent-encoded URLs. Decoding cannot escape: the lookup is still a map key.
- **ETag (0161).** Each built file gets a weak `ETag`: `W/"` plus 22 base64url characters of the SHA-256 of its bytes, computed once at startup. `If-None-Match` naming it (weak comparison, a list, or `*`) answers 304 with the ETag, `cache-control` and `nosniff`, and no body. `no-cache` revalidation therefore costs no body.
- **Tests.** `server/test/callerSecret.test.ts` covers the empty-key forgery repro, byte lengths around 32 including multibyte, and W1556 only under the production gate. `server/test/assets.test.ts` "RFC 0057 amendment (backlog 0161)" covers `island-checkout.js` and `plain-abcdefgh.js` (not immutable), hex and dated names, `café` and spaced names, malformed escapes, and ETag/304. Conformance additions are in `caller-token-signed.test.ts` (E1556) and `build-assets-headers.test.ts` (island-checkout `no-cache` with ETag and 304; a non-ASCII asset).
- **Spec.** Server state reads "`createApp({ secret })` (<32 bytes: E1556; default per process, W1556 in production)". Build reads "else `no-cache`, ETag". Editorial cuts keep k.server at 1,499 tokens. "E1553 `static` deployable has a route with" becomes "`static` deployable route with". "Hono on Node" becomes "Hono". "dev diagnostic" becomes "dev diag". E1555's "(at `createApp`)" is dropped; the Conformance clauses state the startup rejection. "default: the URL's" becomes "else the URL's". "share one process" becomes "share a process".

## Alternatives
- **`__Host-` alone, no signature.** It closes planting on https but not invented values or the replay of leaked raw tokens. It also leaves http dev with no check at all. Rejected. The signature costs one HMAC per request that sends a cookie.
- **A server-side record of issued tokens.** It needs storage, survives restarts only through `ctx.storage`, and grows with every browser. Rejected: an HMAC is stateless.
- **Trust `x-forwarded-proto`.** It is spoofable without a proxy. Rejected for an explicit `secure`.
- **Refuse production without `secret` (an E15xx).** That would force key management on every test and demo, and a random default fails closed. Rejected for now; documented as a production requirement.
- **Hashed by name alone.** Unknown files with hash-like names would be pinned. Rejected (proposal 4).
- **Refuse every symlink.** Stricter than needed: a link inside the build is harmless. Rejected. The rule is real path inside the root, and directory links are never descended, which also rules out loops.

## Migration
- **Existing cookies.** Pre-0057 `keel-caller` values are unsigned, so the next write mints a signed one. Entries recorded under the old caller no longer match, so undo by caller refuses them. This fails closed, like the 0054 migration. On https the old plain cookie lingers until the browser session ends and is ignored.
- **Deployments.** Behind a TLS-terminating proxy, pass `createApp({ secure: true })`. With more than one instance, or to keep callers across restarts, pass the same `createApp({ secret })` everywhere (32+ random bytes, from the environment).
- **Builds.** Vite's default naming is unchanged and hashed, so built chunks stay `immutable`. Files copied into `assets/` by hand, and source maps, are now `no-cache`. An entry configured outside `assets/` is now E1555.
- **App code.** None. `caller` is still an opaque string compared for equality.

## Token impact
- k.server: 1,499 to 1,499 tokens (additions offset by editorial cuts).
- Runtime: one HMAC and one SHA-256 per request that sends a caller cookie; asset headers are static.
- Size: `@keel/server` goes from 11,393 bytes gzip (after rfc:0054) to 12,019. That is 11,724 for the signed cookie, the asset walk and the header rules, plus 295 for the amendment: the E1556 and W1556 startup checks, the stricter hash rule, path decoding and the ETag with 304. The budget goes from 11.5 kB (11,776 bytes) to 12 kB (12,288 bytes, `tooling/budgets.json`, D7). Each addition closes a red-team finding, and nothing removable was found.
