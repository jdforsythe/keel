# RFC 0068: `.ts` components export `Props`, an empty JSON body is `{}`, `scaffold project` writes `<name>/`, a resource unwraps a `Result`

Status: implemented (ADR-0057)

## Problem
Backlog 0120. The golden-1-api eval (2026-11-07) did not converge, and its runs and the golden-2 runs found these gaps:
- **`.ts` components.** The api deployable's document views (`BoardApi`, `ActionApi`, `SuggestionsApi`) are plain `.ts` so `node server.ts` loads them with type stripping alone. `render` and `properties` need the component's `Props`, but E1752 counted a `.ts` file's `Props` as a second export and E1104 reported it as a schema outside a `*.schema.ts`. Both rules exempted `Props` and `uses` only in `.tsx`/`.jsx`.
- **Empty JSON body.** k.server said a JSON body decodes by the action's input schema and gave no rule for zero bytes. `typed.json()` failed, the input was parsed as `undefined`, and the reply was 422 `keel.fields` with one root key `""`. An action whose input is `s.object({})` refused a bodiless JSON POST.
- **`keel scaffold project <name> --workspace`** wrote into the working directory, not `<name>/`.
- **Resource error state.** The keel skill says no throw (use `Result`), and a `@keel/services` client returns a `Result`. `resource` reached `error` only on a throw or rejection, so the eval app wrote `Promise.reject(...)` to show a failed call.
- **Import cycle.** An action returning `ok(routes.href(...))` imports `routes.ts`, which imports the action for `routes.actions(...)`. Under vitest, a test that imports the `*.server.ts` first attaches `undefined` as the action with no error; under Node it is a TDZ error (ADR-0052 noted it).
- **Briefs.** golden-2 exports sat at rung `none` because its `pass.ts` did not grade the ledger (21 of 31 items today). The golden-1 client brief named `keel check|test|build` scripts, but the workspace scaffold writes `tsc --noEmit && biome check modules test`, `vitest run` and `vite build`.

## Proposal
1. **k.component.** A component file is a PascalCase `.tsx`/`.jsx` with a default export, or a PascalCase `.ts`/`.js` (`BoardApi.ts`; not `board.ts`, not `Board.server.ts`) whose default export is a function (a declaration, an arrow, or a top-level one it names) whose first parameter's type names `Props` (`props: Props`, `props: Infer<typeof Props>`). Only such a file may also export `Props` and `uses`; `Config.ts` with `export default { a: 1 }` and a `Props` schema is E1104 (backlog 0197). `@keel/check` gains `isComponentFile`, the one definition E1752 (`oneExport`) and E1104 (`schemaInSchemaFile`) call. The compiler already attaches `Name.Props` for any lowered file, `.ts` included.
2. **k.server.** A JSON action body of zero bytes decodes as `{}`. The action runs when its input accepts `{}`; otherwise 422 `keel.fields` names each missing field. A non-empty body that is not JSON keeps the root `""` key. This follows the existing status mapping (decode failure is `keel.fields`, 422) and needs no new code.
3. **k.scaffold.** `keel scaffold project <name>` writes under `<name>/`, with or without `--workspace`. The CLI gives the generator the files under `<name>/` as its tree and prefixes every write, record and refusal path. `scaffold('project', ...)` itself stays pure and project-relative, so later operations run inside the new directory unchanged.
4. **k.reactive.** A fetcher that resolves a keel `Result` is unwrapped: `ok(v)` settles `ready` with `v`, `err(e)` settles `error` with `e`. A throw or rejection still settles `error`. Any other value is `ready` as is, a plain `{ ok: false, error }` payload included. k.schema `ok` and `err` give each result a non-enumerable `Symbol.for('keel.result')` key (JSON, spread, `toEqual` and `structuredClone` skip it), and `@keel/reactive` checks that key, so it needs no dependency on `@keel/schema` (backlog 0198). The signature is `resource<T>(fetcher: () => Promise<T>): Resource<Settled<T>>`, where the exported `Settled<T>` maps `Result<V, E>` to `V` and leaves any other type, `{ ok: boolean; value?: V }` included, as `T`. Inference of `T` is unchanged, so a `Promise.reject` branch still infers. A value typed exactly as a `Result` variant but built as a literal, not by `ok`/`err`, is typed unwrapped and stays whole at runtime; Results are made with `ok`/`err`.
5. **Cycle.** The cycle stays: the manifest file owns attachment (ADR-0052). The keel-api skill and the eval slices say to import `routes.ts` before any `*.server.ts`, tests included. A router guard that reports E1505 for an `undefined` action value is filed as backlog.
6. **Evals.** golden-2 `pass.ts` runs `pnpm ledger --diff --scope golden-2:` and requires every `golden-2:` item at rung `example` or better, as golden-1 does; its brief says so. The golden-1 brief names the scaffold's scripts. Both briefs and the three spec slices state where `scaffold project` writes, the `.ts` component rule, the empty JSON body and the resource `Result` rule.

## Alternatives
- **Empty JSON body as 400 with its own code.** A new code for one case, when decoding already fails as `keel.fields`. Treating zero bytes as no body matches a FormData POST with no fields.
- **Empty JSON body as an empty FormData.** `decodeStrings` reads an absent checkbox as `false`, which a JSON client never means.
- **`scaffold('project')` returning `<name>/` paths.** Every later operation, test and fixture that chains `project` then `module` would have to strip the prefix. The directory is the CLI's concern.
- **Resource overloads (`Result` first, plain second).** A fetcher with a `Promise.reject` branch failed to resolve either overload (TS2769) in the existing property test.
- **Unwrap by shape.** `resource<Result<number, E>>(async () => ok(1))` type-checked with the wrong value type, and a third-party `{ ok: false, error }` payload landed in the error state (backlog 0198).
- **Break the cycle with a separate actions file.** It needs wiring in `createApp` and `createRouter`; ADR-0052 rejected it.

## Spec diff
- **k.component Shape.** "A file may also export `Props` and `uses`" becomes "A component file, `.tsx` or a plain `.ts` one (PascalCase name, default export, no JSX; rfc:0068), may also export `Props` and `uses`". Conformance adds "A plain `.ts` component file exporting `Props` and `uses` beside its default export reports neither E1752 nor E1104." and "A PascalCase `.ts` file whose default export is not a function taking `Props` and that exports a `Props` schema reports E1104."
- **k.server Request flow.** "Then decode FormData or JSON (empty: `{}`) by the action's input (fail: `keel.fields`, not called)". The Conformance clause "A POST with invalid FormData returns 422, ..." becomes "A POST with invalid FormData or JSON (empty JSON too) returns 422, does not call the action, and lists the field errors." Three phrases are shortened to keep the section at 1,500 tokens.
- **k.scaffold Generators.** `project` names the `--workspace` files and "`keel scaffold project <name>` writes under `<name>/` (rfc:0068)". Conformance adds "`keel scaffold project <name>`, with or without `--workspace`, creates every file under `<name>/` and none beside it."
- **k.reactive API.** Adds "a fetcher's throw or rejection is `error`, and a resolved `Result` (k.schema) unwraps: `ok(v)` is `ready` with `v`, `err(e)` is `error` with `e` (rfc:0068)". Conformance adds "A fetcher resolving a keel Result `err(e)` settles `error` with `e`, one resolving `ok(v)` settles `ready` with `v`, one resolving a plain object shaped like a Result settles `ready` with that object, and one that throws or rejects settles `error` with the thrown value." and "A fetcher typed `Promise<Result<T, E>>` gives `Resource<T>`, and one typed `Promise<{ ok: boolean; value?: T }>` compiles and gives a `Resource` of that type."

## Conformance diff
- **Added** `packages/check/conformance/component-ts-props-0068.test.ts` (k.component): `Props` and `uses`, or `Props` alone, beside a PascalCase `.ts` default function taking `Props` report neither code; an object default, a function not taking `Props`, and a lowercase `.tsx` report E1104; a camelCase `.ts` still reports E1104 and a third export still reports E1752.
- **Changed** `packages/server/conformance/post-invalid-formdata-422.test.ts` (k.server): the header and first title quote the amended clause; new tests cover a JSON body failing the input, an empty JSON body naming each required field, and an empty JSON body running an action whose input accepts `{}`.
- **Added** `packages/scaffold/conformance/project-into-name-dir.test.ts` (k.scaffold): with and without `--workspace`, the real `keel` binary creates only `<name>/`, and a second run is E1351 with nothing written.
- **Added** `packages/testing/conformance/resource-keel-result-0068.test.ts` (k.reactive; the testing package has both `@keel/reactive` and `@keel/schema`): `err(e)`, `ok(v)`, plain Result-shaped objects, a sync throw, an async throw, a rejection and a plain value, each a property; and a TypeScript-compiler probe for `Result<T, E>`, an explicit `resource<Result<...>>`, `{ ok: boolean; value?: T }`, plain and rejecting fetchers, plus two cases that must not compile.
