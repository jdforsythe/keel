# RFC 0060: `x-forwarded-proto` upgrades the caller cookie to `__Host-`, W1557, and a server DOM that answers selectors

Status: accepted (ADR-0047)

## Problem
- **Red team 0160.** `secure` defaulted to the request URL's scheme. Behind a TLS-terminating proxy that scheme is `http:`, so the default Node deployment set `keel-caller` without `Secure` and read the unprefixed name. A sibling subdomain could then plant a caller cookie: signing (RFC 0057) only means it must first get a valid value, which one POST of its own gives it.
- **Red team 0156.** The DOM-free server tree that `createApp` installs under plain Node had no `querySelector`. Compiled templates find each bound element below the root with `root.querySelector('[id="…"]')`, so every such page threw `TypeError: __kr0.querySelector is not a function` and answered 500. The golden apps rendered only under happy-dom, which hid it. Rendering the real golden pages under plain Node also found two more gaps. `@keel/forms` checks `el instanceof HTMLInputElement`, a global the server tree lacked. A route's `errorElement` was called outside a render unit, so a compiled one threw `text() called outside a mount` and its 404 became a 500.

## Proposal
1. **Upgrade-only `x-forwarded-proto`.** With `secure` unset, a request is https when its URL is, or when the first comma-separated `x-forwarded-proto` value is `https` (trimmed, any case). The header never makes an https URL count as http. An explicit `secure` wins over both. Spoofing the header over plain http only makes that client's own cookie `__Host-` and `Secure`, which its browser will not store over http. A browser cannot add the header to another site's request without a CORS preflight.
2. **W1557.** Under the E1555 production gate (`mode` production, `NODE_ENV` neither `development` nor `test`), a `createApp` without `secure` writes one W1557 `diag` to `log` at startup: `secure: true` is the production setting.
3. **Fixation residual risk, documented.** Over plain http, or behind a proxy that sends no `x-forwarded-proto` while `secure` is unset, the cookie stays `keel-caller`, and a sibling can still plant a validly signed value. A request's `Cookie` header does not say whether a cookie was `Secure` or which host set it. Rotating unprefixed cookies on a write would rotate every http caller, break undo by caller, and the sibling would plant again. docs/THREAT-MODEL.md records this as a by-design limit that https and `__Host-` close.
4. **Server DOM selectors.** `querySelector` and `querySelectorAll` on elements, fragments and the document, and `matches` and `closest` on elements. The subset is what compiled output (`[id="…"]`) and `@keel/runtime-dom` (`[data-k-island]`, `script#k-state`) use. It covers a type or `*`, `#id`, `.class`, `[name]`, and `[name=value]` with a quoted or ident value, compounds of these, and `,` lists. CSS escapes are decoded. Type and attribute names match ASCII case-insensitively. Anything else (combinators, pseudo-classes, other attribute operators, an empty or malformed list) throws a `SyntaxError` whose message names the selector and the subset. A lookup never silently finds nothing. A `<template>`'s content is not searched, as in the DOM, and parsed HTML now puts a nested `<template>`'s children into its `content`.
5. **Server form controls.** `createElement` and the parser give `input`, `select`, `textarea` and `option` their own classes, installed as `HTMLInputElement`, `HTMLSelectElement`, `HTMLTextAreaElement` and `HTMLOptionElement`, plus `HTMLElement`. `name` and `disabled` reflect their attributes on `button`, `fieldset` and the controls. `input.type` reflects its attribute (unknown: `text`). `value`, `checked` and `selected` are the control's state and never appear in the markup, as in a browser. The exceptions are input types whose value is the attribute (hidden, buttons, checkbox and radio, `on` by default). `select.value` is the last option marked selected, else the first enabled option of a single select. Setting it selects the first match. Every element class clones as itself (backlog 0167); clones keep an input's value and checkedness and a textarea's value, as the DOM's cloning steps do, and nothing else. There is no value sanitization and no radio-group exclusivity.
6. **`errorElement` in a render unit.** `renderChain` renders a route's `errorElement` through `renderUnit`, as it renders components.

## Alternatives
- **Emit `getElementById` refs from the compiler.** A detached template clone is in no document, so the browser's `getElementById` cannot find it either. The compiler and runtime-dom would both change for a server-only gap.
- **Diag instead of upgrade on `x-forwarded-proto: https` over http.** That warns on every proxied request and still leaves the cookie unprefixed.
- **Trust `x-forwarded-proto` both ways.** A client could downgrade an https request to the unprefixed name a sibling can plant.
- **Serialize control values into the markup.** Server HTML would then differ from what a browser's `outerHTML` and happy-dom produce for the same tree. Whether server-rendered forms should show their initial values is a separate question for `@keel/forms` and `@keel/ui`: write the `value` attribute.
- **A full selector engine.** Combinators and pseudo-classes cost bytes for selectors no kernel code asks for. The `SyntaxError` names the gap if one ever does.

- **k.server Server state.** The header becomes "(rfc:0044, 0054, 0057, 0060)". "`Secure` on https (`createApp({ secure })`, else the URL's)" becomes "`Secure` on https (`createApp({ secure })`; default the URL's or `x-forwarded-proto`, W1557 in production)".
- **Editorial, to keep k.server at 1,499 tokens.** Topology: "`node` (Hono; no DOM global; serves the resume entry)" becomes "`node` (Hono; serves the resume entry)". Since backlog 0073 `createApp` installs a server tree as `document`, so "no DOM global" was stale. Dev server: "Dev serves `/__keel/inspect` (k.cli)." is dropped, since k.cli Inspect specifies it.

## Conformance diff
- None. The changed clause is covered by unit tests: `packages/server/test/forwardedProto.test.ts` (the 0160 repro, no downgrade, an explicit `secure` wins, a planted `keel-caller` counts as none on an upgraded request) and `packages/server/test/callerSecret.test.ts` (W1557 once, none with `secure`, in dev or in development).
- **0167 tests.** `compiledTemplate.test.ts` "backlog 0167 repro" (a compiled `<button value={…}>` keeps `value`, a cloned select is an `HTMLSelectElement` with its value) and `serverDomClone.property.test.ts` (seed 1337: `cloneNode(true)` keeps each node's class, attributes and markup).
- **0156 tests.** `packages/server/test/compiledTemplate.test.ts` holds the backlog repro, intrinsics below the root, and a compiled `errorElement` 404. `packages/server/test/serverDomQuery.test.ts` covers the selector subset, the `SyntaxError` cases and the form controls. `packages/server/test/serverDomQuery.property.test.ts` is a fast-check property, seed 1337: on random nested trees, `[id="…"]`, `querySelectorAll` and `#id` agree with a reference pre-order walk. `apps/golden-1/test/ssrNode.test.ts` and `apps/golden-2/test/ssrNode.test.ts` run in the node environment. They serve every GET route of the real pages (and the api deployables' GET routes) through `createApp` and assert status and text, including each app's `errorElement` 404. The repros failed before the change.

## Migration
- **Behind a TLS proxy without `secure`.** Callers move from `keel-caller` to `__Host-keel-caller` on their next write, so undo by caller refuses older entries (fail closed, as in RFC 0057). Production should pass `secure: true`.
- **App code.** None. Server-rendered pages that used to 500 under plain Node now render.

## Token impact
- k.server: 1,499 to 1,499 tokens (the clause grows, two editorial cuts offset it).
- Size: `@keel/server` goes from 12,019 bytes gzip to 13,692. That is about 1.6 kB for the selector subset and the form controls the golden pages need, and a few bytes for W1557 and the header. The budget goes from 12 kB (12,288 bytes) to 13.5 kB (13,824 bytes, `tooling/budgets.json`, D7). None of it is removable without a page failing under plain Node.
