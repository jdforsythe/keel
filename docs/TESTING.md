# Testing and the ledger

**Rungs.** `proven` (type-level tests; closed-form `explore` over a store's whole space) · `exhaustive` (`explore` from a chosen state, payloads or depth) · `probabilistic` (schema-generated properties and `simulate`, with seed counts) · `example` (hand cases, golden flows) · `monitored` (std.monitor tallies from production, `.keel/monitored.json`). The ledger lists every public function and spec clause with its highest rung (`none` when no evidence exists) and evidence path.

**Kernel requirements.** Conformance green · property tests for every exported pure function · mutation score >= 80% for `schema`, `reactive`, `store`, `router`; >= 70% elsewhere · a11y assertions in `ui`, `runtime-dom` · output budgets in `cli`, `check`.

**Mutation.** `pnpm mutate [--filter=@keel/<pkg>]` (turbo; nightly in CI) or `pnpm --filter @keel/<pkg> mutate` runs Stryker (vitest runner, incremental) through the one runner `tooling/mutate.mjs` with the shared factory `tooling/stryker.mjs`; each package has a 3-line `stryker.config.mjs`. Prints one trailer `ok|fail mutate <pkg> score 84.2% (threshold 80%)`; `KEEL_FORMAT=json` prints the NDJSON summary. The report is `packages/<pkg>/reports/mutation/mutation.json`; `pnpm ledger` (`keel ledger --write tooling/ledger/ledger.json`) turns it into one claim per mutated file, keyed by the sha256 of the source the report holds, and records the package score over them; a claim is fresh while the file on disk has that hash, and a changed file's claim is stale (W1714) and left out of the score. `keel ledger --diff` fails E1713 when a package's score over fresh claims is below its threshold. One mutation run holds a machine-wide lock (`os.tmpdir()/keel-mutate.lock`); a second `pnpm mutate` fails E0010, and `pnpm test` beside a live run prints W0012 and runs anyway. A run with no mutant finished for ten minutes ends E0011 with its results saved; run again to resume. `KEEL_MUTATE_CONCURRENCY=<n>` caps the test runner processes of a run on a shared machine. Thresholds are never lowered; a temporary floor needs a `TODO` and a backlog line.

**Wall-clock bounds.** Every package, app and scaffolded project builds its vitest config with `keelConfig` (`@keel/tooling/vitest-config`), which loads the watchdog setup file first in every worker. A watchdog thread beside the test's thread kills the worker process when a test (with its hooks) runs past `allowed × 2 + 30 s`, where `allowed` is its timeout plus two hook timeouts, so vitest's own timeout always fires first when the thread can yield; collection and the hooks between tests are bounded the same way with `allowed` at least 60 s, and a worker whose parent process is gone is killed at once. It prints one line, `T0001 conformance/x.test.ts:1:1 watchdog killed "<test>" after 81.2s (bound 80.0s)`, kills the worker's own child processes with it, and the run fails (a fork worker: vitest reports the worker error, exit 1; a thread pool: the whole vitest process dies, exit 137). A worker also kills its child processes, and theirs, on every other way it ends (exit, SIGTERM, SIGINT, SIGHUP, or vitest's death closing its channel), so a process a test started never outlives the worker; only a SIGKILL of the worker itself skips this. A mutation run is bounded by its budget below, and its whole Stryker process group by the stop and kill path.

**Mutation run time.** No run is longer than its budget: `tooling/budgets.json` `mutate`, in minutes (`default` 30; a package may have its own entry). Stryker runs in its own process group (the core and its test runners). At the budget the runner sends that group one SIGINT, Stryker saves what it tested, and the run ends `fail mutate <pkg> time budget 30m reached at 5,120 of 8,634 mutants; run again to resume (1800.4s)`. The next run starts from the saved results, so a cold package is several bounded runs.
- Cache: `<git common dir>/keel-mutation/<pkg>.json`, shared by every worktree of a clone, so one run of a package at a time per clone (`<pkg>.run.json` holds the claim); CI restores that directory and always saves it under a key of its own run. `<pkg>.times.json` beside it holds the dry run's time per test file.
- Order: test files run shortest first (`@keel/tooling/quick-first`), so a mutant a quick test kills never pays for a slow one. A package with its own vitest config for mutation runs names the sequencer there.
- Watch and stop: `pnpm mutate:status` prints one line per live run (`check 5,120 of 8,634 mutants, 3,100 reused, 41 a minute, about 14m left`); `pnpm mutate:stop` sends the one SIGINT to every live run's group and waits for it: `ok mutate-stop 1 stopped, 0 killed, no process left (14.2s)`. Stryker exits without saving on a second signal, so the budget, `mutate:stop` and Ctrl-C all claim the run file first and only the first one signals; never signal Stryker by hand. A clean stop saves the cache. A group still alive 120 s after its SIGINT is killed with SIGKILL (nothing saved), by `mutate:stop` or by the runner, whichever is waiting; every ending checks the group by PID and the summary line says `no process left` or names the pids left. `pnpm mutate:changed` ends its whole sequence on a stop: the live package's run stops and no further package starts.
- Per task: `pnpm mutate:changed [--base <ref>]` runs only packages changed since `<ref>` (default `origin/master`), and only a package's changed `src` files when nothing but prose changed beside them; the report keeps every other file's results. The whole run is the nightly one.
- Light run: `pnpm mutate:stale [--list] [--only <pkg>] [--chunk <n>] [--concurrency <n>] [--minutes <n>] [--missing]` runs the `src` files whose ledger claim is stale (the file on disk no longer hashes to the claim's `sha`); with `--missing` also the files that have no claim. Packages go one at a time, in chunks of `--chunk` files (default 4) through `tooling/mutate.mjs`, with `KEEL_MUTATE_CONCURRENCY` set to `--concurrency` (default 3) unless it is already set, so it can share a machine. `--minutes` (default 20) bounds the whole call: no chunk starts after it, and the live chunk is stopped as `pnpm mutate:stop` stops it, saving its results. One line per finished chunk, then `ok mutate-stale 12 files left in 3 packages; run again to resume`. `--list` prints the packages, files and chunks and starts nothing. It holds the same machine-wide lock.

**Coverage.** `pnpm coverage [--filter @keel/<pkg>]` (turbo, four packages at a time, one on a machine with four cores or fewer) runs each package's or app's tests once with v8 coverage through its `coverage` script (`tooling/coverage.mjs`, which sets `KEEL_COVERAGE=1` for `keelConfig`). It measures `src/` and `unsafe/` (`modules/` of an app), leaving out tests, `types/`, `*.d.ts` and the files `tooling/generate.mjs` writes, and writes `coverage/coverage-summary.json` and `coverage/meta.json` (commit, whether the package's files differed from it, time), git-ignored. One line per package: `ok coverage @keel/std-text 100% lines, 98% branches, 100% functions, 98.48% statements (5.1s)`. It sets no floor. Without `KEEL_COVERAGE` the test config has no coverage settings, so `pnpm test` is unchanged. A covered line or branch is one the tests executed, not behaviour they proved: an executed line can still be wrong, and mutation scores are the check on that.

**Evidence report.** `pnpm evidence:report` writes `tooling/ledger/evidence.json`, committed, the one source a website or `tasks/COVERAGE.md` reads; its `schema` field is the shape's version. It holds the committed ledger's totals and clauses per spec section by rung, exports and route and WCAG items by rung; per package and app, test files and cases by kind (conformance, unit, other), property calls, files calling `simulate`, `explore` or `prove`, expected failures and skipped cases; mutation score, threshold, report date and stale claims; and coverage from `pnpm coverage`. A package with no run has `null` values and a `reason` (`no mutation run`, `not measured`); one with no local measurement keeps the committed entry, which names its commit. Keys are sorted, so a re-run on the same tree changes only `generatedAt`. `--check` exits 2 with S0007 when the ledger and test parts differ from a fresh count (mutation and coverage need runs and are not compared); `--markdown` also rewrites `tasks/COVERAGE.md` from it. The counting rules are in the header of `tooling/evidence.mjs`. A test count is static, read from the files, not a run: a case may be skipped or failing. A rung of `example` means one passing test names the item, not a proof.

**CI.** `.github/workflows/ci.yml` is generated from `tooling/ci.source.json` and runs on pushes to `master` and on every pull request; a newer push cancels the run it supersedes. The `check` job runs `pnpm check`, then `keel test` in golden-2 (it writes the `reports/a11y.json` the ledger reads), `pnpm ledger --diff`, and `node tooling/ci-shards.mjs --verify`, which fails E0013 when a test task is in no shard or in two; it saves turbo's cache (`.turbo/cache`) for the jobs after it. `test-shard` is a matrix of jobs: `tooling/ci-shards.mjs <n>` deals every workspace package with a test task to one shard, heaviest first by the task's recorded seconds on the 2-core runner (a package without a record weighs its count of test files), and runs that shard's tasks through turbo one at a time, every task even after one fails, streaming their output. A package the script lists in `SPLIT` (`@keel/cli`) runs as several parts with vitest's `--shard=i/k`, each part in a different job, so every test file runs once. It names each task as it starts, prints `file <path> <s>s` as each test file ends, ends with one line per task (result, seconds, peak memory of its processes, least free memory, its five slowest files) and prints each failed task's whole log; a cancelled step prints the task it cut and for how long. `node tooling/ci-shards.mjs --plan` prints the shards and their expected seconds; `--verify` also fails E0013 when a part of a split package is in no shard or in two, or two parts share one. `test` passes only when every shard passed. `postgres` runs the std-db files that take `KEEL_TEST_POSTGRES_URL` against a Postgres 17 service; `build`, `budgets` and `golden-1-images` follow `test`. Every job on a push or pull request has a time limit. On a pull request `mutate-pr` mutates the changed packages; nightly `mutate` mutates every package and weekly `eval` runs the evals.

**Conformance rules.** Written by `conformance-writer` from the spec section before implementation · imports public API only · lives in `packages/<pkg>/conformance/` · changes only via `rfc:NNNN` PRs (hook + CI).

**Evals.** `evals/` holds agent tasks with pass criteria. Metrics: converged ledger-green rate, iterations to green, tokens to green, unsafe count. Run weekly across >= 2 models; results committed to `evals/results/`.

**Harness.** `@keel/testing` addresses elements by id. `find(id).state` and `a11y()` report `active` (the option `aria-activedescendant` names), `sort` and `checked` (`'mixed'` included). `fire` takes `keydown` with `key`, `shift`, `alt` and `mod`. `renderRoute(id, { url })` opens a page from a path and query; `location()` returns the history's length and `scrollY`. A widget's a11y claim holds only when every WCAG-mapped rule ran: an axe "needs review" result counts as not run, and the claim stays `none`.

**Determinism.** All kernel tests run under a seeded clock and PRNG via `ctx`. A test reading wall time fails lint.
