## Decisions
- D1: API per conformance fixtures: `createRouter(manifest, { ctx, history })` -> `{ navigate, route, App, dispose }`; `route` is a `Computed` read with `.get()`. `RouterHistory = { push, replace, current, onPop }`; `onPop` may return an unsubscribe. `browserHistory()` added so a real entry can build one (sets `scrollRestoration = "manual"`).
- D2 (superseded by D18, D20 for guards kept): `manifest()` registers routes in a process-wide table; `href(id)` and `Form` read it (fixtures call `href` and `Form` with only an id). Re-declaring an id replaces it (HMR, per-test manifests in forms conformance); cross-module duplicate ids are left to `keel check`. Same for `guard(name)`: a process-wide table, last declaration wins, resolved by name at navigation time.
- D3: Manifest validation throws `Error` with `code`: E1502 duplicate pattern (vs every registered route), E1503 path/params mismatch or malformed path, E1504 required search field, E1505 non-verb actions key, E1506 layout with a path or local cycle. Unknown layout names and cross-manifest cycles are E1506 at `createRouter` (layouts may live in another module's manifest; avoids import-order dependence). Unknown guard name at navigation renders `keel.unexpected` (E1506 in message).
- D4 (amended by D19): `href` is typed by `Href` brand only; the id parameter is `string` (no registry type). Typed ids need codegen or a `Register` interface: follow-up. `href` throws for an unknown id or a layout id (code E1501), and for search on a route without a search schema (E1504). Absent optionals are stripped before `encode` (the schema rejects explicit `undefined`).
- D5: URL parsing is manual (no `new URL`), so dot segments are not normalized; segments are `decodeURIComponent`ed (malformed escapes: 404). Rank: candidates with equal segment count, lexicographic static(0)/param(1) string, lowest wins.
- D6: Search parsing: undeclared keys dropped; `decodeStrings`, then drop the top-level keys named in issues and retry until ok. Known edge: an optional string search value `""` reads back as absent (schema `fromStrings`).
- D7 (superseded by D22): Params failure (404) renders the nearest `errorElement` of the matched chain alone (bare), without layouts: their loaders must not run, so their `data` would be missing. No match at all, or no errorElement in the chain: the root default (`role="alert"`, `data-keel-error`). `route.get().id` is `null` for 404s. Guard failures other than `keel.denied` also render bare.
- D8: Loaders do not use `resource`: a resource drops its value while `loading`, which conflicts with "previous page stays rendered" and "revalidation changes neither scroll nor focus". Each committed view owns one `signal` per chain level (in its own root scope, disposed when replaced); components get `data` as a getter over that signal, so `ok(null)` revalidation updates data without re-rendering unless a component reads `data` during render.
- D9: Navigation commits synchronously when the chain has no guards and no loaders (forms conformance mounts and reads the page synchronously after `createRouter`). Otherwise `pending` goes true, guards run in order, loaders start together in chain order, and the latest navigation token wins. History is pushed at commit (the URL matches what is rendered); a denied push pushes the redirect target; initial/pop redirects replace.
- D10: Rendering uses runtime-dom ops: `App` is a fragment with an anchor and a root `boundary` (fallback: default alert; its `reset` is called on the next commit). Each chain level with an `errorElement` is its own `boundary` whose fallback is that errorElement (k.errors "every route is a boundary"). A loader `err` renders the nearest errorElement at or above the outermost failing level, with layouts above it.
- D11 (lookup superseded by D21): `Form` finds its router through a render-scoped `active` slot set only while the router renders (like the runtime's render context); outside a router render it is a plain native form. Submit listener is attached on the form element and removed by a child `scope` when the render unit is disposed. Slots `loading`/`error` use the `cond` op. The action input is always decoded from FormData (one path, same as no-JS); `form.values()` is not used. Decode failure is `keel.fields` `{ [path]: rule }` and the action is not called.
- D12 (amended: forms changed `pending` to `setPending(v)`, coordinator-directed): `FormHandle` (exported) = `{ pending: Signal<boolean>; values(); onResult(r: Result<Href | null, KeelError>); validate(): Result<unknown, SchemaError> }`. Sequence: `validate()` (err: stop, no request), `pending.set(true)`, run action, `pending.set(false)`, `onResult`, then revalidate or navigate. `@keel/forms` `FormState` is assignable (forms conformance 33/33 green against this router).
- D13 (kept, see D23): Scroll positions are kept in a router-owned map keyed by URL (the fixtures' history has no entry state). Saved for the committed URL whenever a navigation commits; pop restores the target URL's saved value (0 if none). `navigate` (push or replace) focuses `main` (adds `tabindex="-1"`, `preventScroll`) and scrolls to the hash target or top; initial load, pop, and revalidation do not move focus.
- D14: `Router<S>` is parameterized by route state (`createRouter` returns `Router<RouteState<M>>`); a manifest-parameterized `Router<M>` was invariant through the conditional `RouteState` and broke `ReturnType<typeof createRouter>` in fixtures. `RouteState<M>` widens to plain records when `M` has non-literal keys.
- D15: `RouteDef.component`/`errorElement` are method signatures (bivariant) so components can declare narrower props than `RouteProps`; per-route prop typing is not checked (follow-up with typed manifests).
- D16 (superseded by D24): Unsafe +2: `unsafe/toHref.ts` (brand a built path), `unsafe/narrowRoute.ts` (typed route union over the untyped computed). Both justified inline.
- D17: Loader output is validated in-process with `output.parse`; failure renders `keel.unexpected` with message E1554. Thrown loaders, guards, and actions become `keel.unexpected` via `attempt`.

- D18 (review 1): no global route table. `manifest()` compiles and validates only its own entries into a table it owns (`WeakMap<Manifest, Table>`); E1502 pattern collisions and E1506 layouts (unknown, with a path, cycle) are checked within the manifest at `manifest()` time, so a deployable passes the union (`manifest({ ...a.routes, ...b.routes })`) to its router. `createRouter` uses only its manifest's table for matching, `Form`, and guard redirects. Same-id redeclare inside one manifest cannot reach runtime (an object literal keeps one key; TS/biome report duplicate keys), so no runtime check exists for it.
- D19 (review 2): one public form, the free `href(id, params?, search?)`, because router, ui, and forms conformance all call it after `manifest()` with no router in reach (fixture actions call it too). `id` resolves in the most recently declared manifest containing that id (a `Map<id, Table>` updated by `manifest()`; read only by free `href` and by `Form` outside a router). No `routes.href` (it would be a second way). `id` is typed `string` (augmentation is forbidden and a free function cannot see `keyof M`); unknown ids are left to `keel check` under E1501 and throw at runtime.
- D20 (review 3, not applied): guards stay declared by name, `guard(name, { redirect }, fn)` with `guard: "auth"` in the manifest, resolved at navigation through a process-wide name table. Router conformance `fixtures.ts` declares guards exactly that way (and the spec example uses `guard: 'auth'`), so guard-by-reference needs an `rfc:NNNN` changing fixtures and spec first.
- D21 (review 4): `Form` walks `owner()` then `.parent` to the nearest scope registered in `WeakMap<Scope, RouterCore>`; `router.App` opens its own `scope` and registers it (via `owner()` inside the scope body, before the first render). Outside any router `Form` is a native form (no interception, no signals). The `active` render slot is deleted.
- D22 (review 5): params failure renders `keel.notFound` in the nearest `errorElement` of the matched chain, inside the layouts above it when none of them declares a loader or a guard (a guard that did not run must not gate visible chrome), otherwise alone; no errorElement: root default. The same rule applies to a non-denial guard error. Written into k.router Matching. `route.get().id` is `null` for a 404.
- D23 (review 5): scroll stays keyed by URL. The conformance in-memory history exposes no index or entry state (`push(url)`, `replace(url)`, `current()`, `onPop(fn(url))`), and the router cannot infer back vs forward from a pop URL, so per-entry keys are not available without changing `RouterHistory` and the fixture (rfc).
- D24 (review 6): unsafe count 0. `Href` is minted by the `isHref` type predicate (`/`-rooted, no `#`) inside `hrefIn`; the typed route union is built at construction by the `isRouteStateOf(routes, x)` predicate (id is null or a key of the manifest) inside the `route` computed. Both `unsafe/` files deleted.
- D25: rfc:0006 moved generators to `@keel/schema/gen`; router property tests import `gen` from there.
- D26 (golden-1 bug 1): the router passes `ctx` (from `createRouter(routes, { ctx })`) as the third argument to every layout and page `component`; `RouteDef.component(props, slots?: undefined, ctx?: Ctx)`. `renderView(v, ctx)`. Test: test/ctxAndChildren.test.ts (sim clock reads 0).
- D27 (golden-1 bug 2, rfc:0008): layouts get their page as `props.children` thunk (`() => Node`), `RouteProps.children` retyped. `Form` renders `children` through `internal/renderChildren.ts` (copy of ui's; forms-order forbids importing ui): thunk, node, string or array. `FormProps.children` widened. BLOCKER: `conformance/fixtures.ts` (lines 8, 112-114: layouts read `p.children` as a Node) must move to the thunk in an `rfc:NNNN` PR; until then 17 router conformance tests fail and `tsc` reports TS2322 in fixtures.ts. Not edited here.
- D28 (bug fix, no RFC): `App` installs one document-level click listener (removed with the App scope) that intercepts primary, unmodified clicks on same-origin `a[href]` (no `target` other than _self, no `download`) inside the App's host, `preventDefault`s and navigates with push. `browserHistory` already pushState/popstate. Spec k.router Client gained the sentence. Test: ctxAndChildren.test.ts.
- D29 (bug fix, no RFC): guard denial always redirects to `href(redirect) + '?next=' + encodeURIComponent(current href)`, whether or not the target declares `next` (its own search parsing drops it if undeclared). Server already behaved so. Test: guardNextAndFields.test.ts.
- D30 (bug fix, no RFC): `keel.fields` data values are human messages (k.forms text), not rule names. `internal/messageFor|nodeAt|unwrapNode` are copies of @keel/forms' (router precedes forms in deps order); `fieldsError` takes the action input node.
