- D6 (golden lane, 2026-11-11): `digest.latest` lives in a plain `ctx.storage` key, not a `stores` factory: only an action saves factory stores and each server keeps its own copy, so a job's write would stay invisible.
- D7: `refresh` enqueues with no `key`; a fixed key makes every refresh after the first finished job a no-op (keys of the last 1,000 finished jobs are remembered).
- D8: the digest feed polls its own storage key every 1,000 ms of `ctx.clock` and yields on any field change; the board read is a module-level `service({ module: 'api', schema: board })` with output `ListsReply`.
- D9: the exit eval extends task `golden-1-api` (no new task folder): a hidden in-process suite (`acceptance.test.ts`, writes its own `routes.json` from the manifests) and a built-process proof (`splitBuilt.ts`, copies the app under the git-ignored `.fixtures/`). Transcripts normalise each UUID to its first-appearance index; the built proof also maps every `at` to one placeholder (real clock).
- D10: `apps/sessions` `check` does not run `keel check`: seven errors exist there (E1002, E1701 in `test/resumeRecording.test.ts`, `test/resumeReplay.test.ts`); backlog line to file at batch end. `@hono/node-server` stays in the three apps' `package.json` until the orchestrator drops it with the lockfile.
- D11: golden lane committed with the exit eval RED: built topology B answers 404 for `POST /digest/refresh` on `api` because `dist/api/routes.json` lists only the client deployable's routes (backlog 0345), so forwarding never learns a node peer's paths. Confirmed by patching the three `digest.*` entries into `dist/api/routes.json`: the built proof then passed 3 of 3.
