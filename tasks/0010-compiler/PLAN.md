## Decisions
- D1: Parse with `oxc-parser` `parseSync(path, source, { sourceType: 'module', lang })` (lang from extension); walk with oxc's typed `Visitor` (no casts needed; unsafe count stays at the one eval site). Rewrite with `magic-string`: only outermost JSX ranges, E1401 edits, intrinsic-only `@keel/runtime-dom` imports, and a prepended header change; TS is preserved byte for byte.
- D2: `compile(files, { mode })` is pure: returns `{ outputs, artifacts, hashes, diagnostics }`; outputs in input order; artifacts built with sorted keys; `hashes[name] = "fnv1a:" + FNV-1a(canonical JSON)` (in-house, no crypto). Diagnostics sorted by path, line, col, code. The Vite plugin (`@keel/compiler/vite`) writes `.keel/<name>` as `{ data, hash }`, chmod 0444.
- D3: Generated code imports `* as __k from "@keel/runtime-dom/ops"` (namespace grows `_` until absent from the source); templates hoisted as `const __kt<i> = __k.template(html)` after the import. One template per element root; a fully static root compiles to just `__k.clone(__kt<i>)`.
- D4: Node references inside a cloned root: elements by `root.querySelector('[id="<id>"]')` (every element has an id; robust to parser-inserted nodes such as tbody); text/anchor children by `parent.childNodes[i]`. All refs are taken before any op runs. Dynamic text child = one-space text placeholder; adjacent text nodes separated by `<!---->`; components and control flow get a `<!---->` anchor (`replaceWith(Component(...))` for components, op anchor for If/For/Match/Boundary).
- D5: Element ids: literal `id` kept; otherwise `<file>.<ordinal>` (`<file>` per D19) where the ordinal counts every intrinsic element of the file in source order from 0 (explicit ids also consume an ordinal, so adding an id never renames siblings). Derived ids are written into the template. E1404 checks across all files of one compile.
- D6 (amended by D17): Op signatures (from packages/runtime-dom/src/ops): `cond(anchor, when, then)`, `list(anchor, each, key: item => k, render(item: () => T, index: () => number))`, `match(anchor, on, key, cases: { [tag]: (value: () => U) => Node })`, `boundary(anchor, children, fallback)`. Users write row/case callbacks with plain values (`(item) => item.name`, per conformance); the compiler rewrites reads of identifier params to accessor calls (`item()`), or wraps destructured params once.
- D7: Match discriminant: explicit `key="..."` on Match, else the `Props` schema union key (static `s.union(key, [...])` resolution), else `state` if all Case tags are resource states, else `tag`.
- D8 (amended by D20): E1401 simple patterns (`{ a, b: c }`, no defaults/rest/nesting) are rewritten in the output to `props.a` reads; the same edits form the fix.
- D9: `mode: "server"` currently emits the client module. Server HTML rendering (escaping, `data-k`, `<!--[-->` regions, using runtime-dom `internal/safeUrl`) is not built: follow-up.
- D10 (superseded): `mode` is back to `"client" | "server"` after the rfc:0000 conformance fix typed `constantFrom`.
- D11: Parse errors are reported as `E1000 syntax error: ...` and the file is passed through unlowered. E1000 is not in the spec code table: needs a spec line (RFC).
- D12: E1501 (k.router) implemented compiler-side for literal URL attributes that are neither absolute (`scheme:`/`//`) nor a `#fragment`. E1003 literals are replaced with `about:blank` in the template.
- D13: a11y.json: role = explicit `role` else implicit role by tag (input by type); name source = `aria` (aria-label/labelledby) > `alt` > `label` (ancestor label or `for`) > `text` (only for name-from-content roles) > `none`.
- D14: deps.json nodes: signal/computed/resource declarations, effect calls, props fields, bindings (text/attr/prop/on and the tracked input of cond/list/match); edges by identifier name within a file; `on` bindings have no edges.
- D16: Children the HTML parser would restructure inside one template (`p > div`, `table > tr`, `a > a`, headings in headings, non-option in select, ...) are cloned from their own template and inserted with `replaceWith` (`internal/canNest.ts`), so the DOM always equals the JSX tree and `childNodes` indices hold.
- D17: Row/case parameter rewrite is scope-aware. `analyze` records every declaration with its scope (function, block, for, switch, catch, program; `var` to the function) and `bindsTo` resolves a read to its innermost declaring scope; only reads that resolve to the callback's own parameter are rewritten. Destructured (or defaulted) parameters become an accessor `x` plus a trailing default parameter `p = (<pattern>) => ({ names })` (padded past the index slot); each read of a bound name becomes `p(x()).name`, so rows and cases stay live when the item for a key changes. E1401's rewrite uses the same resolver.
- D18: Artifact maps are null-prototype objects filled via `Object.hasOwn`/Maps (ids, a11y, canonical JSON, merge); internal lookup tables are Maps, so ids or tags such as `constructor`/`__proto__` are kept and never resolve to prototype members.
- D19 (spec decision, k.component IDs line updated): derived ids use `<file>` = project-root-relative path without extension with `/` as `.` (`src/orders/OrderList.tsx` -> `src.orders.OrderList.0`); `compile` paths are taken as root-relative (`./` and `\` normalized). Removes false E1404 between `a/index.tsx` and `b/index.tsx`. Spec question for freeze: inserting an element shifts the ordinal of every later derived id in the file (accepted for now).
- D20: E1401 fix is a real unified patch: `--- a/<path>`, `+++ b/<path>`, one `@@ -l,c +l,c @@` hunk per changed line range with up to 3 context lines (hunks whose context would overlap merge, as diff does), `\ No newline at end of file` markers. Tested with `git apply --check` and `git apply` in a temp dir under test/.
- D21: Vite plugin compiles only the changed module (cached by source), merges per-module artifacts (`internal/mergeArtifacts`; cross-module duplicate ids fail the later module with E1404), evicts modules on `watchChange` delete, skips a write when the serialized artifact is unchanged, and writes temp + chmod 0444 + rename. Quadratic passes removed: identifier filtering uses a sorted-span coverage index; `record`/`select`/`owner` use binary search over sorted idents/JSX/edits/elements; rules index identifiers by name once. (`componentAt` remains a linear scan per binding.)
- D22: Any `on*` attribute on an element, in any case (`onclick`, `onClick`), is an event binding; a string or bare value (`onclick="..."`) is never emitted and reports E1002 (code from a string). `./testing` is dev-only: `esbuild` is an optional peer dependency (also a devDependency); `happy-dom` stays a devDependency (tests supply the DOM).
- D15: `evaluate` (test helper) runs esbuild `transformSync(loader: 'ts', format: 'cjs')` then `new Function` inside a never-disposed root `scope` (module-level signals would otherwise be E1203). The `new Function` lives in `unsafe/runCommonJs.ts` (unsafe count 1).
- D29 (rfc:0008): a component call lowers JSX children to a `children` thunk in the props object (`children: () => "Go"` for a single static text child, else `() => <fragment>`); the `slots` argument is no longer emitted (reserved for named slots, later RFC); `ctx` is passed as `Name(props, undefined, ctx)`. Tests: conformance/children-default-slot.test.ts (uses stand-in base elements: `evaluate` cannot require `@keel/ui`).
- D23 (0040 styles): `collectStyles` reads style props on JSX elements whose tag is a base element imported from `@keel/ui` (and static `styles({...})` calls): every literal token per (prop, breakpoint, state) is a usage, plus literal leaves of `?:`/`&&`/`||` values so dynamic switches have rules. `styles.json` = `{ usages }`, one single-prop `StyleUsage` per (prop, token, breakpoint, state), keyed and sorted by canonical JSON, merged/deduplicated across modules. A base element without spreads whose `class` is absent or literal gets each fully static style attribute (incl. a static `states`) dropped and one `class: "<names> <existing>"` prop added, in ui `classesOf` order; dynamic attributes stay. Names come from `internal/className.ts`, a copy of ui's `className`/`ident`/base-36 FNV-1a (comment points at ui); `test/className.test.ts` imports ui's by relative path (test only) and asserts equality on fixtures + a seeded property, and that every rewritten class is a rule of ui `compileStyles` over `styles.json`.
- D24 (0040 build-time evaluation): the Vite plugin is build tooling, not kernel runtime code, so it may use anything at build time. It never imports router/ui itself: `internal/evaluateProject` bundles a generated entry with esbuild (stdin, `resolveDir` = app root, app modules under the root lowered by `compile`, workspace packages bundled as is), writes it to an os temp dir, `import()`s it once, and reads back JSON `{ css, routes, problems }` computed in the app's own module graph by `compileStyles` (`@keel/ui/css`) and `routesArtifact` (`@keel/router`). Specifiers are string constants so S0003 does not apply (no `@keel/router` import in compiler code). Usages with unknown tokens are dropped from the CSS and warned (`E1801 ...`; `check` reports them at source); E1807 (unsafe token value) also warns. Requires `esbuild` (optional peer, present in the workspace) and the app depending on `@keel/ui`/`@keel/router`.
- D25 (0040 Vite plugin flow): `configResolved` reads `topology.ts` statically (`internal/parseTopology`, oxc; literal deployable names, module ids, adapters; problems throw in build, warn in serve). `buildStart` compiles every app source under the root (`internal/listSources`: no dot/build/test dirs, no `*.test.*`/`*.d.ts`) into the module cache, then evaluates (D24) and flushes artifacts (`routes.json` from the evaluation). `transform` only compiles files under the root: linked workspace packages resolve to real paths outside it and must not be compiled (found by an end-to-end `vite build`: runtime-dom's own `innerHTML` tripped E1002). `virtual:keel.css` resolves to `/__keel.css`; its `load` re-evaluates when usages or project files (`tokens.ts`, `topology.ts`, `routes.ts`, `*.schema.ts`) changed; in dev a change re-evaluates and `reloadModule`s the CSS. Topology changes recompile cached modules (E1004 exemption). Verified end to end: Vite 5 `build()` of a scratch client app (tokens, topology, store, routes, ListsPage) produced CSS with `:root`, dark-scheme and `min-width` blocks and a bundle that renders `<main class="k-p-2 k-md-p-3 k-bg-bg"><span class="k-fg-fg">0</span></main>` under happy-dom. Plugin type-checks against Vite 5's `Plugin`.
- D26 (0040 `uses`): when a file exports `uses` (`export const uses = [...]` or `export { x as uses }`), its default-export component body becomes `let v; scope(() => { for (const u of uses) u.store.uses([u]); v = (() => { <body> })(); }); return v;` (expression bodies likewise). `@keel/store` has no free `uses()`; per-transaction `t.store.uses([t])` is the store API, and the own child scope keeps the declaration from restricting the parent or siblings (spec: "in the component's scope"). Runtime enforcement only sees code running with that scope as `owner()`; event handlers run outside reactive scopes (store/runtime-dom concern, not changed here).
- D27 (0040 ctx): every component call passes the innermost enclosing component function's third parameter: its name when declared (identifier or defaulted identifier), else `<ns>props, <ns>slots, <ns>ctx` / `, <ns>slots, <ns>ctx` / `, <ns>ctx` are inserted as parameters (an unparenthesized arrow param is wrapped). Functions with a rest parameter or a destructured third parameter pass none. Only components that render a child component get parameters. Zero-length insertions are applied with `appendLeft` and sort before other items at the same position.
- D28 (0040 topology, routes, entry): `compile(files, { topology, routes })`. E1004 is skipped when every deployable owning the file (`modules/<id>/...` -> deployables listing `<id>`; other files -> all) has `adapter: 'client'` (`internal/clientOnly`). `routes` is copied sorted into `routes.json` (default `{}`); `mergeArtifacts` unions routes and style usages. Generated `/@keel/entry.ts` (`internal/entryCode`) for the selected `client` deployable (`KEEL_DEPLOYABLE`, else first by name): `import "virtual:keel.css"`, `createCtx({ mode: "real" })`, the deployable's `modules/<id>/routes.ts` (one manifest used as is, several merged with `manifest({ ...a.routes, ...b.routes })`), `createRouter(table, { ctx, history: browserHistory() })`, `mount(router.App, document.getElementById("app"), { ctx })`. Scaffold's `index.html` should be `<div id="app"></div><script type="module" src="/@keel/entry.ts"></script>` (coordinate with 0023).
- D30 (0040, needed by golden app 1): top-level `const x = store(...)` (from `@keel/store`) and `signal`/`computed`/`resource` (from `@keel/reactive`) initializers are wrapped in `<ns>root(() => ...)`, a never-disposed module root `scope` (the runtime throws E1203 outside a scope, so `export const board = store(...)` could not load in the browser or under vitest). An exported store in `modules/<id>/` without an explicit id gets `{ id: "<id>.<export>" }` (k.store Ids: "the compiler fills it from the export name"); an options object without `id` gets it inserted.
- D31 (rfc:0008 follow-up): a JSX child expression that is a call of `slots.<name>`, `<x>.children`, or a `children` binding (optional calls too) is inserted as a node (`replaceWith((call) ?? "")`), not bound as text (was `[object DocumentFragment]`).
- D32 (check conformance): `ruleUrlLiteral` also inspects base-element URL props (`Link to`, `Image src`, by `@keel/ui` import); absolute URLs (any scheme, `//`) and `#fragment` are allowed; a literal script/data URL is exactly one E1003 (E1003 before E1501).
- D33 (check conformance): `@keel/ui` base elements with a literal `id` are elements for E1404 and `ids.json`/`a11y.json` (tag/role/name of the DOM element they render: Box/Text by `as`, Heading `h<level>`, Button, Link `a`, Image `img` (decorative -> presentation), Input/TextArea/Select/Checkbox with name `label`). They take no ordinal (derived ids unchanged) and are not passed to lowering (`ElementInfo.base`).
- D34 (coordinator): `module(def)` + `ModuleSchema` exported from `@keel/compiler` (k.module manifest: schema + lowerCamel id, returns the def frozen with literal types, throws `code: 'keel.module'`; cross-module checks stay k.check/0030). `tsconfig.strict.json` (base strict profile + `allowImportingTsExtensions`, `noEmit`, `jsx: preserve`, no `jsxImportSource`) shipped and exported as `./tsconfig.strict.json` (also in `files`); verified tsc checks component props through JSX without a JSX namespace. Test: `test/module.test.ts`.
