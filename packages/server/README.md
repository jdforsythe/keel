# @keel/server

**Spec:** k.server, k.topology · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `topology(def)`, `commitStores(ctx, factory, fn)` and `identity({ identify, handle? })` (app code uses only these) · `createApp({ topology, routes?, ctx, mode?, deployable?, guards?, log?, artifacts?, inspect?, assets?, secret?, secure?, std?, runners?, peers?, origin?, allow?, maxStreams?, identity? }) -> Promise<{ fetch(req), close() }>` (generated entry, `keel dev`; Hono) · `start(opts)` from `@keel/server/internal/start` (the generated production entry only) · `installServerDom` from `@keel/server/internal/dom` · types `AppOptions`, `Identity`, `ServerApp`, `Runner`, `LogSink`, `Topology` (re-exported from `@keel/compiler`, its one definition). A GET of `/@keel/entry.ts` answers the generated resume entry a document with islands loads; without a build a document scripts `/@keel/entry.ts?d=<deployable>`, the resume entry over `/@keel/islands.ts?d=<deployable>`, that deployable's islands (no `deployable` given: `/@keel/entry.ts`); in production with `assets` (the `keel build` output `dist/<deployable>`), documents load the built entry instead and the regular files under `assets/` are served `nosniff`, `immutable` when the manifest names them with a `-<hash>` (8 base64url characters not all lowercase letters, or 8+ hex), else `no-cache`, each with a weak ETag honored by `If-None-Match` (304), keyed by decoded path; a symlink resolving outside `assets/` is not read. The build's top-level `keel-mark.svg` (copied from `public/`, a regular file only) is served the same way. Every document's head has `<title>` the deployable name and, with a build, a stylesheet link per served `.css` file under `/assets/` that the manifest's entry chunk names, and the mark as icon, all escaped and none inline; a `keel.notFound` default alert is `<h1>Not found</h1>`. Guards, loaders and actions get `url`, the absolute request URL, `caller`, `user` (below), and `stores`; an API route's guards, loaders and actions also get `bearer` (below).
- **Invariants:** `topology` throws E1552 for a bad shape or empty `modules`, and E1566 for a `host` on a deployable that is not `client`, naming an unknown or non-`node` deployable, or naming a host another `client` names (k.hosting). `createApp` rejects with E1552 (unknown module, module in two deployables, no `deployable` among several) or E1553 (`static` with params or actions), E1511 (a `client` or `static` deployable serving an API route), E1558 (a `client` or `static` deployable serving a route whose loader is live or names `stores`, or whose action names `stores`), or E1555 (production `assets` without a client manifest entry); `std` (a `.keel/std.json`) is read at startup and bound to `ctx` for `stdConfig` (E1160 missing, malformed or hand-edited; E1158 failing a registered schema). Flow mirrors k.router and k.guards (404, 308, guards then concurrent loaders; deny 302/303 with `?next=`). Status: notFound 404, denied 403, fields 422, unexpected 500, other 400. Writes (POST/PUT/PATCH/DELETE) must be same-site (`Sec-Fetch-Site` same-origin/none, own `Origin`, `accept: application/json` + `x-keel: 1`, or neither header), else 403 `keel.denied`. Actions by verb or a POST's `_method`; submitted values drop `__proto__`, `constructor`, `prototype`; a `content-type: application/json` body (k.services client) is parsed with the action input instead of FormData; bad FormData or JSON 422, action not run; documents get 303, `accept: application/json` the `Result`. An API route (`api: true`, k.api) is answered as a runtime request whatever `accept` says: GET/HEAD with a loader get `{ id, results }`, without one 405 with `allow` listing its action methods; a write's action declares `output` and gets the `Result` JSON, never 303: its `ok` value is parsed by `output` before any store is saved (refused: an E1554 `diag` naming the path, a record key as `*`, never the value, and 500 `keel.unexpected`, nothing saved), its `.pii()` values join the request's scrub set, then the stores are saved, then it answers 200 `{ ok: true, value: <encoded> }` (a 409 `keel.conflict` sends no value); its guards, loaders, live loaders and actions get `bearer`, the `authorization` header's value, less leading and trailing spaces and tabs, when it is `bearer` in any letter case, one or more spaces and a token68 of 1 to 4,096 characters with any trailing `=`, as a `Secret` whose revealed text no `diag` holds, else `undefined` with no error and no log line (the raw header is not kept; a page's guard and loader get `undefined`); its response to a request carrying `authorization` is `cache-control: no-store`; a guard denial is 403 `keel.denied`, its `redirect` (optional on an API route's guard) not followed. A 405's `allow` lists GET, HEAD (not for a loader-less API route) and the route's action methods. `mode` defaults to `production`, which scrubs `keel.unexpected` to `unexpected`; dev adds a panel. Documents hold one `#k-state` `{ stores, islands, route?, error?, form?, std? }` (`error`: when a loader failed, its `{ code, message: code, data: { at? } }` and nothing else, which the resume entry reports after the served `nav`) (`route`: the served route `{ id, path, href, params, search }`, params and search encoded, on route documents, which the resume entry reports as the ctx's first `nav`) (`std`: the bound `std.json` config of `clientStd` packages for the served deployable's modules, on island documents only); element roots get `data-k-island`. `log` gets one `req` per request after any `diag` (E1554). In `dev`, `GET /__keel/inspect` returns `{ live: true, graph: inspect(), stores: { [id]: { state, log } }, ids, a11y, routes }` (artifacts read from the `artifacts` dir per request, `{}` without it), only for a loopback or `inspect.origins`-listed host and an absent, own, or listed `Origin` (listed ones echoed for CORS; others 403 `keel.denied`); production: route-table 404.
- **Dependencies:** `hono`, `@keel/schema`, `@keel/router`, `@keel/store`, `@keel/reactive`, `@keel/ctx`.
- **Rungs:** conformance; properties (seed 1337): status by code, FormData round trip, topology round trip, one `req` per request.
- **Scope:** string renderer (string, or a DOM node serialized). Each route level renders with the runtime in its server mode, which writes the `<!--[-->` … `<!--]-->` regions `resume` claims (k.resume); a child level's content starts with a `<!--k-->` comment; a layout's `children` thunk throws E1255 on its second call, and a thrown kernel code fails the level and is logged as that `diag`. Streaming is later work.
- **Server DOM.** Without a DOM global, `createApp` installs a DOM-free tree (`installServerDom`): enough of `Node`, `Element`, `DocumentFragment`, `<template>` and the form controls (`HTMLInputElement`, `HTMLSelectElement`, `HTMLTextAreaElement`, `HTMLOptionElement`) for compiled templates, `@keel/ui` and `@keel/forms` to render. `querySelector`, `querySelectorAll`, `matches` and `closest` take a type or `*`, `#id`, `.class`, `[name]` and `[name=value]`, compounds of them and `,` lists; any other selector throws a `SyntaxError`. Control `value`, `checked` and `selected` are state, as in a browser, so they never appear in the markup.

## Topology

- **Runners.** `runners: { [moduleId]: Runner[] }`; each `run(ctx, signal)` of the served deployable's modules starts once after startup. A `run` that rejects before `signal` aborts writes a `keel.unexpected` `diag` and runs again 1,000 ms later on `ctx.clock`. `close()` aborts the shared signal and every open event stream, unbinds the ctx and resolves when every `run` has settled. A module with runners and no routes is valid (E1552).
- **Peers and calls.** `peers: { [deployable]: URL | string | ServerApp }`. `createApp` binds its `ctx` (the `globalThis` key `Symbol.for("keel.modules")`, read by `@keel/services`): each module of the served deployable answers `service({ module })` through this app, each module of a peer through that app in process or its URL by `ctx.net.fetch`. A request whose path no local route matches but a peer's route does (by `routes.json` in `artifacts`) is forwarded with its method, path, search, headers but `host`, body and `x-keel-forwarded: 1`, and its response returned unchanged; one already carrying `x-keel-forwarded` is not forwarded.
- **Origin.** `origin` replaces the request's origin in `url`, the same-site `Origin` comparison and the cookie's `Secure`; with it, no W1557.
- **Allowed origins** (k.hosting). `allow` lists http(s) origins, matched exactly against the request's `Origin` (scheme, host, port); an entry that is not an http(s) origin rejects `createApp` with E1560 naming its index, never its value. With any entry, every API-route response carries `vary: origin`, appended to any `vary` it has. On an API route only, a request from a listed origin: an `OPTIONS` with `access-control-request-method` is 204 with `access-control-allow-origin` (that origin), `access-control-allow-methods` (the route's), `access-control-allow-headers: accept, authorization, content-type, x-keel`, `access-control-allow-credentials: true`, `access-control-max-age: 600`, `vary: origin`, and no guard, loader or action runs; any other method's response carries the origin, credentials and `vary` headers, and a write passes the same-site check. Pages, assets and other origins are unchanged (preflight 405, write 403, no other header). The caller cookie is unchanged; a listed origin with `sec-fetch-site: cross-site` is one W1567 `diag` per origin per app.
- **Host** (k.hosting). When a `client` deployable names the served one its `host`, production `assets` must hold that client's `index.html` (else E1555), and a GET or HEAD that matches no route, is not forwarded to a peer, is neither runtime (`accept: application/json`) nor an event stream, and is not under `/assets/` gets it: 200, `text/html`, `no-cache`. The copied client `assets/` are served as the host's own.
- **Live loaders.** A GET with `accept: text/event-stream` to a route whose loader is live runs the guards (a redirect is 403 `keel.denied`), opens its `stores` once, and streams through Hono's `streamSSE` one `data: <Result JSON>` per yield (`ok` encoded by `output`) and `:` per 15 s of `ctx.clock`, `cache-control: no-store`, until `fn` returns or its `signal` aborts (request abort, reader cancel, `close()`). A non-live route there is 406. With `maxStreams` (a positive integer, default 1,000) streams open, one more passes the guards and gets 503 `keel.busy` with `data: { limit }`, running no loader; a stream frees its place when it ends for any reason. A live loader in a non-`node` deployable is E1558 at `createApp`, and at the call in `keel check` and `keel build`.
- **Production entry.** `start({ topology, deployable, routes, runners, open?, dir })` parses `PORT` (default 8080), `KEEL_ORIGIN`, `KEEL_SECRET` (32+), `KEEL_ALLOW_ORIGINS` (comma-separated http(s) origins; `*` or a path fails), `KEEL_PEER_<NAME>` per other `node` deployable and `KEEL_DATABASE_URL` (the deployable's `storage`: `'sqlite'` an optional `file:` URL, default `file:/data/keel.sqlite`; `'postgres'` a required `postgres:` or `postgresql:` URL; `'file'` not read) with `DeployEnv`; a failure prints one `E1560 <KEY> fails DeployEnv (<rule>)` line, never the value, and exits 1. A `'sqlite'` deployable on a Node older than 22.13 (by major and minor; `start`'s second argument, `process.versions.node` by default) prints one `E1560 storage 'sqlite' needs Node 22.13 or newer; this is <version>` line first and exits 1 before `open`. Then `open(url)`, the `@keel/std-db` driver the generated entry passes, gives the ctx its `drivers.storage` before listening (a rejection with `code` E2152 or E2153 prints that diag without the code prefix and exits 1; any other rethrows); SIGTERM or SIGINT stops listening, awaits `app.close()`, then the driver's `close()`, and exits 0. `topology()` keeps a deployable's `storage` and `shells`. It serves `createApp` (production, real ctx, `dir` as `assets` and `artifacts`, `std.json` there when present) with `@hono/node-server`, logs to stdout, and on SIGTERM or SIGINT stops listening, awaits `close()` and exits 0. Before anything else it installs `uncaughtException` and `unhandledRejection` listeners (`@keel/server/internal/onUncaught`; `createApp` installs none, so a process that embeds it chooses its own): each writes one `diag` E1577 `uncaught <exception|rejection> in work of route <id>`, the route of the request whose async context the failing work ran in, else `-`, with the error's `frames` and none of its text. The first then stops listening, lets requests in flight finish for at most 10,000 ms, awaits `close()` and the driver's `close()`, and exits 1, so a supervisor (a container restart policy, systemd, the platform) restarts the process; a later one writes its record only. `keel dev` installs the same listeners with the thrown text appended, scrubbed of that request's values and cut, and keeps serving.

## Server state

Server state is per request (k.server Server state): a loader or action names a factory with `stores`; the server runs it once per request in an isolated child scope of the request scope (`openStores`), restores a factory's stores from one `ctx.storage.read` of their keys `keel.store.<id>` (`snapshot({ meta: true })` JSON; k.persist), reusing the parse in the in-process copy of that `ctx.storage` (`copyOf` from `@keel/store/internal`, one per storage object) when the value read is the one it parsed, and after an action's `ok` saves in one `ctx.storage.commit` (`saveStores`): each changed store's snapshot with `expect` the value it was restored from, each opened unchanged key as a condition. A refused commit is 409 `keel.conflict` with nothing saved, so another request or process that saved any store this request opened, changed or only read, since it read it, wins, and a save of several stores is atomic. Once the commit lands, each changed store is reported to `observe` on the server ctx as `{ kind: 'save', store, head, from }` (`from`: the head before the save, 0 when none was saved); a 409, `err` or throw reports none. `commitStores(ctx, factory, fn)` (from `@keel/server`, for runners and jobs; E1551 outside `*.server.ts`) is that path outside a request: one `read`, `fn(S)` returning a `Result`, and on `ok` one `commit` and its `save` events; a refused commit runs `fn` again on a fresh read, at most 3 runs in all, then resolves `err` `keel.conflict`; `err` or a throw saves nothing; it resolves `fn`'s `Result`. A `tx` refused as concurrent returns `keel.conflict` with `{ store, transaction, base, head }`, which the action answers 409 like any `err`. `err` or a throw saves nothing and drops the instances, so a re-render reads storage. Factory stores need explicit ids (a default `store.<n>` id throws). `#k-state` snapshots only the request-registry stores an island level's render created, looked up through `stores()` or read (a page with no island ships `stores: {}`; a store only a guard, loader, action or static level touched is not sent; k.leave); module-level stores are process-wide: while a request runs (guards, loaders, action, renders, through every `await`, an `AsyncLocalStorage`), a write to a module-registry store (`tx`, `restore`, `undo`, `undoWhere`) throws E1256 and changes nothing, so the level fails as a throw does and an action answers 500. The check follows async context: a timer, promise callback or job the request started is checked for its whole life, also after the response, and its throw from a timer is an uncaught exception; a callback registered outside the request (at module load) is not checked, even when the request resolves it. Runners and start-up run unchecked, also when `createApp` is called inside a request. The caller: the cookie is `__Host-keel-caller` with `Secure` when the request is https, else `keel-caller`. `createApp({ secure })` decides that; unset, the request URL's scheme does, upgraded (never downgraded) by a first `x-forwarded-proto` value of `https` from a TLS-terminating proxy. `secure: true` is the production setting: a deployed production start without `secure` writes one W1557 `diag`. Over plain http a sibling host can still plant a validly signed `keel-caller` (see docs/THREAT-MODEL.md); only a value the server signed (`token.mac`, HMAC-SHA-256 under `createApp({ secret })`, at least 32 UTF-8 bytes else E1556 at startup, default 32 random bytes per `createApp` with a W1556 `diag` on a deployed production start; `callerSigner`) counts. A write without one gets a token minted with `ctx.random.id("Caller")`, signed, and set `Path=/; HttpOnly; SameSite=Lax`; a read without one gets `""`; loaders and actions see `caller` as the cookie value's base64url SHA-256, never the value, so stored `meta.caller` cannot be replayed as a cookie; apps record it as `tx` meta and undo with `undoWhere`. The cookie has no `Max-Age` unless the served `node` deployable sets `caller: { days }` (an integer 1 to 400, E1578) in `topology.ts`; then the cookie it mints carries `Max-Age=<days × 86,400>` from that write and is never extended. Snapshots keep at most each store's `logLimit` entries (k.store). Action results, 303/302 redirects, and 403 refusals send `cache-control: no-store`.

## Identity

Keel authenticates no one (k.user). A project may have `identity.server.ts` beside `topology.ts`, default-exporting `identity({ identify, handle? })`; each `node` deployable's generated entry (`server.mjs`, `keel dev`) passes it as `createApp({ identity })`. `identify({ request, caller }, ctx)` gets the incoming `Request` without its body and the caller it presented, and answers a user id or `""`. It runs once per request the deployable answers on a route (page, API route, event stream), after the same-site check and before guards; never for assets, `/__keel/*`, a forwarded path or `handle`, and nothing is cached between requests. A throw is 500 `keel.unexpected` with one `diag` `identify threw: <name>`; an answer that is not a string of at most 256 characters is 500 with `identify returned: invalid`; past 5,000 ms on `ctx.clock`, 503 `keel.busy` (`data: { limit: 5000 }`); no guard, loader or action then runs. Guards, loaders (live too) and actions get its answer as `user`, `""` with no identity source; an event stream keeps the `user` it opened with. No header, cookie, search or body value of the client sets `user`.

`handle: { path, fn }` mounts a library's own endpoints (sign-in, callback, sign-out): a request at `path` or under it goes to `fn(request, ctx)` with its body (over `maxBodyBytes`: 413), after the same-site check for a write, and `fn`'s `Response`, `set-cookie` included, is returned with the security headers added. `path` is lowercase `/` segments with no route at or under it, else `createApp` rejects with E1579. The only cookie the kernel sets is the caller cookie.

Pages reach `handle` through `identity.ts` beside `topology.ts` (k.mount): it default-exports `identityMount(path)` from `@keel/router`, and `identity.server.ts` gives `handle: { path: mount.path, fn }` with `mount` its default import (E1580 otherwise). A page links there with `mount.href(subpath?, search?)` and posts there with a `Form` whose `action` is one, which the browser sends natively (urlencoded, the form's own fields); a module importing `identity.ts` must be served from an origin that mounts `handle`: a `node` deployable, or a `client` one with `host` and no `shells` (E1581). Nothing changes in `createApp` for such a post: it meets the same-site check, `fn` answers it (a 303 to a page `Href` with its library's `set-cookie`, or back to the form's page with a search key such as `?error=credentials`), and its `Response` is returned as given, with no cookie added.

A forwarded request keeps its headers, so the peer runs its own `identify`. A `service({ module })` call made with `user` carries `x-keel-user`: the user, an expiry 60 s ahead on `ctx.clock` and an HMAC-SHA-256 under `createApp({ secret })` over method, path, search, user, expiry, the receiving deployable's name (`createApp({ deployable })`, else `''`) and the SHA-256 of the body as sent, newline-joined. A `user` over 256 characters is `api.input` at the sender. A server that verifies it against its own name and the body it read (copied, capped at `maxBodyBytes`), with the expiry not passed and at most 65 s ahead of its clock and a `user` of at most 256 characters, uses it as `user` and runs no `identify`; any other `x-keel-user` is ignored. Within its window a captured header replays that one request to that deployable; plain `http` between peers exposes it.

## Security

Every response carries `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `X-Frame-Options: DENY` and `Permissions-Policy: camera=(), microphone=(), payment=(), usb=()`; over https (the caller cookie's rule) also `Strict-Transport-Security: max-age=63072000` (k.security). Every document carries one fixed `Content-Security-Policy` with a fresh nonce (two `ctx.random.id("Nonce")` values without hyphens) on its module script and on `<meta property="csp-nonce">`, plus `Reporting-Endpoints: keel-csp="/__keel/csp"`; dev sends it as `Content-Security-Policy-Report-Only` with `'unsafe-inline'` in `style-src`. Other responses carry `default-src 'none'; frame-ancestors 'none'`. A hosted client's `index.html` carries the `csp.txt` policy, its `connect-src` adding each `keel-peer` origin. No option widens the policy.

`POST /__keel/csp` takes `application/csp-report` and `application/reports+json` bodies up to 16 KiB (else 413), without the write proof, and answers 204; each violation is one `csp` log record `{ directive, blocked, route }` (`blocked`: `inline`, `eval`, `trusted-types` or an origin; `route`: the route id the document's path matches, else `-`), never a path, query or sample. In 60 s of `ctx.clock` at most 100 reports are logged, at most 10 from one source (the last `x-forwarded-for` entry, else the peer address; a report with neither counts toward the 100 only); the rest are counted, and the window's end writes `{ dropped }`. Sources are held in memory for the window (at most 64 characters each) and never logged. The per-source cap binds behind a proxy that appends `x-forwarded-for`; without one a client can vary the header and is held by the global cap of 100 only. A write behind a TLS-terminating proxy passes the same-site check when its `Origin` is the request's host over https and `x-forwarded-proto` says https.

In `'dev'` mode a route whose render has a text binding that renders nothing (a node or a function bound as text) logs one `diag` E1406 naming the route id, the first time (k.place). An uncaught throw in an action, loader or runner is one `keel.unexpected` `diag`; in json it carries `frames`, the throw's first 5 stack positions in app code (outside `packages/`, `node_modules/`, `.keel/` and the folder holding `artifacts`), each `<path>:<line>:<col>` relative to that folder (the project, for `keel dev`'s `<project>/.keel`). A position in `<artifacts>/server.mjs`, the production bundle, is read through `server.mjs.map` beside it (loaded on the first such throw, at most 32 MB, never served) and is project-relative; one with no mapping is dropped, and a missing, over-cap or malformed map is one `keel.unexpected` `diag` for the process. Under `--enable-source-maps` Node has already mapped the stack against the map's folder, so a position under `<artifacts>/` beside a `server.mjs` is taken relative to `<artifacts>`. A frame from a workspace sibling outside the project folder is dropped. Without `artifacts` `frames` is `[]`. The error itself carries no stack. It, its frames, the error's message and cause, every other `diag` of the request and the request's `req` path hold `[pii]` in place of each `.pii()` value of the decoded action input, the loaders' outputs and the opened stores' states, and `[secret]` in place of the revealed value of each `Secret` made or revealed while the request runs (each string or number in it at any depth, and each record key, `json` key and undeclared object key, not a boolean or a declared field name): its decoded action input, `bearer`, and any later parse such as a loader's after an `await` or a minted token (k.privacy). A written form of 1 or 2 code units (a value that short, as written) is replaced only where it stands as a whole token, with no letter, digit, combining mark or `_` right before or after it; its longer encoded copies are replaced wherever they stand. Each value is matched as written, URL-encoded (a value with a lone surrogate has no URL form), JSON-escaped and base64 (padded; for a value of at least 8 bytes as UTF-8 also without its `=` padding and in the URL-safe alphabet), case-insensitively (letter case in the Basic Multilingual Plane, one code unit at a time, base64 included, so a near copy may be over-marked, never missed); an unpadded base64 copy is matched where the value was encoded on its own, or inside a longer encoded string from a byte offset that is a multiple of 3 and either to its end or for a byte length that is a multiple of 3, and not elsewhere in a longer encoded string, where its characters depend on the bytes around it. A padded copy goes with its `=` padding, in either alphabet. Where matches overlap, the longest one's mark (`[secret]` when as long) replaces the whole run, so the whole of each marked copy is replaced; a copy cut short or with a character changed is not a copy and stays as it is. Each text is read once, in steps linear in its length, however many values the request has; past 2,000,000 characters of distinct written forms, or past 100,000 distinct secret values, or once one `Secret` holds more than 1,000,000 values to read, the set takes no more values and stays past: a `diag` keeps the server's own prefix (`loader <id> threw: `, `action <id> threw: `, `guard <id> threw: `, `runner rejected, rerun in 1000 ms: `) and is one mark after it (`[secret]` when the scope's set holds a secret, else `[pii]`), a `diag` with no such prefix (E1554, E1508) is one mark whole, each frame is one mark, and the `req` path is one mark (`GET [secret] app.reset 200 4ms`). Below the caps the prefix is scrubbed with the rest. A thrown text is scrubbed whole and clipped only after, so no clipped part of a value is left: a `diag` holds the scrubbed thrown text, cut as k.serverlog says below, and the dev response's 89-character message is clipped from the scrubbed text. Every other thrown text the server sends on is scrubbed the same way first: an output encode that throws in a loader or in a live loader's stream line, a component or errorElement that throws while rendering (its errorElement's `error`, the default alert and the dev message), and a guard redirect that fails. No value makes the scrub throw, and no thrown value makes the server throw: a value whose `name`, `message`, `stack`, `toString` or `toJSON` throws, a Proxy or a revoked Proxy is read inside a try and, when a read throws, described by `Object.prototype.toString` or its `typeof` alone; a runner that throws one runs again, and `fetch` never rejects (a throw past every guard of the handler, the app's own `log.write` say, is a bare 500 and one fixed `keel.unexpected` `diag` that names the matched route id when there is one; when that `diag` cannot be written either, stderr gets one fixed `keel.unexpected` record in the log's format, once per process, holding nothing of the value or the request). The request's set follows its own promise chain (`AsyncLocalStorage`), so overlapping requests and an in-process peer's request each mark only their own records. Each call of a runner's `run` has its own set, made fresh for each rerun, and its rejection's `diag` is scrubbed with it; a `Secret` made at startup (module scope, `createApp`'s options) or in an earlier request joins the set of each request or `run` that reveals it, walked once per set; a value revealed outside every scope and kept as plain text is in no set and marks nothing. Before that scrub, each `req` path segment that stands where a route of `routes` has a secret `params` field (a route of another deployable included, so a path forwarded to a peer is marked too) is `[secret]` whole, and one where it has a `.pii()` field (the field or a node above it marked) is `[pii]` whole, `[secret]` where both stand, whatever the client sent there (any mix of raw characters and percent-escapes in either case, an escape that does not decode, a `+` or `;`, a value the schema refuses). A route lines up from the path's first non-empty segment by its segments up to and including the marked one, empty segments skipped (a route led by a prefix param also without that segment): a param fits any segment, and a static segment fits one equal to it decoded once in either letter case, or one that does not decode. When a non-empty segment follows the marked one, the path is cut there: the marked segment and the rest are one mark, `[pii]` or `[secret]` as that segment is (`/reset/ab/<v>` of `/reset/:token` logs `/reset/[secret]`, `/confirm/a/<v>/done` of `/confirm/:token/done` logs `/confirm/[secret]`), so a value holding a raw `/` leaves no part and no slash count behind. When the table has a secret param, the path is also cut as `[secret]` at its first segment whose raw text holds `%2F` or `%5C` in either case (`/reset%2F<v>` logs `/[secret]`); a table whose only marked params are `.pii()` does not cut there. The cut does not depend on a route matching, and with several cuts the earliest wins (`[secret]` when two fall on one segment) and the marks before it stay. It over-marks and never leaks: a served path longer than a secret route it lines up with loses its tail (with `/u/:email` marked `.pii()`, `/u/a@b.c/x` logs `/u/[pii]`; with `/reset/:token` and `/reset/help/faq`, a request for the second logs `GET /reset/[secret] app.faq 200`; the route id still names the page), and a route whose secret param is its first segment or follows only a prefix param (`/:token`, `/:lang/:token`) lines up with every path, so every path of two or more segments logs as one `[secret]`. A path no route lines up with is written as it came. These are the stated limits: a raw `/` in a plain param before the secret (`/o/a/b/k/<v>` of `/o/:org/k/:key`); a typo in a static segment, a homoglyph, a double encoding, `;jsessionid`, a trailing dot or `%20`; an extra leading segment (`/en/reset/<v>` with no prefix param, or a proxy base path left in place); and a secret `search` value in a link missing its `?` (`/callback&code=<v>`), where with its `?` the query is never logged. A failed peer forward's `diag` is `peer unreachable: <name>`, the thrown error's `name` when it is a runtime error name (`Error`, `TypeError`, `RangeError`, `AbortError`, `TimeoutError`, `DOMException`), else `Error`, never its message, which a runtime may write with the URL in it. A request that runs no route (a preflight, `/__keel/csp`, a path forwarded to a peer, inspect) has no request values to scrub, so its path is marked by route segments alone, and a peer path that only `routes.json` names, with no route in `routes`, is written as it came.

`@keel/server/csp` exports `cspPolicy({ nonce, dev? } | { peers })` (the policy text) and `securityHeaders({ https })` (the six headers, and HSTS), which `keel build` and `keel evidence` read.

## Extension points

Each record is written by k.serverlog: a `diag` message and each frame, and a `req` method and path, are scrubbed, then escaped, then cut. Each control character (U+0000 to U+001F, U+007F to U+009F), U+2028, U+2029 and `…` is written as `\u` and four lowercase hex digits in compact and json alike, so a compact record is one line, holds no terminal escape, and a thrown `\n` cannot forge a second record. A message or path keeps the longest head whose escaped form is at most 2,048 characters, a frame or method 256, then `…+<n>`, `n` the scrubbed characters left out (`action app.save threw: Error: bad {"q":"aaaa…+1046501`); `…` in a record is always a cut. When the request or a runner's `run` holds a secret or `.pii()` value, a text over 2,000,000 characters is not read and is one mark, a `diag` keeping its prefix; with none, nothing is scrubbed and only the head is read. A record is then at most 8,192 characters and 12,288 bytes of UTF-8 plus a `req` record's route id.

`guards`: route `guard` names resolve here, then in the router registry. `inspect.origins`: extra origins the dev inspect endpoint answers. `LogSink`: any `{ format, write(line) }`.
