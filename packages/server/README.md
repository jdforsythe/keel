# @keel/server

**Spec:** k.server, k.topology · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `topology(def)` (app code uses only this) · `createApp({ topology, routes?, ctx, mode?, deployable?, guards?, log?, artifacts?, inspect?, assets?, secret?, secure?, std?, runners?, peers?, origin?, allow?, maxStreams? }) -> Promise<{ fetch(req), close() }>` (generated entry, `keel dev`; Hono) · `start(opts)` from `@keel/server/start` (the generated production entry only) · `installServerDom` from `@keel/server/dom` · types `AppOptions`, `ServerApp`, `Runner`, `LogSink`, `Topology` (re-exported from `@keel/compiler`, its one definition; RFC 0046). A GET of `/@keel/entry.ts` answers the generated resume entry a document with islands loads (RFC 0046); without a build a document scripts `/@keel/entry.ts?d=<deployable>`, the resume entry over `/@keel/islands.ts?d=<deployable>`, that deployable's islands (no `deployable` given: `/@keel/entry.ts`); in production with `assets` (the `keel build` output `dist/<deployable>`), documents load the built entry instead and the regular files under `assets/` are served `nosniff`, `immutable` when the manifest names them with a `-<hash>` (8 base64url characters not all lowercase letters, or 8+ hex), else `no-cache`, each with a weak ETag honored by `If-None-Match` (304), keyed by decoded path; a symlink resolving outside `assets/` is not read (RFC 0048, 0057). The build's top-level `keel-mark.svg` (copied from `public/`, a regular file only) is served the same way. Every document's head has `<title>` the deployable name and, with a build, a stylesheet link per served `.css` file under `/assets/` that the manifest's entry chunk names, and the mark as icon, all escaped and none inline; a `keel.notFound` default alert is `<h1>Not found</h1>`. Loaders and actions get `url`, the absolute request URL (RFC 0027), `caller`, and `stores` (RFC 0044).
- **Invariants:** `topology` throws E1552 for a bad shape or empty `modules`, and E1566 for a `host` on a deployable that is not `client`, naming an unknown or non-`node` deployable, or naming a host another `client` names (k.hosting). `createApp` rejects with E1552 (unknown module, module in two deployables, no `deployable` among several) or E1553 (`static` with params or actions), E1511 (a `client` or `static` deployable serving an API route), or E1555 (production `assets` without a client manifest entry); `std` (a `.keel/std.json`) is read at startup and bound to `ctx` for `stdConfig` (E1160 missing, malformed or hand-edited; E1158 failing a registered schema; rfc:0066). Flow mirrors k.router (404, 308, guards then concurrent loaders; deny 302/303 with `?next=`). Status: notFound 404, denied 403, fields 422, unexpected 500, other 400. Writes (POST/PUT/PATCH/DELETE) must be same-site (`Sec-Fetch-Site` same-origin/none, own `Origin`, `accept: application/json` + `x-keel: 1`, or neither header), else 403 `keel.denied`. Actions by verb or a POST's `_method`; submitted values drop `__proto__`, `constructor`, `prototype`; a `content-type: application/json` body (k.services client) is parsed with the action input instead of FormData; bad FormData or JSON 422, action not run; documents get 303, `accept: application/json` the `Result`. An API route (`api: true`, k.api) is answered as a runtime request whatever `accept` says: GET/HEAD with a loader get `{ id, results }`, without one 405 with `allow` listing its action methods; a write gets the `Result` JSON, never 303; a guard denial is 403 `keel.denied`, its `redirect` (optional on an API route's guard) not followed. A 405's `allow` lists GET, HEAD (not for a loader-less API route) and the route's action methods. `mode` defaults to `production`, which scrubs `keel.unexpected` to `unexpected`; dev adds a panel. Documents hold one `#k-state` `{ stores, islands, route?, error?, form?, std? }` (`error`: when a loader failed, its `{ code, message: code, data: { at? } }` and nothing else, which the resume entry reports after the served `nav`) (`route`: the served route `{ id, path, href, params, search }`, params and search encoded, on route documents, which the resume entry reports as the ctx's first `nav`, rfc:0071) (`std`: the bound `std.json` config of `clientStd` packages for the served deployable's modules, on island documents only, rfc:0069); element roots get `data-k-island`. `log` gets one `req` per request after any `diag` (E1554). In `dev`, `GET /__keel/inspect` returns `{ live: true, graph: inspect(), stores: { [id]: { state, log } }, ids, a11y, routes }` (artifacts read from the `artifacts` dir per request, `{}` without it), only for a loopback or `inspect.origins`-listed host and an absent, own, or listed `Origin` (listed ones echoed for CORS; others 403 `keel.denied`); production: route-table 404.
- **Dependencies:** `hono`, `@keel/schema`, `@keel/router`, `@keel/store`, `@keel/reactive`, `@keel/ctx`.
- **Rungs:** conformance; properties (seed 1337): status by code, FormData round trip, topology round trip, one `req` per request.
- **Scope:** string renderer (string, or a DOM node serialized); server-mode compile, streaming and `<!--[-->` regions are later work.
- **Server DOM.** Without a DOM global, `createApp` installs a DOM-free tree (`installServerDom`): enough of `Node`, `Element`, `DocumentFragment`, `<template>` and the form controls (`HTMLInputElement`, `HTMLSelectElement`, `HTMLTextAreaElement`, `HTMLOptionElement`) for compiled templates, `@keel/ui` and `@keel/forms` to render. `querySelector`, `querySelectorAll`, `matches` and `closest` take a type or `*`, `#id`, `.class`, `[name]` and `[name=value]`, compounds of them and `,` lists; any other selector throws a `SyntaxError`. Control `value`, `checked` and `selected` are state, as in a browser, so they never appear in the markup (backlog 0156).

## Topology

- **Runners.** `runners: { [moduleId]: Runner[] }`; each `run(ctx, signal)` of the served deployable's modules starts once after startup. A `run` that rejects before `signal` aborts writes a `keel.unexpected` `diag` and runs again 1,000 ms later on `ctx.clock`. `close()` aborts the shared signal and every open event stream, unbinds the ctx and resolves when every `run` has settled. A module with runners and no routes is valid (E1552).
- **Peers and calls.** `peers: { [deployable]: URL | string | ServerApp }`. `createApp` binds its `ctx` (the `globalThis` key `Symbol.for("keel.modules")`, read by `@keel/services`): each module of the served deployable answers `service({ module })` through this app, each module of a peer through that app in process or its URL by `ctx.net.fetch`. A request whose path no local route matches but a peer's route does (by `routes.json` in `artifacts`) is forwarded with its method, path, search, headers but `host`, body and `x-keel-forwarded: 1`, and its response returned unchanged; one already carrying `x-keel-forwarded` is not forwarded.
- **Origin.** `origin` replaces the request's origin in `url`, the same-site `Origin` comparison and the cookie's `Secure`; with it, no W1557.
- **Allowed origins** (k.hosting). `allow` lists http(s) origins, matched exactly against the request's `Origin` (scheme, host, port); an entry that is not an http(s) origin rejects `createApp` with E1560 naming its index, never its value. With any entry, every API-route response carries `vary: origin`, appended to any `vary` it has. On an API route only, a request from a listed origin: an `OPTIONS` with `access-control-request-method` is 204 with `access-control-allow-origin` (that origin), `access-control-allow-methods` (the route's), `access-control-allow-headers: accept, content-type, x-keel`, `access-control-allow-credentials: true`, `access-control-max-age: 600`, `vary: origin`, and no guard, loader or action runs; any other method's response carries the origin, credentials and `vary` headers, and a write passes the same-site check. Pages, assets and other origins are unchanged (preflight 405, write 403, no other header). The caller cookie is unchanged; a listed origin with `sec-fetch-site: cross-site` is one W1567 `diag` per origin per app.
- **Host** (k.hosting). When a `client` deployable names the served one its `host`, production `assets` must hold that client's `index.html` (else E1555), and a GET or HEAD that matches no route, is not forwarded to a peer, is neither runtime (`accept: application/json`) nor an event stream, and is not under `/assets/` gets it: 200, `text/html`, `no-cache`. The copied client `assets/` are served as the host's own.
- **Live loaders.** A GET with `accept: text/event-stream` to a route whose loader is live runs the guards (a redirect is 403 `keel.denied`), opens its `stores` once, and streams through Hono's `streamSSE` one `data: <Result JSON>` per yield (`ok` encoded by `output`) and `:` per 15 s of `ctx.clock`, `cache-control: no-store`, until `fn` returns or its `signal` aborts (request abort, reader cancel, `close()`). A non-live route there is 406. With `maxStreams` (a positive integer, default 1,000) streams open, one more passes the guards and gets 503 `keel.busy` with `data: { limit }`, running no loader; a stream frees its place when it ends for any reason. A live loader in a non-`node` deployable is E1558 at `createApp`.
- **Production entry.** `start({ topology, deployable, routes, runners, dir })` parses `PORT` (default 8080), `KEEL_ORIGIN`, `KEEL_SECRET` (32+), `KEEL_ALLOW_ORIGINS` (comma-separated http(s) origins; `*` or a path fails) and `KEEL_PEER_<NAME>` per other `node` deployable with `DeployEnv`; a failure prints one `E1560 <KEY> fails DeployEnv (<rule>)` line and exits 1. It serves `createApp` (production, real ctx, `dir` as `assets` and `artifacts`, `std.json` there when present) with `@hono/node-server`, logs to stdout, and on SIGTERM or SIGINT stops listening, awaits `close()` and exits 0.

## Server state

Server state is per request (RFC 0044, k.server Server state): a loader or action names a factory with `stores`; the server runs it once per request in an isolated child scope of the request scope (`openStores`), restores each store from `ctx.storage` `keel.store.<id>` (`snapshot({ meta: true })` JSON, parsed once per stored version) through the deployable's write-through in-process copy (`Served.saved`), all of a factory's keys in one `inOrder` section so a request reads them as of the same saves, and after an action's `ok` saves the changed ones (`saveStores`), or answers 409 `keel.conflict` when another request saved any store this request opened, changed or only read, since it restored it. Once every changed store is stored, each is reported to `observe` on the server ctx as `{ kind: 'save', store, head, from }` (`from`: the head before the save, 0 when none was saved), in save order; a 409, `err` or throw reports none. A `tx` refused as concurrent returns `keel.conflict` with `{ store, transaction, base, head }`, which the action answers 409 like any `err`. `err` or a throw saves nothing and drops the instances, so a re-render reads storage. Factory stores need explicit ids (a default `store.<n>` id throws). `#k-state` snapshots only the request registry (stores created while rendering); module-level stores are process-wide and never written by server code. The caller (RFC 0057): the cookie is `__Host-keel-caller` with `Secure` when the request is https, else `keel-caller`. `createApp({ secure })` decides that; unset, the request URL's scheme does, upgraded (never downgraded) by a first `x-forwarded-proto` value of `https` from a TLS-terminating proxy (RFC 0060). `secure: true` is the production setting: a deployed production start without `secure` writes one W1557 `diag`. Over plain http a sibling host can still plant a validly signed `keel-caller` (see docs/THREAT-MODEL.md); only a value the server signed (`token.mac`, HMAC-SHA-256 under `createApp({ secret })`, at least 32 UTF-8 bytes else E1556 at startup, default 32 random bytes per `createApp` with a W1556 `diag` on a deployed production start; `callerSigner`) counts. A write without one gets a token minted with `ctx.random.id("Caller")`, signed, and set `Path=/; HttpOnly; SameSite=Lax`; a read without one gets `""`; loaders and actions see `caller` as the cookie value's base64url SHA-256 (RFC 0054), never the value, so stored `meta.caller` cannot be replayed as a cookie; apps record it as `tx` meta and undo with `undoWhere`. Snapshots keep at most each store's `logLimit` entries (k.store). Action results, 303/302 redirects, and 403 refusals send `cache-control: no-store`.

## Extension points

`guards`: route `guard` names resolve here, then in the router registry. `inspect.origins`: extra origins the dev inspect endpoint answers. `LogSink`: any `{ format, write(line) }`.
