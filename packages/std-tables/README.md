# @keel/std-tables

**Spec:** std.tables · **Status:** proposed · **verified:** (none)

Data tables whose query lives in the route search: sortable, filterable, searchable and paged, from a store or a loader.

## Contract

- **Public API** (`.`, client-safe):
  - `columns(row, { key, rowHeader?, show, sort?, search?, filter?, compare? })` reads the `s.object` `row` and returns a `Columns` value with one kind per field: `text` (a string, an `s.id`, or a format whose JSON is a string), `number` (`s.int`, `s.number`), `enum`, `boolean`, `value` (anything else, an optional field included). `key` is an unmarked `text` or `number` field (its values become element ids); `rowHeader` (default the first of `show`) is one of `show`; `search` columns are `text`; `filter` columns are `enum` or `boolean`; a `value` column sorts only through `compare`. Anything else throws E2851; the message starts with the code.
  - `tableSearch(columns)` returns the route `search` schema, every key optional: `sort` (an enum of the sort columns), `dir` (`asc`, `desc`), `page` (int, 1 or more), `q` (string, at most 200, with `search` columns) and each filter column under its own name. One schema per `columns` value. It throws E2852 for a filter column named `sort`, `dir`, `page` or `q`, and for a `.pii()` search or filter column, so nothing marked reaches the URL.
  - `tablePage(row)` is the schema `{ rows, total, page, pages }`.
  - `applyQuery(columns, rows, search, { pageSize, locale })` returns a `TablePage`: rows where some search column contains `q` and each filter equals (lower-cased with `locale`); sorted stably by `sort` and `dir` (`text` through `Intl.Collator(locale)`, `number` numerically, `enum` in declaration order, `boolean` false first), ties by key ascending, input order without `sort`; then the page clamped to 1 to `pages`. Pure and deterministic. It throws E2853 for `pageSize` outside 1 to 500, a `locale` that is not a std.i18n `Locale`, and a key repeated or not 1 to 64 of `[A-Za-z0-9_-]`.
  - `TableSearch({ id, label, search, href, delay? })` renders a search `Input` `<id>.input` whose value is `q` and whose label follows `label` (a getter updates it); `delay` ms (default 300, on the router's `ctx.clock`) after the last input it replaces the history entry with `href` of the same search, `q` set to its first 200 characters (absent when empty) and no `page`. The input keeps its text while the route's `q` is the value it last sent (text typed while that search loads, and text past 200 characters, stays and does not filter); any other `q` (a link, back, forward) replaces the text, so a sort or pager link activated while a search loads, minted from the search before it, re-applies the old `q` and replaces the typed text. `search` and `delay` are read where used; `label` is read once, since `Input` takes it as a string.
  - `DataTable({ id, label | labelledBy, columns, search, href, locale, rows + pageSize | page, selected?, onSelect?, text, cells?, header?, actions?, empty?, styles? })` renders a native table of `Part`s with APG Sortable Table semantics. Parts: `<id>.table` (`aria-rowcount` when the page holds fewer rows than `total`), `.head`, `.body`, `.header.<col>` (`aria-sort` on the sorted column only), `.sort.<col>` (a link: same search, this `sort`, `desc` when already `asc` on it, else `asc`, no `page`), `.row.<key>` (`aria-rowindex` in the whole result), `.cell.<key>.<col>`, `.select.<key>`, `.selectAll` (`mixed` when part of the page is selected; toggles the page's keys), `.pager` (`navigation`), `.previous`, `.next`, `.status`. A given `page` has its keys checked as `applyQuery` checks them (E2853). Each part is made inside its container's `children` thunk in document order (the head before the body, the pager's links and `.status` in their places), so a served table resumes in place. When a navigation removes the focused pager link, focus moves to `.status`; on a page the router keeps (a search-only navigation) the table, its `.status` and the focused element are the same nodes. `cells` is required by type for shown columns whose values are not text or numbers; numbers default to `formatNumber(n, locale)`; `locale` is a std.i18n `Locale`. Every visible word comes from `text`. Read once at build: `id`, `columns`, `styles` (collected by the compiler), and whether `selected`, `actions` and `labelledBy` are given, since they fix the table's columns and naming. Read where they are shown, so a change updates the mounted table: `label` or `labelledBy`'s value, `text`, `locale`, `search`, `href`, `rows`, `pageSize`, `page` and `selected`. Slots render with their row or branch: `cells` and `actions` when a row renders, `header` when its column's sort changes, `empty` when the result empties.
  - Types `Columns`, `ColumnSpec`, `ColumnKind`, `Field`, `TableQuery`, `TablePage`, `TableText`, `TableStyles`, `DataTableProps`.
- **Dependencies:** `@keel/ui` (`Link`, `@keel/ui/aria` `Part`), `@keel/runtime-dom` (`For`, `If`), `@keel/reactive`, `@keel/router` (`Href`; `findRouter` from its internal entry), `@keel/schema`, `@keel/ctx`, `@keel/std-i18n`.
- **Rungs:** conformance (examples and properties, seed 1337); properties that `columns` over generated row schemas throws E2851 exactly for a wrong entry and otherwise derives one kind per field, that `applyQuery` over rows and searches generated from the schemas is deterministic, counts the filtered rows, pages them without loss in order, and clamps the page, and that `tableSearch` refuses every marked search or filter column.

## Extension points

None. The rules are thrown at the call, so the package registers no check rule.

## Unsafe

count: 1
- `unsafe/asQuerySchema.ts`: the search schema built column by column is typed as the query its columns describe.
