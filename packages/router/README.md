# @keel/router

**Spec:** k.router · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `navigate(href: Href, opts?: { replace? }) -> Promise<void>`: navigates the router whose `App` encloses the caller, else the only one mounted (a callback's case), push or `replace`; with none or several mounted it does nothing. `manifest(routes)`: each entry is a page (`path`, `component`, optional `title(props)` whose `props.data` is typed as its loader's `output` value; k.head), a layout (`component`, no `path`) or an API route (`api: true`, `path`, a loader or actions, no `component`/`errorElement`/`title`/`layout`; k.api) -> `{ routes, href(id, params?, search?) -> Href, actions({ [id]: { POST?, PUT?, PATCH?, DELETE? } }) }` (id, params, search typed from the manifest; `routes.actions` is a statement after the manifest that attaches each path route's actions once, so an action may `return ok(routes.href(...))`) · `loader({ output, params?, search? }, fn)` · `action({ input, output, params? }, fn)` -> `ApiAction` (an API route's: `fn` returns `ok(value)` of `output`'s type and gets `bearer`) · `action({ input, params? }, fn)` -> `Action` (a page's: `ok(href)` or `ok(null)`, no `output`) (`fn` gets `params`/`search` as `Infer` of the declared schemas and the absolute `url`; a `loader` or `action` `output` holding `s.secret` throws E1113) · `guard({ redirect }, fn)` -> `Guard` (fits pages, layouts and API routes) · `guard({}, fn)` -> `ApiGuard` (fits API routes only), held by reference in `guard` · `createRouter(manifest, { ctx, history, caller?, mode? }) -> { navigate(href, { replace? }), route, App, dispose }`; `route.get()` is `{ id, params, search, pending }`; `mode` is `mount`'s, `'dev'` or `'production'` (the default; any other value reads as `production`): outside `dev` every `keel.unexpected` the default alert, a route's `errorElement` or a `Form`'s `error` gets is `{ code: 'keel.unexpected', message: 'unexpected', data: {} }`, as the server renders it, while ctx observers and `mount`'s `onError` get the full error · `Form({ method, action: Href, form?, error? })` (`method` is `'POST'` when `action` is a `MountHref`) · `identityMount(path) -> { path, href(subpath?, search?) -> MountHref }` (k.mount: what a project's `identity.ts` default-exports; `href` is `path`, the subpath, then the `search` map's keys sorted, keys and values `encodeURIComponent`-encoded; a subpath that is not `''` or `/`-led segments of `[A-Za-z0-9._~-]`, or has a `.` or `..` segment, throws E1582) · `routesArtifact(manifest)` · `browserHistory()`. Types in `src/index.ts` (`Guard`, `ApiGuard`, ...). Server internals (`compileRoutes`, `compileTable`, `matchUrl`, `needsBare`, `parseSearch`, `runGuard`, `fieldsError`, `formHandle`, `publicError(error, mode)` the one rule for what a `keel.unexpected` shows outside `dev`, used by the router and the server; types `Level`, `Located`, `Match`, `Segment`, `Table`) are in `@keel/router/internal`, not public API, with `findRouter()` (the `RouterCore` rendering the calling component, else the only mounted one, else `null`: its `ctx`, `navigate(href, { replace? })`, `accepts` (`null` when no route of its table matches the action), `submit`; for kernel and stdlib components) and `createRouterWith(manifest, opts, state?)`: `createRouter` plus `opts.leave(url, replace)`, the document navigation (default `location.assign`, or `location.replace` with `replace`; the harness records it), and a `ServerState` (`@keel/store/internal`) that runs loaders and actions naming `stores`, each loader run and each submit one `state.request()` (an action's `ok` saves, a conflict is its `err`, `err` or a throw saves nothing, the request ends before revalidating or navigating); `renderRoute` uses it. `createRouter` passes no `state`, so a loader or action naming `stores` is `keel.unexpected` (k.server Server state). **`@keel/router/match`** (public and versioned): `matchHref(routes, href) -> { id, params, search } | null` matches an href as a navigation does (static beats `:param`, params decoded by schema, failing search keys dropped; `null` when no page matches, an API route's path included, or params fail); `routes.href(id, params, search)` is its inverse. It never seals the manifest. guards get `{ url, caller, user, bearer }` and loaders and actions `user` and `bearer` (`createRouter(..., { caller? })`, default `""`; `user` is k.user's, `""` in the client router; `bearer` is the request's `Authorization: Bearer` token as a `Secret` on an API route, `undefined` elsewhere and in the client router); navigations report `nav`, loader and action `err` report `error` to ctx observers.
- **Invariants:** the committed page renders as one row keyed by its path when it rendered without an error (else by its view): a navigation that changes only the search or hash, and whose guards and loaders all succeed (every one re-runs), keeps the page, its nodes and focus (a focused element the new data removed hands focus to the element with its id, else, when no widget took it, the page's first `role="status"` region, else `main`); another path, a loader `err` or a page showing its `errorElement` renders anew; revalidation keeps the page. `props.search` and `props.data` are getters whose bindings update in place (a top-level read is its value at build); `params` is a plain value. `title` is written at each commit. The last navigation started wins: a superseded one runs to completion and its result is dropped. A route Boundary that caught a throw is reset by the kept page's next navigation. Each `manifest` validates only its own entries (throws `code` E1502-E1507, E1510 for an entry that is no page, layout or API route, E1510 for an entry whose `api` is other than `true`, E1508 for a guard without `redirect` on a page or layout; E1510 for an API route with neither loader nor action and E1508 for a guard `redirect` naming an API route on the first read of the table: `href`, matching, `createRouter`, `createApp`; E1505: `actions` in an entry; E1507: a loader schema that is not the route's own value); `routes.actions` throws E1505 (unknown or layout id, non-verb key, second attach) E1507 (an action `params` that is not the route's own) or E1512 (an action without `output` on an API route, or with one on a page) before attaching anything and owns its table; manifests never interact. `routes.href` takes page ids only (an API id fails to compile and throws E1501) and resolves only in its own manifest; the client router matches no API route, so a link to one is a document request; a link click, `navigate` or `ok(href)` to any path its table has no page for (an API route, the identity mount, another deployable's page) is a document navigation (`leave`), while an initial load or a history pop of one renders the 404; `routesArtifact` marks API routes `api: true`; a router and its redirects use only their own manifest. A `Form`'s `action` is an `Href`, rendered as given: inside a router whose table matches it, the router submits to that route's action (E1505 when that route lacks the method); otherwise (no router, or no route matches) the browser posts it: on `submit` the `form` handle validates (an error prevents the submit), a chosen file throws E1583 and sends nothing, else `pending()` is `true` until a back-forward cache `pageshow`. `href` is deterministic, omits absent optionals, sorts search keys, throws for unknown ids. Static beats `:param`; trailing slash is canonicalized. Bad params: `keel.notFound` in the nearest `errorElement`, inside its layouts only if none has a loader or guard; no guard or loader runs. Guards outermost first; `keel.denied` redirects with `?next=`. Loaders start together after guards; the previous page stays until they settle; an `err` renders the nearest `errorElement` under its layouts. `ok(null)` reruns each chain loader once, no re-render; `ok(href)` pushes. After `navigate` to another route: focus the page's first `h1`, else `main` (`tabindex="-1"`); within one route focus stays (on the element with the same id when the page is rebuilt); then scroll to the hash target, else to the top unless only the search changed (a search-only push or replace keeps scroll); pop restores the arriving history entry's saved scroll (router-minted entry keys; `RouterHistory.push/replace(url, key)`, `onPop(fn(url, key?))`).
- **Dependencies:** `@keel/schema`, `@keel/reactive`, `@keel/runtime-dom` (`boundary`, `cond`), `@keel/ctx` (types), `@keel/store` (the `ServerState` type).
- **Rungs:** conformance; properties (seed 1337): href/match round-trip over generated manifests, static beats param, trailing slash.

## Extension points

`FormHandle` (`{ [formHandle]: FormSeam }`, `formHandle` from `@keel/router/internal`; seam `setPending`, `validate`, `onResult`): `<Form form>` calls `validate()` (an `err` stops the submit), `setPending(true)`, runs the action from FormData, `setPending(false)`, then `onResult(result)`. `Form` finds its router through the owner scope chain (the `App` scope); outside a router, or when no route of its table matches `action`, it is a native form whose validation runs through the runtime's delegated `on`, so a submit queued before resume is validated at its replay. It renders through the runtime's `element`, so at resume the served form, its hidden `_method` input and its children are claimed in place. `children` is a thunk (`() => Node | readonly Node[] | string`), so the content is made inside the form; JSX children compile to one. Implemented by `@keel/forms`. `RouterHistory`: any `{ push, replace, current, onPop }`.
