# @keel/router

**Spec:** k.router, k.contract, k.routes · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `navigate(href: Href, opts?: { replace? }) -> Promise<void>`: navigates the router whose `App` encloses the caller, else the only one mounted (a callback's case), push or `replace`; with none or several mounted it does nothing. `contract(id, entries)` (from `@keel/router/contract` only, which imports `@keel/schema` alone; k.contract): entries keyed by route id, each a page `{ path, params?, search? }`, a layout `{ layout: true }` or an API entry `{ method, path, output, params?, query?, body?, errors?, timeout?, events? }` -> frozen `{ kind: 'keel.contract', module, entries, href(id, params?, search?) -> Href }` (`href` takes page ids only, typed from the entry); it throws E1510, E1513 (an API name), E1503, E1504, E1653, E1113, E1502 and E1509 · `manifest(contract, binding)`: every entry bound and nothing else, a page `{ component, loader?, guard?, layout?, errorElement?, title?, POST?, PUT?, PATCH?, DELETE? }`, a layout `{ component, loader?, guard?, layout?, errorElement? }`, an API GET `{ loader, guard? }`, an API write `{ action, guard? }` (`title(props)` gets `props.data` typed as its loader's `output` value; k.head; `layout` a layout id of the contract, exact, or an id `<module>.<name>` of another module's contract, resolved by `routeTable`) -> frozen `{ kind: 'keel.routeTable', contract, contracts: [contract] }`; the binding type is keyed by id, so each fault fails at its key or member (k.routes Where rules fire) · `routeTable(...tables)` -> frozen `{ kind: 'keel.routeTable', contracts }`, the union (nested tables flatten; E1502 one module twice or a path pattern two modules share, E1509, E1506 a `layout` naming no layout entry of the union or a cycle across modules; a manifest whose chain names another module's layout throws E1506 when served alone) · `loader(contract, id, { stores? }, fn)` on an API GET (`fn` answers the entry's `output`; an async generator, live, on an `events: true` entry only) · `loader(contract, id, { output, stores? }, fn)` on a page or layout (an `output` holding `s.secret` throws E1113) · `action(contract, id, { stores? }, fn)` -> `ApiAction` on an API write (`fn` gets the decoded `body` and `bearer`, answers `output`) · `action(contract, id, { input, stores? }, fn)` -> `Action` on a page (`ok(href)` or `ok(null)`) (`fn` is typed from the entry and never annotated); a loader's `run(args, ctx)` and an action's `run(input, args, ctx)` call `fn` directly (`args.url` a string), and an absent `args.stores` is what the declared factory returns for `ctx` in a scope of its own, released after `fn`, `undefined` without one; `run` saves nothing · `guard({ redirect }, fn)` -> `Guard` (fits pages, layouts and API routes) · `guard({}, fn)` -> `ApiGuard` (fits API routes only), held by reference in `guard` · `createRouter(routes, { ctx, history, caller?, mode?, mount? }) -> { navigate(href, { replace? }), route, App, dispose }`; `route.get()` is `{ id, params, search, pending }`; `mode` is `mount`'s, `'dev'` or `'production'` (the default; any other value reads as `production`): outside `dev` every `keel.unexpected` the default alert, a route's `errorElement` or a `Form`'s `error` gets is `{ code: 'keel.unexpected', message: 'unexpected', data: {} }`, as the server renders it, while ctx observers and `mount`'s `onError` get the full error; `opts.mount` is the identity mount's `path` (a project with `identity.ts` starts its router with it): no page matches at or under it, so a link, `navigate` or `ok(href)` there is a document navigation even where a `:param` route would fit, and another router in the process is unaffected · `Form({ method, action: Href, form?, error? })` (`method` is `'POST'` when `action` is a `MountHref`) · `identityMount(path, { links }?) -> { path, links, href(subpath?, search?) -> MountHref }` (k.mount: what a project's `identity.ts` default-exports; a `path` that is not lowercase `/` segments throws E1580; `href` is `path`, the subpath, then the `search` map's keys sorted, keys and values `encodeURIComponent`-encoded; a subpath that is not `''` or `/`-led segments of `[A-Za-z0-9._~-]`, or has a `.` or `..` segment, throws E1582) · `routesArtifact(routes)` (an API entry has `api: true`, its `method`, its `query` as `search`; `actions` a page's bound verbs or an API write's method) · `browserHistory()`. Types in `src/index.ts` (`Guard`, `ApiGuard`, ...). Kernel internals (`bindingsOf(routes)`, each id to `{ contract, entry, binding }`; `compileRoutes(routes)`, the compiled table `{ bindings, table, located }`; `entryAt(located, route, method)` and `allowAt(located, route)`, the entry answering a method at a path pattern and the pattern's `allow`; `encodeHref`; `matchUrl`, `needsBare`, `parseSearch`, `runGuard`, `fieldsError`, `formHandle`, `publicError(error, mode)` the one rule for what a `keel.unexpected` shows outside `dev`, used by the router and the server; types `Level`, `Located`, `Match`, `Segment`, `Table`) are in `@keel/router/internal`, not public API, with `findRouter()` (the `RouterCore` rendering the calling component, else the only mounted one, else `null`: its `ctx`, `navigate(href, { replace? })`, `accepts` (`null` when no route of its table matches the action), `submit`; for kernel and stdlib components) and `createRouterWith(routes, opts, state?)`: `createRouter` plus `opts.leave(url, replace)`, the document navigation (default `location.assign`, or `location.replace` with `replace`; the harness records it), `opts.onError(error)`, given a render throw no `errorElement` caught before the root alert shows it (the harness raises it), and a `ServerState` (`@keel/store/internal`) that runs loaders and actions naming `stores`, each loader run and each submit one `state.request()` (an action's `ok` saves, a conflict is its `err`, `err` or a throw saves nothing, the request ends before revalidating or navigating); `renderRoute` uses it. `createRouter` passes no `state`, so a loader or action naming `stores` is `keel.unexpected` (k.server Server state). **`@keel/router/match`** (public and versioned): `matchHref(routes, href) -> { id, params, search } | null` matches an href as a navigation does (static beats `:param`, params decoded by schema, failing search keys dropped; `null` when no page matches, an API route's path included, or params fail); a contract's `href(id, params, search)` is its inverse. Guards get `{ url, caller, user, bearer }` and loaders and actions `user` and `bearer` (`createRouter(..., { caller? })`, default `""`; `user` is k.user's, `""` in the client router; `bearer` is the request's `Authorization: Bearer` token as a `Secret` on an API route, `undefined` elsewhere and in the client router); navigations report `nav`, loader and action `err` report `error` to ctx observers.
- **Invariants:** the committed page renders as one row keyed by its path when it rendered without an error (else by its view): a navigation that changes only the search or hash, and whose guards and loaders all succeed (every one re-runs), keeps the page, its nodes and focus (a focused element the new data removed hands focus to the element with its id, else, when no widget took it, the page's first `role="status"` region, else `main`); another path, a loader `err` or a page showing its `errorElement` renders anew; revalidation keeps the page. `props.search` and `props.data` are getters whose bindings update in place (a top-level read is its value at build); `params` is a plain value. `title` is written at each commit. The last navigation started wins: a superseded one runs to completion and its result is dropped. A route Boundary that caught a throw is reset by the kept page's next navigation. `manifest` throws E1515 (an unbound entry, a key the contract lacks, a binding entry without its `component`, `loader` or `action`, a handler declared for another id or contract, a plain loader on an `events: true` entry or a live one elsewhere), E1510 (a member the entry's kind refuses), E1508 (a page or layout guard without `redirect`, a redirect to an API entry) and E1506 (an id of its own contract that is no layout, an id not of the form `<module>.<name>`, a cycle within it). A path pattern holds one page or one contract's API entries at distinct methods; HEAD is answered by the GET entry, and `allowAt` lists GET, HEAD, POST, PUT, PATCH, DELETE as present. A contract's `href` takes page ids only (an API or layout id fails to compile and throws E1501); the client router matches no API entry, so a link to one is a document request; a link click, `navigate` or `ok(href)` to any path its table has no page for (an API entry, the identity mount, another deployable's page) is a document navigation (`leave`), while an initial load or a history pop of one renders the 404; a path holding a `\` matches no page; a guard's `redirect` names a page of its table. A `Form`'s `action` is an `Href`, rendered as given: inside a router whose table matches it, the router submits to that route's action (E1505 when that route lacks the method); otherwise (no router, or no route matches) the browser posts it: on `submit` the `form` handle validates (an error prevents the submit), a chosen file throws E1583 and sends nothing, else `pending()` is `true` until a back-forward cache `pageshow`. `href` is deterministic, omits absent optionals, sorts search keys, throws for unknown ids. Static beats `:param`; trailing slash is canonicalized. Bad params: `keel.notFound` in the nearest `errorElement`, inside its layouts only if none has a loader or guard; no guard or loader runs. Guards outermost first; `keel.denied` redirects with `?next=`. Loaders start together after guards; the previous page stays until they settle; an `err` renders the nearest `errorElement` under its layouts. `ok(null)` reruns each chain loader once, no re-render; `ok(href)` pushes. After `navigate` to another route: focus the page's first `h1`, else `main` (`tabindex="-1"`); within one route focus stays (on the element with the same id when the page is rebuilt); then scroll to the hash target, else to the top unless only the search changed (a search-only push or replace keeps scroll); pop restores the arriving history entry's saved scroll (router-minted entry keys; `RouterHistory.push/replace(url, key)`, `onPop(fn(url, key?))`). In a shell (k.return) the browser's part of a navigation to the identity mount is Keel's: `@keel/router/internal`'s `mountRequests(ctx, { id, open, close?, origin? })`, which a shell package calls before the router starts, makes each `Link` click, `navigate`, `ok(href)` and `Form` post to a path under an `identityMount` a mount request through `ctx.net` (a GET, or a POST of the urlencoded named controls and submitter; `x-keel: 1`, `accept: application/json`, `redirect: 'manual'`). Only the answer's status and `location` are read: a page of the table is a client-side navigation; a path under the mount the next GET, five redirects in a row at most, own-scheme ones included; an `http:` or `https:` URL elsewhere, or a path of `KEEL_ORIGIN` that is neither, opens through `open` (the external browser), and any other scheme opens nothing; a location on the shell's own scheme is read as a return link that takes no opening and continues the chain; a location whose path begins `//` or `/\` once dot segments are removed (`/.//evil.example/x`) is ignored: nothing opens or navigates and the page stays; a GET answered without a redirect opens its own URL; each time `open` is called for a chain the page started (a `Link` click, `navigate`, `ok(href)`, a `Form`, and the redirects after it) an opening is recorded first, unless the ctx is link-started or the launch holds it, and for a chain a return link started none is, `{"deadline":n}` in `ctx.storage` `keel.return` with `n` `ctx.clock.now() + 600000`, replacing any other; when that write fails the browser still opens and an older pending opening stays pending until its own deadline; a POST answered without one, and a request that fails, leave the page, and a `Form`'s `pending()` is true until its chain ends. It returns `{ link, launch, fired }`. `link(url)` is the intake of return links `<id>:/<path>?<search>` (k.links; scheme compared without case; any other URL, and a path that begins `//` or `/\` once dot segments are removed, is ignored and takes nothing), sorted by path: a page of the table is a client-side navigation at any time; a mount `path` plus one of its `links`, exactly, is a mount request GET at any time; any other path under the mount first takes the pending opening in one `commit`, then calls `close` (the external browser's, when given) and is a mount request GET, and is ignored, with no request, when none is pending, its deadline is reached, the stored value is of another shape, another link took it first, or storage fails; anything else is ignored. None but the third kind takes the opening. A link taken any of these ways makes the ctx link-started until a person's act: meanwhile no mount request records an opening, whoever starts it. `launch(links)` is the shell's launch report (k.links Launch), once per ctx, a later one ignored: until it, an opening made with no act since the ctx started is held (the browser opens, nothing is stored); a report of `[]` records the held opening with its deadline 600000 ms after it opened, unless a later opening was recorded or failed to store; `null` (a failed read) or links drop it and make the ctx link-started until a person's act, whether or not a link is taken, so a mount request in flight records no opening; then the links are delivered in order. A person's act (k.opening Link-started) is a trusted `pointerdown`, `pointerup`, `mousedown`, `touchend` or `keydown` other than Escape, heard by listeners `mountRequests` attaches once per ctx on the window in the capture phase; `click()`, `requestSubmit()` and events the page's code dispatches are none, and with no window there is none. The act and link-started state is held per ctx in memory only, never stored, and read as the browser opens, not when the chain starts. `fired(event)` is how the test harness's `fire` marks one (`click`, `submit`, a `keydown` other than Escape). `identityMount` records each `path` and each declared link it is given, which is how a shell knows the mount; `links` entries are subpaths of `href`'s form, none `''`, none repeated, else it throws E1584.
- **Stubs (k.boundary):** `serverOnly(file, name)` (`@keel/router/internal`) is the function a browser build puts in place of each export of a server-only file: calling it throws an Error with code E1008 `<name> of <file> runs only on the server`. `manifest` accepts a stub wherever a loader, action or guard goes and skips the checks that read it (the declared id, E1508 `redirect`), which ran when the build evaluated `routes.ts` in Node; running a stubbed member is the stub's E1008.
- **Dependencies:** `@keel/schema`, `@keel/reactive`, `@keel/runtime-dom` (`boundary`, `cond`), `@keel/ctx` (types), `@keel/store` (the `ServerState` type).
- **Rungs:** conformance; properties (seed 1337): href/match round-trip over generated contracts, static beats param, trailing slash.

## Extension points

`FormHandle` (`{ [formHandle]: FormSeam }`, `formHandle` from `@keel/router/internal`; seam `setPending`, `validate`, `onResult`, `restore`): `<Form form>` calls `validate()` (an `err` stops the submit), `setPending(true)`, runs the action from FormData, `setPending(false)`, then `onResult(result)`. Rendered for the post it sent that the server answered `keel.fields` (the 422 re-render, and its resume, through `servedForm` from `@keel/runtime-dom/internal`), it calls `restore(values, errors)` before its children render, so the controls bind to the submitted values and errors. `Form` finds its router through the owner scope chain (the `App` scope); outside a router, or when no route of its table matches `action`, it is a native form whose validation runs through the runtime's delegated `on`, so a submit queued before resume is validated at its replay. It renders through the runtime's `element`, so at resume the served form, its hidden `_method` input and its children are claimed in place. `children` is a thunk (`() => Node | readonly Node[] | string`), so the content is made inside the form; JSX children compile to one. Implemented by `@keel/forms`. `RouterHistory`: any `{ push, replace, current, onPop }`.
