# @keel/check

**Spec:** k.check (+ k.module checks, k.compat) · **Status:** proposed · **verified:** (none)

## Contract

- **Public API:** `check(files, opts?)` -> `{ diagnostics, summary }` over `{ path, source }[]`; `opts`: `root` (module resolution, default cwd), `budgets` (E1755), `artifacts` (`hashes` for E1005), `types: false`, `base` (the parsed `surface.json` of the deployed code, for E1562). `format(diags, { mode, limit, quiet, code, ms })` (`compact` default, `json` NDJSON + summary, `pretty`). `defineRule(def)`, `rules()`, `reportedCodes()` (every code `check()` can report: pipeline plus registry; rfc:0065), `explain(code)`. Types for each (`Diagnostic`, `Summary`, `RuleDef`, ...). RFC 0070: `RuleInput.project` is the code files of the file's project plus its `topology.ts`, one shared array.
- **Invariants:** diagnostics are `{ kind: 'diag', code, path, line, col, message, see?, fix? }` (that key order), deduped, sorted by path, line, col; one-line messages under 90 chars; `fix` is a git-applicable unified diff. Compiler diagnostics pass through unchanged. TS errors encoding a Keel rule map to it (E1802, E1501, E1003, E1001), others are E1751 `TS<code> ...`; JSX types come from `@keel/runtime-dom/jsx-runtime`. A throwing rule is E1756; the rest still run. Static only: app code is never evaluated (rendered a11y is `keel test`, rfc:0023). Compact: grouped by code, 5 per code (or `limit`) then `... +N more`, long fixes become a pointer, trailer `ok|fail N errors, M warnings` plus an indented counts line; no ANSI, no timestamps; deterministic. `explain` <= 120 tokens per kernel code.
- **Module pass (k.module, E1151-E1157):** a project pass over every parsed code file. Manifests are `modules/<id>/module.ts` (key and id prefix: the folder id) and stdlib `node_modules/@keel/std-x/module.ts` (key: the package name, imported as `@keel/std-x/<File>`), read statically (literal `module({...})` objects and string arrays only; anything else makes the module opaque and unenforced). Each non-test file belongs to the module with the longest folder prefix; files outside every module are not checked. Cross-module imports are relative paths naming the exporting file (export name = file stem). E1151 non-public import (at the import) · E1152 import, `href()` or `service({ module })` into a module not in `deps` (at the import, call or `module` literal; fix: add the dep to the manifest) · E1153 one per deps cycle, at the smallest id's manifest, message lists the cycle · E1154 `public.exports` naming no file stem / `public.routes` naming no declared route (at the manifest; fix: remove the entry) · E1155 `manifest({...})` route keys, `store(..., { id })`, `transaction(store, 'name', ...)`, `s.error('code', ...)` not prefixed `<id>.` (callees count only when imported from `@keel/router`/`@keel/store`/`@keel/schema`) · E1156 `ctx.<cap>` or `const { cap } = ctx` with `cap` not in `capabilities`, or an `observe` import from `@keel/ctx` (any alias; or `<namespace>.observe`) without `observe` there (rfc:0071), once per file and capability (fix: add it) · E1157 `href()`, or a `service({ module })` endpoint whose literal `path` matches a route of that module (`:param` segments match any), to a route of another module not in its `public.routes`; the endpoints are the `endpoints({...})` literal its `schema` resolves to through consts and relative imports. A route's owner is the module declaring it, else the module whose id is its first segment. Fixes are diffs of the manifest.
- **Compat pass (k.compat, E1561-E1562):** reads each intact, fresh `.keel/surface.json` among the files (`keel build` writes it; its `sources` hashes must match the project's files, else E1005 `does not match its sources`). `accepts(A, B)` is decided on the JSON Schema of each node: `{}` accepts any; a union `B` when each member is accepted, a union `A` when one member accepts; literals and enums value by value; number and string bounds inside; integer only by integer; arrays, records item by item; objects by required fields, field by field, and a closed `A` only a closed `B` with no other field; anything it cannot read only when equal. E1561 per `service({ module })` endpoint: no route of the module at its method and path, or the route's `params`/`search`/`input` refusing its `params`/`query`/`body` (an absent one sends `{}` closed), or its `output` refusing the route's answer (GET: `{ id, results }`; actions: `ok` of `Href | null`), or an `errors` schema refusing an error answer (`{ ok: false, error: { code, message, data } }`); at the endpoint key, naming the first refused field and the producer's schema; no fix. E1562 with `base`: each base endpoint whose caller and module share no deployable of the project's topology, against the current route (request as E1561, then the base `output` against the current answer; a missing route is reported at `.keel/surface.json`); at the route's schema field (read statically through `routes.actions`, `manifest`, `action`/`loader` options, `s.object` fields, consts and relative imports), with a fix appending `.optional()` when making the one missing required field optional clears it.
- **Dependencies:** `@keel/compiler`, `@keel/ctx`, `@keel/schema`, `@keel/reactive`, `@keel/store`, `@keel/runtime-dom`, `@keel/ui`, `oxc-parser`, `typescript`, `happy-dom`.
- **Rungs:** conformance; properties (seed 1337) for format and diff round-trip; token budget on 10 injected errors.

## Extension points

**Rule registry.** `defineRule({ code, message, explain, see?, check, fix? })`: `check({ file, ast, artifacts })` returns findings `{ path, line, col, data? }`; `fix(finding, { file, ast })` returns `{ start, end, text }` edits or `null`, rendered as a unified diff. `message` may be a function of the finding. Stdlib codes are E2xxx/W2xxx; another code or a duplicate throws `E1753 ...`. Rules are pure; the registry is process-wide.
