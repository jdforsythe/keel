# @keel/check

**Spec:** k.check (+ k.module checks, k.compat) · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `check(files, opts?)` -> `{ diagnostics, summary }` over `{ path, source }[]`; `opts`: `root` (module resolution, default cwd), `budgets` (E1755), `artifacts` (`hashes` for E1005), `types: false`, `base` (the parsed `surface.json` of the deployed code, for E1562). `format(diags, { mode, limit, quiet, code, ms })` (`compact` default, `json` NDJSON + summary, `pretty`). `defineRule(def)`, `rules()`, `reportedCodes()` (every code `check()` can report: pipeline plus registry; rfc:0065), `explain(code)`. Types for each (`Diagnostic`, `Summary`, `RuleDef`, ...). RFC 0070: `RuleInput.project` is the code files of the file's project plus its `topology.ts`, one shared array.
- **Invariants:** diagnostics are `{ kind: 'diag', code, path, line, col, message, see?, fix? }` (that key order), deduped, sorted by path, line, col; one-line messages under 90 chars; `fix` is a git-applicable unified diff. Compiler diagnostics pass through unchanged. TS errors encoding a Keel rule map to it (E1802, E1501, E1003, E1001; at the key or `api: true` of a `manifest({...})` entry, read from the entry literal: E1510 for an entry with neither `component` nor `api: true` or an API route without `path`, and for an API route with `component`, `errorElement`, `title` or `layout` with a fix removing them, E1508 for a guard without `redirect` on a page or layout), others are E1751 `TS<code> ...`; JSX types come from `@keel/runtime-dom/jsx-runtime`. A throwing rule is E1756; the rest still run. Static only: app code is never evaluated (rendered a11y is `keel test`, rfc:0023). Compact: grouped by code, 5 per code (or `limit`) then `... +N more`, long fixes become a pointer, trailer `ok|fail N errors, M warnings` plus an indented counts line; no ANSI, no timestamps; deterministic. `explain` <= 120 tokens per kernel code.
- **Compliance rules:** E1105 (`reveal` outside `*.server.ts`, tests included) and E1111 (a `.pii()` node in a `manifest` entry's `params` or `search`, through consts, imports, re-exports, namespace members, spreads and schema arguments; a table, entry or schema it cannot read is reported too; a schema returned by `tableSearch` from `@keel/std-tables` (an audited export that refuses a marked column when called), as a package's route table, is the package's) and E1112 (in app code, a value `reveal` returns given to `tx` or `store` from `@keel/store`, `set` or `commit` on a `storage`, a `console` method or an `Error` global, followed through same-file locals (each value given, destructuring included), members, spreads, literals, templates, operators other than comparisons and tests, `?:`, `await`, `String()`, `JSON.stringify()` and methods called on it; any other call, a parameter and an import end it; one finding per sink call, at the argument; no fix), k.privacy; E1570 (an absolute or protocol-relative URL in `src`, `poster`, `data`, `srcset`, `action`, `formaction`: a literal, a const, a template or `+` head, `new URL`'s base) and E1571 (one given to `ctx.net.fetch`, also through a `ctx` alias or `{ net }`, or `service({ base })` outside `*.server.ts`) and E1576 (a `@keel/*` specifier with an `internal` path segment in an import, type-only included, a re-export, or a literal `import()` or `require()`, in any code file outside the project root's `packages/`, `node_modules/` and `.keel/`, tests and `unsafe/` included; also any `#` specifier, which no `package.json` the checker reads can resolve; a template literal with no substitutions counts as a literal; computed specifiers are not followed), k.security; E1804 (contrast against the element's `bg`, else its nearest JSX ancestor's; large at 24px, or 18.66px at weight 700) and E1820 (reversed `direction` over two or more focusable base elements; fix: plain direction, children reversed), k.a11y; E1822 (`@keel/ui/aria`, or a path into its `aria` source, named in an import, a re-export, or a literal or substitution-free template `import()`/`require()` by a code file outside the project root's `packages/`, `node_modules/` and `.keel/`, tests included; a file under `unsafe/` may import it but not re-export it; a package `imports` alias is E1576 instead; no fix); E1823 (a `styles` value, part or spread that is not an object literal, from the compiler; no fix), k.aria.
- **Module pass (k.module, E1151-E1157):** a project pass over every parsed code file. Manifests are `modules/<id>/module.ts` (key and id prefix: the folder id) and stdlib `node_modules/@keel/std-x/module.ts` (key: the package name, imported as `@keel/std-x/<File>`), read statically (literal `module({...})` objects and string arrays only; anything else makes the module opaque and unenforced). Each non-test file belongs to the module with the longest folder prefix; files outside every module are not checked. Cross-module imports are relative paths naming the exporting file (export name = file stem). E1151 non-public import (at the import) · E1152 import, `href()` or `service({ module })` into a module not in `deps` (at the import, call or `module` literal; fix: add the dep to the manifest) · E1153 one per deps cycle, at the smallest id's manifest, message lists the cycle · E1154 `public.exports` naming no file stem / `public.routes` naming no declared route (at the manifest; fix: remove the entry) · E1155 `manifest({...})` route keys, `store(..., { id })`, `transaction(store, 'name', ...)`, `s.error('code', ...)` not prefixed `<id>.` (callees count only when imported from `@keel/router`/`@keel/store`/`@keel/schema`) · E1156 `ctx.<cap>` or `const { cap } = ctx` with `cap` not in `capabilities`, or an `observe` import from `@keel/ctx` (any alias; or `<namespace>.observe`) without `observe` there (rfc:0071), once per file and capability (fix: add it) · E1157 `href()`, or a `service({ module })` endpoint whose literal `path` matches a route of that module (`:param` segments match any), to a route of another module not in its `public.routes`; the endpoints are the `endpoints({...})` literal its `schema` resolves to through consts and relative imports. A route's owner is the module declaring it, else the module whose id is its first segment. Fixes are diffs of the manifest.
- **Compat pass (k.compat, E1561-E1563, W1564, E1567):** reads each intact, fresh `.keel/surface.json` among the files (`keel build` writes it; its `sources` hashes must match the project's files, else E1005 `does not match its sources`). `accepts(A, B)` is decided on the JSON Schema of each node: `{}` accepts any; a union `B` when each member is accepted, a union `A` when one member accepts; literals and enums value by value; number and string bounds inside; integer only by integer; arrays, records item by item; objects by required fields, field by field (a field an open `B` lacks only when `A`'s field accepts any value), and a closed `A` only a closed `B` with no other field; anything it cannot read only when equal. E1561 per `service({ module })` endpoint: no route of the module at its method and path (GET: a route with a loader), or the route's `params`/`search`/`input` refusing its `params`/`query`/`body` (an absent one sends `{}` closed), or its `output` refusing the route's answer (GET: the loader's `output`; actions: `Href | null`), or an `errors` schema refusing the error answer (a KeelError `{ code, message, data }`); at the endpoint key, naming the first refused field and the producer's schema; no fix. E1562 with `base`: each base endpoint whose caller and module share no deployable of the project's topology (an unreadable `topology.ts`: none share one), against the current route (request as E1561, then the base `output` against the current answer; a missing route is reported at `.keel/surface.json`); at the route's schema field (read statically through `routes.actions`, `manifest`, `action`/`loader` options, `s.object` fields, consts and relative imports), with a fix appending `.optional()` when making the one missing required field optional clears it. With `--base`, for each store in both surfaces (`stores`: id, state and payload schemas): E1563 when the current state schema refuses the base one, at the refused field of the `store(schema, initial, { id })` source, with the same fix; W1564 per base transaction gone or whose payload now refuses the base one, no fix. E1572 (a `storage` or `shells` package missing from `package.json` `dependencies`; fix adds it at the spec of the first `@keel/` dependency) and E1573 (`shells` off a `client` deployable, or an id that is not reverse-DNS) at the deployable in `topology.ts`. E1567 (rule): a `service({ base, schema })` in app code, `base` not an http(s) URL literal, with an endpoint a route of an app module serves (literal path, and the method in `routes.actions` unless GET or HEAD), at `base`, naming the module; no fix.
- **API pass (k.api, E1511):** per project with a topology, each literal `api: true` route (`routeLiterals`, ids by module from their first segment) in a module a `client` or `static` deployable serves, at the module id in that project's `topology.ts` (line 1 when the topology comes from `opts`); no fix. `routes.json` must also match each entry's `api` literal (E1005).
- **Host pass (k.hosting, E1566):** per project with a topology, each bad `host` (`hostProblems` from `@keel/compiler/hosting`), at the first `host` after the deployable's name in that project's `topology.ts`; no fix. `keel explain` has rows for E1565, E1566 and W1567.
- **Dependencies:** `@keel/compiler`, `@keel/ctx`, `@keel/schema`, `@keel/reactive`, `@keel/store`, `@keel/runtime-dom`, `@keel/ui`, `oxc-parser`, `typescript`, `happy-dom`.
- **Rungs:** conformance; properties (seed 1337) for format and diff round-trip; token budget on 10 injected errors.

## Extension points

**Rule registry.** `defineRule({ code, message, explain, see?, check, fix? })`: `check({ file, ast, artifacts })` returns findings `{ path, line, col, data? }`; `fix(finding, { file, ast })` returns `{ start, end, text }` edits or `null`, rendered as a unified diff. `message` may be a function of the finding. Stdlib codes are E2xxx/W2xxx; another code or a duplicate throws `E1753 ...`. Rules are pure; the registry is process-wide.
