# @keel/check

**Spec:** k.check (+ k.module checks, k.compat) · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `check(files, opts?)` -> `{ diagnostics, summary }` over `{ path, source }[]`; `opts`: `root` (module resolution, default cwd), `budgets` (E1755), `artifacts` (`hashes` for E1005), `types: false`, `base` (the parsed `surface.json` of the deployed code, for E1562). `format(diags, { mode, limit, quiet, code, ms })` (`compact` default, `json` NDJSON + summary, `pretty`). `defineRule(def)`, `rules()`, `reportedCodes()` (every code `check()` can report: pipeline plus registry). `@keel/check/explain` exports `explain(code)` (k.explain), apart from `check()`: the explanation table plus the rules `defineRule` registered in the same process. Types for each (`Diagnostic`, `Summary`, `RuleDef`, ...). `RuleInput.project` is the code files of the file's project plus its `topology.ts`, one shared array. The privacy readers (k.privacy-reads), for stdlib and library rules: `carriesReveal(node, input)` (E1112's value walk, one file, any other call ends a value), `schemaHolds(expr, input, names)` (`'yes' | 'unknown' | 'no'`, E1111's schema walk asked for named exports) and `outputSchemas(input)` (`{ expr, line, col }[]` of the `output` of `contract` entries and of `loader` declarations, inline or a `const`; a `decl()` call is not read).
- **App code and `unsafe/`:** a file under `unsafe/` is app code but for its lifted ranges, the function written as the second argument of an `unsafe(reason, () => ...)` call; inside one E1252, E1451, E1452, E1601, E1603, E1651, E1757, E1758, E1759 and W1608 are not reported and every other code is. E1757 in such a file reads `outside an unsafe() call`.
- **Invariants:** diagnostics are `{ kind: 'diag', code, path, line, col, message, see?, fix? }` (that key order), deduped, sorted by path, line, col; one-line messages under 90 chars; `fix` is a git-applicable unified diff. Compiler diagnostics pass through unchanged. TS errors encoding a Keel rule map to it (E1802 for a missing prop; a blank literal `label` (no visible character: only White_Space, Default_Ignorable_Code_Point, `Cf`, `Cc`, `M` or U+2800, JSX numeric character references decoded and named ones such as `&copy;` not counted) on a `@keel/ui` base element, read through parentheses, `as`, `satisfies`, `!` and object-literal spreads, is E1802 from a per-file rule that runs without types, a computed one is unchecked, and so is a `Host` (JSX, or a call's object literal) with neither or both of `label` and `labelledBy` when no spread may give one; E1501, E1003, E1001; inside the entries argument of `contract(...)` or the binding argument of `manifest(...)`, coded by the node the error starts at, never its TS code (k.routes): a contract key without the module prefix is left to the module pass (E1155), any other contract error E1510 (a member the entry's kind refuses: with a fix removing it); in a binding, at or under `layout` E1506, at or under a member the entry's kind refuses E1510 with a fix removing it, a key the contract lacks E1515 with a fix removing the entry, anywhere else, the argument included, E1515 naming what is missing), others are E1751 `TS<code> ...`; JSX types come from `@keel/runtime-dom/jsx-runtime`. A throwing rule is E1756; the rest still run. Static only: app code is never evaluated (rendered a11y is `keel test`). Compact: grouped by code, 5 per code (or `limit`) then `... +N more`, long fixes become a pointer, trailer `ok|fail N errors, M warnings` plus an indented counts line; no ANSI, no timestamps; deterministic. `explain` <= 120 tokens per kernel code.
- **Dynamic imports:** W1608 (k.ctx, a warning): an `import()` expression in an app code file, at `import`. Not reported: an `import()` that is E1603, a `Host`'s `code` in E1824's form, and a message set's `load` as the third argument of `messages` from `@keel/std-messages`.
- **Format literals:** E1108 (k.formats): a `formatLiteral` call (bound to `@keel/schema` by name, alias or namespace member, tests included) whose `text` is no string literal, whose `format` type names no one format the schema registry holds under its name (a `line`, `para` or message format among them), or whose `text` the registered format's `parse` refuses; at the argument at fault, no fix. The type pass reads `N` from the type of `format` (so it needs `types` on); `check()` imports nothing, so the registry is the process's (`keel check` imports each `@keel/std-*` package in `deps` first), and no app code runs.
- **Compliance rules:** E1105 (`reveal` outside `*.server.ts`, tests included) and E1111 (a `.pii()` or `s.secret` node in a `contract` entry's `params`, `search` or `query`, through consts, imports, re-exports, namespace members, spreads and schema arguments; the contract read as `readContract` (`@keel/compiler/internal`) reads it for `routes.json`, so entries or an entry not written out, a spread or computed key among them, a non-literal `method`, `path`, `layout` or `events`, or a schema it cannot read is reported at it; a schema returned by `tableSearch` from `@keel/std-tables` (an audited export that refuses a marked column when called), as a package's route table, is the package's), k.privacy; E1112 (in app code, a value `reveal` returns that reaches a log, storage, a file, store state or a throw; it is followed through bindings, literals, operators, members, methods and the standard conversions and encodings, and any other call ends it; one finding per sink, no fix), k.reveal; W1114 (a warning: an `Input` from `@keel/ui` with a literal `type="password"` or a password `autocomplete` token, bound by `f.field('<literal path>')` of a `form(<schema>)` const, where the schema node at the path is an `s.<name>()` call other than `s.secret`; a computed path or `type`, a numeric segment, a `field` in a variable and a schema step it cannot follow report nothing; no fix), k.privacy-reads; E1570 (an absolute or protocol-relative URL in `src`, `poster`, `data`, `srcset`, `action`, `formaction`, a backslash read as `/` as browsers do (`/\host`, `\\host`): a literal, a const, a template or `+` head, `new URL`'s base) and E1571 (one given to `ctx.net.fetch`, also through a `ctx` alias or `{ net }`, or `service({ base })` outside `*.server.ts`) and E1576 (a `@keel/*` specifier with an `internal` path segment in an import, type-only included, a re-export, or a literal `import()` or `require()`, in any code file outside the project root's `packages/`, `node_modules/` and `.keel/`, tests and `unsafe/` included; also any `#` specifier, which no `package.json` the checker reads can resolve; a template literal with no substitutions counts as a literal; computed specifiers are not followed), k.security; E1804 (contrast against the element's `bg`, else its nearest JSX ancestor's; large at 24px, or 18.66px at weight 700) and E1820 (reversed `direction` over two or more focusable base elements; fix: plain direction, children reversed), k.a11y; E1823 (a `styles` value, part or spread that is not an object literal, from the compiler; no fix), k.aria; E1824 (a `Host` from `@keel/ui` whose `code` is not `() => import("<relative path>").then((m) => m.<export>)`, at the prop, or one without `input` and no spread, at the element; no fix), k.host-element; E1825 (a `.css` specifier in an import, a re-export or a literal `import()` or `require()` of an app file that no `Host`'s literal `code` in the project imports; one per specifier; no fix), k.host-code.
- **Module pass (k.module, E1151-E1156, E1158, E1165):** a project pass over every parsed code file. Manifests are `modules/<id>/module.ts` (key and id prefix: the folder id) and stdlib `node_modules/@keel/std-x/module.ts` (key: the package name, imported as `@keel/std-x/<File>`), read statically (literal `module({...})` objects and string arrays only; anything else makes the module opaque and unenforced). Each non-test file belongs to the module with the longest folder prefix; files outside every module are not checked. Cross-module imports are relative paths naming the exporting file (export name = file stem). E1151 non-public import (at the import); a module's `<id>.contract.ts` or a stdlib package's `./contract` is no export and needs `deps` only · E1152 import into a module not in `deps` (at the import; fix: add the dep to the manifest) · E1153 one per deps cycle, at the smallest id's manifest, message lists the cycle (through a `*.guard.*` import of an edge of the cycle: `module deps cycle through guard <name>: <ids>`, `see` k.guards) · E1154 `public.exports` naming no file stem (at the manifest; fix: remove the entry) · E1165 an app module in `deps` the module does not use: no non-test file of it imports from that module (static, type-only, re-export or literal dynamic import, the contract included) and no binding of either module names a layout of the other; `@keel/std-*` entries are not judged; at the entry, one per entry (fix: remove it), and E1153 is unchanged · E1155 contract keys (`contract('<id>', {...})` from `@keel/router/contract`), `store(..., { id })`, `transaction(store, 'name', ...)`, `s.error('code', ...)` not prefixed `<id>.` (callees count only when imported from their kernel package) · E1156 `ctx.<cap>` or `const { cap } = ctx` with `cap` not in `capabilities`, or an `observe` import from `@keel/ctx` (any alias; or `<namespace>.observe`) without `observe` there, once per file and capability (fix: add it). Fixes are diffs of the manifest.
- **Contract passes (k.contract, k.routes):** read each app module's `modules/<id>/<id>.contract.ts` and each `routes.ts` binding statically. E1513 a `contract()` call outside its module's contract file (a package's `./contract` aside), a second one, a wrong id or export name, a `routes.ts` binding another module's contract, or an API id whose name is not one lowerCamel segment; no fix · E1514 a contract import that is no `*.schema.ts` file or package, at the import; no fix · E1502 two entries on one path pattern (API entries at distinct methods aside) in a contract, and any shared pattern across the modules of one deployable's table · E1503, E1504 from the contract literal · E1653 a `body` on a GET API entry (rule, fix removes it) · E1509 per deployable table. A deployable's table is the contracts of the modules `topology.ts` gives it; with none, every module forms one.
- **Compat pass (k.compat, E1562, E1563, W1564, W1568, E1567):** reads each intact, fresh `.keel/surface.json` (`version: 2`) among the files (`keel build` writes it; its `sources` hashes (of each file's normal form, built from a parse by `sourceHash` of `@keel/compiler/internal`: a formatter's change is not stale) must match the project's files, else E1005 `does not match its sources`). `accepts(A, B)` is decided on the JSON Schema of each node: `{}` accepts any; a union `B` when each member is accepted, a union `A` when one member accepts; literals and enums value by value; number and string bounds inside; integer only by integer; arrays, records item by item; objects by required fields, field by field (a field an open `B` lacks only when `A`'s field accepts any value), and a closed `A` only a closed `B` with no other field; anything it cannot read only when equal. With `base`, for each API entry of each base contract with a base caller in a deployable other than the contract module's (an unreadable `topology.ts`: every caller is split; no topology: none is): E1562 when the current entry is gone from its method and path (no fix), when its `params`, `query` or `body` refuses the base one (an absent one sends `{}` closed), or when the base `output` or a declared `errors[status]` refuses the current one; at that member of the current contract file (read statically through consts and relative imports), with a fix appending `.optional()` when making the one missing required field optional clears it. A `base` that is no `version: 2` surface is one W1568 and nothing is compared. For each store in both surfaces (`stores`: id, state and payload schemas): E1563 when the current state schema refuses the base one, at the refused field of the `store(schema, initial, { id })` source, with the same fix; W1564 per base transaction gone or whose payload now refuses the base one, no fix. E1572 (a `storage` or `shells` package missing from `package.json` `dependencies`; fix adds it at the spec of the first `@keel/` dependency; `dependencyNeed(at)` builds that diagnostic for one package, with `version` for one that must be listed at an exact text, which the cli's shell plugin pass calls) and E1573 (`shells` off a `client` deployable, or an id that is not reverse-DNS) at the deployable in `topology.ts`. E1567 (rule): a `service({ base, schema })` in app code, `base` not an http(s) URL literal, with an endpoint an app contract's API entry serves (method, HEAD as GET, and path), at `base`, naming the module; no fix.
- **API pass (k.api, E1511):** per project with a topology, each API entry (an entry with `method` in a module's contract, or a placed stdlib module's route literal; ids by module from their first segment) in a module a `client` or `static` deployable serves, at the module id in that project's `topology.ts` (line 1 when the topology comes from `opts`); no fix. `routes.json` must also match each entry's `method` (E1005).
- **Host pass (k.hosting, E1566):** per project with a topology, each bad `servedBy` (`servedByProblems` from `@keel/compiler/hosting`), at the first `servedBy` after the deployable's name in that project's `topology.ts`; no fix. `keel explain` has rows for E1565, E1566 and W1567.
- **Styles and documents (k.topology, k.head, E1587, W1012):** per project with a topology, each bad `styles` entry (`stylesProblems`: not a string literal, a relative path, or a package export that is not a `.css` file) is E1587, no fix; a project root `index.html` is W1012, which Keel never reads.
- **Placed stdlib pass (k.topology, E1586):** per project with a `topology.ts`, each placed id that is a stdlib module (`stdPlacedExports` from `@keel/compiler/std`, under `root`) whose package resolves `./contract` and not `./routes`, at the id's string in `topology.ts`; a package with neither is silent; no fix.
- **Route chain stores (k.server, E1550):** per project, each page or layout `loader` in a `modules/<id>/**/*.server.ts` whose `stores` names a factory it reads (a top-level function or `const` function of the file, or an import of one; its ids the literal `id` of each `@keel/store` `store` call in it and in each function it calls, of its file or imported) is compared with the loaders of the layouts above it: a different factory creating one id is E1550 at the deeper `stores` value, naming both factories, the id and the layout; no fix. A chain follows each `manifest` binding's literal `layout`; a page no binding names is read as under each layout of its module's contract.
- **Build-time writes (k.store, E1304):** in a component file, a `tx` from `@keel/store` whose every enclosing function up to the default-exported component is that component or a function child of `For`, `If`, `Match`, `Case` or `Boundary`; a call is not followed.
- **Node pages under test (k.testing, W1723):** in a test file, `renderRoute` with a literal id whose module the project's `topology.ts` places in a `node` deployable and an options literal with no `app`.
- **Boundary (k.boundary):** E1571 reads E1004's reach (`clientReach` from `@keel/compiler/internal`, per project `topology.ts` directory); E1759's browser file is one that is not server-only, so a `client` module's `*.server.*` and `*.guard.*` files are browser files and a `node` module's are not; E1009 is a use of `guard` from `@keel/router`, and E1551 of `loader` or `action`, in an app file other than `*.guard.*` or `*.server.*` (any case; tests and `packages/` aside; no fix), each read from the compiler's binding pass over the project (`projectHandlerUses`; k.bundle Handlers: a namespace member, a re-export, a value read count); E1010 (a miscased relative specifier) passes through from the compiler. The compile pass reads the project's own `topology.ts` when the caller passes none.
- **Dependencies:** `@keel/compiler`, `@keel/ctx`, `@keel/schema`, `@keel/reactive`, `@keel/store`, `@keel/runtime-dom`, `@keel/ui`, `oxc-parser`, `typescript`, `happy-dom`.
- **Rungs:** conformance; properties (seed 1337) for format and diff round-trip; token budget on 10 injected errors.

## Extension points

**Rule registry.** `defineRule({ code, message, explain, see?, check, fix? })`: `check({ file, ast, artifacts })` returns findings `{ path, line, col, data? }`; `fix(finding, { file, ast })` returns `{ start, end, text }` edits or `null`, rendered as a unified diff. `message` may be a function of the finding. Stdlib codes are E2xxx/W2xxx; another code or a duplicate throws `E1753 ...`. Rules are pure; the registry is process-wide.
