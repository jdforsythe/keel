# @keel/store

**Spec:** k.store, k.sync · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `store(schema, initial, { id?, clock?, logLimit?, keyLimit? }) -> Store<T>` (inside a scope, else E1203): readonly `schema`, `id`; `get(key)`, `select(fn) -> Computed`, `check(state) -> Result<T, store.invariant>` (parse and run every invariant; never commits or logs), `log() -> LogEntry[]`, `snapshot({ meta }?) -> Snapshot<T>`, `restore(snap) -> Result<T, SchemaError>`, `undo() -> boolean`, `undoWhere(pred) -> boolean` (undo the latest entry only if `pred` holds for it), `head() -> number` (reactive), `uses([t])`. `stores() -> ReadonlyMap<string, Store<unknown>>` (live stores of the caller's registry). `isolate(scope)` (the scope gets its own registry). `transaction(store, name, payloadSchema, (state, p) => state, { concurrent }?) -> Transaction<T, P>` (readonly `name`, `schema` = payload schema, `store`, `concurrent`: `'reject'` (default) or `'rebase'`). `tx(t, payload: P | unknown, { meta, base, key }?) -> Result<T, SchemaError | store.undeclared | store.invariant | keel.conflict>` (payload typed by the transaction's schema; a value typed `unknown` is validated at run time). `invariant(store, check)`. Types `Store`, `Transaction`, `TxOptions`, `LogMeta` (JSON record), `LogEntry { id, name, payload, at, meta?, base?, key? }`, `Snapshot { state, log, initial, head, keys }`. `stores()` is reactive (readers rerun when a store joins or leaves); `store.payloads` maps transaction names to payload schemas.
- **Invariants:** state changes only through `tx`; payload and result state are validated, copied and deep-frozen. Any `err` or throw leaves state and log unchanged; a throwing transaction rethrows. A commit sets state and log in one `batch`. `get(key)` reruns readers only when that key changes. `at` comes from `clock` (default: per-store counter, never `Date`). `head()` is 0 for a new store and rises by one per commit and per undo that undoes; an entry's `id` is the head its commit produced, so ids rise and an undo leaves a gap; `snapshot()` carries `head`, `restore` sets it (without one: the latest entry's `id`, else 0), and folding never changes it. Writes: `base` (an integer >= 0) other than `head()` is concurrent: a `'reject'` transaction returns `keel.conflict` with data `{ store, transaction, base, head }` and commits nothing, a `'rebase'` one applies to the current state and its entry keeps `base`; a write that is not concurrent keeps no `base`. `key` (1 to 64 characters): the store keeps `keys`, the `{ name, key }` of its latest `keyLimit` commits made with a `key` (default 1024, a positive integer, else `store` throws), oldest first; when `keys` holds the transaction's name with that `key`, `tx` returns `ok` with the current state and commits nothing, checked after `uses` and before `base`; the same `key` on another transaction commits. `undo`, `undoWhere` and folding past `logLimit` or a secret leave `keys` as it is; a refused or matched write adds nothing to it. `base` and `key` are entry fields, never `meta`, so snapshots keep them; a wrong-typed `base`, `key` or `keys` is `schema.invalid`. `snapshot()` holds `keys`, at most `keyLimit`; `restore` sets it (a snapshot without it: its log entries' keys), keeping the latest `keyLimit`. `undo` replays the log minus its last entry from the base: `initial`, or the snapshot `initial` after `restore`. At most `logLimit` entries (default 256, a non-negative integer, else `store` throws) are kept: a commit or `restore` past it folds the oldest into the base, so snapshots hold at most `logLimit` entries and `undo`/`undoWhere` return `false` once no kept entry is left. `meta` is copied, frozen and never in state; `snapshot()` drops it, `snapshot({ meta: true })` keeps it, `restore` keeps what it is given. `snapshot()` is JSON-safe (schema `encode`). A payload may hold `s.secret` values: `tx` copies it through its codec with each `Secret` kept (shared; it is frozen), so `log()` entries `reveal` it, and `snapshot()` folds every entry up to the last whose payload holds one into `initial`, so no secret is written (a secret in state still throws at `snapshot()`); `restore` validates state and each entry's shape (else `err`); a log naming a transaction the store no longer declares, or a payload its schema refuses, folds (k.persist): `state`, `head` and `keys` are kept, `state` becomes `initial` and no entry is kept; otherwise `initial` and every payload are validated against its transaction. `uses` is bound to `owner()` and dropped when that scope is disposed; `tx` consults the calling scope and its ancestors, and a caller with no declaring scope in its chain is unrestricted. Default id is `store.<n>` (module counter); a store registers in the registry of the nearest isolated scope on its `owner()` chain, else the module registry; `stores()` lists the caller's registry; a duplicate live id throws within one registry. Transaction names are unique per store. `@keel/store/internal` `moduleWrites.check`, when set, runs first in every `tx` on a module-registry store and may throw (`@keel/server` sets one that throws E1256 during a request). A store created while `resume` holds a `#k-state` snapshot for its id (`Symbol.for("keel.waitingSnapshots")`) restores it at creation.
- **Internal:** `@keel/store/internal` (not public API; `@keel/server` and `@keel/testing`), the server-state runner of k.server Server state: `serverState(ctx) -> { request() -> { stores(factory) -> Promise<unknown>, save() -> Promise<keel.conflict | null>, end() } }`; `openStores(ctx, rq, factory, seen?)` (the request's one instance of `factory`, opened by `openHeld`); `openHeld(ctx, rq, factory, seen?) -> Promise<Held<S>>` (runs `factory` in an isolated child scope of `rq.scope`, restores each store from one `ctx.storage.read` of its keys `keel.store.<id>`, registers it in `rq.held`; `seen(schema, state)` per restored store; a default `store.<n>` id throws, and so does an id that another factory the request still holds opened, with `store <id>: id already in use by a live store`); `saveStores(ctx, rq)` (after an action's `ok`: one `ctx.storage.commit` of every opened key, each changed snapshot with `expect` the value it was restored from and each unchanged key as a condition; `false` is `keel.conflict` and drops those keys from the copy; `true` reports one `save` event `{ store, head, from }` per changed store; nothing changed: no commit); `commitStores(ctx, factory, fn)` (k.persist: a fresh request, `fn(S)`, on `ok` `saveStores`; a refused commit runs `fn` again on a fresh read, at most 3 runs, then `err` `keel.conflict`; resolves `fn`'s `Result`); `copyOf(storage)` (the in-process copy of one storage object: each key's last value read or committed and its parse, reused when a `read` returns the same text; it decides no conflict); `savedOf(raw)`; `storeShapes(factory, ctx?) -> { id, state, transactions }[]` (the stores `factory` creates on one run in a detached isolated scope, default a sim ctx: state schema and payload schemas by name, for `.keel/surface.json`); `sourcesOf(t) -> { fn, invariants } | undefined` (a transaction's declared function and its store's invariants in declaration order, for `prove`); types `ServerState`, `ServerRequest`, `StateRequest` `{ scope, held }`, `Factory`, `Held`, `Opened`, `Saved`, `SavedCopy`, `SaveConflict`, `Sources`, `StoreShape`.
- **Dependencies:** `@keel/schema`, `@keel/reactive`, `@keel/ctx`.
- **Rungs:** probabilistic: conformance and `test/` properties against a pure model (replay, undo inverse, restore), seed 1337. E1301 static, E1302 and E1303 (no secret in state) are checker rules; `store()` also throws E1303 at construction when the state schema holds `s.secret` (path from `@keel/schema/internal`).

## Extension points

`invariant(store, check)`: checks are permanent for the store and run on every candidate state.
