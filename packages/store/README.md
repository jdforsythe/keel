# @keel/store

**Spec:** k.store, k.sync · **Status:** implemented · **verified:** (none)

## Contract

- **Public API:** `store(schema, initial, { id?, clock?, logLimit? }) -> Store<T>` (inside a scope, else E1203): readonly `schema`, `id`; `get(key)`, `select(fn) -> Computed`, `check(state) -> Result<T, store.invariant>` (parse and run every invariant; never commits or logs), `log() -> LogEntry[]`, `snapshot({ meta }?) -> Snapshot<T>`, `restore(snap) -> Result<T, SchemaError>`, `undo() -> boolean`, `undoWhere(pred) -> boolean` (undo the latest entry only if `pred` holds for it), `head() -> number` (reactive), `uses([t])`. `stores() -> ReadonlyMap<string, Store<unknown>>` (live stores of the caller's registry). `isolate(scope)` (the scope gets its own registry). `transaction(store, name, payloadSchema, (state, p) => state, { concurrent }?) -> Transaction<T, P>` (readonly `name`, `schema` = payload schema, `store`, `concurrent`: `'reject'` (default) or `'rebase'`). `tx(t, payload: P | unknown, { meta, base, key }?) -> Result<T, SchemaError | store.undeclared | store.invariant | keel.conflict>` (payload typed by the transaction's schema; a value typed `unknown` is validated at run time). `invariant(store, check)`. Types `Store`, `Transaction`, `TxOptions`, `LogMeta` (JSON record), `LogEntry { id, name, payload, at, meta?, base?, key? }`, `Snapshot { state, log, initial, head }`. `stores()` is reactive (readers rerun when a store joins or leaves); `store.payloads` maps transaction names to payload schemas.
- **Invariants:** state changes only through `tx`; payload and result state are validated, copied and deep-frozen. Any `err` or throw leaves state and log unchanged; a throwing transaction rethrows. A commit sets state and log in one `batch`. `get(key)` reruns readers only when that key changes. `at` comes from `clock` (default: per-store counter, never `Date`). `head()` is 0 for a new store and rises by one per commit and per undo that undoes; an entry's `id` is the head its commit produced, so ids rise and an undo leaves a gap; `snapshot()` carries `head`, `restore` sets it (without one: the latest entry's `id`, else 0), and folding never changes it. Writes: `base` (an integer >= 0) other than `head()` is concurrent: a `'reject'` transaction returns `keel.conflict` with data `{ store, transaction, base, head }` and commits nothing, a `'rebase'` one applies to the current state and its entry keeps `base`; a write that is not concurrent keeps no `base`. `key` (1 to 64 characters): when a kept entry holds it, `tx` returns `ok` with the current state and commits nothing, checked after `uses` and before `base`. `base` and `key` are entry fields, never `meta`, so snapshots keep them; a wrong-typed `base` or `key` is `schema.invalid`. `undo` replays the log minus its last entry from the base: `initial`, or the snapshot `initial` after `restore`. At most `logLimit` entries (default 256, a non-negative integer, else `store` throws) are kept: a commit or `restore` past it folds the oldest into the base, so snapshots hold at most `logLimit` entries and `undo`/`undoWhere` return `false` once no kept entry is left. `meta` is copied, frozen and never in state; `snapshot()` drops it, `snapshot({ meta: true })` keeps it, `restore` keeps what it is given. `snapshot()` is JSON-safe (schema `encode`). A payload may hold `s.secret` values: `tx` copies it through its codec with each `Secret` kept (shared; it is frozen), so `log()` entries `reveal` it, and `snapshot()` folds every entry up to the last whose payload holds one into `initial`, so no secret is written (a secret in state still throws at `snapshot()`); `restore` validates state, `initial` and every payload against its transaction. `uses` is bound to `owner()` and dropped when that scope is disposed; `tx` consults the calling scope and its ancestors, and a caller with no declaring scope in its chain is unrestricted. Default id is `store.<n>` (module counter); a store registers in the registry of the nearest isolated scope on its `owner()` chain, else the module registry; `stores()` lists the caller's registry; a duplicate live id throws within one registry. Transaction names are unique per store.
- **Dependencies:** `@keel/schema`, `@keel/reactive`.
- **Rungs:** probabilistic: conformance and `test/` properties against a pure model (replay, undo inverse, restore), seed 1337. E1301 static, E1302 and E1303 (no secret in state) are checker rules; `store()` also throws E1303 at construction when the state schema holds `s.secret` (path from `@keel/schema/internal`).

## Extension points

`invariant(store, check)`: checks are permanent for the store and run on every candidate state.
