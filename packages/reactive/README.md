# @keel/reactive

**Spec:** k.reactive · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `scope(fn, { onError?, detached? }) -> Scope { dispose, parent, onDispose(fn), run(fn) -> T }` · `owner() -> Scope | undefined` · `signal(v) -> Signal<T> { get, set }` · `computed(fn, { equals? }) -> Computed<T> { get }` · `effect(fn, { writes? }) -> Effect { dispose }` · `batch(fn) -> T` · `resource(fetcher) -> Resource<Settled<T>> { get(): ResourceState<Settled<T>>, refetch }` · `inspect() -> { nodes: { id, kind }[], edges: { from, to }[] }`. `@keel/reactive/internal` (kernel only): `pulse()` for registries and `lastResource` for `Match` resource ids.
- **Invariants:** Glitch-free push-pull: a computed recomputes at most once per commit, lazily, only if a source changed; a result `equals` the last (default `Object.is`) keeps the old value and stops propagation. Store `select` returning structures should pass `equals`. A commit is one changing `set` or the outermost `batch`; effects run once after it (and on creation); a throwing effect does not stop the others; the first error is rethrown (`fn`'s own first, in `batch`), unless the effect's nearest ancestor scope declares `onError`: then that handler receives it after the commit, the effect is marked failed (never reruns) and nothing is rethrown (a throw inside `onError` propagates). A computed's throw (from `fn`, or from `equals`) is its outcome until a source it read changes: it runs once per commit, every reader's `get()` throws that error (a `try` around it catches it), a read without a source change does not rerun it, and a throw or the first value after one always counts as a change (`equals` is not consulted), so readers rerun on recovery, also to the value from before the throw. A computed owned outside a `Boundary` therefore keeps its error until a source it read changes, so a Boundary `reset()` that re-renders reads the same error again. A retry follows only the sources the throwing run read, so a computed that throws before reading any source keeps its error until it is disposed; disposing a computed drops its value and error. A throw while a commit brings a node's sources up to date (a scope's `onDispose` hook) still reruns that node and is rethrown after it, so no reader misses a later write. Disposing a scope disposes and unsubscribes everything in it, nested and mid-run included. A throwing `onDispose` hook does not stop a disposal: every owned node is disposed and every hook runs (owned nodes in creation order, then the node's own hooks), then the first error in that order is rethrown; a disposal by a commit's rerun surfaces it from that commit like an effect's throw (`onError` included), and `dispose()` throws it to its caller. When a rerun's own run throws after a hook threw, the hook's error is the one rethrown; when `scope(fn)` or `run(fn)` throws, `fn`'s error wins over a hook's. A `detached` scope is a root: `parent` undefined, no owner disposes it or lends it an `onError` (without its own, an effect's throw rethrows from the commit that ran it), `fn` runs untracked (writes still checked); only its own `dispose()` ends it (a recorder that outlives the component that started it). `scope.run(fn)` creates under that scope from anywhere (e.g. inside an effect, outliving its reruns); reads inside it subscribe nothing; writes are still checked against the running computation's `writes`; a throw propagates and leaves the scope live. `resource`: `loading -> ready | error` only; fetcher reruns on `refetch()` or a change of a signal it read; latest request id wins; a throw or rejection is `error`, and a keel `Result` (branded by k.schema `ok`/`err`) unwraps (`ok(v)` is `ready` with `v`, `err(e)` is `error` with `e`; a plain `{ ok, error }` object stays `ready`; `Resource<Settled<T>>`); a reader throwing on `ready` fails it via `loading`.
- **Errors** (`Error` with `code`, `see`): `E1201` write in a computed, or in an effect to a signal/resource (`refetch`) not in `writes` · `E1202` self-read, self-invalidation, or effects unsettled after 1000 passes · `E1203` primitive outside a scope · `E1205` read of a disposed computed · `E1206` `run` on a disposed scope. Check rule `E1207` (`@keel/check`): `scope` given `detached: true` or a non-literal options object in every file but a kernel package's own; a detached scope has no `parent`, so it escapes `uses` and the request store registry. A module root, `scope(fn)` made while `owner()` is undefined (a module's top level), has no `parent` either and lives until its own `dispose()`: state a library keeps for its module's life is made in one with `run`.
- **Dependencies:** none at runtime.
- **Rungs:** conformance; properties (DAG vs model, run counts, equals, inspect edges, scope trees, `run`-attached trees and untracked reads, resource orders).

## Extension points

None. One way per concept; no `untrack` (an untracked read is `scope.run`, which also names the owner), no aliases.
