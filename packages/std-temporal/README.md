# @keel/std-temporal

**Spec:** std.temporal · **Status:** proposed · **verified:** (none)

## Contract

- **Public API:** format types `Instant` (`2026-11-10T09:30:00.000Z`, UTC to the millisecond), `PlainDate` (`2026-11-10`), `TimeZone` (`UTC` or a Zone or Link name of the pinned IANA tz release, kept as written: `Asia/Kolkata`, `Asia/Calcutta`; not `utc`) and `Duration` (`PT1H30M`, `-PT0.500S`, whole milliseconds within 1e15), each in years 0001 to 9999 where it has a date; `UTC` (`formatLiteral(TimeZone, 'UTC')`); a known `Instant`, `PlainDate`, `TimeZone` or `Duration` in source is `formatLiteral(Instant, '1970-01-01T00:00:00.000Z')` from `@keel/schema` (E1108 when it does not parse); `DateStyle` (`short | medium | long | full`), `UnitStyle` (`long | short | narrow`); `instantOf(ms): Result<Instant, TemporalError>`, `epochMs(i)`, `plainDateOf(i, zone)`, `addDays(d, days): Result<PlainDate, TemporalError>`, `durationOf(ms)`, `durationMs(d)`; `formatDate(d, locale, style)`, `formatInstant(i, locale, zone, style)`, `formatDuration(d, locale, style)`; type `TemporalError` (`temporal.outOfRange`).
- **Invariants:** importing the package registers `temporal.Instant`, `temporal.PlainDate`, `temporal.TimeZone` and `temporal.Duration` (idempotent). Each value has one canonical text (ISO 8601 for instants, dates and durations; the exact IANA spelling for zones), so `encode` is the identity, equal values are equal strings and string order is time order for instants and dates. No export reads the clock (the current instant is `instantOf(ctx.clock.now())`), the host locale or the host time zone: calendar math uses `Date` UTC methods, formatting uses `Intl` with the given `Locale`. `formatDuration` is built from `Intl.NumberFormat` units and `Intl.ListFormat`. `TimeZone` accepts a name on the list in `src/internal/zoneNames.ts` and never asks the host's `Intl`; `gen` draws from that list's Zone names and `UTC`, so a value parses and one seed gives the same zones on every host. The host's tz data matters only where a zone is used: `plainDateOf` and `formatInstant` throw `RangeError` for a zone the host's `Intl.DateTimeFormat` lacks. The list is generated by `pnpm generate` from `tooling/tzdata.source.zi`, the `# version`, Zone and Link lines of one IANA release's `tzdata.zi`; a new release replaces that file and regenerates. `plainDateOf` gives `i`'s UTC date when the date in `zone` would leave years 0001 to 9999 (about 15 hours from the bounds).
- **Dependencies:** `@keel/schema` (`s.format`), `@keel/std-i18n` (`Locale`).
- **Rungs:** conformance (example + probabilistic), properties for `addDays` additivity, instant order, and `formatDate` and `formatDuration` injectivity per locale.

## Extension points

Uses the **schema type registry** (k.schema `s.register`). It registers four format types (k.formats) over `s.string()`; parse, encode, generator and doc derive from them.

## Unsafe

count: 1. `unsafe/notDuration.ts`: the `RangeError` std.temporal specifies for `durationOf` over a count that is no integer within 1e15, a throw in a library's code.
