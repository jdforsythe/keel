# @keel/compiler

**Spec:** k.compiler + k.component (+ k.module `module()`) · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `compile(files, { mode?, topology?, routes? })` -> `{ outputs, artifacts, hashes, diagnostics }`. `topology` (parsed `topology.ts`) places each module for E1004's reach (k.boundary Reach: the graph from each route component and every `client` module file, with the chain in the message; `clientReach` in `@keel/compiler/internal`, shared with `@keel/check`; it follows `new URL(<literal>, import.meta.url)` and `?worker`, `?sharedworker`, `?url` specifiers; server-only is `*.server.*` or `*.guard.*`, any extension, any case) and reports E1010 for a relative specifier naming a project file in another case; `routes` is a precomputed `routes.json` (default `{}`). `module(def)` / `ModuleSchema` (k.module manifest: `ModuleSchema` includes the lowerCamel `id` rule; `module` validates, returns the frozen def unchanged, throws `code: 'keel.module'`). `@keel/compiler/tsconfig.strict.json`: the strict app profile (no `jsxImportSource`; JSX is lowered by the plugin). `@keel/compiler/testing` (dev-only; optional peer `esbuild`, DOM env): `evaluate(code)`. `routeLiterals(files, { topology?, root? })`: the literal route table of the manifests `vite build` evaluates, read with oxc and never run (`keel check` compares `routes.json` with it): ids, `path`, `layout`, `api`, action verbs, `params`/`search` presence and a guard's literal `redirect` (`null` for a guard declared without one); a spread `...x.routes` of the `routes` export of a package in the module's `deps` is read from the file the package's `exports` name, resolved from `<root>/modules/<m>/` (`root` defaults to `process.cwd()`). `@keel/compiler/routes` (build-time; peer `esbuild`): `buildRoutes(root)` evaluates them and writes `.keel/routes.json` with the plugin's writer (`keel build` when every deployable is `node`). `stdArtifact(files)` -> `{ data, hash, diagnostics }`: `.keel/std.json`, each app manifest's literal `std` by package and module id, E1158 for a bad entry (in `artifactHashes`). `@keel/compiler/std/*`: `importDeps(root, files)` imports each `@keel/std-*` dep of the app manifests once (E1159), `readStd(text)`, `bindStd(ctx, data)` (`createApp` and a `client` entry), `bindClientStd(ctx, kStateText)` (the resume entry binds `#k-state`'s `std` before `resume`), `clientStd(pkg)` (a package's config is client-readable; default server-only) and `clientStdData(data, modules)` (what a browser gets: `clientStd` packages, served modules), and the accessor `stdConfig(ctx, pkg, Config)` -> `{ [moduleId]: Config }`. `std/importDeps` also imports a std package's `./tools` export (a throw is E1159); `std/clientStd(pkg, keys?)` sends only `keys` of each module's config to the browser.
- **Vite plugin** (`@keel/compiler/vite`, no options): in every browser build (k.boundary, k.bundle), and through `worker.plugins` in each worker's bundle, loads a server-only JS or TS file (named on disk `*.server.*` or `*.guard.*`, any case) as a stub (each export `serverOnly(file, name)` from `@keel/router/internal`, throwing E1008), keeps Node built-ins (a shipped list for Node 22 and later, any `node:`) external and maps none, fails a miscased file with E1010 in every build and, after bundling, fails with `E1007 server code in browser build: <reason>: <chain>` when the graph of any bundle (a worker's chain runs through the file naming it) holds a server-only file (any query, any extension), a Node built-in, or a file using `loader`, `action` or `guard` (the binding pass `@keel/check` shares) outside the `client` deployable's own modules; `node:sqlite` maps to `process.getBuiltinModule` in the server build only; `envPrefix` exposes no variable to `import.meta.env`, a project `envPrefix` or `define` fails the build before bundling (`environment config`, chain the config file), and an emitted browser file holding the value of a `KEEL_*` variable of 8 or more characters (but `KEEL_PEER_*`, `KEEL_ORIGIN`, `KEEL_DEPLOYABLE`, `KEEL_SHELL`, `KEEL_INSPECT_ORIGINS`) fails it (`environment value`, chain the variable's name and the file, never the value); a transform never fails on E1004, which `keel check` reports. It compiles each changed module under the root (linked workspace packages are skipped), merges artifacts, writes `.keel/{a11y,deps,ids,routes,std,styles}.json` as read-only `{ data, hash }` atomically and only on change, under the root `configResolved` gave (before it runs, nothing). Reads `topology.ts` statically at `configResolved` (`parseTopology`: `modules`, `adapter`, `host`, `storage`, `shells`). At `buildStart` it compiles every app source (no tests) for style usages and evaluates `tokens.ts` and the deployable's `modules/<id>/routes.ts` once at build time (esbuild bundle from the app root, run in Node): `compileStyles` from `@keel/ui/css` -> the `virtual:keel.css` module (`/__keel.css`); `routesArtifact` from `@keel/router` -> `routes.json`. For a `client` deployable (`KEEL_DEPLOYABLE` or the first by name) it serves the generated entry **`/@keel/entry.ts`** (index.html: `<div id="app"></div><script type="module" src="/@keel/entry.ts"></script>`): imports `virtual:keel.css`, `createCtx({ mode: 'real' })`, `bindStd(ctx, <client-readable std.json data>)` when there is any, `createRouter(<merged manifests>, { ctx, history: browserHistory(), mode })` and `mount(router.App, #app, { ctx, mode })` (one `mode`, a string literal from Vite's command: `"dev"` only when Vite reports the command `serve`, `"production"` for `build`, another command or none; the entry reads no `import.meta.env`), and under `"dev"` posts `{ graph: inspect(), stores }` to `/__keel/inspect` after mount and then at most once a second on change. The resume entry of a `node` deployable takes the same literal; the text `resumeEntry` returns unbundled is `"production"`. A `vite build` with a `client` `KEEL_DEPLOYABLE` keeps the project's Vite config and writes `dist/<name>/` (k.hosting Artifact): `index.html` (the project's, else a default one with `#app` and the entry), hashed `assets/` and `keel-mark.svg` (from `public/`, else the brand mark), every URL root-absolute; `index.html` gets one `<meta name="keel-peer" data-deployable="<name>" content="<origin>">` per `node` deployable whose `KEEL_PEER_<NAME>` is set (E1565 when it is not an http(s) origin), and the generated entry binds each module of the topology to its deployable's tagged origin, else the document's (k.hosting Peers); only the first `client` by name writes `.keel/`. A `vite build` with a `node` `KEEL_DEPLOYABLE` builds the resume entry and its islands into `dist/<name>/` (hashed `assets/`, manifest `CLIENT_MANIFEST` = `.vite/manifest.json` from `@keel/compiler/internal/entry/CLIENT_MANIFEST`), then `server.mjs` (Topology below), and writes no `.keel/` (`keel build` runs it per node deployable). Dev and preview servers serve `GET /__keel/inspect` (k.cli Inspect): `.keel/` ids, a11y, routes plus the last posted live half (`live: false` before one), and under `keel dev` the inspector sections each `node` deployable's dev app serves (an app's section replaces the page's of that id; of two apps serving one id, the first by deployable name); POST JSON only; GET and POST answer only a loopback or listed `Host` with an absent, own, or listed `Origin` (extra origins from comma-separated `KEEL_INSPECT_ORIGINS`, `:*` any port; listed ones get CORS; others 403 `keel.denied`). Build-time only: the plugin needs `esbuild` and the app must depend on `@keel/ui`, `@keel/router`, `@keel/ctx`, `@keel/runtime-dom`.
- **Types** (`@keel/compiler/client`, types only; k.bundle Types): declares `import.meta.env` as `BASE_URL` and `MODE` (`string`), `DEV`, `PROD` and `SSR` (`boolean`), with `strictImportMetaEnv` so any other key is a type error, and the default imports of `*?worker`, `*?sharedworker` and `*?url`. `keel check` loads it when it resolves from the project root; the scaffold's `tsconfig.json` lists it in `types`.
- **Topology** (k.topology): a `client` `KEEL_DEPLOYABLE` with `KEEL_SHELL` (`capacitor` or `tauri`, from `keel build --target`; k.shell) builds into `dist/<name>/<shell>/www/` and writes no `.keel/`, its entry creating `createCtx({ mode: 'shell', drivers })` from `capacitorDrivers` (`@keel/std-capacitor`) or `tauriDrivers` (`@keel/std-tauri`) with `{ origin: new URL(KEEL_ORIGIN) }`; when the project has `identity.ts` (k.return) that entry also imports `/identity.ts` and, before the router starts, calls `shellMount(ctx, { id, origin })` from the shell package's `/shellMount` with the deployable's shell `id`; without `KEEL_SHELL` the client entry is a real ctx, unchanged. With `identity.ts` every client entry imports its default export and starts the router with `mount: <it>.path` (k.mount), so no page matches at or under the mount. E1581 (k.mount) is a module importing `identity.ts` that a `static` deployable, or a `client` one without `host`, serves; `shells` do not change it. for a `node` `KEEL_DEPLOYABLE`, `vite build` builds the client entry into `dist/<name>/` and then, in the same Vite builder (`environments.ssr`, every dependency bundled, no code splitting), the generated production entry `virtual:keel/server` (`serverEntryCode`: `installServerDom` from `@keel/server/internal/dom` first, then dynamic imports of `topology.ts`, each module's `routes.ts` and `runners.server.ts`, for a deployable whose `storage` is `'sqlite'` or `'postgres'` an `open` that imports that `@keel/std-db` driver when first called (a build reads `node:sqlite` through `process.getBuiltinModule` when the driver first runs, so `server.mjs` loads on a Node without it), and `start` from `@keel/server/internal/start` with `dir: import.meta.dirname`; a `'postgres'` build keeps `pg-native` external and gives the bundle a `require` from `createRequire`) into `dist/<name>/server.mjs` with an external `server.mjs.map` beside it (sources relative to the project, one outside it as `../`; no `sourcesContent`), then copies `.keel/routes.json` and `.keel/std.json` beside it, and copies in `dist/<client>/` of each `client` deployable whose `host` it is, without overwriting its own files, recording the client's `assets/` in its manifest under `keel:host` (k.hosting Host). `@keel/compiler/hosting/*`: `originOf(value)` (the origin of an http(s) origin with no path, else undefined), `peerOrigins(topology, env)` (`keel-peer` origins and the E1565 keys) and `hostProblems(topology)` (the E1566 problems), shared by `keel build`, `keel check` and `@keel/server`. A parsed topology carries a literal `host`. With a `node` deployable the dev server is `keel dev`'s one origin: `virtual:keel/dev` (`devEntryCode`, loaded through `ssrLoadModule`) creates one dev `createApp` per `node` deployable (real ctx, its runners, `.keel/` artifacts, the others as in-process peers); `devMiddleware` answers a request a `node` deployable's route (an API route included) matches through that app (streaming the body) and passes the rest to Vite; a changed app source closes the dev apps and the next request reloads them; the dev module calls `inspectorsReload` (`@keel/compiler/inspect/inspectorsReload`) first, so a module evaluated again registers its `inspector` section in place of the one it registered before, while two registrations of one id in one load are E1057; a changed source outside the project root (a linked package) loads the whole server graph again. With no `client` deployable, `/@keel/entry.ts` is the resume entry over every `node` deployable's islands. `pathCollisions(files, topology, root?)`: E1559 for a literal route path (params compared by position) in two deployables, at the second route, naming both. `serverOnlyCalls(files, topology)`: E1558 at each call, in a `modules/<m>/**/*.server.ts(x)` of a module a `client` or `static` deployable serves, of `loader` or `action` from `@keel/router` (named or through `import * as`) whose options name `stores`, whose loader `fn` is `async function*` (inline, or a top-level function or `const` of the file), or that it cannot read: options not an object literal, or with a spread or computed key; a spread argument; a loader `fn` neither inline nor a top-level function or `const` of the file. The message names the form it could not read (options not an object literal; options spread or computed; `fn` not a function of the file). An alias (`const l = loader`), a destructure from a namespace import (`const { loader } = r`), a `fn` that is not `async function*` but returns a generator, or a call made from another file is not read; `createApp` still throws E1558 for those holding server state.
- **Output:** JSX lowers to `@keel/runtime-dom/ops`: one hoisted `template(html)` per element root, cloned once per render; each dynamic expression is exactly one `text`/`attr`/`prop`/`on` binding; `<Foo a={x}>kids</Foo>` is `Foo({ get a() { return x }, children: () => kids }, undefined, ctx)` where `ctx` is the enclosing component's third parameter (added when absent); `{props.children()}`, `{slots.x()}` and, in a component, a call of a member of its first parameter alone or left of `??` (`{props.icon()}`, `{props.icon?.() ?? 'x'}`) are slot calls: what they return is placed as content, once (k.place). `If`/`For`/`Match`/`Boundary` lower to `cond`/`list`/`match`/`boundary` (`If` `fallback` is `cond`'s `otherwise`). A child expression holding elements (`{a ? <b/> : <i/>}`, an array, `map()`, a function) is E1403 and lowers to nothing. Static style props on `@keel/ui` base elements become one `class` with ui's atomic names; dynamic ones stay props. A file exporting `uses` runs its default-export component in its own scope that declares them (`t.store.uses([t])`). Top-level `store`/`signal`/`computed`/`resource` are created in a module root scope; exported stores under `modules/<id>/` get `{ id: '<id>.<export>' }`. A `@keel/ui` base element with a literal `id`, as a JSX tag or a call `Button({ id: "cart.buy", … })`, is called as `stamp(id, Button)(props)`: when it is bound (`data-k`), its `data-k` becomes that id, the stamp k.errors `data.at` reads. TypeScript outside JSX is otherwise kept byte for byte. A `@keel/runtime-dom` import is removed only when every binding it imports is an intrinsic used solely as a JSX tag; an intrinsic called, passed as a value or named in a parameter or destructuring default (`If({ when, children })` in a plain `.ts` module) keeps it.
- **Artifacts:** `styles.json` `{ usages: [{ props: { <prop>: <token> }, breakpoint?, state? }] }` (one per literal token, dynamic `?:`/`&&` leaves included, deduplicated, sorted), read from `@keel/ui` base elements, `Part` from `@keel/ui/aria`, and each part of the `styles` prop of any other component (a `styles` value, part or spread that is not an object literal is E1823, except the enclosing component's own part styles forwarded, resolved by binding: its first parameter's `.styles` or a member of it, a `styles` destructured from that parameter or by a top-level `const { styles } = props`, and `?? {...}` or `|| {...}` over one; a lowercase helper is not a component and forwards nothing; a JSX spread attribute onto a component is not read); `state` is one of `selected`, `checked`, `expanded`, `highlighted`, `hover`, `focusVisible`, `active`, `disabled`; `routes.json` per k.router; `ids.json`/`a11y.json` include `@keel/ui` base elements with a literal `id` (by the DOM tag they render).
- **Ids:** literal `id` kept, else `<path>.<ordinal>` over the file's DOM elements (`src.orders.OrderList.0`); written into the template.
- **Invariants:** `compile` is pure and deterministic (sorted keys, FNV-1a hash per artifact, no clock, no fs); static text and attributes are HTML-escaped at compile time; literal `javascript:`/`data:` URLs become `about:blank`.
- **Diagnostics:** E1001 E1002 E1003 E1004 (k.compiler; a value import, re-export, literal `import()` or `new URL(<literal>, import.meta.url)` of a server-only module, `*.server.*` or `*.guard.*` of any extension and case, from client-reachable code; a query names its file; a `routes.ts` may import them), E1010 (k.bundle; a miscased relative specifier), E1401 (unified-patch fix) E1402 E1403 (elements in a child expression bind nothing; `If` fix for `&&`/`?:` when `If` is imported) E1404 (k.component; base-element ids count), E1501 for string paths in `href`/`src`/`action`/`formaction`, `Link to`, `Image src` (absolute URLs and `#x` allowed; E1003 wins), E1000 syntax error (pending spec line). Unknown tokens in `keel.css` are left out and warned (E1801 is `check`'s). E1002 resolves names through the module resolver, exported for `@keel/check` at `@keel/compiler/internal` (not app-facing); `script`/`style` take literal text and attributes only, and nothing binds into them.
- **Dependencies:** oxc-parser, magic-string; runtime-dom, reactive, schema, store; esbuild (optional peer: `evaluate` and the Vite plugin). The generated code imports `@keel/reactive` and `@keel/runtime-dom/ops`; the generated entry and the build-time evaluator import router/ui/ctx (and the entry reactive/store) from the app.
- **Rungs:** conformance (example + probabilistic), property tests (determinism, ids, XSS, class-name parity with ui).

## Not yet

`mode: "server"` emits the client module: no separate server HTML renderer (`@keel/server` renders the client module with the runtime in its server mode, which writes the `<!--[-->` regions; k.resume); E1005 is k.check's; cross-module checks of `module()` manifests are k.check's (0030).
