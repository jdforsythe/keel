# @keel/compiler

**Spec:** k.compiler + k.component (+ k.module `module()`) · **Status:** implemented · **verified:** (none)

## Contract

- **Public API:** `compile(files, { mode?, topology?, routes? })` -> `{ outputs, artifacts, hashes, diagnostics }`. `topology` (parsed `topology.ts`) exempts files of `client` deployables from E1004; `routes` is a precomputed `routes.json` (default `{}`). `module(def)` / `ModuleSchema` (k.module manifest: `ModuleSchema` includes the lowerCamel `id` rule; `module` validates, returns the frozen def unchanged, throws `code: 'keel.module'`). `@keel/compiler/tsconfig.strict.json`: the strict app profile (no `jsxImportSource`; JSX is lowered by the plugin). `@keel/compiler/testing` (dev-only; optional peer `esbuild`, DOM env): `evaluate(code)`. `routeLiterals(files, { topology? })`: the literal route table of the manifests `vite build` evaluates, read with oxc and never run (`keel check` compares `routes.json` with it, rfc:0059). `@keel/compiler/routes` (build-time; peer `esbuild`): `buildRoutes(root)` evaluates them and writes `.keel/routes.json` with the plugin's writer (`keel build` when every deployable is `node`). `stdArtifact(files)` -> `{ data, hash, diagnostics }`: `.keel/std.json`, each app manifest's literal `std` by package and module id, E1158 for a bad entry (in `artifactHashes`). `@keel/compiler/std/*` (rfc:0066): `importDeps(root, files)` imports each `@keel/std-*` dep of the app manifests once (E1159), `readStd(text)`, `bindStd(ctx, data)` (`createApp` and a `client` entry), `bindClientStd(ctx, kStateText)` (the resume entry binds `#k-state`'s `std` before `resume`, rfc:0069), `clientStd(pkg)` (a package's config is client-readable; default server-only) and `clientStdData(data, modules)` (what a browser gets: `clientStd` packages, served modules), and the accessor `stdConfig(ctx, pkg, Config)` -> `{ [moduleId]: Config }`. RFC 0070: `std/importDeps` also imports a std package's `./tools` export (a throw is E1159); `std/clientStd(pkg, keys?)` sends only `keys` of each module's config to the browser.
- **Vite plugin** (`@keel/compiler/vite`, no options): compiles each changed module under the root (linked workspace packages are skipped), merges artifacts, writes `.keel/{a11y,deps,ids,routes,std,styles}.json` as read-only `{ data, hash }` atomically and only on change. Reads `topology.ts` statically at `configResolved`. At `buildStart` it compiles every app source (no tests) for style usages and evaluates `tokens.ts` and the deployable's `modules/<id>/routes.ts` once at build time (esbuild bundle from the app root, run in Node): `compileStyles` from `@keel/ui/css` -> the `virtual:keel.css` module (`/__keel.css`); `routesArtifact` from `@keel/router` -> `routes.json`. For a `client` deployable (`KEEL_DEPLOYABLE` or the first by name) it serves the generated entry **`/@keel/entry.ts`** (index.html: `<div id="app"></div><script type="module" src="/@keel/entry.ts"></script>`): imports `virtual:keel.css`, `createCtx({ mode: 'real' })`, `bindStd(ctx, <client-readable std.json data>)` when there is any (rfc:0069), `createRouter(<merged manifests>, { ctx, history: browserHistory() })`, `mount(router.App, #app, { ctx })`, and in dev builds (`import.meta.env.DEV`) posts `{ graph: inspect(), stores }` to `/__keel/inspect` after mount and then at most once a second on change. A `vite build` with a `node` `KEEL_DEPLOYABLE` builds only the resume entry and its islands into `dist/<name>/` (hashed `assets/`, manifest `CLIENT_MANIFEST` = `.vite/manifest.json` from `@keel/compiler/entry/CLIENT_MANIFEST`) and writes no `.keel/` (k.server Build, RFC 0048; `keel build` runs it per node deployable). Dev and preview servers serve `GET /__keel/inspect` (k.cli Inspect): `.keel/` ids, a11y, routes plus the last posted live half (`live: false` before one); POST JSON only; GET and POST answer only a loopback or listed `Host` with an absent, own, or listed `Origin` (extra origins from comma-separated `KEEL_INSPECT_ORIGINS`, `:*` any port; listed ones get CORS; others 403 `keel.denied`, RFC 0022). Build-time only: the plugin needs `esbuild` and the app must depend on `@keel/ui`, `@keel/router`, `@keel/ctx`, `@keel/runtime-dom`.
- **Output:** JSX lowers to `@keel/runtime-dom/ops`: one hoisted `template(html)` per element root, cloned once per render; each dynamic expression is exactly one `text`/`attr`/`prop`/`on` binding; `<Foo a={x}>kids</Foo>` is `Foo({ get a() { return x }, children: () => kids }, undefined, ctx)` where `ctx` is the enclosing component's third parameter (added when absent); `{props.children()}` / `{slots.x()}` are inserted as nodes. `If`/`For`/`Match`/`Boundary` lower to `cond`/`list`/`match`/`boundary` (`If` `fallback` is `cond`'s `otherwise`). A child expression holding elements (`{a ? <b/> : <i/>}`, an array, `map()`, a function) is E1403 and lowers to nothing (rfc:0061). Static style props on `@keel/ui` base elements become one `class` with ui's atomic names; dynamic ones stay props. A file exporting `uses` runs its default-export component in its own scope that declares them (`t.store.uses([t])`). Top-level `store`/`signal`/`computed`/`resource` are created in a module root scope; exported stores under `modules/<id>/` get `{ id: '<id>.<export>' }`. A `@keel/ui` base element with a literal `id`, as a JSX tag or a call `Button({ id: "cart.buy", … })`, is called as `stamp(id, Button)(props)`: when it is bound (`data-k`), its `data-k` becomes that id, the stamp k.errors `data.at` reads. TypeScript outside JSX is otherwise kept byte for byte. A `@keel/runtime-dom` import is removed only when every binding it imports is an intrinsic used solely as a JSX tag; an intrinsic called, passed as a value or named in a parameter or destructuring default (`If({ when, children })` in a plain `.ts` module) keeps it.
- **Artifacts:** `styles.json` `{ usages: [{ props: { <prop>: <token> }, breakpoint?, state? }] }` (one per literal token, dynamic `?:`/`&&` leaves included, deduplicated, sorted); `routes.json` per k.router; `ids.json`/`a11y.json` include `@keel/ui` base elements with a literal `id` (by the DOM tag they render).
- **Ids:** literal `id` kept, else `<path>.<ordinal>` over the file's DOM elements (`src.orders.OrderList.0`); written into the template.
- **Invariants:** `compile` is pure and deterministic (sorted keys, FNV-1a hash per artifact, no clock, no fs); static text and attributes are HTML-escaped at compile time; literal `javascript:`/`data:` URLs become `about:blank`.
- **Diagnostics:** E1001 E1002 E1003 E1004 (k.compiler), E1401 (unified-patch fix) E1402 E1403 (elements in a child expression bind nothing; `If` fix for `&&`/`?:` when `If` is imported; rfc:0061) E1404 (k.component; base-element ids count), E1501 for string paths in `href`/`src`/`action`/`formaction`, `Link to`, `Image src` (absolute URLs and `#x` allowed; E1003 wins), E1000 syntax error (pending spec line). Unknown tokens in `keel.css` are left out and warned (E1801 is `check`'s). E1002 resolves names through the rfc:0053 resolver, exported for `@keel/check` at `@keel/compiler/internal` (not app-facing); `script`/`style` take literal text and attributes only, and nothing binds into them (rfc:0058).
- **Dependencies:** oxc-parser, magic-string; runtime-dom, reactive, schema, store; esbuild (optional peer: `evaluate` and the Vite plugin). The generated code imports `@keel/reactive` and `@keel/runtime-dom/ops`; the generated entry and the build-time evaluator import router/ui/ctx (and the entry reactive/store) from the app.
- **Rungs:** conformance (example + probabilistic), property tests (determinism, ids, XSS, class-name parity with ui).
