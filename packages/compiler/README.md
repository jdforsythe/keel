# @keel/compiler

**Spec:** k.compiler + k.component (+ k.module `module()`) · **Status:** implemented · **verified:** (none)

## Contract

- **Public API:** `compile(files, { mode?, topology?, routes? })` -> `{ outputs, artifacts, hashes, diagnostics }`. `topology` (parsed `topology.ts`) exempts files of `client` deployables from E1004; `routes` is a precomputed `routes.json` (default `{}`). `module(def)` / `ModuleSchema` (k.module manifest: `ModuleSchema` includes the lowerCamel `id` rule; `module` validates, returns the frozen def unchanged, throws `code: 'keel.module'`). `@keel/compiler/tsconfig.strict.json`: the strict app profile (no `jsxImportSource`; JSX is lowered by the plugin). `@keel/compiler/testing` (dev-only; optional peer `esbuild`, DOM env): `evaluate(code)`. `routeLiterals(files, { topology?, root? })`: the literal route table of the manifests `vite build` evaluates, read with oxc and never run (`keel check` compares `routes.json` with it): ids, `path`, `layout`, `api`, action verbs, `params`/`search` presence and a guard's literal `redirect` (`null` for a guard declared without one); a spread `...x.routes` of the `routes` export of a package in the module's `deps` is read from the file the package's `exports` name, resolved from `<root>/modules/<m>/` (`root` defaults to `process.cwd()`). `@keel/compiler/routes` (build-time; peer `esbuild`): `buildRoutes(root)` evaluates them and writes `.keel/routes.json` with the plugin's writer (`keel build` when every deployable is `node`). `stdArtifact(files)` -> `{ data, hash, diagnostics }`: `.keel/std.json`, each app manifest's literal `std` by package and module id, E1158 for a bad entry (in `artifactHashes`). `@keel/compiler/std/*` (rfc:0066): `importDeps(root, files)` imports each `@keel/std-*` dep of the app manifests once (E1159), `readStd(text)`, `bindStd(ctx, data)` (`createApp` and a `client` entry), `bindClientStd(ctx, kStateText)` (the resume entry binds `#k-state`'s `std` before `resume`, rfc:0069), `clientStd(pkg)` (a package's config is client-readable; default server-only) and `clientStdData(data, modules)` (what a browser gets: `clientStd` packages, served modules), and the accessor `stdConfig(ctx, pkg, Config)` -> `{ [moduleId]: Config }`. RFC 0070: `std/importDeps` also imports a std package's `./tools` export (a throw is E1159); `std/clientStd(pkg, keys?)` sends only `keys` of each module's config to the browser.
- **Vite plugin** (`@keel/compiler/vite`, no options): compiles each changed module under the root (linked workspace packages are skipped), merges artifacts, writes `.keel/{a11y,deps,ids,routes,std,styles}.json` as read-only `{ data, hash }` atomically and only on change. Reads `topology.ts` statically at `configResolved`. At `buildStart` it compiles every app source (no tests) for style usages and evaluates `tokens.ts` and the deployable's `modules/<id>/routes.ts` once at build time (esbuild bundle from the app root, run in Node): `compileStyles` from `@keel/ui/css` -> the `virtual:keel.css` module (`/__keel.css`); `routesArtifact` from `@keel/router` -> `routes.json`. For a `client` deployable (`KEEL_DEPLOYABLE` or the first by name) it serves the generated entry **`/@keel/entry.ts`** (index.html: `<div id="app"></div><script type="module" src="/@keel/entry.ts"></script>`): imports `virtual:keel.css`, `createCtx({ mode: 'real' })`, `bindStd(ctx, <client-readable std.json data>)` when there is any (rfc:0069), `createRouter(<merged manifests>, { ctx, history: browserHistory() })`, `mount(router.App, #app, { ctx })`, and in dev builds (`import.meta.env.DEV`) posts `{ graph: inspect(), stores }` to `/__keel/inspect` after mount and then at most once a second on change. A `vite build` with a `client` `KEEL_DEPLOYABLE` keeps the project's Vite config and writes `dist/<name>/` (k.hosting Artifact): `index.html` (the project's, else a default one with `#app` and the entry), hashed `assets/` and `keel-mark.svg` (from `public/`, else the brand mark), every URL root-absolute; `index.html` gets one `<meta name="keel-peer" data-deployable="<name>" content="<origin>">` per `node` deployable whose `KEEL_PEER_<NAME>` is set (E1565 when it is not an http(s) origin), and the generated entry binds each module of the topology to its deployable's tagged origin, else the document's (k.hosting Peers); only the first `client` by name writes `.keel/`. A `vite build` with a `node` `KEEL_DEPLOYABLE` builds the resume entry and its islands into `dist/<name>/` (hashed `assets/`, manifest `CLIENT_MANIFEST` = `.vite/manifest.json` from `@keel/compiler/internal/entry/CLIENT_MANIFEST`), then `server.mjs` (Topology below), and writes no `.keel/` (`keel build` runs it per node deployable). Dev and preview servers serve `GET /__keel/inspect` (k.cli Inspect): `.keel/` ids, a11y, routes plus the last posted live half (`live: false` before one); POST JSON only; GET and POST answer only a loopback or listed `Host` with an absent, own, or listed `Origin` (extra origins from comma-separated `KEEL_INSPECT_ORIGINS`, `:*` any port; listed ones get CORS; others 403 `keel.denied`, RFC 0022). Build-time only: the plugin needs `esbuild` and the app must depend on `@keel/ui`, `@keel/router`, `@keel/ctx`, `@keel/runtime-dom`.
- **Topology** (k.topology): for a `node` `KEEL_DEPLOYABLE`, `vite build` builds the client entry into `dist/<name>/` and then, in the same Vite builder (`environments.ssr`, every dependency bundled, no code splitting), the generated production entry `virtual:keel/server` (`serverEntryCode`: `installServerDom` from `@keel/server/internal/dom` first, then dynamic imports of `topology.ts`, each module's `routes.ts` and `runners.server.ts`, and `start` from `@keel/server/internal/start` with `dir: import.meta.dirname`) into `dist/<name>/server.mjs` with an external `server.mjs.map` beside it (sources relative to the project, one outside it as `../`; no `sourcesContent`), then copies `.keel/routes.json` and `.keel/std.json` beside it, and copies in `dist/<client>/` of each `client` deployable whose `host` it is, without overwriting its own files, recording the client's `assets/` in its manifest under `keel:host` (k.hosting Host). `@keel/compiler/hosting/*`: `originOf(value)` (the origin of an http(s) origin with no path, else undefined), `peerOrigins(topology, env)` (`keel-peer` origins and the E1565 keys) and `hostProblems(topology)` (the E1566 problems), shared by `keel build`, `keel check` and `@keel/server`. A parsed topology carries a literal `host`. With a `node` deployable the dev server is `keel dev`'s one origin: `virtual:keel/dev` (`devEntryCode`, loaded through `ssrLoadModule`) creates one dev `createApp` per `node` deployable (real ctx, its runners, `.keel/` artifacts, the others as in-process peers); `devMiddleware` answers a request a `node` deployable's route (an API route included) matches through that app (streaming the body) and passes the rest to Vite; a changed app source closes the dev apps and the next request reloads them. With no `client` deployable, `/@keel/entry.ts` is the resume entry over every `node` deployable's islands. `pathCollisions(files, topology, root?)`: E1559 for a literal route path (params compared by position) in two deployables, at the second route, naming both. `serverOnlyCalls(files, topology)`: E1558 at each call, in a `modules/<m>/**/*.server.ts(x)` of a module a `client` or `static` deployable serves, of `loader` or `action` from `@keel/router` (named or through `import * as`) whose options name `stores`, whose loader `fn` is `async function*` (inline, or a top-level function or `const` of the file), or that it cannot read: options not an object literal, or with a spread or computed key; a spread argument; a loader `fn` neither inline nor a top-level function or `const` of the file. The message names the form it could not read (options not an object literal; options spread or computed; `fn` not a function of the file). An alias (`const l = loader`), a destructure from a namespace import (`const { loader } = r`), a `fn` that is not `async function*` but returns a generator, or a call made from another file is not read; `createApp` still throws E1558 for those holding server state.
- **Output:** JSX lowers to `@keel/runtime-dom/ops`: one hoisted `template(html)` per element root, cloned once per render; each dynamic expression is exactly one `text`/`attr`/`prop`/`on` binding; `<Foo a={x}>kids</Foo>` is `Foo({ get a() { return x }, children: () => kids }, undefined, ctx)` where `ctx` is the enclosing component's third parameter (added when absent); `{props.children()}` / `{slots.x()}` are inserted as nodes. `If`/`For`/`Match`/`Boundary` lower to `cond`/`list`/`match`/`boundary` (`If` `fallback` is `cond`'s `otherwise`). A child expression holding elements (`{a ? <b/> : <i/>}`, an array, `map()`, a function) is E1403 and lowers to nothing (rfc:0061). Static style props on `@keel/ui` base elements become one `class` with ui's atomic names; dynamic ones stay props. A file exporting `uses` runs its default-export component in its own scope that declares them (`t.store.uses([t])`). Top-level `store`/`signal`/`computed`/`resource` are created in a module root scope; exported stores under `modules/<id>/` get `{ id: '<id>.<export>' }`. A `@keel/ui` base element with a literal `id`, as a JSX tag or a call `Button({ id: "cart.buy", … })`, is called as `stamp(id, Button)(props)`: when it is bound (`data-k`), its `data-k` becomes that id, the stamp k.errors `data.at` reads. TypeScript outside JSX is otherwise kept byte for byte. A `@keel/runtime-dom` import is removed only when every binding it imports is an intrinsic used solely as a JSX tag; an intrinsic called, passed as a value or named in a parameter or destructuring default (`If({ when, children })` in a plain `.ts` module) keeps it.
- **Artifacts:** `styles.json` `{ usages: [{ props: { <prop>: <token> }, breakpoint?, state? }] }` (one per literal token, dynamic `?:`/`&&` leaves included, deduplicated, sorted), read from `@keel/ui` base elements, `Part` from `@keel/ui/aria`, and each part of the `styles` prop of a component imported from `@keel/std-headless` or `@keel/std-tables`; `state` is one of `selected`, `checked`, `expanded`, `highlighted`, `hover`, `focusVisible`, `active`, `disabled`; `routes.json` per k.router; `ids.json`/`a11y.json` include `@keel/ui` base elements with a literal `id` (by the DOM tag they render).
- **Ids:** literal `id` kept, else `<path>.<ordinal>` over the file's DOM elements (`src.orders.OrderList.0`); written into the template.
- **Invariants:** `compile` is pure and deterministic (sorted keys, FNV-1a hash per artifact, no clock, no fs); static text and attributes are HTML-escaped at compile time; literal `javascript:`/`data:` URLs become `about:blank`.
- **Diagnostics:** E1001 E1002 E1003 E1004 (k.compiler; a value import, re-export or literal `import()` of a `*.server.ts` module from client code), E1401 (unified-patch fix) E1402 E1403 (elements in a child expression bind nothing; `If` fix for `&&`/`?:` when `If` is imported; rfc:0061) E1404 (k.component; base-element ids count), E1501 for string paths in `href`/`src`/`action`/`formaction`, `Link to`, `Image src` (absolute URLs and `#x` allowed; E1003 wins), E1000 syntax error (pending spec line). Unknown tokens in `keel.css` are left out and warned (E1801 is `check`'s). E1002 resolves names through the rfc:0053 resolver, exported for `@keel/check` at `@keel/compiler/internal` (not app-facing); `script`/`style` take literal text and attributes only, and nothing binds into them (rfc:0058).
- **Dependencies:** oxc-parser, magic-string; runtime-dom, reactive, schema, store; esbuild (optional peer: `evaluate` and the Vite plugin). The generated code imports `@keel/reactive` and `@keel/runtime-dom/ops`; the generated entry and the build-time evaluator import router/ui/ctx (and the entry reactive/store) from the app.
- **Rungs:** conformance (example + probabilistic), property tests (determinism, ids, XSS, class-name parity with ui).
