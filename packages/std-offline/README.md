# @keel/std-offline

**Spec:** std.offline · **Status:** conformance-covered · **verified:** (none)

An outbox of writes made offline: each keeps its key and base, goes out in order on reconnect, and waits for the user when refused.

## Contract

- **Public API:**
  - `outbox(id, api, { module, limit = 100, maxBytes = 262144 })`, over the k.services `endpoints` map of module `module`'s routes, returns `Outbox<D>`: the reads and log of the client store `id` (`get`, `select`, `head`, `log`, `snapshot`, `restore`, …) with state `{ entries: OutboxEntry[] }`, changed only by `<id>.add`, `<id>.settle` and `<id>.resolve`. Inside a scope the store is created at once and the outbox stops flushing when that scope is disposed; at module level (no scope) it is created on first use and lives as long as the module, as a module-level `store` does. It throws E2651 (an Error with `code`) when an endpoint body holds an `s.secret`.
  - `Write` (schema and type) `{ key: s.id('Write'), base: s.int({ min: 0 }) }`: the `write` field of each endpoint body an outbox sends to. The action passes it to the store: `tx(t, payload, { meta, ...input.write })`.
  - `send(ctx, outbox, endpoint, input, { base, owner })`, `input` typed by the endpoint without `body.write`, `owner` the signed-in user's id or `""`, resolves `OutboxResult<O>`: `{ state: 'sent', value }`, `{ state: 'queued' }`, `{ state: 'conflict', head }` or `{ state: 'failed', error }` (an `ApiError`, `offline.full`, `offline.storage` when a write to `ctx.storage` rejected, or `offline.owner`).
  - `drain(ctx, outbox, { owner })`, inside a scope (E1203 outside one), loads the stored outbox, makes `owner` the ctx's owner, flushes, and flushes again on each `{ kind: 'net', online: true }` until the scope is disposed.
  - `resolve(ctx, outbox, key, 'mine' | 'theirs')` resolves `false`, changing nothing, for a key with no such entry. `'mine'` queues a `conflict` entry again, last, with `base` set to its `head`, flushes, and resolves that entry's `OutboxResult` as `send` does (`queued` when offline or the flush stops first; typed `false | OutboxResult<O>`, `O` the union of the api's outputs); `'theirs'` removes a `conflict` or `failed` entry and resolves `true` (`boolean`). A `Resolution`-typed argument resolves the union of both.
  - Schemas and types `OutboxEntry` (`{ key, endpoint, owner, input, base, at, state, head?, error? }`), `Resolution`; types `Outbox`, `OutboxResult`, `SendInput`.
  - `./tools` (node): rule E2651, an `outbox` whose endpoints map (inline, a `const` of the same file, or one imported from a project file) has an endpoint body holding `s.secret`. No fix.
- **Invariants:**
  - `send`, `drain` and `resolve` first load the outbox stored in `ctx.storage` `keel.outbox.<id>`, once per ctx, so a write made before `drain` keeps the stored entries. The load reads entry by entry and adds, in order, each stored entry the store lacks, a `sending` one as `queued`, while the entries stay within `limit` and `maxBytes`; the rest, and any value that is not an `OutboxEntry`, are not loaded, and the next write of the outbox drops them. A stored entry that holds an `origin`, or no string `owner`, loads `failed` with `offline.owner`, owner `""` and no `origin`, and the outbox is written back once.
  - Each entry holds the `owner` its `send` was given. `send` and `drain` make their `owner` the ctx's owner: every entry of another owner that is not `failed` becomes `failed` with `offline.owner` (`{ code, message: <outbox id>, data: {} }`), and the outbox is written to `ctx.storage` only when one did. A flush posts only `queued` entries of the ctx's owner; on a ctx no owner was given (a `'mine'` `resolve` alone) it posts nothing. An entry whose owner stops being the ctx's while it is in flight, and is not answered 2xx, is `failed` with `offline.owner`. A `failed` entry is never posted; `'theirs'` removes it.
  - `send` adds an entry with `body.write` `{ key: ctx.random.id('Write'), base }` and `at` from `ctx.clock`, writes `{ entries }` as JSON to `ctx.storage` `keel.outbox.<id>`, and flushes when online. An outbox holding `limit` entries, or whose encoded entries would pass `maxBytes`, refuses with `offline.full` and adds nothing. When the write to `ctx.storage` of `send` or of a `'mine'` `resolve` rejects, the entry is `failed` with `offline.storage` (in memory), nothing is posted, and the call resolves that `failed`. A flush already running does not post the entry until that write settles. An `offline.storage` error's message is the outbox id, never the text the storage threw, so a `Form` can show it.
  - One flush per outbox, one request in flight, entries in the order added, each through `service({ module, schema: api })` with its original key, read as `service({ module })` reads answers: a 2xx `{ ok: true, value }` gives `value` decoded by `output`, an error status the err's `error` decoded by `errors[status]`, and an endpoint that declares no 409 has its 409 read as JSON. On a ctx no `createApp` bound it posts to `http://<module>.keel.invalid` plus the path, and in a page to the document's origin. 2xx removes the entry. `api.network` (a 502 `keel.unreachable` among them) and `api.timeout` keep it `queued` and stop the flush until the next `send`, a reconnect while draining, or a retry 1 s later doubling to 60 s on `ctx.clock` while online. A 409 `keel.conflict` err naming `data.transaction` leaves it `conflict` with `data.head`, whether or not the endpoint declares a 409; another 409 is sent once more, then `failed`. Any other status is `failed` with its `ApiError`. The flush moves on after `conflict` and `failed`.
  - An entry naming no endpoint of the outbox's api (an own key of the map) is `failed` with `api.input`. A write to `ctx.storage` that rejects while flushing fails the entry in hand with `offline.storage` (in memory) and releases the flush, so later sends flush.
  - A resent entry keeps its key, so a write the server already committed commits nothing again while the store keeps that key: its last `logLimit` keyed writes.
  - Every effect goes through `ctx` (`clock`, `net`, `random`, `storage`) and `observe`, so one seed and one script of sends and connectivity changes give byte-equal outbox and server logs.
- **Dependencies:** `@keel/check` and `oxc-parser` (tools only), `@keel/ctx`, `@keel/reactive`, `@keel/schema`, `@keel/services`, `@keel/store`.
- **Rungs:** conformance (examples and properties, seed 1337) for sending online through the module's service, queueing offline, flush order, lost responses, 409s, resolve and its answer, a rejected storage write, a full outbox, backoff, owners, E2651 and determinism; properties for scripts of sends, connectivity changes and lost responses that apply every entry once, in order, and for stored mixes of owners, `origin`s and missing owners, of which a drain posts exactly its owner's entries.

## Extension points

Uses the **check rule registry** (k.check: E2651 from `./tools`).

## Unsafe

count: 1. `unsafe/asResult.ts`: a `sent` value is decoded by the output schema of the endpoint `send` named, so it takes that endpoint's output type.
