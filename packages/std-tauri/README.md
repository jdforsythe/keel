# @keel/std-tauri

**Spec:** std.shells, std.tauri, k.return · **Status:** proposed · **verified:** (none)

The storage and net drivers of an app packaged with Tauri for Linux, macOS and Windows.

## Contract

- **Public API:** `tauriDrivers({ origin: URL, connect?: readonly string[] }): { storage, net }`, `connect` the other exact origins `net` sends to (k.shell Origins; none when absent). A shell build's generated entry passes the result to `createCtx({ mode: 'shell', drivers })`; app code never imports it.
  - `@keel/std-tauri/tools`: registers the Tauri shell target with `shellTarget('tauri', target)` (`@keel/cli`) when `keel check` or `keel build` imports it for a `client` deployable declaring `tauri`; exports `crateName(pkg: string)` (the crate name of a `package.json` `name`) and `tauriHttpCapability(origin, connect?, identity?)` (the http permission for `origin`, when given, and each `connect` origin, with `identity` also the opener's for `origin`; undefined with nothing to allow). Files, under `deploy/<name>/tauri/`: `tauri.conf.json` (only with a policy: `identifier`, `productName`, `version`, `build.frontendDist` `www`, window `main` titled `name`, `app.security.csp` the policy with `ipc: http://ipc.localhost` in `connect-src`, `plugins["deep-link"].desktop.schemes` the one `id`, `plugins.http.scopeRedirects` `true`), `Cargo.toml` (`tauri`, `tauri-build`, `serde_json`, `tauri-plugin-store`, `tauri-plugin-http`, `tauri-plugin-deep-link` and `tauri-plugin-single-instance` at exact versions, `rust-version` 1.95; with an `identity.ts` also `tauri-plugin-opener`), `build.rs`, `src/main.rs`, `src/lib.rs` (the plugins; single-instance first), `capabilities/default.json` (`core:default`, `store:default`, `deep-link:default`; with an `identity.ts` also `opener:allow-open-url` for `https://*`). `Cargo.lock` is never generated. Plugins the app lists: none. Tools: `cargo` of Rust 1.95 (`CARGO_HOME`, `~/.cargo/bin`, `PATH`), WebKitGTK 4.1 through `pkg-config` on Linux, `@tauri-apps/cli` in `devDependencies`. Build: `capabilities/http.json` for `KEEL_ORIGIN` (none with no `node` deployable) and the `connect` origins only, and no such file, one an earlier build left removed, when there is nothing to allow, Keel's mark as `icons/icon.png` in the build folder when `deploy/<name>/tauri/` has none, then `tauri build --debug --no-bundle` with Cargo's `bin` first on `PATH`, a new `Cargo.lock` copied back. CI: one `tauri` job on `ubuntu-24.04` installing the WebKitGTK packages and uploading the debug binary.
  - `@keel/std-tauri/shellMount`: `shellMount(ctx, { id, origin: URL, mount })`, `mount` being the project's `identity.ts` default export (an `identityMount`), whose `path` and `links` its requests and return links are read against. The generated entry calls it before the router starts when the project has `identity.ts` (k.return). Navigations under the identity mount become mount requests through `ctx.net`; the external browser is the default browser (`@tauri-apps/plugin-opener` `openUrl`), opened on `origin` for a root-relative URL; the shell reports its launch to the router once, when `@tauri-apps/plugin-deep-link` `getCurrent` settles (k.links Launch: its URLs, `null` as no link, a rejection as a failed read), and listens for `onOpenUrl` after that report; the router's intake sorts each link on the scheme `id` by its path (k.links): a page navigates, a declared mount path sends one GET, any other mount path takes the pending opening (one link per opening, within 600000 ms, kept in `ctx.storage` `keel.return` across a relaunch). From a taken link until a person's act (a trusted pointer, touch or non-Escape key input), and before the launch report with no act, no page's mount request records an opening. The launch links are taken once: the first `onOpenUrl` that repeats them is dropped. The generated Tauri files hold the deep-link and single-instance crates and permission in every shell, the opener's only for a project with `identity.ts`.
- **Invariants:** `storage` keeps k.persist's contract on `@tauri-apps/plugin-store`, over two files in the app's data directory, `keel.json` and `keel.b.json`, each holding one whole copy of every key with its generation and a checksum. The first call loads both and takes the newer whole copy (`keel.json` on equal generations). A `set` or a `true` `commit` saves the next copy first to the file the copy was not read from, then to the other, before it resolves, so a value survives an app restart and a crash at any point of a save leaves a whole copy of the earlier or the new state. A file that is missing, cut short or fails its checksum is never read as an empty store: the other file's copy is read. Only a fresh install, or a crash inside the very first save (`keel.b.json` alone, cut short), starts empty; files holding no whole copy otherwise make every call reject with an error naming both files and are never overwritten. Calls run one at a time, so `read` is one cut and `commit` stores all of its values or none. A write that rejects rejects with the plugin's error, and the next call loads again from the files, so the driver reads what they hold. A failed load is tried again on the next call. A key twice in a `commit` rejects with E1606, whose message names no key.
- **Platform:** plugin-store's `save()` is `fs::write`, which truncates its file before writing it, and the plugin opens a file it cannot parse as an empty store; the driver reads each file through `reload`, whose error tells a missing file (`os error 2` or `3`) from one that does not parse, so the two-file save above is what keeps a crash from losing keys. A write costs two whole-file saves and no `fsync`: a SIGKILL leaves a whole copy, while a power loss inside the system's write-back window is not covered. `net.fetch` sends a request on the page's own scheme and host (`tauri://localhost`, read from `location`) to `origin` with its method, path, search, headers and body (with no `origin` it refuses one, with a `TypeError` and no native call), a request to `origin` or a `connect` origin as given, and refuses every other URL with a `TypeError` and no native call, through `@tauri-apps/plugin-http`'s `fetch`, which the build's capability allows for the same origins only. Every request is sent with `maxRedirections: 0`, so a 3xx resolves as it came, `location` included, its cookies kept by the Rust client's store; the driver follows: `redirect: 'manual'` resolves the 3xx, `'error'` rejects it, and `'follow'` sends each hop as one more request, at most 20, each held to the same origins (a 303 unless `HEAD`, and a 301 or 302 after a `POST`, continue as a bodiless `GET`; a hop to another origin drops `authorization`). `plugins.http.scopeRedirects` holds a direct call of the plugin that follows redirects to the capability's scope at each hop. The Rust client's cookie store (the plugin's default `cookies` feature) keeps every cookie, the caller cookie too, and sends each to its own origin only; no `set-cookie` header reaches the page. The plugin writes only cookies with an expiry to its file, so the caller cookie, which has none, lasts one run of the app. A failure rejects with a `TypeError` that names no URL, which k.services reports as `api.network`; an aborted request rejects with the signal's reason. The global `fetch` stays unpatched. `net.online()` reads `navigator.onLine`.
- **Dependencies:** `@keel/ctx`, `@keel/cli` (the `shellTarget` registration of `./tools`), `@tauri-apps/api`, `@tauri-apps/plugin-store`, `@tauri-apps/plugin-http`; for `shellMount` `@keel/router`, `@tauri-apps/plugin-deep-link` 2.6.3 and `@tauri-apps/plugin-opener` 2.7.3. A desktop scheme registers only from an installed bundle, so the `--no-bundle` artifact of `keel build --target tauri` receives no return link.
- **Rungs:** conformance (example + probabilistic, both plugins unmodified over Tauri's `mockIPC` under happy-dom), properties for storage against a model map, with injected save failures and a restart, for a save cut at every byte offset and for writes killed at random offsets (the read is always the earlier or the new state), and for the origin map, the origin list and the redirect follower (hops, method and body rules, the list at every hop).

## Extension points

Supplies the **storage and net drivers** (k.persist) a shell build's generated entry passes to `createCtx`, and the **shell target** (k.shell) of Tauri through `@keel/std-tauri/tools`.
