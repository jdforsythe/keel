# @keel/cli

**Spec:** k.cli, k.docs, k.review, k.escapes · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `run(argv, io: { cwd, files?, load?, apply?, stdin?, emit?, env?, tty?, fetch?, read?, build? })` -> `Promise<{ code, stdout, stderr }>`, the one engine for every surface (files given or loaded per operation scope; effects of a successful run to `apply`; `test` runs vitest on `io.cwd` when there are tests). `operations` (`{ name, description, input, output, positional, scope }`). `formatter(kind, { schema, compact, pretty })`. `mcp(provide)` / `lsp(provide)` -> `StdioServer` (one throw answers -32603, never stops the server). Binary `keel` (`dist/src/bin.js`) calls `run` with a host `Io` (stdio streaming for `mcp`/`lsp`; writes confined to the cwd); `dev` runs `vite` when `vite.config.ts` exists. `Io.refresh(cwd)` is that disk half up to the bundles (`routes.json` whatever the deployables are, then `surface.json`; no Vite build, no `csp.txt`, nothing under `dist/`): `scaffold` and `codemod` run `build` with it after an applied operation in a project holding a `.keel/` artifact (k.scaffold Refresh), and their trailer counts `artifacts`. `Io.build(cwd)` is the disk half of `build` after its writes, the one path of `keel build` and MCP `build` (absent: the engine's artifacts only): `routes.json` when every deployable is `node`, `surface.json`, then `vite build` with `NODE_ENV=production` (whatever the shell or a project `.env` sets, silently) per `viteTargets(topology.ts)`: the project's own (without a topology, or with a `static` deployable), then one per `client` deployable with `KEEL_DEPLOYABLE`, which writes `dist/<name>/` (k.hosting Artifact), then one per `static` deployable, which writes its documents, `404.html` and `csp.txt` into `dist/<name>/` (k.hosting Static; E1588 for a route that does not answer 200), then one per `node` deployable, which writes `dist/<name>/server.mjs` (the generated production entry, k.deploy Build) and copies in the build of each `client` that names it `servedBy`; `build` and `check` report E1559 for one route path in two deployables (`pathCollisions`), E1558 at each `loader` or `action` call naming `stores`, each live loader and each such call it cannot read in a `*.server.ts` of a module a `client` or `static` deployable serves (`serverOnlyCalls`), E1566 for a bad `servedBy` and, with a `client` deployable, E1565 for a `KEEL_PEER_<NAME>` that is not an http(s) origin (naming the key); `dev [--port N]` (binary, Vite) serves every deployable from one process on one origin (k.topology Local topology), on N (default 5173, `--strictPort`); a port that will not bind is one E1560 line, exit 1. `stdCommand(name, op: StdOperation)` fills a reserved command, `session` (std.sessions) or `report` (std.report): the binary and MCP serve it once filled, `keel session` and `keel report` import the project's std `deps` first, and an unfilled one is I1055, exit 0; `Io.fetch(url, init?)`. `shellTarget(shell: 'capacitor' | 'tauri', target: ShellTarget)` registers a shell target; the types `ShellTarget`, `ShellApp`, `ShellJob`, `ShellProbe`, `ShellBuild` and `Probe` describe it.
- **Invariants:** argv and MCP arguments share one input schema: unknown flag or bad value E1052, unknown command E1051, exit 2. Exit 1 on an E diagnostic or failing summary. `build` runs `check` first and stops on an error (E1005 aside: the build rewrites generated output), printing the check's records (k.boundary Build gate). `check` (every surface) and `build` first import each `@keel/std-*` package in an app manifest's `deps` (`importDeps`; E1159), so stdlib rules and config schemas register; `build` also writes `.keel/std.json`. `ledger --write` writes `hostElements` after `unsafe`: the `<Host>` elements and `Host(...)` calls of `@keel/ui`'s `Host` in `packages/<pkg>/{src,unsafe}`, `apps/<app>/**` and a root `modules/**`; `--diff` without `--scope` reports a rise as E1706 (k.host-element). Compact default when `!tty` or `KEEL_AGENT=1`. Cap 5 per code (`--limit`, `--verbose`), `--quiet` trailer only, `--code` filters display. No timing: equal input, equal bytes. scaffold/codemod (`@keel/scaffold`; `scaffold route <id> --path <p> [--api]`, `--api` for a route that answers JSON with no page; `codemod place <module> --to <deployable> [--adapter]` moves a module between deployables) and build (`@keel/compiler`, `.keel/` artifacts, and the deploy files of `topology.ts` from `@keel/scaffold` `deployDrift`, read-only, the CI workflow unless a directory above holds `pnpm-workspace.yaml`) return writes; `--dry-run` diffs equal the apply. `build` (through `Io.build`) also writes `.keel/surface.json` (k.compat Surface, `{ data, hash }`, read-only, `version: 2`): each app module's contract and `routes.ts`, and each placed stdlib module's `./contract` and `./routes`, evaluated through a Vite SSR server (app files compiled by `@keel/compiler`); `data` holds `contracts` (by module: `module`, `callers` from `contractCallers`, `entries` by API id with `method`, `path`, `params`, `query`, `body`, `output`, `errors`), `stores` (each store a bound handler's `stores` factory creates: state and transaction schemas) and `sources` (hash of each evaluated file); a contract file that throws is one E1006 diagnostic, writes no surface and exits 1. `build --target <shell> [--platform <p>] [--release]` (k.shell, `@keel/cli/shell`, loaded only then; `shell` is `capacitor` or `tauri`) first checks, before any work or write: a `client` deployable declaring the shell, and `--platform` one of the target's `platforms` (missing when it has some), else E1052; with a `node` deployable in the topology `KEEL_ORIGIN` an `https:` origin or `http:` on `localhost`, and with none `KEEL_ORIGIN` unset or empty (one E1574 naming the key, no value, either way); then each tool the target lists, one E1575 per missing or older one, `<tool> missing or too old: needs <need>`, and each plugin its `plugins` names that the app's `package.json` `dependencies` lack or hold at another version text, one E1572 with its fix (`keel check` reports those too, once per plugin). Then the plain build runs, then per deployable the shell entry's Vite build with `KEEL_DEPLOYABLE`, `KEEL_SHELL`, `KEEL_ORIGIN` (only with an origin; the target's `build` then gets no `origin` either) and `NODE_ENV=production` into `dist/<name>/<shell>/www/` (no `www/index.html` there is E1049), the `deploy/<name>/<shell>/` files beside it, and the target's `build` in that folder, given the build's `connect` origins (the `keel-peer` origins then the declared `origins.connect` ones, without `KEEL_ORIGIN`), the list the shell entry hands its drivers; a tool's error is cut to the lines from its first error line, at most 12. `--release` builds unsigned release artifacts. The trailer names each artifact: `ok build web tauri dist/web/tauri/target/debug/<crate>`. The cli holds no vendor knowledge: `keel check` and `keel build` import `@keel/std-<shell>/tools` for each shell a `client` deployable declares, or whose `deploy/<name>/<shell>/` folder holds a file while none does (so removing a shell removes its files), and that module calls `shellTarget`; a shell's name in other text or another path imports nothing. The target is held for the `./tools` file that registered it, so each project root reads its own in a process serving several (LSP, MCP). A package that cannot be imported is E1159, one registering a shell twice E1053, a shell with no target registered E1585, and so is a target `files` path with a `..` segment, a `\` or a leading `/`, that is a symlink, or whose nearest existing ancestor's real path is outside the shell folder; none of that set is written. `@keel/cli/shell` exports `shellPlan`, `shellBuild`, `hostShell` and `toolCommand`. `check --base <file>` reads a surface from the project or, outside it, through `io.read`, and passes it to `check` (E1562); absent, non-JSON or not a `version: 2` surface is one W1568 and no E1562. `check` reports E1005 for each generated Dockerfile, `deploy/compose.yaml`, shell file or CI workflow of a project that differs from its `topology.ts`, with the regenerated file as the fix (k.deploy, k.shell); a Tauri shell's `tauri.conf.json` holds `cspPolicy({ peers: [] })` of the project's `@keel/server/csp`. A removal also removes the directories it empties. `inspect [url]` fetches `<url>/__keel/inspect` via `io.fetch` (binary: global fetch; absent: I1055) and prints one `inspect.store` per store, one `inspect.section` per section (with the document's `deployables`, per deployable and section, carrying `deployable`) plus counts; unreachable, non-2xx or not a document: E1056. dev/render: I1055.
- **Evidence (k.evidence):** `evidence [--out <dir>] [--audit <file>]` runs `test`, `check` and `ledger` in process and writes `manifest.json`, `manifest.sig`, `check.ndjson`, `ledger.ndjson`, `a11y.json`, `security.json`, `pii.json` and `deps.json` to `<dir>` (default `evidence/<date>`, the UTC date of the ctx clock: a sim ctx under `KEEL_SEED`, so two runs give equal bytes). The manifest lists the six report files by sha256 and size and is signed with Ed25519 under `KEEL_EVIDENCE_KEY` (PKCS#8 PEM, read only from the environment; absent or not Ed25519: E1061, nothing written); `--audit` takes `pnpm audit --json` output (else E1064); no network request. Diagnostic lines in the bundle keep code and place, never message text. `pii.json` gives each sink the rung of its clause from the project's ledger when it holds that item, else the kernel ledger's rung `@keel/cli` ships (generated from `tooling/ledger/ledger.json`). A bundle with check errors or failed tests is still written, then E1060. `evidence --verify <dir> --key <keyId>` requires the published keyId: the manifest key's id and `keyId` must equal it and the signature must verify with that key, else E1063 (without `--key`, E1063: a key read from the bundle alone proves nothing), re-hashes the listed files, finds unlisted ones and parses each with its schema (E1062), and emits one `evidence` record, compact `ok evidence <dir> 6 files key <keyId>`. `@keel/cli/evidence` exports the schemas (`Manifest`, `CheckLine`, `LedgerLine`, `A11yReport`, `SecurityReport`, `PiiReport`, `DepsReport`, `EvidenceRecord`) and `evidenceCommand`, which the engine imports only when the command runs. `test` writes the harness's render checks to `reports/a11y.json`; `ledger` reads it with `.keel/routes.json` for its `a11y:<routeId>#<criterion>` items and writes them under the ledger file's `a11y` key. `build` writes `dist/<name>/csp.txt` for each `client` and `static` deployable (`cspPolicy({ peers })` of `@keel/server/csp`). MCP and argument JSON Schemas carry `x-keel-pii` on a `.pii()` node.
- **Review (k.review, k.escapes):** `review [paths] [<base>..<head> | --all] [--list] [--fail-on warn]` (`@keel/cli/review`, loaded only then) reads each project in scope (a folder whose `topology.ts` has a default export, not under `modules/`) and the git root's manifests, lockfiles, `.github/`, `.githooks/`, `patches/` and tracked `node_modules/`; a range from git objects (`ls-tree`, `cat-file --batch`, `diff -M`), `--all` (the default) from the working tree's tracked and untracked unignored files. One `review` record per finding, `path` relative to the git root, `id` the first 12 hex of SHA-256 over `<code>\n<path>\n<text>`; novelty by id within a code and path, nearest line for `changed`; loudness danger by novelty, an opt-in one step quieter; the baseline `keel-review.json` read at `<base>`. Compact prints `fail` and `warn` (`list` with `--list`), capped per code like diagnostics; json adds `list`, and `count` with `--list`; the trailer is `ok review 0 fail, 2 warn, 14 listed, 3 accepted`. Exit 1 on a `fail` (or a `warn` under `--fail-on warn`); E1067 to E1070 exit 2 with nothing else. `--accept <id> --reason <text>` adds one entry to the baseline its finding reads. No network; no project code runs.
- **Docs (k.docs):** `docs` prints `docs.entry` per section of the running cli's `docs/map.json` and of each installed package's `docs/index.json`, then per skill (`skills/<name>/SKILL.md`); `docs <id>` one section (`docs.section`, with package and version) or skill (`docs.skill`) verbatim; `docs --for <code>` a `docs.cite` per line citing the code in the installed sections whose index lists it; `docs --sync` the agent files (k.scaffold). A package is installed when `node_modules/@keel/<name>/package.json` resolves from the project root, else from the cli's folder, and names `@keel/<name>`; the binary loads the packages the project's and the cli's `package.json` name or the root's `node_modules/@keel/` holds (file scope `docs`). Under a directory holding `spec/00-map.md` (the Keel repo) it reads `spec/` and `packages/cli/skills/`. A package file whose real path leaves the package's real folder, or over 1,000,000 bytes, is not read. E1065 a section whose package is not installed, E1066 a missing packed file, E1052 an unknown id or two forms. Compact and pretty print a diagnostic's `see` as `see: keel docs <id>`. `scaffold project` (not `--workspace`) adds the agent files; a write a symlink would carry out of the project refuses the edit set (E1357); `check` reports W1356 where `AGENTS.md` holds the Keel block. `@keel/cli/docs` exports `docsCommand`, `agentWarnings` and `agentWrites`, loaded only by the commands that need them.

## Extension points

`shellTarget(shell, target)`: one target per shell, called from `@keel/std-<shell>/tools` (k.shell); a second call for a shell throws E1053. `formatter(kind, def)`: one formatter per record kind; a second registration (kernel kinds `diag`, `summary`, `req`, `a11y`, `evidence`, and k.ledger's `ledger` and `ledger.mutation` included) throws E1053. A record whose kind has no formatter, or that does not fit its schema, renders as E1054.
