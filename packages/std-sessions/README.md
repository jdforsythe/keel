# @keel/std-sessions

**Spec:** std.sessions · **Status:** implemented · **verified:** (none)

## Contract

- **Public API:** stdlib module `sessions` (`module.ts` at the package root; capabilities `clock`, `observe`, `session`, `storage`). Subpaths `./record`, `./replay`, `./minimize`, `./session`, `./Session`, `./redact`, `./tools`, `./commandJob`, `./routes`; the root (the browser budget) re-exports `record`, `replay`, `redact`, `session` and the schemas, not `minimize`, `redactSession` or the node subpaths.
  - `record(ctx, { limit = 500, upload? })` returns `{ events(), errors(), stop() }`, one per ctx. The base is the ctx's route when it starts, else its first `nav`. `tx` comes from each store's `log()`; `nav`, `fire`, `resource` and `error` come from `observe` (k.ctx). Past `limit` the buffer drops through its oldest `nav` and rebases there; with none buffered it rebases to now and keeps the appended input. With `upload`, the first error puts the session through `session(ctx)`. Without `document` it is a no-op. It registers inspect section `sessions.live`.
  - Redaction: each module's `redact` entries (`<subject>:<target>#<path>`, subjects `tx`, `store`, `route`, `el`, `error`) become their schema's generated value, seeded by the session seed and path. `el:` and `error:` values become `x` repeated. An `el:` entry masks every input value and one-character key of its element, and so does an element once reported masked (a password). `s.secret` fields always go, and `nav` hrefs are rebuilt from the redacted params and search. Every value an entry matched is masked again in later error messages and data, except `data.at`, which only an `error:` entry masks; other free text in errors is out of scope. `redact(schema, value, { paths, seed, salt, strings?, found? })` is the pure function. Path grammar: segments split on `.`; a bare `*` matches any one segment (an array index, a record key or an object field); `\.`, `\*` and `\\` are a literal `.`, `*` and `\` (so `store:a.b#headers.x\.trace` addresses the key `x.trace`). A recorder remembers the newest 256 distinct matched values to scrub from later errors.
  - `seed` is absent for a real or shell ctx (unseeded random), and `deterministic` is then false: a replay runs under seed 0 and may draw other ids.
  - Overflow with no `nav` buffered rebases to the oldest input but the first, at the state it saw; else to now, keeping the appended input or error, so an upload always names its error.
  - Bounds: past `limit` events or 192 KiB of session JSON the buffer cuts by the overflow rule until it fits; an event alone over 192 KiB leaves the session empty, rebased to now. `errors()` keeps the first and last 32. A rejected upload is recorded as a `sessions.putFailed` error (`data.status`). The real `put` sends `keepalive` only up to 64 KiB.
  - `./routes` (node, E2005): `sessions.ingest` (`POST /sessions`: a `Session` up to 256 KiB, else 413 `keel.payloadTooLarge`; invalid input 422 `keel.fields`) and `sessions.list` (`GET /sessions/list`, search `failing`, `since`) behind guard `sessions.reader` (caller hash in config `readers`, else 302 to `sessions.ingest`). Store `sessions.archive` (`archiveStores`, persisted through `ctx.storage`, no log): per fingerprint `count`, `first`, `last` (the ingest clock) and the newest 5 sessions in arrival order, each as `{ bytes, session }` (its encoded JSON length, measured once); at most 64 fingerprints and 4 MiB, the oldest `last` evicted (ties: the smaller key), never the one this write filed. Sizes come from the tracked `bytes`, so a write is linear in the number of sessions. The ingest recomputes `error` and `fingerprint` from the session's events, never keeps a posted value, and applies the 256 KiB bound to the session as filed; `sessions.list` returns the sessions without byte counts. `apps/sessions` runs it.
  - `minimize(session, { routes, maxRuns = 200 })` (subpath `./minimize`, not in the root): replay (not reproduced: `err` `sessions.notReproduced`), the shortest reproducing prefix of the inputs (`fire`, `nav`) by binary search, then ddmin (complements of n chunks, n from 2 doubling; at n = input count these are the single removals in index order) until no single removal reproduces (`minimal: true`) or `maxRuns` (`minimal: false`). Each candidate set is replayed once; the output keeps the base and merges the kept inputs with the observations of their final replay. Deterministic: two runs are equal.
  - `redactSession(session, { routes, expose })` writes every recorded string outside `expose`, and every error message, as `x` repeated (what `to-test` emits, D3).
  - `replay(session, { routes, redact? })` returns `{ observed, state, error, reproduced, unapplied }` under `createCtx({ mode: 'sim', seed })`. It seeds every live store: one the base `state` lacks starts at its snapshot `initial`, so a replay never reads what an earlier run left and `minimize` stays deterministic. `redact` (also on `minimize`) is the recording's entries, bound on the replay ctx so the replay recorder masks what the live one did; `keel session` passes the serving modules' `redact` literals.
  - Fingerprint: 12 hex of sha256 over the first `error` event's `code`, `data.at` as recorded (after redaction) and its `route` (the route id it fired under); with no error event, the base route id. The recorder, `replay`, `minimize` and `sessions.ingest` compute it from the session alone.
  - `session(ctx)`: `put(url, session)` (real POST, shell drop, sim kept in `taken()`) and `id()` from the capability's own ctx.
  - `Session` (`sessions.Session`), `SessionEvent`, `SessionsConfig` (`{ redact?, expose?, readers? }`; only `redact` reaches browsers).
  - `./tools` (node): check rules E2001 (`redact` or `expose` entry with an unknown subject, another module's target, or a path absent from its schema; fix removes it) and E2005 (a non-`node` deployable serves `@keel/std-sessions/routes`), the `session` record formatter, and the `session` command (`stdCommand`): `keel session capture [url]` (inspect section `sessions.live` to `.keel/sessions/<fingerprint>-<id>.json`; null writes nothing), `ingest <url> [--failing] [--since t]` (`GET <url>/sessions/list`, caller cookie from `KEEL_SESSIONS_TOKEN`, each session to `.keel/sessions/`; E1056 on failure), `replay <f>`, `minimize <f> [--max-runs n]` (rewrites `<f>`), `to-test <f>` (writes `modules/<m>/test/session-<fingerprint>.test.ts`, redacted by the route module's `expose`, after a replay of the redacted session reproduces). E2002 (schema), E2003 (input N from 0, or the base: no `topology.ts` deployable serves the route) and E2004 (fingerprint differs; nothing written) are diags at `<f>:1:1`. E2005 follows `export ... from`, `export *` and imports through other project files.
  - Job contract (D1): replay, minimize and to-test write `.keel/sessions/job-<pid>-<n>.test.ts` (it imports each serving module's `routes.ts` and calls `commandJob` from `./commandJob` with the session inline), run `keel test <job> --format=json` in process on the project (its vitest config, environment and `KEEL_TEST=1`), read `JobResult` from `<job>.result.json`, and remove both. The project's vitest `include` must match `.keel/sessions/*.test.ts` (the default does); with no result the test run's diagnostics come back and the summary fails.
- **Dependencies:** `@keel/check`, `@keel/cli` (tools only), `@keel/compiler`, `@keel/ctx`, `@keel/reactive`, `@keel/router`, `@keel/schema`, `@keel/store`, `@keel/testing`, `oxc-parser` (tools only).
- **Rungs:** conformance (examples and properties, seed 1337) for determinism, redaction, overflow, replay, the capability, the server no-op, E2001 and E2005; properties for `sha256`, `redact` and `redactSession`.

## Extension points

Uses **capabilities** (`session`), **inspector hooks** (`sessions.live`), the **rule registry** (E2001, E2005), the **formatter registry** (record kind `session`) and **std config** (`clientStd` with `keys`).
