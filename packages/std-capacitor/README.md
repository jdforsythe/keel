# @keel/std-capacitor

**Spec:** std.shells, k.return · **Status:** proposed · **verified:** (none)

The storage and net drivers of an app packaged with Capacitor for Android and iOS.

## Contract

- **Public API:** `capacitorDrivers({ origin: URL }): { storage, net }`. A shell build's generated entry passes the result to `createCtx({ mode: 'shell', drivers })`; app code never imports it.
  - `@keel/std-capacitor/shellMount`: `shellMount(ctx, { id, origin: URL })`, which the generated entry calls before the router starts when the project has `identity.ts` (k.return). Navigations under the identity mount become mount requests through `ctx.net`; the external browser is `@capacitor/browser` (Custom Tabs on Android, an in-app Safari view on iOS), opened on `origin` for a root-relative URL; a return link on the scheme `id` (`@capacitor/app`: `getLaunchUrl`, then each `appUrlOpen`) closes that browser and is read as a redirect. The launch link is taken once: the first `appUrlOpen` that repeats it is dropped.
  - `keel-capacitor-scheme <android|ios>` (bin; `returnScheme(file, id)` behind it): run by `keel build --target capacitor` in the build folder after `cap sync`. It registers `capacitor.config.json`'s `appId` as a URI scheme in the platform project: in `android/app/src/main/AndroidManifest.xml` one intent filter (`VIEW`, `DEFAULT`, `BROWSABLE`, `<data android:scheme="<id>"/>`) after the launcher's, in `ios/App/App/Info.plist` `CFBundleURLTypes` with that one scheme. A manifest that names the scheme, or a plist that holds `CFBundleURLTypes`, is left as it is. A platform project without that file is left as it is. It prints nothing; an unknown platform or a missing `appId` is one `error:` line and exit code 1.
- **Invariants:** `storage` keeps k.persist's contract on `@capacitor/preferences` (SharedPreferences, UserDefaults), so a value survives an app restart. Every key lives in one Preferences entry, `keel`: a JSON document of `[key, value]` pairs, read on the first call and cached, since one page owns the store. Calls run one at a time, so `read` is one cut, and a `set` or a `true` `commit` is one `Preferences.set` of the whole next document: when it rejects, the call rejects with the plugin's error and the cache keeps the document as it was, so `commit` stores all of its values or none. A key twice in a `commit` rejects with E1606, whose message names no key. A stored document that is not `[key, value]` string pairs makes every call reject with an `Error` whose message names no key or value.
- **Platform:** on Android one `Preferences.set` reaches the disk whole or not at all across a crash: SharedPreferences keeps the old file as a backup until the new one is written, and a SIGKILL of golden-1 at a write on an Android 16 emulator left the earlier or the new document, never a torn one; UserDefaults on iOS is not verified here. Capacitor's documentation calls Preferences storage for lightweight data, not a local database, and states no size limit; the document grows with the stored state and is rewritten whole on each write. `net.fetch` sends a request on the page's own scheme and host (`capacitor://localhost`, `https://localhost`, read from `location`) to `origin` with its method, path, search, headers and body, and any other request as given, through the package's one native plugin, `KeelHttp` (Android `HttpURLConnection`, iOS `URLSession` with the default configuration; shipped in `android/`, `ios/` and `Package.swift`, so `cap sync` installs it from the app's dependencies). Every request goes through it: the `Response` resolves when the headers arrive, and its body is a stream that yields each chunk as the server sends it, at most 16 KiB each, so a server-sent-events stream delivers its events as they come. An abort of the request's signal, or a cancel of the body's reader, cancels the native request and closes its connection. The native client uses the cookie store `CapacitorHttp` uses (Android's default `CookieHandler`, which Capacitor sets to `CapacitorCookieManager`; iOS `HTTPCookieStorage.shared`), which keeps every cookie, the caller cookie too, and sends each to its own origin only, whether or not the `CapacitorCookies` plugin is enabled (that flag only patches `document.cookie`, and is left off); no `set-cookie` header reaches the page. Capacitor removes session cookies when the app starts and stops, so the caller cookie, which has no expiry, lasts one run of the app. A request with `redirect: 'manual'` is not followed (Android `setInstanceFollowRedirects(false)`, iOS a task delegate that refuses the redirect): its 3xx resolves as it came, `location` included, its cookies kept by the native store. On iOS a response that sets a cookie resolves after `URLSession.flush` has written the cookie store to disk, so the cookie outlives a force-stop that follows at once. No native timeout is set on Android; iOS times a request out after 600 s without data. Android refuses `http:` requests unless the app allows cleartext traffic: `keel build --target capacitor --platform android` allows it to the `KEEL_ORIGIN` host and no other in a debug build whose origin is `http:`, and allows none for an `https:` origin or a `--release` build. A failure before the headers rejects with a `TypeError` that names no URL, which k.services reports as `api.network`; one after them errors the body stream with a `TypeError`; an aborted request rejects with the signal's reason. The global `fetch` stays unpatched. `net.online()` reads `navigator.onLine`.
- **Dependencies:** `@keel/ctx`, `@capacitor/core`, `@capacitor/preferences`; for `shellMount` `@keel/router`, `@capacitor/app` 8.1.2 and `@capacitor/browser` 8.0.5. `cap sync` installs a native plugin only from the app's own `dependencies`, so an app with `identity.ts` and a Capacitor shell lists `@capacitor/app` and `@capacitor/browser` there at those versions, beside `@capacitor/core`.
- **Rungs:** conformance (example + probabilistic, Capacitor's web Preferences and a stand-in `KeelHttp` under happy-dom), properties for storage against a model map, with injected write failures and a restart, for the origin map, and for the body stream (any split into chunks reads back the same bytes; no listener is left after an end, a failure or an abort); manual redirects against the stand-in; `shellMount` against stand-in plugins (the launch link once, later links all); `returnScheme` for generated ids and the bin on a temporary folder. Not verified on a device: that a return link reaches a cold-started and a running app, and that the in-app Safari view closes.

## Extension points

Supplies the **storage and net drivers** (k.persist) a shell build's generated entry passes to `createCtx`.
