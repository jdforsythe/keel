# @keel/std-capacitor

**Spec:** std.shells, std.capacitor, k.return · **Status:** proposed · **verified:** (none)

The storage and net drivers of an app packaged with Capacitor for Android and iOS.

## Contract

- **Public API:** `capacitorDrivers({ origin: URL, connect?: readonly string[] }): { storage, net }`, `connect` the other exact origins `net` sends to (k.shell Origins; none when absent). A shell build's generated entry passes the result to `createCtx({ mode: 'shell', drivers })`; app code never imports it.
  - `@keel/std-capacitor/shellMount`: `shellMount(ctx, { id, origin: URL, mount })`, `mount` being the project's `identity.ts` default export (an `identityMount`), whose `path` and `links` its requests and return links are read against. The generated entry calls it before the router starts when the project has `identity.ts` (k.return). Navigations under the identity mount become mount requests through `ctx.net`; the external browser is `@capacitor/browser` (Custom Tabs on Android, an in-app Safari view on iOS), opened on `origin` for a root-relative URL; the shell reports its launch to the router once, when `@capacitor/app` `getLaunchUrl` settles (k.links Launch: its URL, no URL as no link, a rejection as a failed read), and listens for `appUrlOpen` after that report; the router's intake sorts each link on the scheme `id` by its path (k.links): a page navigates, a declared mount path sends one GET, any other mount path takes the pending opening (one link per opening, within 600000 ms, kept in `ctx.storage` `keel.return` across a relaunch) and closes that browser. From a taken link until a person's act (a trusted pointer, touch or non-Escape key input), and before the launch report with no act, no page's mount request records an opening. The launch link is taken once: the first `appUrlOpen` that repeats it is dropped.
  - `@keel/std-capacitor/tools`: registers the Capacitor shell target, platforms `android` and `ios`, with `shellTarget('capacitor', target)` (`@keel/cli`) when `keel check` or `keel build` imports it for a `client` deployable declaring `capacitor`. File: `deploy/<name>/capacitor/capacitor.config.json` (`appId`, `appName`, `webDir` `www`). Plugins the app lists, each at the version this package pins: `@capacitor/preferences` (`storage`) and `@capacitor/app` (launch and return links) always, `@capacitor/browser` only with `identity.ts`; a missing or differing one is E1572 with its fix. Tools: JDK 21 (`java` or `JAVA_HOME`) with the Android SDK (`ANDROID_HOME` or `ANDROID_SDK_ROOT`, holding `platform-tools`), or macOS with Xcode 26; `@capacitor/cli` in `devDependencies`. Build: the app's `package.json` copied in, the `client` policy in `www/index.html` as a meta tag (without the directives a meta tag ignores), `plugins.KeelHttp.allow` (`KEEL_ORIGIN`, then the `connect` origins) added to the build folder's `capacitor.config.json`, `cap add` when the platform folder is missing, `cap sync`, the shell `id` registered as a URI scheme in the platform project (an Android intent filter with `VIEW`, `DEFAULT`, `BROWSABLE`; iOS `CFBundleURLTypes`; a project that already holds either is left as it is), Android's cleartext configuration before Gradle, then Gradle `assembleDebug` or `xcodebuild` for the simulator without signing. CI: an `android` job (`ubuntu-24.04`, JDK 21, uploads the debug APK) and an `ios` job (`macos-15`, Xcode 26, manual).
- **Invariants:** `storage` keeps k.persist's contract on `@capacitor/preferences` (SharedPreferences, UserDefaults), so a value survives an app restart. Every key lives in one Preferences entry, `keel`: a JSON document of `[key, value]` pairs, read on the first call and cached, since one page owns the store. Calls run one at a time, so `read` is one cut, and a `set` or a `true` `commit` is one `Preferences.set` of the whole next document: when it rejects, the call rejects with the plugin's error and the cache keeps the document as it was, so `commit` stores all of its values or none. A key twice in a `commit` rejects with E1606, whose message names no key. A stored document that is not `[key, value]` string pairs makes every call reject with an `Error` whose message names no key or value.
- **Platform:** on Android one `Preferences.set` reaches the disk whole or not at all across a crash: SharedPreferences keeps the old file as a backup until the new one is written, and a SIGKILL of golden-1 at a write on an Android 16 emulator left the earlier or the new document, never a torn one; UserDefaults on iOS is not verified here. Capacitor's documentation calls Preferences storage for lightweight data, not a local database, and states no size limit; the document grows with the stored state and is rewritten whole on each write. `net.fetch` sends a request on the page's own scheme and host (`capacitor://localhost`, `https://localhost`, read from `location`) to `origin` with its method, path, search, headers and body, a request to `origin` or a `connect` origin as given, and refuses every other URL with a `TypeError` and no native call, through the package's one native plugin, `KeelHttp` (Android `HttpURLConnection`, iOS `URLSession` with the default configuration; shipped in `android/`, `ios/` and `Package.swift`, so `cap sync` installs it from the app's dependencies). Every request goes through it: the `Response` resolves when the headers arrive, and its body is a stream that yields each chunk as the server sends it, at most 16 KiB each, so a server-sent-events stream delivers its events as they come. An abort of the request's signal, or a cancel of the body's reader, cancels the native request and closes its connection. The native client uses the cookie store `CapacitorHttp` uses (Android's default `CookieHandler`, which Capacitor sets to `CapacitorCookieManager`; iOS `HTTPCookieStorage.shared`), which keeps every cookie, the caller cookie too, and sends each to its own origin only, whether or not the `CapacitorCookies` plugin is enabled (that flag only patches `document.cookie`, and is left off); no `set-cookie` header reaches the page. Capacitor removes session cookies when the app starts and stops, so the caller cookie, which has no expiry, lasts one run of the app. `KeelHttp` follows no redirect (Android `setInstanceFollowRedirects(false)`, iOS a task delegate that refuses the redirect), so a 3xx resolves as it came, `location` included, its cookies kept by the native store; the driver follows: `redirect: 'manual'` resolves the 3xx, `'error'` rejects it, and `'follow'` sends each hop as one more native request, at most 20, each held to the same origins (a 303 unless `HEAD`, and a 301 or 302 after a `POST`, continue as a bodiless `GET`; a hop to another origin drops `authorization`). `KeelHttp` itself rejects a URL whose origin its `allow` configuration does not list, and every URL when there is none, before a connection opens, which binds script that calls the plugin directly. On iOS a response that sets a cookie resolves after `URLSession.flush` has written the cookie store to disk, so the cookie outlives a force-stop that follows at once. No native timeout is set on Android; iOS times a request out after 600 s without data. Android refuses `http:` requests unless the app allows cleartext traffic: `keel build --target capacitor --platform android` allows it to the `KEEL_ORIGIN` host and no other in a debug build whose origin is `http:`, and allows none for an `https:` origin or a `--release` build. A failure before the headers rejects with a `TypeError` that names no URL, which k.services reports as `api.network`; one after them errors the body stream with a `TypeError`; an aborted request rejects with the signal's reason. The global `fetch` stays unpatched. `net.online()` reads `navigator.onLine`.
- **Dependencies:** `@keel/ctx`, `@keel/cli` (the `shellTarget` registration of `./tools`), `@capacitor/core`, `@capacitor/preferences`; for `shellMount` `@keel/router`, `@capacitor/app` 8.1.2 and `@capacitor/browser` 8.0.5. `cap sync` installs a native plugin only from the app's own `dependencies`, so the app lists the target's plugins there at these versions, beside `@capacitor/core`.
- **Rungs:** conformance (example + probabilistic, Capacitor's web Preferences and a stand-in `KeelHttp` under happy-dom), properties for storage against a model map, with injected write failures and a restart, for the origin map, the origin list and the redirect follower (hops, method and body rules, the list at every hop), and for the body stream (any split into chunks reads back the same bytes; no listener is left after an end, a failure or an abort); manual and followed redirects against the stand-in; `shellMount` against stand-in plugins (the launch link once against a stored opening, no link without one, the browser closed only for an admitted link); `returnScheme` for generated ids. Not verified on a device: that `KeelHttp` refuses an unlisted origin called from script, that a return link reaches a cold-started and a running app, and that the in-app Safari view closes.

## Extension points

Supplies the **storage and net drivers** (k.persist) a shell build's generated entry passes to `createCtx`, and the **shell target** (k.shell) of Capacitor through `@keel/std-capacitor/tools`.
