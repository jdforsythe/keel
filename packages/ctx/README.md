# @keel/ctx

**Spec:** k.ctx, k.sync, k.sim · **Status:** implemented · **verified:** (none)

## Contract

- **Public API:** `createCtx({ mode?, seed?, drivers?, schedule? })` returns a frozen `Ctx`: `clock.now()`, `clock.after(ms, signal?)`, `random.float()`, `random.id(brand)` (a v4 uuid typed `Id<B>` from `@keel/schema`, parses with `s.id(brand)`; the only way to mint an id or token), `net.fetch(req)`, `net.online()`, `storage` (k.persist; async): `get(key)` (`null` when missing), `set(key, value)`, `read(keys)` (each key's value in the order asked, `null` when missing, one cut), `commit(writes)` (each write `{ key, expect, value? }`: when every key holds its `expect` each `value` is stored and it resolves `true`, else nothing is stored and it resolves `false`; a write without `value` is a condition; one key twice rejects with `code: 'E1606'`), `dispose()` (removes the window `online` and `offline` listeners a real or shell ctx's own net added, once; a repeat, a sim ctx and a `drivers` net do nothing; it stops nothing else and the ctx stays usable). `drivers: { storage?, net? }` gives a `real` or `shell` ctx each object as that capability; on a `sim` ctx it throws `Error` with `code: 'E1605'`. `mode: 'sim'` returns `SimCtx`: `clock.advance(ms)` (resolves due `after` waiters in deadline order, ties by registration, before returning), `clock.next()` (earliest pending `after` deadline, else `null`), `net.route(pattern, handler)`, `net.setOnline(online)`. `register(name, { real, shell, sim, plan? })`, `capabilities()`. Schemas `Schedule` and `NetStep` (k.sim): `schedule` (sim only) is `{ net, storage, offline, plans }`; the n-th fetch takes `net[n]` when made, waits its `delay` on the sim clock, then `none` runs the route, `drop` rejects with a `TypeError` and runs nothing, `lost` runs the route and rejects with a `TypeError`, `unavailable` resolves a 503 and runs nothing; the n-th `get`, `set`, `read` or `commit` takes `storage[n]` (`fail` rejects with an `Error`, a failed `set` or `commit` stores nothing); each `offline` window `{ at, ms }` sets the net offline at clock `at` and online at `at + ms` (a `net` event each); past the end of a list a call takes no delay and no fault. A schedule on a real or shell ctx, one failing `Schedule`, or a plan step failing its capability's `plan` schema (at that capability's first access on the ctx) throws `Error` with `code: 'E1604'`. Types: `Ctx`, `SimCtx`, `Capability<T>`, `CtxOptions`, `Drivers`, `StorageWrite`, `Mode`, `Clock`, `SimClock`, `Random`, `Net`, `SimNet`, `RouteHandler`, `KeyValueStorage`. `observe(ctx, fn) -> stop` (events `nav`, `fire`, `resource`, `error`, `save` `{ store, head, from }` (`from`: the head before the save, 0 when none was saved), `net` `{ online }`; types `CtxEvent`, `FireEvent`) and `seedOf(ctx)`; kernel producers use `@keel/ctx/internal` (`report`, `observed`, `quiet`). `observe` is a capability, declared as `observe` in a module's `capabilities` and enforced statically by E1156 (a ctx has no module identity, so the runtime does not gate it); `resume` reports the served route as the first `nav` (params and search encoded, `schemas` `{}`). A new observer first gets the current `nav`, then the `error` events reported since it (the first 16, kept even when nothing observes; a `nav` clears them), each replayed with `at`, `clock.now()` when it was reported (a live event has no `at`), so an observer started late still sees a first-load error and when it happened; `save` and `net` are never replayed.
- **Invariants:** mode defaults to `sim` when `KEEL_TEST=1`, else `real`; seed defaults to 0, coerced to uint32. Sim: clock starts at 0, `advance` and `after` reject negative or non-finite ms (RangeError); an aborted `after` rejects with `signal.reason`; real `after` is `setTimeout` clamped to 2^31-1, cleared on abort; random is xoshiro128** seeded via splitmix32, same seed same sequence; net is an in-memory route table (exact URL, or prefix ending `*`; first match wins; else 404), online until `setOnline(false)`: offline, `fetch` rejects with a `TypeError` and every body a route returned that is still open errors; each change of `online()` reports one `net` event; storage is an in-memory map per ctx; a `read` or `commit` runs whole after its schedule step, so concurrent calls apply in a serial order. Every capability object is fresh per ctx. `shell` delegates to `real` until native adapters exist. Real and shell `online()` is `navigator.onLine` where a global `navigator` exists, else true; the window's `online` and `offline` events report a `net` event when it changed, until `dispose()`; a page or test that creates real ctxs repeatedly in one window calls `dispose()` on each when done. Real and shell `storage` and `net` are the `drivers` given, else the platform `localStorage` (which rejects where absent with a message naming `--experimental-webstorage --localstorage-file=<path>` and `drivers`) and `fetch`; a `localStorage` `commit` whose write throws midway (a full quota) puts back each key it wrote, newest first, and rejects with that first error, so it stores all its writes or none. `@keel/ctx/node` exports `fileStorage(path)`: a storage driver in one JSON file, for development and single-process use, read on first use (a missing file is empty; any other read error or contents that are not a JSON object of strings reject every call, naming the file and never its contents, and nothing is written) and rewritten whole (temporary file and rename) on each `set` and each `commit` that stores a value, its new contents current only once written; `keel dev` gives each `node` deployable `drivers: { storage: fileStorage('.keel-dev/<name>.storage.json') }`.
- **Dependencies:** `@keel/schema` (the `Schedule` schema).
- **Rungs:** conformance (example + probabilistic), properties for PRNG and sim clock.

## Extension points

**Capability registry.** `register(name, { real, shell, sim, plan? })` where each factory is `({ seed }) => Impl` and runs once per ctx; with `plan` (the schema of one plan step), the sim factory gets `{ seed, plan }`, `plan` being the schedule's `plans[name]` parsed step by step (default `[]`); `register<T, P>` types the steps as `P`. `register` returns a typed accessor `(ctx) => Impl`, the only way to reach the capability (it is not attached as `ctx[name]`). Each factory's `seed` is derived from the ctx seed and the name, so streams do not correlate. Registering the same name again with the identical implementations object (reference equality) is idempotent and returns the same accessor (HMR safe); a different object, or a kernel name, throws `Error` with `code: 'E1602'`. The registry is process-wide.
