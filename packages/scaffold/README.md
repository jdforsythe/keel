# @keel/scaffold

**Spec:** k.scaffold · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `scaffold(op, input, files)` -> `Result<Edit, ScaffoldError>`; pure, so it is also the dry run (`plan` removed, RFC 0045). `files: ReadonlyMap<path, content>`; `Edit = { files, created, changed, removed }` (sorted paths). `Op`: `project {name, adapter?, workspace?}` · `module {id}` · `route {id, path, file?, api?}` · `component {id: "mod/Name"}` · `store {id: "mod.name"}` · `transaction {id: "mod.store.name"}` (store must exist) · `service {id: "mod", schema, service}` (places the `@keel/services/openapi` sources at `<Mod>Api.schema.ts`/`api.server.ts`, rfc:0039; the cli converts `--openapi`) · `rename {kind: component|store|route|schema|module, from, to}` · `move {name, to}` · `place {module, to, adapter?}` · `add-field {schema, field, type, default?}`. `deployFiles(topology, { ci })` -> path -> text: `deploy/<name>/Dockerfile` per `node` deployable, `deploy/compose.yaml` when there is one, `.github/workflows/ci.yml` when `ci` (k.topology Deploy files). `deployDrift(files, always?)` -> `{ path, want, have }[]`: the generated deploy files of a tree that differ from `deployFiles` of its `topology.ts`; `keel check` reports them (E1005), `keel build` and `tooling/generate.mjs` write them.
- **Invariants:** pure; never mutates `files`; byte-identical output for equal input. All or nothing: a refusal is `KeelError<'scaffold.rejected', diag>`: E1351 duplicate, E1352 naming, E1353 would break check, E1354 required field without default, E1005 generated location or a change to a file whose first line is a generated marker (`// _generated`, `// Generated`, `# _generated`; a relocation with equal bytes is allowed), E1052 bad input or target, E1051 unknown op. E1353 proxy: new TS2307 (unresolved relative import), E1151, E1152, E1153. Codemods are AST-aware (oxc, magic-string): data keys never change (shorthand expands to `key: new`); strings change only as whole segments of an id shape (dotted id, element id). `project`, `module`, `rename module` and `place` write `turbo.json` (module set changes only), the CI workflow and the deploy files; deploy files are kept in a tree with `turbo.json` or a `deploy/` file, the CI workflow in a tree that has one. `place` inserts modules and new deployables in sorted position and removes a deployable it empties, so placing a module back restores a sorted `topology.ts` byte for byte; a new deployable needs `adapter` (E1052), an existing one keeps its own (a different `adapter` is E1052), a module in no deployable is E1052, a deployable name that is not lowerCamel E1352.
- **Dependencies:** `@keel/schema`, `oxc-parser`, `magic-string`.
- **Rungs:** conformance; properties: rename round trip per kind, bare string prefixes survive, determinism, edit set = tree difference, check proxy, import-path helpers, deploy files independent of topology order, drift names exactly a changed file, `place` sequences undone in reverse restore the tree.

## Emitted shape

Code is biome-clean for the repo config, and every generated tree passes the real `keel check` and `keel test` (conformance runs the binary, RFC 0036). `vite.config.ts` sets `test.environment: "happy-dom"`. A route `<mod>.<leaf>` gets `load<Leaf>.server.ts` exporting `load<Leaf>`; `route {api: true}` (`--api`) writes an API entry (`api: true`, `path`, `loader`; k.api), no page component, and a test that requests the path of `createApp` over a sim ctx (the module must sit on a `node` deployable, E1511), and refuses `file`; `id`/`*Id` params are `s.id("<Entity>")`. `project {workspace: true}` targets an app inside the monorepo: `index.html`, `vitest.config.ts`, `workspace:*` deps, only check/test/build scripts, no turbo/CI; tests go under `test/`. `rename module` moves the folder and rewrites ids, topology and manifests. `topology.ts` holds one deployable per line, module lists sorted.

Generated deploy files (each starts with a `_generated` line; read-only): a `node` deployable's Dockerfile is `FROM node:22-slim@sha256:5ec23b7c622b00547753bc6ffd78085dd868a68aeb41c8e0a1418f033e13d96d`, copies `dist/<name>/` only, prepares `/data` for user `node`, declares volume `/data` and port 8080, and runs `server.mjs` with `--experimental-webstorage --localstorage-file=/data/storage`. `compose.yaml` holds one service and one volume per `node` deployable on host ports from 8080, `KEEL_PEER_<NAME>: http://<name>:8080` for each peer, and `KEEL_ORIGIN`/`KEEL_SECRET` from the environment (`${KEEL_SECRET:?}`). The CI workflow has a `keel-paths` job that marks each deployable whose modules or shared files (`package.json`, `pnpm-lock.yaml`, `topology.ts`, `tokens.ts`, `vite.config.ts`) a pull request changes, and a job per deployable (a host's also runs on the modules of the `client` deployables it hosts) with SHA-pinned actions: install, `keel check --base` the base branch's `.keel/surface.json` (without `--base` when it has none), `keel test`, `keel build`, then `docker build` (never pushed) for `node` or an uploaded `dist/<name>` for `client` and `static`.
