# @keel/scaffold

**Spec:** k.scaffold · **Status:** conformance-covered · **verified:** (none)

## Contract

- **Public API:** `scaffold(op, input, files)` -> `Result<Edit, ScaffoldError>`; pure, so it is also the dry run. `files: ReadonlyMap<path, content>`; `Edit = { files, created, changed, removed }` (sorted paths). `Op`: `project {name, adapter?, workspace?}` · `module {id}` · `route {id, path, file?, api?}` · `component {id: "mod/Name"}` · `store {id: "mod.name"}` · `transaction {id: "mod.store.name"}` (store must exist) · `service {id: "mod", schema, service}` (places the `@keel/services/openapi` sources at `<Mod>Api.schema.ts`/`api.server.ts`; the cli converts `--openapi`) · `rename {kind: component|store|route|schema|module, from, to}` · `move {name, to}` · `place {module, to, adapter?}` · `add-field {schema, field, type, default?}`. `deployFiles(topology, { ci, version?, crate?, policy? })` -> path -> text: `deploy/<name>/Dockerfile` per `node` deployable, `deploy/compose.yaml` when there is one, the shell files of each `client` deployable's `shells`, `.github/workflows/ci.yml` when `ci` (k.deploy Deploy files, k.shell Files). `deployDrift(files, always?, policy?)` -> `{ path, want, have }[]`: the generated deploy files of a tree that differ from `deployFiles` of its `topology.ts` (version and crate name from its `package.json`); `keel check` reports them (E1005), `keel build` and `tooling/generate.mjs` write them. `tauri.conf.json` is checked and written only with `policy`, a `client` document's content security policy. `tauriHttpCapability(origin)` is the http permission a Tauri shell build writes for `KEEL_ORIGIN`.
- **Invariants:** pure; never mutates `files`; byte-identical output for equal input. All or nothing: a refusal is `KeelError<'scaffold.rejected', diag>`: E1351 duplicate, E1352 naming, E1353 would break check, E1354 required field without default, E1005 generated location or a change to a file whose first line is a generated marker (`// _generated`, `// Generated`, `# _generated`; a relocation with equal bytes is allowed), E1052 bad input or target, E1051 unknown op. E1353 proxy: new TS2307 (unresolved relative import), E1151, E1152, E1153. Codemods are AST-aware (oxc, magic-string): data keys never change (shorthand expands to `key: new`); strings change only as whole segments of an id shape (dotted id, element id). `project`, `module`, `rename module` and `place` write `turbo.json` (module set changes only), the CI workflow and the deploy files; deploy files are kept in a tree with `turbo.json` or a `deploy/` file, the CI workflow in a tree that has one. `place` inserts modules and new deployables in sorted position and removes a deployable it empties, so placing a module back restores a sorted `topology.ts` byte for byte; a new deployable needs `adapter` (E1052), an existing one keeps its own (a different `adapter` is E1052), a module in no deployable is E1052, a deployable name that is not lowerCamel E1352.
- **Dependencies:** `@keel/schema`, `oxc-parser`, `magic-string`.
- **Rungs:** conformance; properties: rename round trip per kind, bare string prefixes survive, determinism, edit set = tree difference, check proxy, import-path helpers, deploy files independent of topology order, drift names exactly a changed file, `place` sequences undone in reverse restore the tree.

## Emitted shape

Code is biome-clean for the repo config, and every generated tree passes the real `keel check` and `keel test` (conformance runs the binary). `vite.config.ts` sets `test.environment: "happy-dom"`. A route `<mod>.<leaf>` gets `load<Leaf>.server.ts` exporting `load<Leaf>`; `route {api: true}` (`--api`) writes an API entry (`api: true`, `path`, `loader`; k.api), no page component, and a test that requests the path of `createApp` over a sim ctx (the module must sit on a `node` deployable, E1511), and refuses `file`; `id`/`*Id` params are `s.id("<Entity>")`. `project {workspace: true}` targets an app inside the monorepo: `index.html`, `vitest.config.ts`, `workspace:*` deps, only check/test/build scripts, no turbo/CI; tests go under `test/`. `rename module` moves the folder and rewrites ids, topology and manifests. `topology.ts` holds one deployable per line, module lists sorted.

Generated deploy files (each starts with a `_generated` line; read-only): a `node` deployable's Dockerfile is `FROM node:22-slim@sha256:5ec23b7c622b00547753bc6ffd78085dd868a68aeb41c8e0a1418f033e13d96d`, copies `dist/<name>/` only, prepares `/data` for user `node`, declares port 8080 and, per `storage`: `'file'` (default) prepares and declares volume `/data` for user `node` and runs `server.mjs` with `--experimental-webstorage --localstorage-file=/data/storage`; `'sqlite'` keeps the volume and drops the flags; `'postgres'` has no volume. `compose.yaml` holds one service per `node` deployable on host ports from 8080 and a volume per one with a volume, `KEEL_PEER_<NAME>: http://<name>:8080` for each peer, and `KEEL_ORIGIN`/`KEEL_SECRET` from the environment (`${KEEL_SECRET:?}`); `KEEL_DATABASE_URL` is required from the environment for `'postgres'` and passed through when set for `'sqlite'`, never written. Shell files: `deploy/<name>/capacitor/capacitor.config.json` (`appId`, `appName`, `webDir` `www`); `deploy/<name>/tauri/` `tauri.conf.json` (`productName`, `version`, `identifier`, `build.frontendDist` `www`, window `main` titled `name`, `app.security.csp` the policy with `ipc: http://ipc.localhost` in `connect-src`, `plugins["deep-link"].desktop.schemes` the one `id`, the scheme of the shell's return links, k.return), `Cargo.toml` (`tauri` =2.12.5, `tauri-build` =2.7.4, `tauri-plugin-store` =2.5.1, `tauri-plugin-http` =2.9.0, `rust-version` 1.95), `build.rs`, `src/main.rs`, `src/lib.rs` (the store and http plugins) and `capabilities/default.json` (`core:default`, `store:default`); for a project with `identity.ts` (k.return) `Cargo.toml` also holds `tauri-plugin-deep-link` =2.6.3, `tauri-plugin-opener` =2.7.3 and `tauri-plugin-single-instance` =2.5.5 (feature `deep-link`), `src/lib.rs` registers them (single-instance first, so a second launch hands its link to the running app), and the capability adds `deep-link:default` and `opener:allow-open-url` for `https://*`; `tauriHttpCapability(origin, identity)` then also lets the default browser open `origin`. `Cargo.lock` is never generated or removed. The CI workflow has a `keel-paths` job that marks each deployable whose modules or shared files (`package.json`, `pnpm-lock.yaml`, `topology.ts`, `tokens.ts`, `vite.config.ts`) a pull request changes, and a job per deployable (a host's also runs on the modules of the `client` deployables it hosts) with SHA-pinned actions: install, `keel check --base` the base branch's `.keel/surface.json` (without `--base` when it has none), `keel test`, `keel build`, then `docker build` (never pushed) for `node` or an uploaded `dist/<name>` for `client` and `static`. A `client` deployable's shells add jobs on its paths with `KEEL_ORIGIN` from the repository variable: `<name>-tauri` on `ubuntu-24.04` (WebKitGTK packages, uploads the debug binary), `<name>-android` on `ubuntu-24.04` with JDK 21 (uploads the debug APK), and `<name>-ios` on `macos-15` on `workflow_dispatch` only.
