# std.sessions-served: Served-page sessions
status: conformance-covered
`replay`, `minimize` and `to-test` (std.sessions) of a session whose base is a page a `node` deployable serves.

**Served pages.** With `serve(ctx)`, a function resolving a `createApp` result made on `ctx`, the base is a page a `node` deployable serves: `replay` makes the sim ctx, advances it to `at`, calls `serve(ctx)` once, and renders the base with `renderRoute(route.id, { routes, params, search, ctx, app, user })` (k.testing; `user` left out when absent), so guards, loaders and actions run in the app over `ctx.storage`, which starts empty. `state` is not applied: each store starts as the served document resumes it. A page of a `node` deployable never learns its user, so a guarded base needs `user`. A base that resumes as another route than `route.id` (a guard's redirect) is not applied: E2003 `base route <id> redirected to <other id>`, `unapplied` `-1`; such a base is never reproduced, whatever the session recorded, since the replay's own E2003 is its first error and its fingerprint differs even from a session that recorded none. App and page share the ctx's clock and random (k.mount Testing): `serve` gets the ctx with its clock at `at` and its random stream unread, both then draw from that stream, so two replays under one `seed` draw the same values and are equal; where the stream stands after a replay is not part of the result. The server's data comes only from the recorded inputs replayed through the app (a submit runs its action), never from `state`. The server state, loader answers and user of the recorded run are not in the session: a session whose error needs them does not reproduce (E2004).

**to-test.**
- For a `node` deployable the file is `test/session-<fingerprint>.test.ts` in the project folder, where the project's hand-written `app` tests live: a file outside every module, so not client-reachable (k.boundary Reach), and it may import server-only files. It builds the app in the test body as `serve` does, after the clock advance and before `record`, importing `../topology.ts`, each placed module's routes (`../modules/<id>/routes.ts`, or its package's `./routes`; several joined with `routeTable` in `topology.ts` order), each nav's contract from `../modules/<id>/<id>.contract.ts`, and `../identity.server.ts` when there is one, and renders `renderRoute(<id>, { routes, params, search, ctx, app })`. It passes `app`, so `keel check` reports no W1723 on it (k.testing), and no `state`, so it holds no recorded store value.

**Conformance.**
- For a session whose `route.id` a `node` deployable `api` serves, the `to-test` file calls `createApp` with `deployable: "api"`, passes that result as `app` to `renderRoute` and passes no `state`; it is written to `test/session-<fingerprint>.test.ts` beside `topology.ts`; with an `identity.server.ts` in the fixture it imports it, and `keel check` on it reports no W1723 and no E1004; it fails under `keel test` on the buggy fixture and passes once the fix is applied. For a session of a `client` deployable's page the file passes `state` and no `app`.
- `replay` with `serve` of an unmodified session recorded under `renderRoute` with `app` calls `serve` once and returns `reproduced: true`, `unapplied: null`, and every store's final state equal to the recording's.
- With `serve`, a session whose base page's guard admits only user `u1` and redirects anyone else to page `a.signin`: `replay` without `user` returns `unapplied: -1` and `reproduced: false`, and `keel session replay` reports E2003 `base route <id> redirected to a.signin`; with `user: 'u1'` it returns `reproduced: true`, and `to-test --user u1` writes a file whose `renderRoute` options hold `user: "u1"`.
