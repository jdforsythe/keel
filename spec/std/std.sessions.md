# std.sessions: Sessions
status: implemented

**Module.** `@keel/std-sessions` is stdlib module `sessions` (capabilities `clock`, `observe`, `session`, `storage`). Modules set `std['@keel/std-sessions']: { redact?, expose?, readers? }`; browsers get only `redact`.
An entry is `<subject>:<target>#<path>`: `tx:` transaction (payload), `store:` id (state), `route:` id (`params.*`, `search.*`), `el:` element (its values in every event), `error:` code (`data.*`). `record` keeps every value but `redact` entries and `.pii()` values, which become their schema's generated value (`el:`, `error:`: `x` repeated). `s.secret` values (also in `nav` search) and password inputs are always redacted; error messages and `data` (not `data.at`) drop redacted values. `to-test` writes each `s.string()` no `expose` entry names as `x` repeated.

**API.** Capability `session(ctx)`: `put(url, s): Promise<Result<null, KeelError>>` (real: POST, non-2xx `sessions.putFailed`; sim: in `taken(): { url, session }[]`) and `id()`: `random.id('Session')` on its ctx. `record(ctx, { limit = 500, upload?: URL })` returns `{ events(), errors(), stop(): Session }`, one per ctx until `stop()`; `upload` puts it on the first `error`.
```ts
type SessionEvent = { at: number } & ({ kind: 'tx'; store; name; payload } | { kind: 'nav'; href }
  | { kind: 'resource'; id; state: 'loading' | 'ready' | 'error' } | { kind: 'fire'; id; event: TestEvent } | { kind: 'error'; route; error: KeelError } | { kind: 'net'; online })
type Session = { v: 1; id: Id<'Session'>; seed?; deterministic; at; route: { id; params; search }; state: { [store]: JsonValue }; events: SessionEvent[]; error: KeelError | null; fingerprint }
```
`id` matches `^[A-Za-z0-9_-]{1,64}$` (a `random.id` UUID does) wherever a `Session` parses, nested ones included: a session file failing it is E2002, a `sessions.ingest` body 422. The base (`at`, `route`, `state`) is the ctx's route at `record`, else its first `nav`. `seed` is `seedOf(ctx)`, absent (`deterministic` false) when unseeded. `fingerprint`: 12 hex of sha256(`code`, `data.at`, route id) of the first `error` as recorded (none: `''`, `''`, `route.id`). Past `limit` the buffer drops through its oldest `nav`, rebasing there (none: keeps a new input or error, rebases now).

`replay(session, { routes, redact?, serve?, user? })` (`./replay`; the root imports no harness) renders the base (missing stores: `initial`) under a sim ctx of `seed` (absent: 0) at `at`, with the recording's `redact`, then per event advances the clock to `at` and applies inputs (`fire`, `nav`, `net`: `setOnline`), skipping one the previous input already produced (a click's `submit`, an action's `nav`); others are observations. An input it cannot apply is E2003, so the fingerprint differs. Returns `{ observed, state, error, reproduced, unapplied }`: final `state()`; `reproduced` iff fingerprints match; `unapplied` the input index it stopped at, `-1` for the base, else `null`. `minimize(session, { routes, maxRuns = 200, redact?, serve?, user? })`: ddmin over inputs (at `maxRuns`: smallest found), each run as `replay` (with `serve`, one call of `serve` per run, so every run starts from an empty server). `user` (absent: a visitor, `''`) renders the base signed in as `user`, as k.user Testing does; a recording holds no user.

**Served pages.** With `serve(ctx)`, a function resolving a `createApp` result made on `ctx`, the base is a page a `node` deployable serves: `replay` makes the sim ctx, advances it to `at`, calls `serve(ctx)` once, and renders the base with `renderRoute(route.id, { routes, params, search, ctx, app, user })` (k.testing; `user` left out when absent), so guards, loaders and actions run in the app over `ctx.storage`, which starts empty. `state` is not applied: each store starts as the served document resumes it. A page of a `node` deployable never learns its user, so a guarded base needs `user`. A base that resumes as another route than `route.id` (a guard's redirect) is not applied: E2003 `base route <id> redirected to <other id>`, `unapplied` `-1`; such a base is never reproduced, whatever the session recorded, since the replay's own E2003 is its first error and its fingerprint differs even from a session that recorded none. App and page share the ctx's clock and random (k.mount Testing): `serve` gets the ctx with its clock at `at` and its random stream unread, both then draw from that stream, so two replays under one `seed` draw the same values and are equal; where the stream stands after a replay is not part of the result. The server's data comes only from the recorded inputs replayed through the app (a submit runs its action), never from `state`. The server state, loader answers and user of the recorded run are not in the session: a session whose error needs them does not reproduce (E2004).

**Commands** (k.cli `session`). `capture [url]` (default `http://localhost:5173`) saves `sessions.live` to `.keel/sessions/<fingerprint>-0.json`; a section that is absent, `null` (no `record` on the page), an `error` or not a `Session` is E1056 (k.cli), exit 1, nothing written, the message `session capture <case>: <origin>` with `<case>` one of `has no sessions.live section`, `found no recorder (sessions.live is null)`, `sessions.live is an error: <its message, 30 characters>` and `sessions.live is not a session` · `ingest <url> [--failing] [--since t]` fetches `sessions.list` (cookie `KEEL_SESSIONS_TOKEN`) to `.keel/sessions/<fingerprint>-<n>.json` (unreachable, non-2xx or no `sessions.list` result: E1056; an archive with no sessions is `ok`, 0 written) · `replay <f>` · `minimize <f> [--max-runs n]` rewrites it · `to-test <f>` writes `modules/<route module>/test/session-<fingerprint>.test.ts`, or `test/session-<fingerprint>.test.ts` beside `topology.ts` for a page a `node` deployable serves: header `// Session: <fingerprint>, seed <n>`. The last three take `[--user <id>]` (an id that starts with `-`, as in `--user -x`, is refused as a bad value: E1052, k.cli) and run under `keel test` on the deployable serving `route.id` with its modules' `redact`. They replay with `--user` as `user`, and, when that deployable is `node`, with `serve`; `serve` builds the app as the deployable's generated entry does, over the given ctx: `createApp({ topology, deployable, routes, ctx, identity })`, `routes` the table of every module it places (k.topology Route table), `identity` the default export of the project's `identity.server.ts` when there is one; no runners, peers, assets or `std` config. Otherwise they replay without `serve`. The Action `@keel/std-sessions/action` runs them nightly with no `--user`: a `keel-session` issue per reproduced fingerprint, never a push.
- The `to-test` file is one straight-line test: a sim ctx of the session's seed (absent: 0), the clock advanced to `at`, `record(ctx)`, the base rendered with `user: <id>` in its options only when `--user` was given, each input applied in order (`fire` as `h.fire(id, event)`, `nav` as `h.navigate(<contract>.href(...))` with literal arguments, `net` as `ctx.net.setOnline(b)`), the clock advanced only where `at` changes, then `expect(rec.errors()).toEqual([])`.
- For a `client` or `static` deployable it renders `renderRoute(<id>, { routes, params, search, state, ctx })`, `state` holding the recorded value of each store it can import.
- For a `node` deployable the file is `test/session-<fingerprint>.test.ts` in the project folder, where the project's hand-written `app` tests live: a file outside every module, so not client-reachable (k.boundary Reach), and it may import server-only files. It builds the app in the test body as `serve` does, after the clock advance and before `record`, importing `../topology.ts`, each placed module's routes (`../modules/<id>/routes.ts`, or its package's `./routes`; several joined with `routeTable` in `topology.ts` order), each nav's contract from `../modules/<id>/<id>.contract.ts`, and `../identity.server.ts` when there is one, and renders `renderRoute(<id>, { routes, params, search, ctx, app })`. It passes `app`, so `keel check` reports no W1723 on it (k.testing), and no `state`, so it holds no recorded store value.

**Ingest.** `./contract` (std.contracts): `sessions.ingest` (`POST /sessions`, `Session`, over 256 KiB 413) recomputes `error` and `fingerprint` from `events`, adds it to store `sessions.archive` (per fingerprint `count`, `first`, `last`, newest 5; at most 64 fingerprints and 4 MiB, oldest `last` out, not the one written). `sessions.list` (`/sessions/list`, query `{ failing?, since? }`) loads it behind guard `sessions.reader`: `user` or `caller` in `readers`, else 403.

**Rules.** E2001 `redact`/`expose` entry whose subject is unknown or another module's, or whose path its schema lacks (fix removes it) · E2002 session file fails `sessions.Session` · E2003 replay cannot apply input N or the base · E2004 replay fingerprint differs (`minimize`, `to-test` stop) · E2005 a non-`node` deployable serves `routes` · E2006 a `record` `upload` not credential-free http(s) on the page's origin. E2002-E2004 diag the file at 1:1.

**Conformance.**
- Under one sim seed, one script of fires produces byte-equal sessions; events are in occurrence order with `at` equal to `ctx.clock.now()` then.
- A redacted payload value never appears in the session JSON, and the redacted payload parses with its transaction's schema.
- After overflow, a session holds at most `limit` events and its replay ends in the same `state()` as the live app.
- Replaying an unmodified session reproduces every store's final state and its fingerprint.
- `minimize` output reproduces the fingerprint; removing any one of its input events does not; two runs are equal.
- The `to-test` file passes `keel check`, fails under `keel test` on the buggy fixture, and passes once the fix is applied.
- A `to-test` file holds no recorded `s.string()` value outside `expose`, and no `s.secret` or password value.
- A valid POST to `sessions.ingest` is listed under its fingerprint; invalid input is 422 `keel.fields`; a sixth of one fingerprint keeps 5, counts 6; a caller not in `readers` gets 403 `keel.denied`.
- The `session` capability has all three implementations; shell `put` returns `ok(null)` and sends nothing.
- Without a global `document`, `record` records no event through transactions and errors and never calls `put`.
- E2001-E2005 each fire on a fixture, not on its clean twin.
- `record` throws E2006 on a cross-origin `upload`, not on a same-origin one.
- A POST naming another session's `fingerprint` is filed under its own recomputed one; 20 flood POSTs totalling less than 4 MiB leave an earlier real session in place.
- `keel session capture <url>` against an inspect document whose `sessions.live` section is absent, is `{ doc, value: null }`, is `{ doc, error }`, or holds a value that fails `sessions.Session` emits one E1056, writes no file and exits 1; with a section holding a valid `Session` it writes `.keel/sessions/<fingerprint>-0.json` and exits 0.
- `sessions.Session` refuses a session whose `id` is `''`, `../x`, `a b` or 65 `a`s, its first issue's `path` being `['id']`, and accepts `id`s `a`, `A-z_9` and 64 `a`s; `keel session replay` of a session file whose `id` is `../x` emits E2002 and exits 1; a POST of that session to `sessions.ingest` is 422 `keel.fields`.
- For a session whose `route.id` a `node` deployable `api` serves, the `to-test` file calls `createApp` with `deployable: "api"`, passes that result as `app` to `renderRoute` and passes no `state`; it is written to `test/session-<fingerprint>.test.ts` beside `topology.ts`; with an `identity.server.ts` in the fixture it imports it, and `keel check` on it reports no W1723 and no E1004; it fails under `keel test` on the buggy fixture and passes once the fix is applied. For a session of a `client` deployable's page the file passes `state` and no `app`.
- `replay` with `serve` of an unmodified session recorded under `renderRoute` with `app` calls `serve` once and returns `reproduced: true`, `unapplied: null`, and every store's final state equal to the recording's.
- With `serve`, a session whose base page's guard admits only user `u1` and redirects anyone else to page `a.signin`: `replay` without `user` returns `unapplied: -1` and `reproduced: false`, and `keel session replay` reports E2003 `base route <id> redirected to a.signin`; with `user: 'u1'` it returns `reproduced: true`, and `to-test --user u1` writes a file whose `renderRoute` options hold `user: "u1"`.
- A `to-test` file written without `--user` holds no `user` option; one written with `--user u1` holds `u1` once and no other user id.
