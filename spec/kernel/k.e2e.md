# k.e2e: End-to-end tests
status: implemented
From `@keel/testing/e2e`: a test of the built app in a real browser against its real server, run by `keel test --e2e`. The page handle, its waits and what a failure prints: k.e2e-page.

**Files.** An end-to-end test is a file `test/**/*.e2e.ts` or `modules/*/test/**/*.e2e.ts` of a project. `keel test` runs none of them. `keel test --e2e [paths] [--engine chromium|firefox|webkit] [--no-sandbox]` (k.e2e-run Browser) runs them alone (`paths` narrows them as for `keel test`), in this order: `keel build`, stopping on its failure as `keel build` does; the browser check (Browser); then vitest (k.e2e-run) with the project's `vitest.config.ts`, its `include` replaced by the two globs, `environment` `node`, `pool` `forks`, at most 2 files at once, and `KEEL_TEST=1` and `KEEL_E2E=1` set. A run with no e2e file builds nothing and prints `ok test 0 tests`. In an e2e file, E1701 (k.testing) holds as in any test, and a harness `render`, `renderRoute`, `resumeDocument` or `simulate` call is E1736.

**Browser, build input, time, ledger.** k.e2e-run.

**serve.** `serve(options?)` resolves a `Served` handle once each deployable answers. `options`: `project` (a folder, default the one `keel test` runs in), `env` (a record, or a function of the data folder's path returning one), `origins` (`{ [origin]: Answered }`), `dev` (`true` runs `keel dev`), `page` and `props` (Libraries). Per `node` deployable of `project`'s `topology.ts` it starts `node dist/<name>/server.mjs` (with `--experimental-webstorage --localstorage-file=<data>/<name>.localstorage` for `storage: 'file'`) with the environment k.e2e-run Environment gives, `HOST=127.0.0.1`, `PORT` a free port the OS gave, `KEEL_SECRET` 32 random bytes as hex, the same for each deployable of one `serve`, `KEEL_ORIGIN` its origin `http://127.0.0.1:<port>`, `KEEL_PEER_<NAME>` each other `node` deployable's origin, `KEEL_ALLOW_ORIGINS` each served client's origin, `KEEL_DATABASE_URL` `file:<data>/<name>.sqlite` for `storage: 'sqlite'`, and `KEEL_FORMAT=json`; `env` is added last and replaces any of these. Each `static` deployable and unserved `client` one is served from `dist/<name>/` by a host of the run that answers as k.hosting says a static host does, with `csp.txt` as the `content-security-policy` header. `<data>` is a new folder in the run folder (k.e2e-run Teardown), one per `serve`. A `dist/<name>/` missing, a name of a served module's `env` (k.deploy) or `KEEL_DATABASE_URL` for `storage: 'postgres'` that `env` does not give, a process that exits, or a deployable that gives no HTTP answer to `GET /` within 20 s (k.e2e-run Time) rejects E1737 naming the deployable and the cause, with its last 10 log records; the processes it started are stopped. A `PORT` the server refuses as in use (E1560) is retried with another free port, at most 3 times.

**Served.** `origin(deployable?)`: a deployable's origin, default the first deployable of `topology.ts` that serves documents. `open(path, { deployable?, scripts?, hold?, cookies? })`: a page (k.e2e-page) in a new browser context of its own; `cookies` are `{ name, value, origin, sameSite?, secure?, httpOnly? }` put in that context before the load, the one way a test gives a cookie a value, and no verb reads one back. `fetch(path, init?)`: a request from the test process to that origin, no cookie sent, no redirect followed. `serverLog(deployable?)`: every record the deployable's process wrote, in order, as parsed json (OUTPUT.md Server log). `state(store)`: a server store's value as the deployable's storage holds it, read through that storage's driver (k.persist) and parsed by the store's schema. `until(store, test, { within?, fixed? })`: resolves once `test(value)` is true of that value, read again after each commit the storage reports through `watch` (k.persist Watch), else every 100 ms; bounded as k.e2e-page Waits says, E1735. `log(store)`: `{ head, digest, entries }` of the store as that storage holds it: `digest` the SHA-256 hex of the stored snapshot's text byte for byte, `entries` the `{ id, name, digest }` of each log entry (k.store) in order, an entry's `digest` the SHA-256 hex of its payload's JSON; no payload or value is given, so equal digests show equal stored bytes without showing personal data. `stop(deployable?, { drain? })`: SIGKILL, every deployable when none is named; with `drain: true`, SIGTERM, resolving once the process has exited (k.deploy: it stops listening and awaits `close()`). `start(deployable?)`: starts a stopped deployable again on its port and data, resolving once it answers. `dispose()`.

**Answered origins.** `answer(handler)` starts a loopback HTTP server of the test that answers each request with `handler(request)`: `Answered` `{ origin, requests(), dispose() }`, `requests()` as k.requests holds them. A server reaches it through `env` (`PAYMENTS_URL: payments.origin`). `origins` maps an origin a browser page requests to it: each context of the `serve` sends its requests through a proxy of the `serve`, which sends a request for a mapped origin, or a `<name>.peer.keel.test` one, to its server; what else a page may reach, and the certificate: k.e2e-run Reach. The page's content security policy and CORS apply as to the real origin.

**Isolation.** Each `serve` has its own processes, ports, data folder and `KEEL_SECRET`; each `open` its own context: cookies, storage, service workers and cache. A `serve` or `answer` handle made while a test runs is disposed when the test ends as k.test-run Disposal says of a harness handle, a `Served` handle with each page it opened: its processes are stopped and its data folder removed.

**Libraries.** In a library's folder (k.library-pack Own folder) `serve({ page, props, wrap?, tokens? })` serves one component. `page` is a path, resolved against the library's folder, of a file under its `src/` whose export is named as the file. `wrap` is a component file under its `test/` that takes `children`, the page rendered inside it (a layout, a landmark, a surrounding form). `tokens` is a file under its `test/` exporting `tokens`, which replaces the library's defaults (k.ui), as an app restyling it would. Each call writes a host project in a new folder `.keel/e2e-host-<random>/` of the library: a `topology.ts` of one `client` deployable `web`, one module whose route `/` renders the export with `props` (JSON values, parsed in the page by its `Props` schema: a failure is a `pageerror`). It builds it with `keel build` and serves `dist/web/` as an unserved `client`. The folder is removed when the handle is disposed, so calls in several files at once never share one. The host resolves packages from the library's own `node_modules`: `@keel/compiler`, `@keel/router` or `@keel/server` missing there is E1737 naming the first, with a fix adding it to `devDependencies`. `keel pack` never packs a `.keel/e2e-host-*` folder. `page`, `wrap` or `tokens` outside a library's folder, or outside the folder named for it, is E1736 naming the path. A component that needs route params, a guard or a server is tested in an app that installs the library.

**Control.** A built app runs on a real ctx (k.ctx). A test controls the browser's network (`offline`, k.e2e-page), each deployable's life (`stop`, `start`), the answers of mapped origins, the data a `serve` starts from (empty), and when a held page's scripts run. The sim clock, `ctx.random`'s seed, a net schedule's delays and faults, storage faults, `simulate` and `replay` (k.sim) do not reach a built app, and nothing stands in for them: a test of a timer waits the real time (k.e2e-run Time).

**Rules.** E1734 and W1734 (k.e2e-run) · E1735 (k.e2e-page) · E1736 a harness call in an e2e file, `@keel/testing/e2e` called when `KEEL_E2E` is not `1`, or a `page`, `wrap` or `tokens` path outside its folder · E1737 a deployable that did not start · E1738 (k.e2e-page).

**Conformance.**
- `keel test` in a project holding `test/a.test.ts` and `test/b.e2e.ts` runs `a.test.ts` alone; `keel test --e2e` runs `b.e2e.ts` alone, after `keel build` has written `dist/`.
- `keel test --e2e` in a project with no `playwright-core` installed prints one E1734 `playwright-core is not installed`, runs no test, reports none skipped and exits 1.
- `keel test --e2e` in a project with no e2e file prints `ok test 0 tests` and leaves `dist/` as it was.
- A test calling `renderRoute` in `test/b.e2e.ts` fails with E1736, and `serve()` in `test/a.test.ts` under `keel test` rejects E1736.
- `serve()` of a project with `node` deployables `api` and `web` starts both, each with its own free port, one `KEEL_SECRET`, and `KEEL_PEER_API` set in `web` to `api`'s origin, and `serverLog('api')` holds a `req` record for a `fetch('/')` of `api`.
- `serve()` of a project whose only deployable is `static` starts no process, and a `fetch` of a path that is no file answers 404 with `404.html` and the `content-security-policy` header equal to `dist/<name>/csp.txt`.
- `serve()` of a deployable whose served module's manifest names `env` `PAYMENTS_URL`, given no such `env`, rejects E1737 naming the deployable and `PAYMENTS_URL`, and leaves no process running.
- Two `serve()` calls of one project in one test have different ports, data folders and `KEEL_SECRET`s, and a store saved through one is not in `state` of the other.
- `until(board, (b) => b.lists.length === 1)` resolves once a page's add is committed, and rejects E1735 naming the store's id when no commit makes it true within the bound.
- After `stop()` a `fetch` of the deployable's origin rejects; after `start()` it answers, and `state(store)` holds what was saved before `stop()`.
- A page of a `serve` whose `origins` map `https://api.example.com` to an `answer` returning `Response.json({ ok: true }, { headers: { 'access-control-allow-origin': '*' } })` receives that answer for a request the page's code makes there while the policy's `connect-src` lists the origin, and the request is refused, with the `answer`'s `requests()` empty, when it does not.
- After a test that made a `serve` ends, passed or failed, none of its processes runs and its data folder is gone.
- `keel test --e2e` writes `reports/tests/e2e.json` and leaves `reports/tests/run.json`; a later `keel test` writes `run.json` and leaves `e2e.json`.
- An `it` calling `serve` and declaring no timeout has 60 s, and 60 s with `KEEL_TEST_TIME_SCALE=0.1`.
- A page's `fetch` with header `x-a: 1` to a mapped origin whose `answer` answers `OPTIONS` 204 with `access-control-allow-origin: *` and no `access-control-allow-headers` rejects in the page, and that `answer`'s `requests()` holds one `OPTIONS` and no `GET`.
- `open('/', { cookies: [{ name: 'gh', value: 'g1', origin: 'https://api.example.com', sameSite: 'None', secure: true }] })` puts the cookie in the context, and `cookies()` then lists `gh` with no value.
- After two transactions committed through a page, `log(store)` holds `head` 2 and `entries` with ids 1 and 2 and each transaction's name, and after a `stop()` and `start()` it is equal, `digest` and each entry's `digest` among it.
- `log(store)`'s `digest` is the SHA-256 hex of the text the storage holds at the store's key, and an entry whose payload is `{ "title": "Milk" }` has `digest` the SHA-256 hex of `{"title":"Milk"}`.
- `stop('api', { drain: true })` sends SIGTERM and resolves once the process has exited with code 0, and `serverLog('api')` then holds what the process wrote while draining.
- In a library folder holding `src/Card.ts` and `@keel/compiler`, `@keel/router` and `@keel/server` in `devDependencies`, `serve({ page: 'src/Card.ts', props: { title: 'Hi' } })` serves a page whose `find('card.title')` text is `Hi`; without `@keel/router` it rejects E1737 naming `@keel/router`.
- Two files of one library calling `serve({ page: 'src/Card.ts' })` at once each serve their page, and after both end no `.keel/e2e-host-*` folder is left.
- `serve({ page: 'src/Card.ts', wrap: 'test/Frame.ts' })` serves `Card` inside `Frame`'s `children`, and with `tokens: 'test/dark.ts'` the page's `style` reads the colours that file gives.
- `serve({ page: '../other/src/Card.ts' })` and `serve({ page: 'test/Card.ts' })` in a library's folder reject E1736 naming the path.
