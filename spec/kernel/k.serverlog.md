# k.serverlog: Server log records
status: implemented

**Purpose.** How the server writes each record of its log (k.server Log, docs/OUTPUT.md), so that no request or thrown value makes a record long, splits it across lines or fakes a cut, and no cut shows what the scrub (k.privacy Server log) marked.

**Parts.** A record's variable parts are a `diag` record's message and each of its `frames`, and a `req` record's method and path. Lengths count UTF-16 code units, called characters here. Each part is written in three steps, in this order:
1. Scrub, as k.privacy Server log says, a `req` path after Path below. When the request, or a runner's `run`, holds a secret or `.pii()` value, a text over 2,000,000 characters is not read: it is one mark as past the scrub's cap, a message keeping its prefix (`loader <id> threw: `). With no such value nothing is scrubbed.
2. Escape. Each control character (U+0000 to U+001F, U+007F to U+009F), U+2028, U+2029 and `…` (U+2026) is written as `\u` and four lowercase hex digits, in compact and json alike; a parsed json value holds those six characters.
3. Cut. A message or path keeps the longest head of its scrubbed text whose escaped form is at most 2,048 characters; a frame or method, 256. When text is left out, `…+<n>` follows the head, `n` the scrubbed characters left out: `action app.save threw: Error: bad {"q":"aaaa…+1046501`. Only that head is read.

**Thrown values.** A value thrown out of a guard, a loader, an action, a live stream, a render or a runner, an uncaught one's (E1577, whose prefix k.leave Process gives) among them, is written by what the code says of it, never by its text. Its message, its `String()` and JSON forms and its `data` are a person's or a library's words, and the scrub knows only the values this request declared. The `diag` message is `<owner> <id> threw: <class>[ <code>] #<fingerprint>[ at <file>:<line>]`, then ` <- <class>[ <code>]` for each cause (`cause`, at most 8 steps): `loader p.def threw: Defect E2801 #9f3c21ab at modules/p/def.server.ts:12 <- Result postgres.database`.
- `<class>` is `Defect` for a defect (k.defects); `Result` for a `KeelError`; for an `Error`, its `name` when that is `Error`, `TypeError`, `RangeError`, `SyntaxError`, `ReferenceError`, `URIError`, `EvalError`, `AggregateError`, `AbortError` or `TimeoutError`, else `Error`; `value` for anything else.
- `<code>` is a defect's code, or a `KeelError`'s when `s.error` declared that code in this process or it is a kernel code; any other `KeelError` code is written `[code]`, and a thrown object's `code` property is not written.
- `<fingerprint>` is 8 lowercase hex digits: the first 32 bits of HMAC-SHA-256, keyed by `KEEL_SECRET` (without one, by a key made at start), over the class, a line feed and the value's text. Equal failures have equal fingerprints across the processes that share the secret; no text is recovered from one without the key.
- `at <file>:<line>` is the top frame of an `Error`'s stack, as `frames` writes it.
- Full text: only under `createApp`'s `mode: 'dev'`, or until the instant `KEEL_LOG_THROWN` names, a second `diag` follows the first, its message `<owner> <id> threw: ` and the value's text (an `Error`'s `name: message`, a defect's `data` as JSON after it, any other value's JSON or `String()`), written by Parts, so a reader pairs a fingerprint with its text. `KEEL_LOG_THROWN` is an ISO 8601 instant at most 24 hours after the start; any other value is E1596 at start, naming no part of it, and the process does not serve. Both instants are readings of the app's ctx clock (k.ctx `clock.now()`): the start is its reading when `createApp` reads `KEEL_LOG_THROWN` and `KEEL_SECRET` from the environment, and a throw prints its text while its own reading is before the instant. Every record of Conformance below that quotes thrown text is that second record, with full text on.
- `frames` and the site are positions in app code (`<file>:<line>`, k.deploy), not thrown text. Without full text the log holds no thrown value and no mark standing for one: its only marks are those the scrub writes in a frame, a site or a `req` path (k.privacy Server log, Path).
- Under `mode: 'dev'` a page shows a defect's code, class and text (k.defects); in production no response body holds the class, the fingerprint or the text (k.server Status).

**Path.** Before the scrub, a segment at a secret `params` field of any route of `routes` (any deployable's) is `[secret]` as sent, at a `.pii()` one `[pii]`, `[secret]` if both. A route lines up from the first segment, skipping empties (a prefix-param route also without it), to that param: a param fits any segment, a static one the same text once decoded and case-folded, or undecodable. A longer path is cut there, the rest joining that mark: `/:t` and `/:p/:t` (`t` secret) mark any path whole. A secret param also cuts a path as `[secret]` at a segment holding `%2F` or `%5C` (any case). Each mark and each cut also takes in the `/`s before its segment but one, and a mark at the last non-empty segment the `/`s after it, so no slash of a value is left: `/reset//<v>`, `/reset/<v>/` and `/reset/<v>//` log `/reset/[secret]`, and `//reset//<v>/` logs `//reset/[secret]`. A path no route lines up with (a static typo, an extra leading segment, a raw `/` in an earlier param, `&` for `?`) is logged as sent.

**Marker.** After the escape a part holds no `…` of its own, so `…` in a record, compact or json, is always a cut. In json the marker is inside the string and the record stays one valid object; a head that ends in the first half of a surrogate pair is written as its escape there.

**Order.** The cut runs after the scrub and keeps a head of the scrubbed text, so each character it writes is one a whole-text scrub left, and a value straddling the cut point is already one mark. Cutting first would keep a straddling value's head, which a scrub of whole forms cannot find. The scrub reads at most 2,000,000 characters of a text and the cut at most 2,048, so a record's cost is bounded for any input.

**Record.** A `diag` holds at most 5 frames (k.deploy), a runner's too. A record is then at most 8,192 characters and 12,288 bytes of UTF-8 in either form, plus a `req` record's route id: its other text is the server's own (code, `see`, status, time) or a `csp` record's parts, which k.security bounds. The bounds hold for every record the server writes, in dev and production: `req`, `diag`, `csp`, the last resort's `diag` and its one stderr line.

**Rules.** E1596 `KEEL_LOG_THROWN` set to a value that is no ISO 8601 instant or lies more than 24 hours after the start, at start.

**Conformance.**
- An action throwing an `Error` whose message is 1,000,000 `a`, and a runner rejecting with it, log in compact and json a `diag` whose message is its first 2,048 characters then `…+<n>`, `n` the characters left out; every json line parses.
- With a revealed 64-character secret in a thrown message at each offset that puts the 2,048th written character inside it, no logged line holds 8 consecutive characters of the secret, in compact and json.
- A thrown message holding a line feed, a carriage return, U+001B, U+0085, U+2028 and U+2026 logs one line per record in compact, with `\u000a`, `\u000d`, `\u001b`, `\u0085`, `\u2028` and `\u2026` in their places; the parsed json message holds those texts.
- A request for a 5,000-character path logs a `req` path of its first 2,048 characters then `…+2952`, in compact and json.
- An action that reveals a secret and throws 2,000,001 characters logs `action <id> threw: [secret]`; with no secret or `.pii()` value it logs the first 2,048 characters then `…+<n>`.
- For a thrown message of 1,000,000 `"`, U+20AC or U+0001, every logged line is at most 8,192 characters and 12,288 bytes of UTF-8.
- A revealed secret of 8 bytes or more thrown JSON-escaped twice, `encodeURI`d, form-encoded, unpadded base64 and base64url logs `[secret]` in each place; a 2-character one inside a word logs as is.
- Of `/reset/:token` (`token` secret), `/reset//<v>`, `/reset///<v>`, `/reset/<v>/`, `/reset/<v>//` and `/reset//a%2Fb` log the `req` path `/reset/[secret]`, and `//reset//<v>/` logs `//reset/[secret]`; of `/u/:email` (`.pii()`), `/u//a@b.c/` logs `/u/[pii]`.
- In production mode, a loader `p.def` throwing `new Error('user jane@x.com failed')`, the string `token=abc123`, the object `{ ssn: '078-05-1120' }` or `defect('user failed', { data: { email: 'jane@x.com' } })`, none of them a value the request declared, logs a `diag` whose message matches `^loader p\.def threw: (Error|value|Defect) #[0-9a-f]{8}( at \S+:\d+)?$`, and no logged line, compact or json, holds `jane`, `abc123` or `078`.
- Two requests that throw `new Error('a')` from one place log the same fingerprint, also from a second process with the same `KEEL_SECRET`; `new Error('b')` there, and `new Error('a')` under another `KEEL_SECRET`, log another.
- A loader throwing `defect('no row', 'E2801', { cause: e })`, `e` the error of `s.error('shop.gone', s.object({}))`, logs a message that starts `loader p.def threw: Defect E2801 #` and ends ` <- Result shop.gone`; with `e` the object `{ code: 'jane@x.com', message: 'm', data: null }` it ends ` <- Result [code]`.
- An `Error` whose `name` was set to `jane@x.com` logs the class `Error`; a `TypeError` logs `TypeError`.
- With `mode: 'dev'`, that first loader's `Error` logs that `diag` and then one whose message is `loader p.def threw: Error: user jane@x.com failed`; where `jane@x.com` is a `.pii()` value of the request's input the second is `loader p.def threw: Error: user [pii] failed`.
- With `KEEL_LOG_THROWN` an instant one hour after start, a throw logs two `diag` records before that instant and one after it; set to `yes`, or to an instant 25 hours after start, `createApp` fails with E1596 and the record holds no part of the value.
- `server.mjs` of a fixture whose loader `/late` throws `new Error('user jane@x.com failed')` 30 ms after its 200 writes one E1577 record whose message matches `^uncaught exception in work of route \S+: Error #[0-9a-f]{8}( at \S+:\d+)?$`, and no line the process writes holds `jane`.
