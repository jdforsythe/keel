# k.privacy: Secrets and personal data
status: conformance-covered

**Purpose.** Two schema marks decide what may leave the process. Personal data serializes where the app sends it (its stores) and is redacted in every sink: sessions, logs, error text, the evidence bundle.

**Secrets.** `s.secret(inner)` parses a raw `inner` value, or an existing secret, to a `Secret<T>` whose value is read only by `reveal(secret): T` (E1105). A secret never serializes: `encode`, `JSON.stringify`, `String()`, template literals and `util.inspect` give the marker `"[secret]"`; it has no own enumerable keys, so spread and `structuredClone` copy nothing. `parse` of the marker fails with rule `secret-missing`, so a store snapshot, `#k-state`, log or session capture never carries or restores the value. `reveal` returns plain data, frozen deep (k.reveal).

**Personal data.** `schema.pii(class)` marks any schema node as personal data, in a `*.schema.ts` file. `PiiClass` is closed: `name` · `contact` (email, phone, handle) · `location` (address, coordinates) · `identifier` (government, account, customer numbers, birth dates) · `financial` · `special` (health, biometric, belief, ethnicity, orientation) · `network` (IP address, device id) · `content` (text a person wrote). The mark keeps the type and every derivation (`parse`, `encode`, `decodeStrings`, `gen`); the node gains `pii: class`, covering every value under it; `doc()` appends ` pii(<class>)` and JSON Schema adds `x-keel-pii`.

**Sinks.**
- Sessions (std.sessions): marked values in payloads, state and error `data` become generated values at capture; error messages drop each.
- Inputs: a control bound (k.forms `field`) to a marked path carries `data-k-pii="<class>"`, and the ctx observer reports its `input` values and one-character `keydown` keys as `x` repeated (k.ctx).
- Server log (k.server): in a `diag` record's message and `frames` and the `req` record's path, each of `piiValues` (k.schema) of the request's decoded action input, its loaders' and actions' outputs and its factories' store states becomes `[pii]`. Each string, number and key but a declared field name (not a boolean) in a `Secret` made or revealed while the request runs (`bearer` too) becomes `[secret]`. A runner's `run` is scoped alike. Past the cap (Cost), a message after its prefix (`loader <id> threw: `), each frame and the path are one mark, `[secret]` if the scope holds a secret, else `[pii]`; a message with no prefix is one mark whole. Each request and runner `run` takes the `onSecret` slot of `@keel/schema/internal` for the server's listener as it begins; each text of a scope during which a package cleared or replaced it is one mark as past the cap, `[secret]`, since its set may lack a secret.
- Copies: a value is marked wherever one of its forms stands in the text or in one of the text's two decoded views (Views). Its forms: the value as given, and its NFC and its NFD where they differ; from 8 bytes of UTF-8, the hex of those bytes; and base64 of them (Base64). A value with a lone surrogate has no hex or base64 form. Letter case folds one code unit at a time, in hex and base64 too, so a near copy may be over-marked. A form under 3 units is marked only as a whole token: no letter, digit, mark or `_` beside it in the view it was found in. Copies that overlap in the text are one mark over all of them, `[secret]` if any is a secret's.
- Views: the decoded view of a text reads it once from the start, writing for each escape what it stands for and any other unit as is: a run of `%` and two hex digits (either case) as bytes, each well-formed UTF-8 sequence among them as its code point and any other byte as its three characters; `+` as a space, or in the second decoded view as `+`; `\u` and four hex digits as that unit; `\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r` and `\t` as their characters; `&amp;`, `&lt;`, `&gt;`, `&quot;` and `&apos;`, `&#` with 1 to 7 decimal digits and `;`, and `&#x` or `&#X` with 1 to 6 hex digits and `;`, as their character, a numeric one only for a code point up to U+10FFFF that is no surrogate. The text is read as is, as each of its two decoded views, as each of the two decoded views of each of those, and as a view of each family of escapes alone, any other unit as is, and as that family's view of that view: the `%` escapes with `+` (as a space, and as `+`), the backslash escapes, the entities. A copy found in a view marks the text it was decoded from, from the first character of the escape its first unit came from to the last character of the escape its last unit came from. So a copy under one or two escapings of these kinds, nested in any order, is found: URL-encoded by any encoder that writes `%` escapes, form-encoded, JSON-escaped with or without `\u` or `\/`, HTML-safe JSON, HTML entities, JSON in a URL; a `+` of the value is found whether an escaping wrote it as `%2B` or left it as is (`encodeURI`, JSON, HTML entities); and a value holding an escape of one family is found under one or two escapings of another family that leave it as is (`JSON.stringify` of `a"b%41`, once or twice; `encodeURI` of `x&amp;y z`).
- Base64: in the standard and the URL-safe alphabet. A value under 8 bytes is matched as its own padded encoding, whole. A value of 8 bytes or more is matched at each of the three byte alignments, alone or inside any longer encoding, as the characters whose six bits all come from its bytes; the mark takes in the character before and the character after that hold some of its bits, at that alignment, and the `=` padding after them. So a base64url JWT payload whose JSON holds the value as is holds a copy.
- Limits, not marked: a copy under three or more escapings; an escape the views do not read (`\x41`, octal, `\U`, `%u`, another named HTML entity, a numeric one without its `;`); a copy part NFC and part NFD, and compatibility forms (NFKC, NFKD, full-width letters); hex of a value under 8 bytes; base64 of a value under 8 bytes inside a longer encoding, unless its own padded encoding stands whole there; a value holding an escape of one family under two escapings of two different families, one of which leaves that escape as is (`a"b%41` JSON-escaped, then URL-encoded); hex or base64 of a text in which the value is itself escaped (base64 of JSON that writes it with `\"`, `\\` or `\u`); base64 with line breaks; hex of UTF-16 and any other encoding, a hash, compression or encryption; a copy cut short, split by other text or with a character changed; a value revealed outside every scope.
- Cost: a scope counts the UTF-8 bytes of its distinct values, secret and `.pii()` together (a lone surrogate 3 bytes; an NFC or NFD form that differs counts as a value). Past 65,536 bytes, or once one `Secret` has more than 1,000,000 values to read (its value and each value, key, array and object inside it counted), its set takes no more values and every text of the scope is past the cap. Below it, the matcher is built in steps linear in the bytes of the set it is built for, built again only when the set has grown, and each text is read in steps linear in its length, each of its readings once; a text over 2,000,000 characters is not read (k.serverlog).
- `req` path: first, a segment at a route's secret or `.pii()` `params` field is marked (k.serverlog Path).
- URLs: a marked or `s.secret` node in a route's `params`, `search` or `query` schema is E1111: a path or query reaches history and proxy logs Keel cannot redact.

**Rules.** E1105 `reveal` imported in an app file other than `*.server.ts`, test files included · E1111 a `.pii()` or `s.secret` node in a route `params` or `search` schema (fix: none), or a route table, entry, `params` or `search` it cannot read statically (a factory call, a computed key); a package's exported table or schema, and `tableSearch`'s (`@keel/std-tables`, refusing a marked column), are the package's. · E1113 an `s.secret` in an `output`, thrown by `contract` or `loader` (k.routes; fix: none).

**Conformance.**
- For every generated secret: it parses; `encode`, `String` and `util.inspect` give the marker, `JSON.stringify` the marker's JSON, `structuredClone` an empty object; parsing a raw value yields a secret revealing it; the marker fails with rule `secret-missing`.
- `s.string().pii('contact')` has `doc()` `string pii(contact)` and JSON Schema `x-keel-pii: "contact"`.
- A marked or `s.secret` field in a route's `params` or `search` schema is E1111; in an action `input` it is not.
- An action throwing the revealed value of a `Secret` input or `bearer`, as a string or in an `Error` message, logs a `diag` record holding `[secret]` and not the value, in dev and production, as does a loader or action throwing one parsed after an `await` or made earlier and revealed in it, a record or `json` key in one, and a runner's; a boolean or declared field name logs as is; of two overlapping requests each marks only its own.
- A secret route param is `[secret]` in the `req` path, escaped any way, in `/%52ESET/<v>` and `//reset//<v>/`, with and without a prefix param, and forwarded to a peer; `/reset/ab/<v>` and `/confirm/a/<v>/done` (of `/confirm/:token/done`) log `/reset/[secret]` and `/confirm/[secret]`; `/en/reset/<v>` logs as sent; a failed forward logs no path.
- An action throwing an `Error` whose message or a stack frame's file path holds a marked input value logs a `diag` record with `[pii]` in its place, in dev and production.
- Under a sim ctx, an `input` fired on an `Input` bound to a marked field reaches `observe` as `x` repeated, and the element has `data-k-pii`.
- An API entry or page loader whose `output` has an `s.secret` field throws E1113; with `s.string()`, none.
- `/reset%2F<v>`, `/RESET%2f<v>`, `/reset%5C<v>` (of `/reset/:token`), `/about` (of `/:t`) and `/en/A` (of `/:p/:t`) log `/[secret]`; `/a%2Fb` with no secret param, as sent.
- For every generated secret of 8 or more UTF-8 bytes with no lone surrogate, each encoding E of it below, and texts p and q of 0 to 20 ASCII letters, digits and spaces that hold no form of it, an action that reveals it and throws an `Error` whose message is p, E, q logs a `diag` whose message ends with a prefix of p, then `[secret]`, then a suffix of q. E is: the value; its NFC; its NFD; `encodeURIComponent` of it, once and twice; `encodeURI` of it; it form-encoded (`URLSearchParams`); `encodeURIComponent` of it with `!`, `'`, `(`, `)` and `*` as `%21`, `%27`, `%28`, `%29` and `%2A`; its `JSON.stringify` less the quotes, as is, with `\u` and four lowercase hex digits for each non-ASCII unit, with `\/` for each `/`, and with `<`, `>`, `&` and `'` as `\u003c`, `\u003e`, `\u0026` and `\u0027`; that first JSON escaping applied twice; it with `&`, `<`, `>`, `"` and `'` as `&amp;`, `&lt;`, `&gt;`, `&quot;` and `&#39;`; it with each code point as `&#<decimal>;`, and as `&#x<hex>;`; `encodeURIComponent` of its `JSON.stringify` less the quotes; the hex of its UTF-8, in lower and in upper case; its base64 and base64url, padded and unpadded.
- For every generated secret of 8 to 40 UTF-8 bytes with no lone surrogate and byte strings a and b of 0 to 5 bytes each, an action that reveals it and throws an `Error` whose message is the base64 or base64url, padded or unpadded, of a, its bytes and b logs a `diag` whose message ends with a prefix of that encoding's characters before index ⌊4·|a|/3⌋, then `[secret]`, then a suffix of its characters after index ⌈4·(|a|+n)/3⌉ − 1 (n the secret's byte count) that starts with no `=`.
- A revealed secret `a b/c?d&e` thrown as `encodeURIComponent` applied three times logs as thrown.
- An action whose input holds 8,192 distinct 8-character ASCII secret strings (65,536 bytes) and throws `bad ` and one of them logs a message ending `bad [secret]`; with 8,193 it logs `action <id> threw: [secret]` and the `req` path `[secret]`; so do 4,096 and 4,097 distinct strings of 8 letters from U+0430 to U+0438 (16 bytes each).
- An action that calls `onSecret(() => {})` from `@keel/schema/internal`, then reveals its `Secret` input and throws `bad ` and its value, logs `action <id> threw: [secret]` and the `req` path `[secret]`; a request after it that calls nothing logs its thrown secret as `bad [secret]`.
- Of `/u/:email` (`.pii()`), `/u/a@b.c`, `/u/a%40b.c`, `/U/a@b.c` and `/u/a@b.c/x` log `/u/[pii]`; `[secret]` if also secret.
