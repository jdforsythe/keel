# k.looks: Library looks
status: proposed

A library ships its look as tokens the app composes in its own `tokens.ts`. `keel check` holds the app's tokens to every name the library's files write, and the library's files to the tokens it ships.

**Names.** A token or look name with no `.` belongs to the app; `brandTokens` (`@keel/ui/brand`) holds only such names. A library's names are `<id>.<name>`, `<id>` its manifest's module id and `<name>` a token name with no `.` (k.ui `TokenName`): `acme.accent`, `acme.2`, `acme.card`. Module ids are distinct (E1166), so two libraries' names never meet, and a key in `tokens.ts` says whose token it sets. A name's custom property is `--k-<group>-<id>-<name>` when `<id>` and `<name>` are alphanumeric (`--k-color-acme-accent`), so a `border` value can name it.

**Shipped tokens.** A library ships tokens through the `./tokens` entry of its `package.json` `exports`, whose `keel` target is `./src/<id>Tokens.ts`; the entry is held to k.library-pack Package as any entry is. That file holds `import { defineTokens } from '@keel/ui'` and `export const <id>Tokens = defineTokens({ ... })` and nothing else. The argument is an object literal whose keys are identifiers or string literals and whose values are string literals or such object literals: no spread, name, call, template, `as` or `satisfies` (`defineTokens` keeps the literal types). It holds k.ui's groups but `base`, no `schemes` (k.schemes), and `themes` only as k.values Library themes allows; every name in a group and every `look` key begins `<id>.`; each token a look names is one the object holds; it passes `TokenSchema`. A top-level `base` or `schemes` key gets its own E1812 message whatever its value, before its value's form is judged. `keel check` reads it as text and never runs it. Its export is not a ledger export (k.library-pack Own folder).

**Needs.** A library needs every name its shipped object holds, in each group, and every look; the object is the list. In a library file, a token name written as a string literal (a token prop, a responsive key, a `states` value, a part style value or a `look`, as k.ui's style props read them) is one its shipped object holds, else E1811 at the literal, in place of E1801. A library with no `./tokens` entry writes no token name: its elements take the app's look through `base` and through the `styles` the app passes (k.aria Part styles).

**In an app.** For each library an app lists (k.library) whose `exports` has `./tokens`, the app's tokens hold every name it needs, else one E1810 for that library at the name `tokens` in `tokens.ts`'s `export const tokens`; with no `tokens.ts`, one at each `deps` entry naming the library, with no fix. Message: `<name> needs <group> "<token>"`, then ` and <n> more` when more are missing, then `; import <id>Tokens from <name>/tokens` when `tokens.ts` has no such import, else `; spread <id>Tokens.<group>`. `<token>` is the first missing name, groups in k.ui's order with `look` last, names as the shipped object writes them. A library file's literal naming a name the library ships is judged by E1810 alone. E1810 to E1814 judge the tokens k.a11y-static Tokens gives the project, the evaluated `tokens` export of its `tokens.ts`, and read the file's text only for positions and the fix; a project whose `tokens.ts` gives no tokens (E1807, or `check()` given the file and no tokens artifact) has none of them judged but E1811 and E1812, which read the library's own files and no tokens, and one with no `tokens.ts` has no tokens, one scheme (`light`) and no dotted names. Each name with a `.` the app's tokens hold belongs to a library the app lists and is one it ships, else E1813 at the opening quote of the first string literal in `tokens.ts` whose value is the name, else at line 1, column 1: `<group> "<token>": <name> ships no such token`, or `<group> "<token>": no library the app lists has id <id>`.

**Fix.** E1810's fix applies when `tokens` is `defineTokens(<object literal>)`, or an imported name `S`, taken as `defineTokens({ ...S })` with `defineTokens` imported from `@keel/ui` when the file does not import it. It adds `import { <id>Tokens } from "<name>/tokens";` after the last import, and for each group the shipped object holds, in k.ui's order with `look` last: `...<id>Tokens.<group>` after the last spread of the literal's `<group>` object, or, when the literal has no `<group>` property, `<group>: { ...S.<group>, ...<id>Tokens.<group> }` at its end, with one `...S.<group>` per top-level spread `...S` of an imported name whose tokens hold that group, in order. A `<group>` written as anything but an object literal gets no fix. The fix moves no comment: the import goes on a new line after the last import's line, its trailing comment kept. The fix's layout is not judged: a test compares the fixed file with the expected one after formatting both with `biome format` under the repo's configuration.

**Entries.** In each listed library's `package.json` `exports`, an entry holding `keel` holds it as its first key and nowhere deeper, else E1815 at each `deps` entry naming the library (`<name> exports "<key>" lists keel after another condition`, or `<name> exports "<key>" nests keel under another condition` when `keel` sits only deeper). `keel check` judges this before it evaluates `tokens.ts`, and evaluates none while an E1815 stands, so the file check reads as source is the file the compiler and `tokens.ts`'s evaluation resolve (both take the `keel` condition, k.library).

**Library contrast.** In an app, an E1804 at an element of a library file, or at a library look, is reported in `tokens.ts`: at the opening quote of the app's key for its `fg` when the app writes one, else for its `bg`, else at the spread `...<id>Tokens.color`, else line 1, column 1; once per pair and combination (k.a11y-static); message `<fg> on <bg> is <ratio>:1 in <combination>, needs <need>:1; override in tokens.ts`.

**Own folder.** In a library's own folder (k.library-pack Own folder) the root `tokens.ts` stands for an app. E1810 and E1811 hold there, so it composes the shipped object, and a key it writes beginning `<id>.` is E1813 `<group> "<token>": the fixture overrides <id>'s default`, so contrast (E1804), the focus color, token names and `keel test`'s render checks judge the library's defaults. A look the fixture holds through a spread of the shipped object is judged (k.a11y-static Message) at its key in `src/<id>Tokens.ts`. `keel pack` runs all of it in its `check` step.

**Rules.** E1810 a listed library's needed name the app's tokens lack (Message; fix: Fix) · E1811 a library file's token name its shipped tokens lack (`<prop>="<value>" is not in <id>Tokens`, `breakpoint "<key>" is not in <id>Tokens`, `look="<value>" is not in <id>Tokens`; with no `./tokens` entry each ends `: <name> ships no ./tokens entry` in place of ` is not in <id>Tokens`; `<value>` clipped at 20 units as k.check Diagnostics clips a message (its first 17 units and `...`); fix: none) · E1812 a `./tokens` entry whose `keel` target is not `./src/<id>Tokens.ts`, at `exports` (`./tokens keel target is not ./src/<id>Tokens.ts`), or a shipped tokens file out of form, at the first node out of form (`<id>Tokens.ts holds <what>; it is one defineTokens literal`, `<what>` one of `another import`, `another statement`, `a spread`, `a type assertion` (`as`, `satisfies`), `a computed value`; `<id>Tokens names <group> "<token>" without <id>.`; `<id>Tokens holds base`; `<id>Tokens holds schemes`; `look "<look>" names <group> "<token>", not in <id>Tokens`; `<id>Tokens fails TokenSchema at <path>`; fix: none) · E1815 a listed library's `exports` entry holding `keel` other than first (Entries; fix: none) · E1813 a name with a `.` in the app's tokens that no listed library ships, or a fixture key overriding a default (In an app, Own folder; fix: none).

**Conformance.** The fixture: a project whose `modules/shop/module.ts` lists `'@acme/ui'` in `deps`, `node_modules/@acme/ui/` holding the k.library fixture's files with `id: 'acme'`, `exports` `{".":{"keel":"./src/index.ts","default":"./index.js"},"./tokens":{"keel":"./src/acmeTokens.ts","default":"./index.js"}}`, `src/acmeTokens.ts` holding `export const acmeTokens = defineTokens({ color: { 'acme.accent': '#0B5CAD', 'acme.ink': '#FFFFFF' }, look: { 'acme.badge': { bg: 'acme.accent', fg: 'acme.ink' } } })` with its import, and `src/Badge.tsx` rendering ``<Text id={`${props.id}.text`} look="acme.badge">x</Text>``.
- In the fixture with `tokens.ts` `import { brandTokens } from "@keel/ui/brand";` and `export const tokens = brandTokens;`, `keel check` reports one E1810 at `tokens` with message `@acme/ui needs color "acme.accent" and 2 more; import acmeTokens from @acme/ui/tokens` and no E1801.
- Applying that fix makes `tokens` `defineTokens({ ...brandTokens, color: { ...brandTokens.color, ...acmeTokens.color }, look: { ...brandTokens.look, ...acmeTokens.look } })` with `defineTokens` and `acmeTokens` imported, and the next `keel check` reports no diagnostic.
- In the fixed project with `'acme.accent': '#b8420d'` after `...acmeTokens.color`, `keel check` reports no diagnostic and `keel build`'s CSS holds `--k-color-acme-accent:#b8420d` and no `#0B5CAD`.
- In the fixed project, a `color` key `'acme.acent': '#000000'` is one E1813 with message `color "acme.acent": @acme/ui ships no such token`, and a key `'zed.x': '#000000'` is one E1813 with message `color "zed.x": no library the app lists has id zed`.
- In the fixed project with the `look` spread removed, `keel check` reports one E1810 with message `@acme/ui needs look "acme.badge"; spread acmeTokens.look`.
- In the fixture with no `tokens.ts`, `keel check` reports one E1810 at the `'@acme/ui'` entry, with no fix.
- In the fixed project, `p="2"` on the badge's `Text` is one E1811 at the literal with message `p="2" is not in acmeTokens`; with the `./tokens` entry and `src/acmeTokens.ts` removed and `look` dropped, `p="2"` is one E1811 with message `p="2": @acme/ui ships no ./tokens entry`.
- `src/acmeTokens.ts` given a spread `...other` in `color` is one E1812 at the spread with message `acmeTokens.ts holds a spread; it is one defineTokens literal`; a `color` key `'accent'` is one E1812 with message `acmeTokens names color "accent" without acme.`; a `"./tokens"` `keel` target `./src/tokens.ts` is one E1812 at `exports`.
- In the library's own folder with root `tokens.ts` composing the shipped object as the fix writes it, `keel check` reports one E1804 at the `'acme.badge'` key of `src/acmeTokens.ts` with message `look.acme.badge: fg "acme.ink" on bg "acme.accent" is 4.42:1 in light, needs 4.5:1` when `acme.accent` is `#787878`, and none when it is `#0B5CAD`.
- In that own folder, a fixture key `'acme.accent': '#000000'` after the spread is one E1813 with message `color "acme.accent": the fixture overrides acme's default`, and `keel pack` then reports it and one E1164 naming `check`.
- With `border: { 'acme.edge': '1px solid var(--k-color-acme-accent)' }` shipped and composed, the CSS declares `--k-color-acme-accent` and `--k-border-acme-edge:1px solid var(--k-color-acme-accent)`, and a `border="acme.edge"` element's rule is `border:var(--k-border-acme-edge)`.
- In the fixed project, `"./tokens":{"default":"./evil.js","keel":"./src/acmeTokens.ts"}` is one E1815 at the `'@acme/ui'` entry with message `@acme/ui exports "./tokens" lists keel after another condition`, and `evil.js`, which writes a file when run, writes none during `keel check`; `"./tokens":{"import":{"keel":"./src/acmeTokens.ts"}}` and `".":{"node":"./index.js","keel":"./src/index.ts"}` are each one E1815.
- In the fixed project with `schemes: ['light', 'dark']` and `'acme.ink': { light: '#FFFFFF', dark: '#FFFFFF' }` shipped against an `acme.accent` of `{ light: '#0B5CAD', dark: '#787878' }`, `keel check` reports one E1804 at the spread `...acmeTokens.color` in `tokens.ts` with message `acme.ink on acme.accent is 4.42:1 in dark, needs 4.5:1; override in tokens.ts` and none under `node_modules/`.
- `src/acmeTokens.ts` with `defineTokens({ ... } as const)` is one E1812 with message `acmeTokens.ts holds a type assertion; it is one defineTokens literal`.
- With `tokens.ts`'s last import line `import { brandTokens } from "@keel/ui/brand"; // brand`, E1810's fix leaves that line as it is and adds the import on the line after it.
