# k.leave: What a request leaves
status: implemented

What a request `createApp` serves (k.server) leaves in its document, in process-wide state and in the process after its response.

**Snapshots.** `#k-state` `stores` holds a request store's snapshot only when an island needs it to resume: the store was created, looked up through `stores()` or read (`get`, `select`, `snapshot`, `log`, `head`) while an island root level's component rendered on the server (k.runtime). A store only a guard, loader, action or static level touched is not in it; nor is a factory store. A document with no island has `stores` `{}`. `#k-state` is not a k.privacy sink: a snapshot holds the store's state and log as they are, `.pii()` values included; E1107 checks them. No `s.secret` value reaches a snapshot: a state schema holding one throws E1303, and a snapshot folds every log entry up to the last secret payload (k.store).

**E1107.** The check judges each `store` call of `@keel/store`, under any local name, as a namespace member, through a `const` alias or a project re-export, in a client-reachable file (k.boundary Reach) of a `node` or `static` module, or in a file outside every module that such a module's file imports, directly or not (k.boundary Following). It is E1107 at the call when the state schema holds a `.pii(class)` node of a class the module manifest's `clientPii` (`PiiClass[]`, default empty) does not list (for a file outside every module, the `clientPii` of each module importing it): `store state reaching #k-state holds .pii('<classes>'), not in clientPii`, the classes cut to fit 89 units; the fix adds the classes, none when more than one manifest lacks them. Also E1107, no fix, in such a file: a state schema the static read (k.privacy-reads) answers `'unknown'` for, a `.pii()` whose class is not a string literal among them, `store state not readable at <part>; cannot show its .pii() classes`, `<part>` the first part of the file the read could not take (a call as its callee and `()`), cut from its front to fit 89 units; `stores()`, `stores() in client code can send every request store to #k-state`; and `store` or `stores` of `@keel/store` used other than as a callee or through an alias above, `<name> of @keel/store used other than as a call; check cannot follow it`. A file of a module only `client` deployables list writes no `#k-state` and is not judged; a store a package creates is the package's.

**Store makers.** In a library's file (k.library), neither server-only nor test code, a `store` call or a store maker's call whose state schema the read can take but for parts each a parameter, or a non-computed member of one, of the top-level function holding it (a function declaration or a `const` bound to a function expression or arrow) is not judged there. That function is then a store maker holding the classes the read took. Each call of a maker, by name through imports, re-exports and the library's entries or as a namespace member, is judged as a `store` call is, at its first character, holding the maker's classes and its state schema's: the caller's argument at each such parameter, then the field each member names of an object literal or a `const` bound to one; a destructuring parameter stands for its whole argument. A step that cannot be taken (a spread or computed key, a literal without the field, any other value) reads the value reached; a missing argument reads nothing. An argument the read cannot take, one at or after a spread argument (`<part>` the spread), and a call of a maker whose chain to a `store` call passes 16 other makers (`<part>` its callee and `()`; it makes no maker) are E1107 `store state not readable at <part>; …` at the call. In judged code, a maker's name or a namespace member naming one used other than as a callee, export specifier or `export default`, and a namespace holding a maker used but through a non-computed member, are E1107 at the name, `store maker <name> used other than as a call; check cannot follow it`, `<name>` as written. In any state schema, `s.enum` and `s.literal` arguments (`@keel/schema`) are values, not read.

**Restore.** At resume, a snapshot its store refuses (`restore` returns `err`), whether in `stores` or created by an island, is the warning `E1253 #k-state snapshot for store "<id>" does not restore`; the store keeps its initial state.

**Module stores.** During a request every state-changing operation on a module store throws E1256 and changes nothing: `tx`, `restore` (but a store's own from a waiting `#k-state` snapshot as it is created), `undo` and `undoWhere`. The request's mark follows async context, not data, through every `await`, timer and promise the request schedules, after its response too: a guarded operation there throws E1256. A callback registered outside a request (at module load, in a runner, at startup) is not checked, even when a request resolves its promise or fills the queue it drains.

**Process.** The production entry (`server.mjs`, k.deploy) and `keel dev` handle every `uncaughtException` and `unhandledRejection`; `createApp` adds no process listener. Each writes one `diag` record E1577 `uncaught <exception|rejection> in work of route <id>`, `<id>` the route of the request in whose async context the work failed, else `-`, with the error's `frames` and no thrown text. In production the first stops the server listening, lets requests in flight finish within 10,000 ms, calls `close()` (k.topology) and the storage driver's `close()`, and exits 1; a later one during that drain writes its record and changes nothing else. `keel dev` appends the thrown text, scrubbed and cut (k.serverlog), and keeps serving.

**Rules.** E1107 a `.pii()` class reaching `#k-state` that `clientPii` does not list (fix adds it) · E1577 an uncaught exception or unhandled rejection in a served process.

**Conformance.** `R(c)` and `U(p)` are E1107's `store state reaching …` for class `c` and `… not readable at …` for part `p`.
- A route whose loader creates stores `a` (a `.pii('contact')` field) and `p`, and whose island page's component reads `p` and creates `b`, serves `#k-state` `stores` with `b` and `p` only; with a static page instead, the document has no module script and `stores` is `{}`.
- A static layout whose render creates store `c`, around an island page that creates `b`: `stores` has `b`, not `c`; the value of a `.pii('contact')` field of `b` is in `#k-state` as the page rendered it.
- `store(Contact, …)` with `email: s.string().pii('contact')` in a component file is E1107 when the module has no `clientPii`, and with `clientPii: ['name']`; with `clientPii: ['contact']`, or in a `*.server.ts` file, it is not; the fix adds `'contact'`.
- In a loader, `restore`, `undo` and `undoWhere` on a module store each throw E1256 and leave its state and head as they were; a store an island creates from a waiting snapshot while resuming restores with no E1256.
- An action that schedules `setTimeout(() => tx(t, p), 30)` and returns `ok(null)` answers before the write; the write throws E1256 and the module store is unchanged.
- A promise made at module load whose `.then` writes a module store, resolved by a loader, commits the write with no E1256.
- `server.mjs` of a fixture whose loader `/late` schedules a throw 30 ms after its 200: one E1577 json `diag` naming route `late` and not the thrown text; a new connection is then refused, a request in flight completes, and the process exits 1 within 11 s. A rejection at module scope names route `-`.
- Under `keel dev` the same throw writes one E1577 holding the thrown text, and a later GET answers 200.
- `createApp` leaves `process.listenerCount('uncaughtException')` and `('unhandledRejection')` as they were.
- A store in `stores`, and one an island creates, each given a `#k-state` snapshot its schema refuses: `resume` warns E1253 for each, and each store holds its initial state.
- In a `node` module with no `clientPii`, `store(Contact, …)` (`email: s.string().pii('contact')`) in `modules/a/contacts.ts`, a file only `modules/a/load.server.ts` imports, is one E1107 whose fix adds `'contact'`; so is `k.store(Contact, …)` (`import * as k from '@keel/store'`), `mk(Contact, …)` (`const mk = store`), and `store(Contact, …)` with `store` from `lib/st.ts` holding `export { store } from '@keel/store'`; it is none in `modules/a/contacts.server.ts` and in a module only a `client` deployable lists.
- In that module, in `modules/a/Page.tsx`: `store(S, …)` (`const S = make()`) and `store(s.object({ e: s.string().pii(c) }), …)` (`c` a parameter) are one E1107 each, messages `U(make())` and `U(s.string().pii())`; `stores()` from `@keel/store` is one E1107, its message above, also when `clientPii` lists every class; `register(store)` is one E1107 at `store`, message `<name> of @keel/store …` naming `store`; none has a fix.
- `store(Contact, …)` in `lib/contacts.ts`, outside every module, imported by `modules/a/Page.tsx` and `modules/b/Page.tsx` of `node` modules: one E1107 at the call with no fix when neither `a` nor `b` lists `contact`, and one whose fix adds `'contact'` to `b`'s `clientPii` when only `a` lists it.
- In `modules/a/Page.tsx` of a `node` module with no `clientPii`, `store(s.object({ v: line({ max: 40 }) }), …)` (`line` from `@keel/std-text`), and `store(tablePage(s.object({ n: s.string() })), …)` (`tablePage` from `@keel/std-tables`), report no E1107 (k.privacy-reads Factories); `store(tablePage(s.object({ e: s.string().pii('contact') })), …)` is one E1107 whose fix adds `'contact'`.
- Let `CHARTS` be a library under `node_modules/@acme/charts/`: `package.json` `{"name":"@acme/charts","version":"1.0.0","type":"module","keel":"library","exports":{".":"./src/index.ts"}}`, a `module.ts` with `id: 'charts'`, `deps: []`, `capabilities: []` and `public: { exports: ['chart', 'wrap', 'leaky'] }`, `src/index.ts` `export { chart, wrap, leaky } from './chart.ts'`, and `src/chart.ts`, importing `s` (`@keel/schema`) and `store` (`@keel/store`), holding `export function chart(id: string, spec: { data: unknown; states: string[] }) { const [first, ...rest] = spec.states; return store(s.object({ state: s.enum([first, ...rest]), data: spec.data }), {}, { id }) }`, `export const wrap = (id: string, data: unknown) => chart(id, { data, states: ['a'] })`, `export function leaky(id: string) { const local = make(); return store(s.object({ data: local }), {}, { id }) }` and `function make() { return s.string() }`. In a project with no `topology.ts` holding `CHARTS` and module `shop` (`deps: ['@acme/charts']`, no `clientPii`), with `P` = `s.object({ e: s.string().pii('contact') })`: `chart('shop.a', { data: P })` in `modules/shop/Page.tsx` is one E1107 at the call's first character, message `R(contact)`, whose fix adds `'contact'`; so are `c.chart('shop.a', { data: P })` (`import * as c from '@acme/charts'`) and `wrap('shop.a', P)`; none is in `modules/shop/load.server.ts`, with `clientPii: ['contact']`, or for `chart('shop.a', { data: s.string() })`; the only E1107 under `node_modules/@acme/charts/` is at the first argument of `leaky`'s `store` call, message `U(local)`.
- In that project, in `modules/shop/Page.tsx` with `const make = () => s.string()`: `chart('shop.a', { data: make() })` is one E1107 at the call, message `U(make())`, no fix; `chart('shop.a', { data: s.string(), start: make() })`, `chart('shop.a')` and `leaky('shop.a')` are none; `store(s.object({ k: s.enum([a, b]), l: s.literal(a) }), {}, { id: 'shop.k' })` (`a`, `b` parameters of the enclosing function) is none.
- With `CHARTS` also exporting `secret` (`src/index.ts`, `public.exports`), a copy of `chart` whose `s.object` also holds `ssn: s.string().pii('ssn')`: `secret('shop.a', { data: s.string() })` in `modules/shop/Page.tsx` is one E1107 at the call, message `R(ssn)`, fix adds `'ssn'`; none with `clientPii: ['ssn']`.
- In that project's `modules/shop/Page.tsx` with `const apply = (f: unknown) => f`: `const m = chart`, `apply(chart, P)` and `[c.chart]` are one E1107 each at the name, `store maker <name> …` with `<name>` `chart`, `chart` and `c.chart`, no fix; `ch('shop.a', { data: P })` (`import { chart as ch } from '@acme/charts'`) is one E1107 at the call, message `R(contact)`.
- There, `chart(...pre, { data: P })` (`const pre: [string] = ['shop.a']`) is one E1107 at the call, message `U(...pre)`, no fix.
