# k.leave: What a request leaves
status: implemented

What a request `createApp` serves (k.server) leaves in its document, in process-wide state and in the process once its response has gone out.

**Snapshots.** `#k-state` `stores` holds a request store's snapshot only when an island needs it to resume: the store was created, looked up through `stores()` or read (`get`, `select`, `snapshot`, `log`, `head`) while a level's component rendered on the server, that level being an island root (k.runtime). A store only a guard, loader, action or static level touched is not in it, however much it holds; nor is a factory store (k.server). A document with no island has `stores` `{}`. `#k-state` is not a k.privacy sink: a snapshot holds the store's state and log as they are, so a `.pii()`-marked value in a store an island creates reaches the browser, as the island needs it to render. The check reports E1107 (below). No `s.secret` value reaches a snapshot: a state schema holding one throws E1303, and a snapshot folds every log entry up to the last secret payload (k.store).

**E1107.** The check judges each `store` call of `@keel/store`, under any local name, as a namespace member, through a `const` alias or a project re-export, in a client-reachable file (k.boundary Reach) of a `node` or `static` module, or in a file outside every module that such a module's file imports, directly or not (k.boundary Following). It reports E1107 at the call when the state schema holds a `.pii(class)` node of a class the module manifest's `clientPii` (a list of `PiiClass`, default empty) does not list, for a file outside every module the `clientPii` of each module whose files import it: `store state reaching #k-state holds .pii('<classes>'), not in clientPii`, the classes cut to fit 89 units; the fix adds the classes, none when more than one manifest lacks them. Also E1107, no fix, in such a file: a state schema the static read (k.privacy-reads) answers `'unknown'` for, a `.pii()` whose class is not a string literal among them, `store state not readable at <part>; cannot show its .pii() classes`, `<part>` the first part of the file the read could not take (a call as its callee and `()`), cut from its front to fit 89 units; a call of `stores()`, by which an island root puts every live request store, a loader's among them, in `#k-state`, `stores() in client code can send every request store to #k-state`; and `store` or `stores` of `@keel/store` used other than as a callee or through an alias above (passed as a value, destructured from a namespace, a computed member), `<name> of @keel/store used other than as a call; check cannot follow it`. A file of a module only `client` deployables list writes no `#k-state` and is not judged; a store a package creates is the package's.

**Store makers.** In a library's file (k.library) that is neither server-only nor test code, a `store` call, or a call of a store maker, whose state schema the read can take but for parts each of which is a parameter of the top-level function holding the call (a function declaration, or a `const` bound to an arrow or function expression), or a non-computed member of one (`spec.data`), makes that function a store maker and is not judged in the library. Each call of a maker, by its name through imports and the library's entries or as a namespace member (`c.chart`), is judged as a `store` call is, at the call's first character. Its state schema is the caller's argument at each such parameter, then the field of an object literal, or of a `const` bound to one, each member names (`spec.data` of `chart(id, spec)`: `data` of the second argument); a parameter written as a destructuring pattern stands for its whole argument. A step that cannot be taken (a spread or computed key, a literal without the field, any other value) reads the value reached so far, and a missing argument reads nothing. An argument the read cannot take is E1107 `store state not readable at <part>; …` at the call. In any state schema, the arguments of `s.enum` and `s.literal` of `@keel/schema` are values and are not read.

**Restore.** At resume, a snapshot its store refuses (`restore` returns `err`), whether the store is in `stores` or an island creates it, is the warning `E1253 #k-state snapshot for store "<id>" does not restore`; the store keeps its initial state.

**Module stores.** During a request every state-changing operation on a module store throws E1256 and changes nothing: `tx`, `restore` (but the one a store makes from a waiting `#k-state` snapshot while it is created), `undo` and `undoWhere`. The request's mark follows async context, not data, through every `await`, timer and promise the request schedules, for their whole life: work a request starts and that runs after its response has gone out is still checked, and a guarded operation there throws E1256. A callback registered outside a request (at module load, in a runner, at startup) is not checked, even when a request resolves its promise or fills the queue it drains.

**Process.** The production entry (`server.mjs`, k.deploy) and `keel dev` handle every `uncaughtException` and `unhandledRejection`; `createApp` adds no process listener, so a process that embeds it chooses its own. Each writes one `diag` record E1577 `uncaught <exception|rejection> in work of route <id>`, the route id of the request whose async context the failing work ran in, else `-`, with the error's `frames` (k.deploy) and no thrown text. In production the first one then stops the server listening, lets requests in flight finish for at most 10,000 ms, calls `close()` (k.topology) and the storage driver's `close()`, and exits 1, so a supervisor restarts it; a later one during that drain writes its record and changes nothing else. `keel dev` appends the thrown text, scrubbed and cut (k.serverlog), and keeps serving.

**Rules.** E1107 a `.pii()` class reaching `#k-state` that `clientPii` does not list (fix adds it) · E1577 an uncaught exception or unhandled rejection in a served process.

**Conformance.**
- A route whose loader creates stores `a` (a `.pii('contact')` field) and `p`, and whose island page's component reads `p` and creates `b`, serves `#k-state` `stores` with `b` and `p` only; with a static page instead, the document has no module script and `stores` is `{}`.
- A static layout whose render creates store `c`, around an island page that creates `b`: `stores` has `b`, not `c`; the value of a `.pii('contact')` field of `b` is in `#k-state` as the page rendered it.
- `store(Contact, …)` with `email: s.string().pii('contact')` in a component file is E1107 when the module has no `clientPii`, and with `clientPii: ['name']`; with `clientPii: ['contact']`, or in a `*.server.ts` file, it is not; the fix adds `'contact'`.
- In a loader, `restore`, `undo` and `undoWhere` on a module store each throw E1256 and leave its state and head as they were; a store an island creates from a waiting snapshot while resuming restores with no E1256.
- An action that schedules `setTimeout(() => tx(t, p), 30)` and returns `ok(null)` answers before the write; the write throws E1256 and the module store is unchanged.
- A promise made at module load whose `.then` writes a module store, resolved by a loader, commits the write with no E1256.
- `server.mjs` of a fixture whose loader `/late` schedules a throw 30 ms after its 200: one E1577 json `diag` naming route `late` and not the thrown text; a new connection is then refused, a request in flight completes, and the process exits 1 within 11 s. A rejection at module scope names route `-`.
- Under `keel dev` the same throw writes one E1577 holding the thrown text, and a later GET answers 200.
- `createApp` leaves `process.listenerCount('uncaughtException')` and `('unhandledRejection')` as they were.
- A store in `stores`, and one an island creates, each given a `#k-state` snapshot its schema refuses: `resume` warns `E1253 #k-state snapshot for store "<id>" does not restore` for each, and each store holds its initial state.
- In a `node` module with no `clientPii`, `store(Contact, …)` (`email: s.string().pii('contact')`) in `modules/a/contacts.ts`, a file only `modules/a/load.server.ts` imports, is one E1107 whose fix adds `'contact'`; so is `k.store(Contact, …)` with `import * as k from '@keel/store'`, `mk(Contact, …)` with `const mk = store`, and `store(Contact, …)` with `store` imported from `lib/st.ts` holding `export { store } from '@keel/store'`; in `modules/a/contacts.server.ts` it is none, and in a module only a `client` deployable lists it is none.
- In that module, in `modules/a/Page.tsx`: `store(S, …)` with `const S = make()`, and `store(s.object({ e: s.string().pii(c) }), …)` with `c` a parameter, are one E1107 each, with messages `store state not readable at make(); cannot show its .pii() classes` and `store state not readable at s.string().pii(); cannot show its .pii() classes`; `stores()` from `@keel/store` is one E1107 with message `stores() in client code can send every request store to #k-state`, also when `clientPii` lists every class; `register(store)` is one E1107 at `store` with message `store of @keel/store used other than as a call; check cannot follow it`; none has a fix.
- `store(Contact, …)` in `lib/contacts.ts`, outside every module, imported by `modules/a/Page.tsx` and `modules/b/Page.tsx` of `node` modules: one E1107 at the call with no fix when neither `a` nor `b` lists `contact`, and one whose fix adds `'contact'` to `b`'s `clientPii` when only `a` lists it.
- In `modules/a/Page.tsx` of a `node` module with no `clientPii`, `store(s.object({ v: line({ max: 40 }) }), …)` with `line` from `@keel/std-text`, and `store(tablePage(s.object({ n: s.string() })), …)` with `tablePage` from `@keel/std-tables`, report no E1107 (k.privacy-reads Factories); `store(tablePage(s.object({ e: s.string().pii('contact') })), …)` is one E1107 whose fix adds `'contact'`.
- Let `CHARTS` be a library under `node_modules/@acme/charts/`: `package.json` `{"name":"@acme/charts","version":"1.0.0","type":"module","keel":"library","exports":{".":"./src/index.ts"}}`, a `module.ts` with `id: 'charts'`, `deps: []`, `capabilities: []` and `public: { exports: ['chart', 'wrap', 'leaky'] }`, `src/index.ts` `export { chart, wrap, leaky } from './chart.ts'`, and `src/chart.ts` importing `s` from `@keel/schema` and `store` from `@keel/store` and holding `export function chart(id: string, spec: { data: unknown; states: string[] }) { const [first, ...rest] = spec.states; return store(s.object({ state: s.enum([first, ...rest]), data: spec.data }), {}, { id }) }`, `export const wrap = (id: string, data: unknown) => chart(id, { data, states: ['a'] })`, `export function leaky(id: string) { const local = make(); return store(s.object({ data: local }), {}, { id }) }` and `function make() { return s.string() }`. In a project with no `topology.ts` holding `CHARTS` and module `shop` (`deps: ['@acme/charts']`, no `clientPii`), with `P` the schema `s.object({ e: s.string().pii('contact') })`: `chart('shop.a', { data: P })` in `modules/shop/Page.tsx` is one E1107 at the call's first character, message `store state reaching #k-state holds .pii('contact'), not in clientPii`, whose fix adds `'contact'`; so are `c.chart('shop.a', { data: P })` with `import * as c from '@acme/charts'` and `wrap('shop.a', P)`; none is reported in `modules/shop/load.server.ts`, with `clientPii: ['contact']`, or for `chart('shop.a', { data: s.string() })`; and the only E1107 under `node_modules/@acme/charts/` is one at the first argument of `leaky`'s `store` call, message `store state not readable at local; cannot show its .pii() classes`.
- In that project, in `modules/shop/Page.tsx` with `const make = () => s.string()`: `chart('shop.a', { data: make() })` is one E1107 at the call, message `store state not readable at make(); cannot show its .pii() classes`, no fix; `chart('shop.a', { data: s.string(), start: make() })`, `chart('shop.a')` and `leaky('shop.a')` are none; `store(s.object({ k: s.enum([a, b]), l: s.literal(a) }), {}, { id: 'shop.k' })` with `a` and `b` parameters of the enclosing function is none.
