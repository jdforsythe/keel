# k.themes: Themes and combinations
status: proposed

A theme re-values tokens an app already holds; a combination is the set of values a visitor sees at once. Schemes and the first paint are k.schemes; value forms are k.values; contrast per combination is k.a11y-static. Here too: E1807's place and words, where the check-time entries may be imported (E1818), and the E1816 and E1817 fixes.

**Themes.** `themes` in `tokens.ts` maps a name to a theme: an optional `when` and any of the groups `color`, `overlay`, `space`, `size`, `radius`, `font`, `fontSize`, `weight`, `shadow` and `border`, each holding only names its top-level group holds, each value in its group's form, an overlay's as its `value` with no `over`. `when` is `choice` (the default: a visitor picks it), `contrast` (on under `prefers-contrast: more`) or `print` (on when printing; it holds no pair). A name is a letter from `a` to `z` then up to 23 letters and digits, not `default`, `system`, `light` or `dark`. At most one theme is `contrast`, at most one is `print`, and at most 8 are `choice`. Anything else fails `TokenSchema` (E1807). `breakpoint`, `motion`, `base` and `look` take no theme: a media query reads no custom property, and a theme changes values, never classes.

**Combinations.** A visitor sees one combination of the tokens (k.schemes): a scheme, at most one `choice` theme, the `contrast` theme on or off and, when printing, the `print` theme, in the light scheme. Its values are the top-level ones, the scheme's value of each pair, then each theme that is on in the order `choice`, `contrast`, `print`, a later value winning and a theme's pair giving the scheme's value. Its name joins with `+` the scheme, or `print` when printing, then the themes on: `light`, `dark+slate`, `print+slate+hc`. The app's combinations, in order: per scheme in `schemes` order, then printing when it has a `print` theme, no `choice` theme and then each in `themes` order, each with the `contrast` theme off and then, when it has one, on. `combinations(tokens)` from `@keel/ui/css` lists them as `{ name, tokens }`, `tokens` that combination's values with no `themes` and no pair; for tokens `TokenSchema` refuses (9 `choice` themes, a second `contrast` or `print`, Themes) it throws E1807 as `defineTokens` does, so it never lists more than 54. In each printing combination E1804 (k.a11y-static) reads a responsive `fg` or `bg` by its `print` key written as a string literal, judged as the `print` theme's values are; with no `print` key, or on screen, a responsive value stays unread (k.a11y-static Values).

**Library themes.** A library's shipped object (k.looks Shipped tokens) may hold `themes` with the keys `contrast` and `print` only, each a theme with no `when` holding names its own groups hold; any other key is E1812 `<id>Tokens holds themes "<key>"; only contrast and print`. The app's `contrast` theme holds every name the shipped `contrast` holds, and its `print` theme every name of the shipped `print`, else E1810 `<name> needs themes.<theme> <group> "<token>"; spread <id>Tokens.themes.<key>.<group>`, whose fix adds that spread to the theme's group as k.looks Fix adds one to a group. A `choice` theme takes the library's top-level values; the app may re-value an `<id>.` name in it, held as a top-level key is (E1813). In a library's own folder, a shipped `contrast` or `print` is judged as a theme of that `when`, whatever the root `tokens.ts` writes; when the root has a theme of that `when`, the two are judged as one, the shipped values over the root's, so the fixture can give its other names a contrast or print value.

**Token errors.** E1807 (k.ui) for tokens `TokenSchema` refuses, whether `keel check` judges the `tokens` export or a `defineTokens` call throws (its error carries the issues), reports the first issue in `TokenSchema`'s order. It sits at the key in `tokens.ts` that writes the issue path's last segment, its line and the column of its first character (a quoted key's opening quote); for a path `tokens.ts` writes through a spread or from another file, at the `...` of the last spread in the deepest object literal of `tokens.ts` on the path. A count past its bound (a second `contrast` or `print` theme, a ninth `choice` theme) is at that theme, the later in source order. The message is `<path>: <what>`, `<path>` the issue path joined by `.`, and `see` is the section holding the rule:
- k.themes: `default, system, light and dark are reserved`, `a theme name is a letter then up to 23 letters and digits`, `when is choice, contrast or print`, `<group> takes no theme` (path `themes.<theme>.<group>`), `not a top-level <group> token`, `a print theme takes one value, not a pair`, `a second contrast theme`, `a second print theme`, `a ninth choice theme; at most 8`;
- k.values: `channels are separated by spaces, not commas` (a function color holding `,`), `a named color; write hex or a function form`, `alpha is for an overlay or a shadow`, `names no color token "<name>"` and `holds 1 to 8 distinct names` (path `overlay.<name>.over`), and `not a <group> value` for any other refused value;
- k.schemes: `is ["light"], ["dark"] or ["light", "dark"]`;
- k.ui: `is no token group`, `is no key here` (any other unknown key), and `under 3:1 on base.page's bg in <combination>` (path `base.focus`, whose value is a color token's name).

When the message would pass 89 units, `<path>` drops leading segments behind one `.../` until it fits, and a last segment still too long keeps its first units and `...`, so `: <what>` is never cut, in any format, `--format=json` among them. E1810's theme message, E1816 and E1817 fit alike: each name in them, the longest first, keeps its first units and `...` until the message is 89 units, so no fixed word is cut. A `tokens.ts` that throws otherwise is `tokens.ts throws: <line>`, the first line of its message clipped at 60 units by k.check Diagnostics' clip, and one with no `tokens` export `tokens.ts exports no tokens`, each at line 1, column 1, `see` k.a11y-static.

**Check-time entries.** `@keel/ui/tokens` (`defineTokens`, `TokenSchema`, the value forms) and `@keel/ui/css` (`compileStyles`, `combinations`, `contrast`, `contrastTable`) run under Node only: in `keel check`, `keel build`, `keel dev` and tests. A value import of either (`import`, `export ... from` or `import()`; `import type` is free, `Tokens` among the types) is E1818 at its specifier in each code file (k.check Trailer) of an app or library, but in a server-only file (k.boundary), a test file (`*.test.*`, `*.spec.*`) and a tool config (`*.config.*`), and in `tokens.ts` at a project root, each file it imports and a library's `src/<id>Tokens.ts` (k.looks) while no client entry reaches them: no route `component` and no file of a `client` module, by value imports, re-exports and `import()` (k.boundary Following). Message: `<entry> is check and build time only; use token names or @keel/ui/brand`, `<entry>` `@keel/ui/tokens` or `@keel/ui/css`; fix: none.

**Fixes.** E1816 (k.schemes Rules), with `labels` an object literal: for `labels lack <name>` the fix adds `<name>: "<name>"` after its last property; for `labels name no theme <key>` it deletes that property and its comma. For `needs a choice theme`, at a JSX element, it deletes the element and, when that was the file's one use of its `ThemeSelect` import, that specifier, or the whole import declaration when it held no other. E1817 (k.a11y-static Overlays) `sits on "<backdrop>", not in its over`, when the overlay's `over` in `tokens.ts` is an array literal of fewer than 8 names: the fix, in `tokens.ts`, adds `"<backdrop>"` after its last element. An overlay on an overlay has none: `over` names only colors.

**Conformance.**
- `themes: { slate: { color: { text: '#222222' } } }` is accepted with a color token `text`; each of `themes: { light: {} }`, `themes: { a: { when: 'hover' } }`, `themes: { a: { color: { nope: '#000000' } } }`, `themes: { a: { breakpoint: { md: '1px' } } }`, `themes: { a: { look: {} } }`, `themes: { a: { when: 'print', color: { text: { light: '#000000', dark: '#ffffff' } } } }`, two themes with `when: 'print'` and nine themes with no `when` fails `TokenSchema`, each one E1807 in `tokens.ts`.
- With color tokens `text` `{ light: '#1a191e', dark: '#F3F3F3' }` and `surface` `{ light: '#F9F9F9', dark: '#141317' }` and `themes: { slate: { color: { surface: { light: '#F4F7FB', dark: '#10151C' } } }, hc: { when: 'contrast' }, paper: { when: 'print', color: { text: '#000000' } } }`, `combinations(tokens)` names, in order, `light`, `light+hc`, `light+slate`, `light+slate+hc`, `dark`, `dark+hc`, `dark+slate`, `dark+slate+hc`, `print`, `print+hc`, `print+slate`, `print+slate+hc`, and in `print+slate` `text` is `#000000` and `surface` `#F4F7FB`, in `dark+slate` `#F3F3F3` and `#10151C`; with nine `choice` themes it throws E1807.
- In the k.looks fixture with `acmeTokens` also holding `themes: { contrast: { color: { 'acme.accent': '#08427D' } } }` and the app's `tokens.ts` adding `themes: { hc: { when: 'contrast', color: {} } }`, `keel check` reports one E1810 with message `@acme/ui needs themes.hc color "acme.accent"; spread acmeTokens.themes.contrast.color`; after its fix, none, and the CSS's `keel.contrast` layer declares `--k-color-acme-accent:#08427D`; a shipped `themes: { slate: {} }` is one E1812 with message `acmeTokens holds themes "slate"; only contrast and print`.
- With `tokens.ts` holding, at its line 4, column 5, the key of `light: {}` in `themes`, of `text: { light: '#000000', dark: '#ffffff' }` in the `color` of a theme `paper` with `when: 'print'`, or of `accent: 'rgb(184, 66, 13)'` in `color`, each alone, `keel check --format=json` reports one E1807 at line 4, column 5 with, in turn, message `themes.light: default, system, light and dark are reserved` and `see` `k.themes`, `themes.paper.color.text: a print theme takes one value, not a pair` and `k.themes`, and `color.accent: channels are separated by spaces, not commas` and `k.values`.
- With `color: { ...designTokens.color, text: '#222222' }` in `tokens.ts` and `designTokens.color.ink` `'red'`, the one E1807 is at that spread's `...` with message `color.ink: a named color; write hex or a function form`; a `tokens.ts` that throws `new Error('boom')` is one E1807 at line 1, column 1 with message `tokens.ts throws: boom`; with a color token named by 80 `x`s given a pair in a `print` theme `paper`, the message is at most 89 units and ends `: a print theme takes one value, not a pair`, in compact and in `--format=json`, and an E1817 for an overlay named by 80 `s`s ends `, not in its over`.
- In a project with a `node` module `a`, `import { defineTokens } from '@keel/ui/tokens'` in route component `modules/a/A.tsx` is one E1818 at the specifier with message `@keel/ui/tokens is check and build time only; use token names or @keel/ui/brand`, and `import { contrast } from '@keel/ui/css'` in `lib/tone.ts`, which `A.tsx` imports, one with `@keel/ui/css`; there is none for those imports in `tokens.ts`, in `tokens.design.ts` that only `tokens.ts` imports, in `modules/a/A.test.tsx`, in `vite.config.ts` or in `modules/a/a.server.ts`, nor for `import type { Tokens } from '@keel/ui/tokens'` in `A.tsx`; when `A.tsx` also imports `tokens.ts`, `tokens.ts`'s import is one E1818; `keel build` with any E1818 exits 1 and writes no `dist/`.
- With color tokens `ink` `#ffffff`, `bg` `#1a191e`, `gray` `#BBBBBB` and `dark` `#000000` and `themes: { paper: { when: 'print', color: { bg: '#ffffff' } } }`, `<Text fg={{ base: 'ink', print: 'gray' }} bg="bg">x</Text>` is one E1804 whose message ends `in print, needs 4.5:1`, and with `print: 'dark'` none; without `paper`, `print: 'gray'` is none.
- With a theme `slate`, applying both E1816 fixes to `<ThemeSelect id="t" label="Theme" labels={{ default: 'Keel', forest: 'Forest' }} />` leaves `labels` evaluating to `{ default: 'Keel', slate: 'slate' }` and no E1816; with `brandTokens`, the fix for a file whose one use is `<ThemeSelect id="t" label="Theme" />`, imported by `import { Box, ThemeSelect } from '@keel/ui'`, deletes the element and leaves `import { Box } from '@keel/ui'`.
- With k.a11y-static's overlay tokens (`over: ['surface', 'card']`), the E1817 fix for `<Box bg="text"><Text fg="on" bg="scrim">x</Text></Box>` makes that `over` `['surface', 'card', "text"]`, after which `keel check` reports no E1817; with an `over` of 8 names, that E1817 has no fix.
