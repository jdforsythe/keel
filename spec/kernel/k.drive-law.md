# k.drive-law: Replays agree
status: implemented

The law two runs of one `SimRun` keep under `simulate` (k.sim, driven as k.drive says), and the law check that replays a run to compare its traces. An *empty replay* is as k.drive defines it.

**Law.** The drive draws no random and reads no real time. Two runs of one `SimRun` and one scenario take the same moments in the same order and report the same observer events (k.ctx) in the same order at the same `ctx.clock.now()`, ending with equal store snapshots. *The same moments* are the `ctx.clock.now()` at each completion the scenario sees (a waiter, a save, a net call); *store snapshots* are the final values of the storage keys the scenario wrote; observer events include the `net` events of the schedule's offline windows. The run's *trace* is the list of moments taken and observer events of the run's ctx and its replicas, each with its `ctx.clock.now()`. The run's trace ends with the final value of each storage key the run wrote, by key in code-unit order, then the snapshot of each live store (`stores()`), by id, its log entries without their `at`. Entries are `{ kind: 'moment', at }`, `{ kind: 'event', at, event }`, `{ kind: 'storage', key, value }`, `value` the stored string as stored, and `{ kind: 'store', id, value }`, `value` the store's snapshot with each log entry's `at` left out (a per-store counter no restore resets). What the law rests on: within the run's context every non-promise resource is pending; work that answers through something made outside the run changes nothing only if it is held with `hold`. Three things escape the tracker and can change a trace: a resource made before the run or outside its context (a worker started at import, a module-level timer, channel or `AsyncResource`), unless the work answering through it is held; an `import()` in app code other than a harness's `routes` loader, which the test runner answers over its own channel; state kept outside the run's stores from one run to the next. `keel check` reports none of them. The law check reports a difference only when `law` is on or on the replays of a failing run, and only when it reaches the trace.

**Law check.** `law` is on by default when `process.env.KEEL_TEST` is `'1'` as `simulate` is called (`keel test` sets it, k.testing), else off; `law: false` turns it off and `law: true` on, under `keel test` or not. With `law` on, after the last run each run that passed is run a second time with its `SimRun`, in run order, and the two traces are compared: a run's outcome is the one it has with `law` off, and a replay's own outcome is not read, only its trace. A failing run's shrunk `SimRun`, unless it failed with E1727 or E1728, is replayed twice before it is reported, whatever `law` is; each run tried while shrinking runs once. The replays share the run's budget (k.drive Stalls): when it runs out during a replay, that replay is stopped and not compared, no later run is replayed, and `simulate` resolves. `simulate` resolves `{ seed, runs, checked }`, `checked` the count of runs whose replay was compared (0 with `law` off). Two traces that differ, final values included, fail with E1729 (k.testing) `two replays of the run differ at trace entry <n>`, the two entries as JSON on the next two lines, in place of E1704.

**Conformance.**
- A scenario that starts ten waiters `ctx.clock.after(Math.floor(ctx.random.float() * 1000))`, each recording its index and `ctx.clock.now()` as it resolves, then awaits `run()`: under `simulate` with `{ runs: 20, seed: 7 }` each run's record lists all ten ordered by time, ties by index, and `replay` of the `SimRun` that run received records an equal list.
- Under `simulate` with `{ runs: 1, seed: 1, law: true }`, a scenario that awaits `ctx.clock.after(10 * k)`, `k` the count of its calls so far counting this one, rejects `simulate` with E1729 whose first line holds `two replays of the run differ at trace entry 0`.
- Under `simulate` with `{ runs: 1, seed: 1 }`, a scenario that awaits `ctx.clock.after(10 * k)`, `k` as above, then throws rejects `simulate` with E1729, not E1704; one that awaits `ctx.clock.after(10)` then throws rejects with E1704.
- Under `simulate` with `{ runs: 1, seed: 1, law: true }`, a scenario that sets storage key `n` to `String(k)`, `k` the count of its calls so far counting this one, and makes no other effect, rejects `simulate` with E1729 whose first line holds `two replays of the run differ at trace entry 0` and whose next two lines are `{"kind":"storage","key":"n","value":"1"}` and `{"kind":"storage","key":"n","value":"2"}`.
- With `process.env.KEEL_TEST` `'1'`, `simulate` with `{ runs: 1, seed: 1 }` of a scenario that awaits `ctx.clock.after(10 * k)`, `k` the count of its calls so far counting this one, and resolves rejects with E1729 whose first line holds `two replays of the run differ at trace entry 0`; with `law: false` added, or with `KEEL_TEST` unset and no `law`, it resolves `{ seed: 1, runs: 1, checked: 0 }`.
- Under `simulate` with `{ runs: 3, seed: 1, law: true }`, a scenario that appends `JSON.stringify({ seed, schedule })` to an array and awaits `ctx.clock.after(10)`: `simulate` resolves `{ seed: 1, runs: 3, checked: 3 }`, the array holds six entries, and its last three equal its first three in order.
- A capability registered with a `sim` factory whose `work()` returns `hold('probe', () => p)`, `p` resolved at the first `work()` call and never settling at later ones: in an empty replay with `{ law: true, budget: 300 }`, a scenario that awaits `work()` makes `simulate` resolve with `runs` 1 and `checked` 0, no sooner than 300 ms of real time after the call.
- In an empty replay with `law: true`, a scenario that counts its calls and throws rejects `simulate` with E1704 after exactly three calls; with `law: false`, the same.
