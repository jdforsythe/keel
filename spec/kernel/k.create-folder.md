# k.create-folder: The folder a new project is written into
status: implemented
How `create-app` (k.create) judges the folder it writes into, writes it all or nothing, and what it reads around it.

**Folder.** A folder is empty when it holds nothing but `.git`, `.DS_Store` and `Thumbs.db`. Any other entry is E1360, unless `--existing`; with it, every path the plan writes that exists is one E1361, at the first in sorted order, naming one, or counting several and listing each in `paths` (docs/OUTPUT.md). Where the folder's file system ignores case (the bin stats one of its entries under the other case), names are compared ignoring it: `agents.md` or `Modules/` collides with `AGENTS.md` or `modules/`, and E1361's `paths` holds both spellings. Each file is created only where none is, and never replaced; an app's `README.md` is left out where one exists. A run first creates `.keel-create`, listing every path it writes, and removes it last, so a run killed mid-write leaves a folder E1366 names. A failed write is E1365, a SIGINT or SIGTERM during the writes E1367 (exit 130 or 143): the files and folders this run made are removed. Writes are judged as k.scaffold Links says (E1357).

**Not done.** It starts no process (no install, no `git init`), opens no connection, reads no environment value but `npm_config_user_agent`, `KEEL_AGENT` and `CI`, writes only inside the folder (and the folders above it that it makes), and reads outside it only its own package and, in each folder above it, `package.json`, `pnpm-workspace.yaml`, `node_modules/@keel/cli/package.json` (Workspace) and whether `.git` exists (for `git init -b main`).

**Rules.** E1360 the folder holds files (fix: name a new folder, or add `--existing`) · E1361 `--existing` and a file the project writes exists (fix: move it aside, or use a new folder) · E1365 a write failed; this run's files are removed (fix by its cause: the folder's permission, disk space, or the path) · E1366 `.keel-create` left by a stopped run lists its paths (fix: remove them and it, or the folder) · E1367 interrupted; this run's files are removed (fix: run it again). Links are E1357.

**Conformance.**
- In a folder holding `notes.txt`, `create-app` reports E1360, exits 1 and writes nothing; in one holding only `.git` and `.DS_Store` it writes the project.
- With `--existing`, a folder holding `README.md` gets the project and its `README.md` unchanged, and one holding `package.json` gets E1361 naming `package.json`, one also holding `tokens.ts` and `topology.ts` one E1361 whose `paths` are the three; nothing is written.
- Run by a user whom file modes bind (not root), with `--existing` and an empty read-only `public/`, `create-app` reports E1365 naming `public/keel-mark.svg` and leaves the folder as it was.
- `createPlan` with `caseless` and a listing holding `agents.md` is E1361 whose `paths` are `AGENTS.md` and `agents.md`, and one holding `Modules/` E1361 whose `paths` are `Modules/` and `modules/`; without `caseless`, neither collides.
- A folder holding `.keel-create` is E1366 naming it, with or without `--existing`; a SIGTERM delivered after the first file is written leaves the folder as it was, exit 143.
- Run as `node --permission` with reads granted to its own package, the folder and its contents, and in each folder above the folder `package.json`, `pnpm-workspace.yaml`, `node_modules/@keel/cli/package.json` and `.git`; writes to the folder and its contents; no addon, child process or worker: `create-app shop` exits 0 and writes the project, for each kind and inside a workspace, and those flags refuse a write beside the folder and a child process; from Node 25 a connection too, and on every Node the bin's `@keel/*` reach names no process or network API (structure-lint S0019).
