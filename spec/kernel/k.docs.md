# k.docs: Installed docs
status: implemented
`keel docs` reads the docs of the Keel packages a project has installed: the map, one area, one spec section, one skill, or what a code, code block, API name or glossary term leads to. It is the k.cli operation `docs` and the MCP tool `docs` (`sync: true` is `--sync`; a refused write answers E1357); `keel explain` is k.explain.

**Packed files.** Each published `@keel/*` package carries the sections it owns: `docs/<id>.md`, the section's text, and `docs/index.json`, `{ sections: [{ id, title, codes }] }`, `codes` every diagnostic code the section cites. `@keel/cli` also carries `docs/map.json`, `{ areas: [{ id, title, sections: [{ id, title, package, holds }] }] }`, every kernel and std section once in one area, `docs/glossary.json`, `{ terms: [{ term, text, ids }] }`, one entry per glossary term with the section ids its text cites, and the published skills, `skills/<name>/SKILL.md`, each opening with `name` and `description` frontmatter.

**Resolution.** The project root is the nearest directory at or above the working directory holding a `package.json`. A package is installed when `node_modules/@keel/<name>/package.json` resolves from the project root, else from the running `@keel/cli`'s folder, and its `name` is `@keel/<name>`. The installed packages are the `@keel/*` names in `dependencies` and `devDependencies` of the project root's `package.json` and of `@keel/cli`'s. The map and the skills come from the running `@keel/cli`; a section comes from the package that `map.json` names, or for an id the map lacks, the installed package whose `index.json` lists it, at the version installed. A package's `docs/`, `docs/*.json`, `docs/<id>.md` or `skills/<name>/SKILL.md` whose real path leaves the package's real folder, or over 1,000,000 bytes, is absent and never read.

**Areas.** Docs are read at three levels: the map, an area, a section. The map lists each area once, in order, with its title; an area lists its sections, in order, with what each holds; a section's title and status are its own first two lines, `# <id>: <title>` and `status: <status>`, and no other file repeats them. Every section is in exactly one area. An area id is one word of lowercase letters; a section id holds a dot and a skill name starts with `keel`, so one id names one thing. Area `other` lists the sections of installed packages whose `index.json` names an id `map.json` lacks; it is printed only when it has one.

**Titles.** A section's title, an area's title and a `holds` text name what they hold in full words, `holds` at most 90 characters. Outside backticks, a word on the `clipped` list of `tooling/titles.json` (`a11y`, `deps`, `compat`, `e2e`, `pii`, `sim`, `config`, `env`) is refused with the words to use, as is a word mixing letters and digits or holding two capitals that is neither a diagnostic code nor on that file's `names` list (`CLI`, `CSP`, `OpenAPI`, `SQLite`, `Z3`). A map or area over its budget is split into two areas; no title is shortened to fit.

**Forms.**
| form | prints |
| --- | --- |
| `keel docs` | a `docs.area` per area of `map.json`, then `other` when it has a section, then a `docs.entry` per skill |
| `keel docs <area>` | the area's `docs.area`, then a `docs.entry` per section of it, in its order |
| `keel docs <id>` | one section (`k.router`, `std.tables`) as `docs.section`, or one skill (`keel-client`) as `docs.skill`: the file's text verbatim |
| `keel docs --for <code>` | a `docs.cite` per line citing the code, in the installed sections whose `index.json` lists it |
| `keel docs --for <block>` | a code block, `E155x`, `E15xx`: a `docs.code` per code of the block an installed section cites, in code order |
| `keel docs --for <name>` | any other key: the `docs.term` of the glossary term equal to it ignoring case, then a `docs.hit` per installed section holding it in a code span, at most 5 |
| `keel docs --sync` | the agent files (k.scaffold) |

`docs.area` is `{ kind, id, title, sections }`, `sections` its count, compact `data Durable storage, concurrent writes and app data, 6 sections`. `docs.entry` is `{ kind, id, title, package, installed, holds }`, compact `k.router Routes @keel/router: <holds>`, with ` not installed` after the package when `installed` is false; a skill's entry has its name as `id`, its `description` up to the last `;` as `title` (all of it when there is none), `@keel/cli`, `true` and `holds` `""`; an entry whose `holds` is `""` prints no `: `. `docs.code` is `{ kind, code, ids }`, the sections citing the code in map order, compact `E1551 k.server k.user`, at most three ids then ` +<n>`. `docs.term` is `{ kind, term, text, ids }`, compact `identity mount: <text>`, `text` cut at 160 characters. `docs.hit` is `{ kind, name, id, title, package, count }`, compact `k.testing Harness and properties 14`: a code span holds the name when its text contains it with no letter, digit, `_` or `$` right before or after it; `count` is the section's spans holding it; hits run by count, most first, then map order. A key matches a glossary term and a code span ignoring case. A key that matches nothing prints only the trailing `summary` record, exit 0. `docs.section` `{ kind, id, package, version, text }` and `docs.skill` `{ kind, id, version, text }` print `text` in compact. `docs.cite` is `{ kind, code, id, line, text }`, compact `k.cli:43 <text>`, `text` cut at 160 characters. A code no installed section cites gives no `docs.cite`, exit 0. More than one of `<id>`, `--for` and `--sync`, or an id that is neither an area, a section nor a skill, is E1052, exit 2.

**The Keel repo.** When a directory at or above the working directory holds `spec/00-map.md`, `keel docs` reads that tree: the map is `spec/00-map.md` as one `docs.section` with id `map`; an area is one `docs.section` with the area's id, `# <area>: <title>` from the map's row, then the table `| id | title | status | holds |`, a row per line of `spec/areas/<area>.md` (`| id | holds |`), title and status from the section's first two lines; a section is `spec/kernel/<id>.md` or `spec/std/<id>.md`, a skill `packages/cli/skills/<name>/SKILL.md`; `--for` reads every line of `spec/**.md` and the terms of `docs/GLOSSARY.md`. `pnpm spec`, `pnpm spec <area>`, `pnpm spec <id>` and `pnpm spec --for <key>` print what `keel docs` prints there.

**See lines.** A diagnostic's `see` prints as `see: keel docs <id>` in compact and pretty; json keeps the id.

**Budgets** (`tooling/budgets.json`). The map, one area and one section fit principle 8's 4,000 tokens: `spec.map` 400, `spec.area` 500 and `spec.section` 3,100 count `pnpm spec`, `pnpm spec <area>` for every area and every section's text; `docs.map` 900 (the areas and the skill entries), `docs.area` 500 and `docs.section` 3,100 count the compact output of `keel docs`, of `keel docs <area>` for every area, and every packed section's `text`; `docs.for` 400 counts `keel docs --for E1451`, `docs.skill` 3,700 every skill's `text`, `docs.agents` 600 the Keel block of `AGENTS.md`. The `docs` tool counts toward `mcp.tools-list` (k.cli).

**Rules.** E1065 the section's package is not installed; the message names the package to add · E1066 an installed package has no `docs/<id>.md` for a section `map.json` gives it, or no readable `docs/index.json`, or `@keel/cli` has no `docs/map.json`; the message names the package and its version.

**Conformance.**
- With fixture packages under `node_modules/@keel/`, `keel docs <id>` prints that package's `docs/<id>.md` byte for byte, exit 0; in json, one `docs.section` with the package's `version`.
- A package present only under `@keel/cli`'s own `node_modules` resolves: `keel docs <its id>` prints its section.
- With `@keel/std-tables` installed nowhere, `keel docs std.tables` emits E1065 naming `@keel/std-tables`, exit 1, and `keel docs <area>` for the area `map.json` gives `std.tables` lists it with `installed: false`.
- An installed package lacking the file for its `map.json` section emits E1066 naming the package and version, exit 1.
- A `docs/` or `docs/<id>.md` linked outside its package is absent (E1066); a package folder linked into a store reads.
- An installed package whose `index.json` lists an id `map.json` lacks: `keel docs` ends its areas with `other`, `sections: 1`; `keel docs other` lists the id; `keel docs <id>` prints it. With no such id, `keel docs` prints no `other`.
- `keel docs` emits a `docs.area` per `map.json` area in map order, then a `docs.entry` per skill, and no section's `docs.entry`; `keel docs keel-client` prints `skills/keel-client/SKILL.md` byte for byte.
- With `map.json` areas `a` (sections `k.x` then `k.y`) and `b` (`k.z`), `keel docs a` emits `docs.area` `{ id: "a", sections: 2 }`, then the `docs.entry` of `k.x`, then of `k.y`, each with its `holds`, and nothing of `k.z`; compact prints `k.x <title> <package>: <holds>`.
- With installed sections `k.x` citing E1551 and E1553 and `k.y` citing E1551 and E1601, `keel docs --for E155x` emits `docs.code` E1551 with `ids` `["k.x","k.y"]`, then E1553 with `["k.x"]`, and nothing for E1601, exit 0; `--for E15xx` adds E1601.
- With `k.x` holding `` `renderRoute(id)` `` and `` `t.renderRoute` ``, `k.y` holding `` `renderRoute` `` once and `k.z` holding only `` `renderRouter` ``, `keel docs --for renderRoute` emits `docs.hit` for `k.x` with `count` 2, then `k.y` with 1, and none for `k.z`; a name in plain text outside backticks counts no span.
- With `glossary.json` term `identity mount`, `keel docs --for "Identity Mount"` emits that `docs.term` first, then its hits; `keel docs --for nothing-here` prints no record, exit 0.
- `keel docs zz` for an area `map.json` lacks emits E1052, exit 2.
- Under a root with `spec/00-map.md` listing area `a` and `spec/areas/a.md` listing `k.x`, `keel docs a` prints `# a: <the map row's title>` and a row `| k.x | <title> | <status> | <holds> |`, title and status read from `spec/kernel/k.x.md`'s first two lines.
- A skill whose `description` is `Build pages; E1401, E19xx` is listed with `title` `Build pages`.
- `keel docs --for <code>` prints each line citing the code in the installed sections listing it and none from a package not installed; a code cited nowhere prints no `docs.cite`, exit 0.
- `keel docs nope` and `keel docs k.cli --for E1051` emit E1052, exit 2. `keel spec` emits E1051.
- Under a root with `spec/00-map.md` and no `node_modules/@keel/` docs, `keel docs k.cli` prints `spec/kernel/k.cli.md` and `--for` reads `spec/`.
- The MCP tools include `docs`, not `spec`; `docs` on `{ id: 'k.cli' }` yields the records of `keel docs k.cli --format=json`, and on `{ id: 'a' }` those of `keel docs a --format=json`.
- A diagnostic with `see` `k.ui` prints `see: keel docs k.ui` in compact and pretty, and `"see":"k.ui"` in json.
