# k.library-pages: Library pages and contract
status: implemented

**Route components.** A library's route component file is one a `manifest(` call of `@keel/router` in a file of the same library (k.library) binds as one entry's `component`: a name the binding file imports by a relative default import and uses nowhere else, the file's stem in no `public.exports`, the file no `exports` target (a `*` pattern's included), and no other import, re-export, `import()`, `require` or `new URL` in a file of the project outside test code naming it, each specifier resolved as the bundler resolves it (its `?query` stripped, a folder to its `index`, `./Page.js` to `Page.ts`; a template with no substitution is a literal; a `#` specifier is E1576 and no `tsconfig.json` alias resolves, k.bundle Aliases). A library one of whose files loads a module by any other specifier (a computed `import()` or `require`, `createRequire`, `import.meta.glob`) has no route component file. The router renders it, once per page, and no caller passes it an `id`. An element there may take a literal `id` (a string, or a template with no substitution) `<id>.<rest>`, with no spread after it, `<id>` the library's manifest `id` and `<rest>` not empty; any other `id` there is judged by k.library Ids (E1161). E1166 keeps `<id>` the library's own: no app module and no other library holds it.

**Contract.** A library's module contract (k.contract) is the one `contract()` call in the file its `package.json` `exports["./contract"]` names, at `keel`, else the target Node imports, when that file is a `src/` `*.contract.ts` file. A `contract()` call in any other file of the library is E1513 `contract() belongs in <path>`, `<path>` the `./contract` file package-relative, or `the file a ./contract export names` when it declares none; with a target naming another file (`dist/` alone, `src/index.ts`), each call is E1513 `contract() belongs in a src/*.contract.ts file, not <target>`.

**Conformance.**
- In the project of k.library's first Conformance bullet, with `src/routes.ts` binding `component: Page` (`import Page from './Page.ts'`) in `manifest(`, `Box({ id: 'charts.page' })` in `src/Page.ts` is no E1161; `shop.page`, `charts`, `charts.` and `chartsx.page` there, and `charts.page` with no `src/routes.ts`, with `Page` in `public.exports` or with a spread after it, are each one E1161.
- In that project, with `src/routes.ts` binding `Page`, `charts.page` in `src/Page.ts` is one E1161 when `src/index.ts` re-exports it as `Status`, when `src/Both.ts` imports it, and when `src/routes.ts` exports `Page`.
- In that project, `charts.page` in `src/Page.ts` is one E1161 when `src/Twice.ts` names it by `./Page.ts?x`, `./Page.js`, `` import(`./Page.ts`) ``, `export * from './Page.ts'` or `require('./Page.ts')`, when another library's file or an app module's file names it by a relative path, when an `exports` pattern `./*` targets `./src/*`, when `src/routes.ts` binds `Page` to two entries, and when `src/Twice.ts` holds `import(n)` or `import.meta.glob`; bound as `./Page` to `src/Page/index.ts`, or as `./Page.ts?v=1`, it is no E1161, as it is when an app's test file imports it.
- In a project whose `modules/shop/module.ts` lists `'@acme/status'`, a library (`module.ts` `id: 'status'`) whose `exports` hold `"./contract": { "keel": "./src/status.contract.ts" }`: `contract('status', ...)` exported as `status` there is no E1513; the same call in `src/other.contract.ts` beside it is one E1513 at `node_modules/@acme/status/src/other.contract.ts`, message `contract() belongs in src/status.contract.ts`; with no `./contract` entry, the call in `src/status.contract.ts` is one E1513, message `contract() belongs in the file a ./contract export names`; a second call there, `contract('shop', ...)` and an export named `page` are each one E1513, messages `a second contract() call; src/status.contract.ts holds one`, `contract id must be 'status', the module of src/status.contract.ts` and ``export the contract as `status` from src/status.contract.ts``.
- In that project, with `"./contract": "./dist/status.contract.js"`, or `"./src/index.ts"`, the call in `src/status.contract.ts` is one E1513, message `contract() belongs in a src/*.contract.ts file, not dist/status.contract.js`, or `not src/index.ts`.
