# k.expect: What `expect` claims and an error carries
status: conformance-covered

**Purpose.** A thrown value becomes a value at `attempt`'s `expect` (k.attempt) and travels to callers, a response and a log. While every type holds, an `expect` can claim every throw while seeming to test, and copy thrown text into the error. This section says what an `expect` does with its parameter and what an error is built from; code that must take every throw is k.supervise's.

**Made errors.** In app code and a library's files a `KeelError` is made only by `X.make` or `X.causedBy` of an `s.error` (k.attempt): an object literal where a `KeelError` is expected is E1458. `keelError` (`@keel/schema`) holds the schemas of the kernel's codes an author returns: `denied`, `notFound`, `unreachable` and `busy`, each with data `{}`; `conflict`, whose data may name the `transaction` refused and the `head` it met (std.offline); and `fields`, whose data maps a field path to its message (k.forms). `keel.unexpected` and `keel.payloadTooLarge` are the kernel's to make.
```ts
return bearer === undefined && user === '' ? err(keelError.denied.make({})) : ok(null)
```

**Message.** The `message` argument of `make` and `causedBy` is a string literal or a template with no substitution (E1460): the code's own words. A value goes in `data`, whose schema says what it is.

**Marked values.** A `.pii()` or `s.secret` value keeps its protection inside an error. The message holds none, being a literal. In `data` a value under a mark of the schema `s.error` declared is treated by that mark at every sink (k.privacy Sinks), and a `Secret` never serializes. Types carry no mark: a marked value put at an unmarked node of `data` is found only by value, where a sink reads text for the values its scope declared (k.privacy Copies, std.sessions): the log's full-text record and a session's recorded error. Not held: such a value in a response, which carries `data` as its schema encodes it.

**Readable.** The `expect` of an `attempt` call is a function check can read: an arrow function or function expression written as the argument, or a name that resolves by symbol to a function declaration, or to a `const` bound to an arrow function or function expression, in a file of the project or of the library the call is in. Any other argument is E1452 at the argument. A function read by name is judged as if written in the call, reported at the argument.

**Decides.** In an `expect` with parameter `x`, an expression *reads the thrown value* when it is `x`, a property of one that does (`x.p`, `x['p']`, `Reflect.get(x, 'p')`), `Object(…)` or `typeof` of one, or a `const` of the function whose initializer does. A *test* is one of:
- `v instanceof C`, `v` reading the thrown value;
- `a === b` or `a !== b` where one side reads the thrown value and the other holds no mention of `x`;
- a call that takes an expression reading the thrown value as an argument and whose return type is `boolean` or a type predicate;
- `r.ok`, `r` being `S.parse(v)` with `v` reading the thrown value, or a `const` of the function bound to one;
- `!t`, `t && e`, `e && t` and `t || u` for tests `t` and `u` and any expression `e`.

A value the `expect` returns, read through `?:`, `&&`, `||`, `??`, a comma's last operand and parentheses, is *selected* when, for a test `t`, it stands:
- in a branch of `t ? a : b`, or as `e` in `t && e`;
- in a branch of `if (t)`;
- after `if (t) return undefined` with no `else`, later in its statement list (`return` and `return void 0` too, alone or alone in a block);
- in a `case c:` clause of `switch (v)` before any `default` clause, `v` reading the thrown value and `c` holding no mention of `x`.

The `expect` claims by a test or it is E1452:
1. Its return type holds `undefined`.
2. Each value it returns that is not `undefined` is selected.

So `(x) => (void x, T)`, `(x) => T.make({}, typeof x)` and a function that returns an error on every path fail 1, and `(x) => (x === x ? T : undefined)`, `(x) => (x ? T : undefined)` and a `default` clause's error fail 2. Check cannot prove a test narrow: `x instanceof Object`, `typeof x !== 'bigint'`, `x !== 1`, an error where a test fails (`x instanceof C ? undefined : T`) and a call true of every value pass and claim nearly every throw; `keel review` lists them (R1017, k.escapes).

**Carries.** The rule is on what is made, not on how a value reached it: each value an `expect` returns that is not `undefined` is a `KeelError` whose `data` is *closed*: its type is a number, a boolean, a literal type, `null` or `undefined`; a union or intersection of closed types; or an array, a tuple or an object with no call signature whose elements, properties and index signatures are closed. Else it is open: `string`, `bigint`, a template literal type, `symbol`, `object`, `unknown`, `any`, a type parameter, an unresolved type.
- For `X.make(data)` or `X.causedBy(cause, data)` written in the `expect`, `data` is read through object and array literals and each property value or element is judged by its own type, so a literal written there is closed; any other expression by the type it has. A returned value that is no such call is judged by its type's `data`, but a `const` declared outside the `expect`, made before it runs.
- So destructuring, a reassigned `let`, a conditional, an object built earlier and `Txt.parse(v).value` with `Txt = s.string()` are refused alike; `s.literal`, `s.enum`, number and boolean schemas cross: a status, a count, a flag, a closed code (`reasonOf`, k.attempt).
- An expression there that mentions `x` holds no read of `message`, `stack`, `cause` or `errors`, and no `String(…)`, `toString()`, `JSON.stringify(…)`, template or `+`.
Anything else is E1460. Open text from a thrown value has no form: carry a code or a closed reason; the text is the log's, inside the `KEEL_LOG_THROWN` window (k.serverlog Thrown values). E1460 is the type pass's (k.check): `keel check` always runs it, and with it off (`check(files, { types: false })`) no data is judged. Not held: a function that reads the thrown value's text and returns a number.

**Rules.**
- E1452 (k.errors) also: an `expect` check cannot read, message `expect is not readable here: write the function in the call`; one that fails Decides 1, message `expect claims every throw: it never returns undefined`; one that fails Decides 2, message `expect claims every throw: return the error where instanceof, ===, a guard or .ok holds`, at the argument. `keel explain E1452` lists the tests and the shapes. No fix.
- E1458 (k.attempt) also: an object literal whose contextual type is a `KeelError`, at the literal, message `KeelError written by hand: declare it with s.error and pass X.make(data)`. No fix.
- E1460 text that is not the code's own in an error. A `message` argument of `make` or `causedBy` that is no literal, at the argument: `error message is not a literal: pass values as data`. Data that fails Carries, at the property value, element or value judged: `expect copies thrown text: carry a number, a boolean or a closed code` when it mentions `x`, else `error data an expect returns is open text: carry a number, a boolean or a closed code`. A returned expression that reads the thrown value and is no `make` or `causedBy` call, at it: `expect builds its error from the thrown value: return X.make(data)`. No fix.
Each finds its callee as k.unsafe One path says.
