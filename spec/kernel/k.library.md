# k.library: Libraries
status: proposed

**Kind.** A library is a package of Keel code that an app checks and compiles as its own; the stdlib packages are libraries. Its `package.json` has `"keel": "library"` and a scoped name (`@acme/charts`). Its root `module.ts` is a k.module manifest: `id` prefixes its route ids, store ids, transaction names and error codes; `deps` names the libraries it uses; `capabilities` and `public.exports` as for an app module, `public.exports` being its surface. Its code is in `src/` and, when it has any, `unsafe/`. An `exports` entry the app's compiler reads lists a `keel` condition first, its `.ts` or `.tsx` source, before the built `types` and `default` that TypeScript's declaration readers and Node take (k.library-pack); an entry without one is read at its other target.

**In an app.** An app module lists a library in `deps` by its package name. A `deps` entry that begins with `@` names a package; any other entry is a module id of the project. The app's libraries are those its manifests list and, transitively, those their manifests list, each found as Node resolves the name from the listing manifest's folder; a linked package is followed to its real path. A library's files are the files under `src/` and `unsafe/` of the folder holding its `package.json`. `check()` reads a library's `package.json`, root `module.ts` and `.keel/ledger.json` from the files it is given, under `node_modules/<name>/`. For them:
- The compiler resolves imports with the `keel` condition on every surface (dev, build, test) and transforms a library's files as the app's: JSX, element ids, and style props into the app's CSS file against the app's `tokens.ts`.
- `keel check` reads them and runs every rule over them, its type pass included, against the app's `tokens.ts`, kernel packages and `topology.ts`. Wherever a section reads app code or a file under `modules/<id>/` (k.check App code, k.boundary Reach), it reads a library's file `<f>` as it reads `modules/<id>/<f>`, `<id>` the library's, and its `unsafe/` files with their lifted ranges; a section's exclusion of `node_modules/` does not cover library files. A diagnostic in a library file is the app's: located at `node_modules/<name>/<f>`, whichever `node_modules` holds it, and carrying no `fix`. Nothing in the app turns a rule off for a library file.
- The k.module rules hold for a library, its root `module.ts` its manifest: E1151 (an app file imports from a library only names its `public.exports` lists), E1152, E1155, E1156. A library in `deps` is used by being listed (no E1165), and is a package a `std` key may name (E1158).
- Where k.module (Std config), k.topology and k.contract read a stdlib package's entry, `./tools`, `./module`, `./routes`, `./contract` or `std` config, they read a library's on the same terms (k.parity By kind). `keel check` and `keel build` import a library's built entry and its `./tools` export before validating, so its rules, formatters and config schema register; its rule codes are held to E1753 as a stdlib package's. A library's routes are served only by a deployable whose `topology.ts` `modules` names its `id`: listing a library in `deps` adds no route, no server code and no identity.

**Guarantees.** Installing a library weakens none of the app's checks, since each runs over the library's files as over the app's: personal data and secrets (k.privacy, k.reveal, k.leave; a library's exported schemas are read as a package's, E1111), the content security policy (E1570, E1571, E1803; a library declares no origin, the app's `topology.ts` does, k.origins), accessibility (k.a11y; `keel test` audits the app routes that render library components), host elements and host code (k.host-element, k.host-code), internal entries (E1576, k.parity Rules) and detached scopes (E1207, k.parity By kind).

**Ids.** Each base element, `Part` and `Host` that a library file renders, as JSX or as a call, takes an `id` prop that is neither a string literal nor a template literal without an expression: it is built from its component's own `id` prop as `<id>.<part>` (k.component IDs), because a derived id holds the file's path, which changes with the installer and the version. Any other is E1161.

**Ledger.** A published library carries `.keel/ledger.json`, the file its own `keel ledger --write .keel/ledger.json` writes (k.ledger File). The app's `keel ledger` counts `unsafe` and `hostElements` over each library's files as over its own files (k.host-element Ledger), so adding a library that holds either makes `--diff` report E1706 until the ledger is written again. A library whose real path is inside the project root is counted once, as the project's own files. For each entry of an installed library's ledger `exports`, `keel ledger` emits `{ kind: 'ledger', item: '<name>/<file>#<export>', rung, evidence: 'library <version>' }`, `<version>` the library's `package.json` `version`, and leaves it out of `rungs` and of `--diff`: the app ran none of that evidence. The file `--write` writes gains `libraries`, `{ [name]: { version, unsafe, hostElements } }` with names sorted, `{}` when the app has none. An installed library is one whose real path lies inside a `node_modules` folder.

**Rules.** E1161 an element in a library file whose `id` is missing, a string literal, or a template literal without an expression (fix: none) · E1162 an installed library whose `.keel/ledger.json` is missing, fails the shape k.ledger File gives, or holds an `unsafe` or `hostElements` other than the count `keel check` makes over its files (message names the field and both values), at each `deps` entry that names it · E1163 a library file whose relative import, re-export or literal `import()` resolves outside its package folder, at the specifier, or a library manifest `deps` entry that does not begin with `@`, at the entry (fix: none; the entry names no module, so it is no E1153 edge and no E1165) · E1166 a library whose `id` is a project module's id or another of the app's libraries' ids, at each `deps` entry that names such a library (message `module id <id> is held by <a> and <b>`, an app module before a library, libraries by package name; fix: none). A diagnostic at an entry is on the entry's line, at a column from its opening quote to its closing one. A package `deps` entry that resolves to no package with `"keel": "library"` is E1159 (k.module).

**Conformance.**
- In a project whose `modules/shop/module.ts` lists `'@acme/charts'` in `deps`, whose `node_modules/@acme/charts/` holds `package.json` `{"name":"@acme/charts","version":"1.0.0","type":"module","keel":"library","exports":{".":{"keel":"./src/index.ts","default":"./index.js"}}}`, `index.js` holding `export {}`, a `module.ts` with `id: 'charts'`, `deps: []`, `capabilities: []` and `public: { exports: ['Badge'] }`, `src/index.ts` holding `export { default as Badge } from './Badge.tsx'`, `src/Badge.tsx` whose `Badge` renders `<Box id={`${props.id}.box`} p="2" />`, and `.keel/ledger.json` as `keel ledger --write .keel/ledger.json` writes it in that folder, and whose `modules/shop/Page.tsx` imports `Badge` from `'@acme/charts'` and renders `<Badge id="shop.badge" />`, `keel check` reports no diagnostic.
- In that project, the page `keel build` renders holds an element with id `shop.badge.box`, and the app's CSS file holds its padding rule.
- In that project, `<box />` in `src/Badge.tsx` is one E1805 in the app's `keel check`, at `node_modules/@acme/charts/src/Badge.tsx`, with no `fix`.
- In that project, with `node_modules/@acme/charts` a symbolic link to a folder beside the project holding the same files, `<box />` in its `src/Badge.tsx` is one E1805 at `node_modules/@acme/charts/src/Badge.tsx`.
- In that project, `<Box p="2" />`, `<Box id="box" />`, `<Box id={`box`} />` and `Box({ p: '2' })` in `src/Badge.tsx` are each one E1161; `<Box id={`${props.id}.box`} />` and `<Box id={partId('box')} />`, `partId` a function of that file, are not.
- In that project, a cast `x as string` in `src/Badge.tsx` is one E1757 at `node_modules/@acme/charts/src/Badge.tsx`, and an import of `@keel/store/internal` there is one E1576.
- In that project, `import x from '../../outside.ts'` in `src/Badge.tsx` is one E1163 at the specifier.
- In that project, `deps: ['shop']` in the library's `module.ts` is one E1163 at the entry; `deps: ['@acme/other']`, naming a library holding the same files with `id: 'other'`, is not.
- In that project, with `modules/charts/module.ts` an app module of id `charts`, `keel check` reports one E1166 at the `'@acme/charts'` entry, message `module id charts is held by charts and @acme/charts`.
- In that project, `deps: ['@acme/none']`, naming no installed package, is one E1159 at the entry; so is `'@acme/plain'`, installed with a `package.json` that has no `keel` field.
- In that project, with `node_modules/@acme/charts/tools.js` registering a rule that reports `E2999` on every app file and `exports` gaining `"./tools": "./tools.js"`, `keel check` reports `E2999`; with `modules/shop/module.ts` listing no `'@acme/charts'`, it does not.
- In that project, with `exports` gaining `"./routes": "./routes.js"`, whose `routes` table holds route `charts.about` at `/about`, the `routes.json` `keel build` writes for a deployable whose `topology.ts` `modules` is `['shop']` holds no `charts.about`, and for one whose `modules` is `['shop', 'charts']` it holds it.
- In that project, with no `.keel/ledger.json` in the library, `keel check` reports one E1162 at the `'@acme/charts'` entry; with one whose `unsafe` is 0 while `unsafe/u.ts` holds one `unsafe(...)` call, one E1162 naming `unsafe`, 0 and 1; with the linked library of the fourth bullet and no ledger file, none.
- In that project, with `unsafe/u.ts` holding one `unsafe(...)` call and the library's `.keel/ledger.json` holding `unsafe` 1 and, in `exports`, `{ "pkg": "charts", "name": "Badge", "file": "src/Badge.tsx", "rung": "example" }`, `keel ledger` emits `{ kind: 'ledger', item: '@acme/charts/src/Badge.tsx#Badge', rung: 'example', evidence: 'library 1.0.0' }`, its `rungs` counts equal those of the project without the library, and `keel ledger --write` writes an `unsafe` one higher than without the library and `libraries` `{ "@acme/charts": { "version": "1.0.0", "unsafe": 1, "hostElements": 0 } }`.
