# k.check-time: Check and build time entries
status: proposed

Where an app or library may import `@keel/ui/tokens` and `@keel/ui/css`, which hold the token grammar and the color maths, so neither reaches a client bundle (k.ui Tokens, k.values Stylesheet).

**Entries.** `@keel/ui/tokens` (`defineTokens`, `TokenSchema`, the value forms, the `Tokens` type) and `@keel/ui/css` (`compileStyles`, `combinations`, `contrast`, `contrastTable`) run under Node only: in `keel check`, `keel build`, `keel dev` and tests. A value import of either (`import`, `export ... from` or `import()`; `import type` and an import or export each of whose names is written `type`, as in `export { type Tokens } from`, erase and are free) in a code file (k.check Trailer) of an app or library is E1818 at its specifier, unless the file is of an exempt kind and no client entry reaches it: no route `component` and no file of a `client` module, by value imports, re-exports and `import()` (k.boundary Following). The exempt kinds: a server-only file (k.boundary); test code and a `*.config.*` file, as k.check App code names them; `tokens.ts` at a project root and each file it imports; a library's `src/<id>Tokens.ts` (k.looks).

**Where it is reported.** Message: `<entry> is check and build time only; use token names or @keel/ui/brand`, `<entry>` `@keel/ui/tokens` or `@keel/ui/css`. An exempt-kind file a client entry reaches is reported not at its own import but at the client entry's import of the reaching chain's first file, in the app's or library's own file (never one under `node_modules/`), once per such import and reached file: `<file> imports <entry>, check and build time only`, `<file>` the reached file's path from the project root, its leading segments dropped behind one `.../` until the message is at most 89 units. Fix: none.

**Conformance.**
- In a project with a `node` module `a`, `import { defineTokens } from '@keel/ui/tokens'` in route component `modules/a/A.tsx` is one E1818 at the specifier with message `@keel/ui/tokens is check and build time only; use token names or @keel/ui/brand`, and `import { contrast } from '@keel/ui/css'` in `lib/tone.ts`, which `A.tsx` imports, one with `@keel/ui/css`; there is none for those imports in `tokens.ts`, in `tokens.design.ts` that only `tokens.ts` imports, in `modules/a/A.test.tsx`, in `vite.config.ts` or in `modules/a/a.server.ts`, nor for `import type { Tokens } from '@keel/ui/tokens'` in `A.tsx`; when `A.tsx` also imports `tokens.ts`, there are two E1818, both at `A.tsx`'s specifier `'../../tokens.ts'`, with messages `tokens.ts imports @keel/ui/tokens, check and build time only` and `tokens.design.ts imports @keel/ui/tokens, check and build time only`, and none in either file; `keel build` with any E1818 exits 1 and writes no `dist/`.
- In that project, with `test/seed.ts` and `theme.config.ts` each holding `import { defineTokens } from '@keel/ui/tokens'`, `lib/load.ts` importing `../test/seed.ts`, and `A.tsx` importing `../../lib/load.ts` and `../../theme.config.ts`, `keel check` reports two E1818 in `A.tsx`, at those two specifiers, with messages `test/seed.ts imports @keel/ui/tokens, check and build time only` and `theme.config.ts imports @keel/ui/tokens, check and build time only`, and none in `test/seed.ts`, `theme.config.ts` or `lib/load.ts`; `export { type Tokens } from '@keel/ui/tokens'` in `A.tsx` is none; without those two imports in `A.tsx` there is none.
