# k.privacy-reads: Static privacy reads
status: conformance-covered

**Purpose.** How `keel check` reads a revealed value, a schema and the outputs of a file without running code, exported so a stdlib rule (k.check Registry) reads them as the kernel's rules do; and the password-control rule built on them. Each reader works by syntax on the checked file and `input.project`; where `schemaHolds` cannot read it answers `'unknown'`, and no rule here or in the stdlib reports there.

**Readers.** `@keel/check` exports three, each taking the rule's `input` (k.check Registry), whose `ast` is the oxc syntax tree of the file (ESTree with TypeScript nodes, each with `start` and `end` offsets):
- `carriesReveal(node, input): boolean`: whether the expression `node` of `input.ast` carries a value `reveal` returns, by k.reveal Flow, a local's value read where `node` stands. What ends a value there ends it here: any other call, a parameter, an import.
- `schemaHolds(expr, input, names): 'yes' | 'unknown' | 'no'` reads the schema expression `expr` of `input.file` through `const`s, project imports and re-exports, object literal fields, spreads, array elements, call arguments, a call's receiver (`X.optional()` reads `X`), both branches of `?:`, both sides of `&&`, `||` and `??`, and a package factory's call (Factories). A part is listed when it is `{ from, name }` of `names` imported by name under any local name, or `<ns>.<name>` of a namespace import of `from`. The answer is `'yes'` when a part is listed; else `'unknown'` when a part is any other call whose callee is not a member (a project function, a package whose source it does not resolve to), a binding it cannot follow (a parameter or a function's local among them), a computed member, an object literal's getter, setter or method, or a literal binding that is not held (Held); else `'no'`. An import from a package `names` does not list is `'no'`: a package's schemas are its own (k.privacy E1111).
- `outputSchemas(input)`: the `output` expressions of `input.ast` in source order, each as `{ expr, line, col }`, the node and its 1-based position: of every entry of a `contract` call (`@keel/router/contract`), entries read as k.contract Static reading reads them, and of the declaration of every `loader` call (`@keel/router`), an object literal or a `const` of the file bound to one. An `output` given another way is not listed.

**Factories.** A call of a package's export, by name or as a namespace member, other than `@keel/schema`'s own constructors, is read through the package's source when `keel check` resolves the specifier, as k.bundle Aliases does, to a `.ts` or `.tsx` file that is not a declaration file (a workspace package's `exports` give one; a package that ships only built code and types gives none): its arguments are read at the call, and each expression the function returns is read in the package's files, a parameter standing for its argument, the body's top-level `const`s and the package's own functions followed, eight calls deep at most. What it cannot read there makes the call `'unknown'`.

**Held.** The read follows a binding only when it is a top-level `const` of a project file. One bound to an object or array literal, or a `const` alias of one, is held when every reference to it, by lexical scope, in every checked file (its own, each importing it by name or through re-exports, and each `ns.<name>` of a namespace import of its file), is one the read takes: a field value, a spread, an array element, a branch of `?:`, an argument of a call `s.<name>(…)` on the `@keel/schema` namespace, a non-computed member read standing in one of those places, an `export` or re-export of it, the initializer of a `const` alias that is itself held, or a type (`typeof x`). Any other reference leaves it not held: an assignment's target or the root of one, `delete`, `++`, a destructuring source, any other call's argument or receiver (`Object.assign(x, …)`, `assign(x, …)` after `const { assign } = Object`, `f(x)`, `x.push(…)`), a value returned, thrown or stored. So does a namespace object of its file used other than as `ns.<name>` (passed, destructured, a computed member) and an `import()` or `export * as` of its file. A schema `@keel/schema` makes needs no such rule: it is frozen (k.schema Frozen), so no reference changes it. A file outside the checked files is not read; a package does not import an app file.

**Password controls.** W1114 is an `Input` (`@keel/ui`, JSX or a call with an object literal) with a literal `type` `password`, or a literal `autocomplete` whose space-separated tokens include `current-password` or `new-password`, whose `field` is `f.field('<path>')`, `f` a `const` of the file bound to a `form(<schema>, …)` call (`@keel/forms`), where the schema, followed as `schemaHolds` follows it and walked one path segment at a time through `s.object` fields, ends at a call `s.<name>(…)` of `@keel/schema` other than `s.secret`. Trailing method calls (`.optional()`, `.pii()`) are passed over at each step. Not reported: a step it cannot follow, a numeric segment, a computed path or `type`, and a `field` held in a variable. A password the server receives as a plain string reaches logs and stores as written; `s.secret` keeps it from both (k.privacy).

**Rules.** W1114 a password control bound to a field whose schema node is not `s.secret` (no fix).

**Conformance.**
- `carriesReveal` is true for `reveal(p.k)`, `{ a: reveal(p.k) }` and a `const` bound to `` `${reveal(p.k)}` ``, and false for `hash(reveal(p.k))`, `reveal(p.k).length`, `reveal(p.k) === h` and a parameter.
- With `names` `[{ from: '@keel/std-tokens', name: 'Digested' }]`, `schemaHolds` is `'yes'` for `s.object({ d: Digested })`, `D.optional()` with `D` an alias of it, `t.Digested` of a namespace import, and a `const` of an imported `*.schema.ts` holding one; `'unknown'` for `s.object({ d: make() })`; `'no'` for `s.object({ d: s.string() })` and for a schema imported from another package.
- `outputSchemas` lists the `output` of an API entry in `contract(...)` and of a page `loader`'s declaration, inline and through a `const`, and nothing for a `loader` given `decl()`.
- `<Input type="password" field={f.field('pw')} label="P" />` with `pw: s.string()` is one W1114, as are `autocomplete="new-password"` without `type`, the schema imported from a `*.schema.ts`, and a nested path `a.pw`; `pw: s.secret(s.string()).optional()`, `f.field(p)`, `pw: make()` and `type={t}` are none.
- With `modules/a/q.schema.ts` holding `export const shape = { q: s.string() }` and `export const Search = s.object(shape)`, and a route of `modules/a/a.contract.ts` whose `search` is the imported `Search`, each of these makes that `search` one E1111 with message `route search not readable statically; cannot show it holds no .pii()`: in `q.schema.ts`, `const r = shape; r.x = s.secret(s.string())`, `const { assign } = Object; assign(shape, { x: s.secret(s.string()) })`, `function f(o) { o.x = 1 } f(shape)` or `shape.x = s.secret(s.string())` inside a function body; in another project file, `import { shape } from './q.schema.ts'` then `shape.x = s.secret(s.string())`, or `import * as n from './q.schema.ts'` then `use(n)`. With none of them, it is clean, also with `Search` bound to `s.object({ ...shape })` or `s.object(shape).optional()` and with `typeof shape` in another file.
- A route `search` imported from a `*.schema.ts` file that binds it by `export let Search = s.object({ q: s.string() })` is one E1111 with message `route search not readable statically; cannot show it holds no .pii()`.
