# k.privacy-reads: Static privacy reads
status: proposed

**Purpose.** How `keel check` reads a revealed value, a schema and the outputs of a file without running code, exported so a stdlib rule (k.check Registry) reads them as the kernel's rules do; and the password-control rule built on them. Each reader works by syntax on the checked file and `input.project`; where `schemaHolds` cannot read it answers `'unknown'`, and no rule here or in the stdlib reports there.

**Readers.** `@keel/check` exports three, each taking the rule's `input` (k.check Registry):
- `carriesReveal(node, input): boolean`: whether the expression `node` of `input.ast` carries a value `reveal` returns, by k.reveal Flow, a local's value read where `node` stands. What ends a value there ends it here: any other call, a parameter, an import.
- `schemaHolds(expr, input, names): 'yes' | 'unknown' | 'no'` reads the schema expression `expr` of `input.file` through `const`s, project imports and re-exports, object literal fields, spreads, array elements, call arguments, a call's receiver (`X.optional()` reads `X`) and both branches of `?:`. A part is listed when it is `{ from, name }` of `names` imported by name under any local name, or `<ns>.<name>` of a namespace import of `from`. The answer is `'yes'` when a part is listed; else `'unknown'` when a part is a call whose callee is not a member (a factory), a binding it cannot follow, a computed member, an object literal's getter, setter or method, or a binding the file changes after its literal; else `'no'`. An import from a package `names` does not list is `'no'`: a package's schemas are its own (k.privacy E1111).
- `outputSchemas(input)`: the `output` expressions of `input.ast`, each with its position: of every entry of a `contract` call (`@keel/router/contract`), entries read as k.contract Static reading reads them, and of the declaration of every `loader` call (`@keel/router`), an object literal or a `const` of the file bound to one. An `output` given another way is not listed.

**Password controls.** W1114 is an `Input` (`@keel/ui`, JSX or a call with an object literal) with a literal `type` `password`, or a literal `autocomplete` holding the token `current-password` or `new-password`, whose `field` is `f.field('<path>')`, `f` a `const` of the file bound to a `form(<schema>, …)` call (`@keel/forms`), where the schema, followed as `schemaHolds` follows it and walked one path segment at a time through `s.object` fields, ends at a call `s.<name>(…)` of `@keel/schema` other than `s.secret`. Trailing method calls (`.optional()`, `.pii()`) are passed over at each step. Not reported: a step it cannot follow, a numeric segment, a computed path or `type`, and a `field` held in a variable. A password the server receives as a plain string reaches logs and stores as written; `s.secret` keeps it from both (k.privacy).

**Rules.** W1114 a password control bound to a field whose schema node is not `s.secret` (no fix).

**Conformance.**
- `carriesReveal` is true for `reveal(p.k)`, `{ a: reveal(p.k) }` and a `const` bound to `` `${reveal(p.k)}` ``, and false for `hash(reveal(p.k))`, `reveal(p.k).length`, `reveal(p.k) === h` and a parameter.
- With `names` `[{ from: '@keel/std-tokens', name: 'Digested' }]`, `schemaHolds` is `'yes'` for `s.object({ d: Digested })`, `D.optional()` with `D` an alias of it, `t.Digested` of a namespace import, and a `const` of an imported `*.schema.ts` holding one; `'unknown'` for `s.object({ d: make() })`; `'no'` for `s.object({ d: s.string() })` and for a schema imported from another package.
- `outputSchemas` lists the `output` of an API entry in `contract(...)` and of a page `loader`'s declaration, inline and through a `const`, and nothing for a `loader` given `decl()`.
- `<Input type="password" field={f.field('pw')} label="P" />` with `pw: s.string()` is one W1114, as are `autocomplete="new-password"` without `type`, the schema imported from a `*.schema.ts`, and a nested path `a.pw`; `pw: s.secret(s.string()).optional()`, `f.field(p)`, `pw: make()` and `type={t}` are none.
