# k.topology: Deployables
status: conformance-covered
**Declaration.** `topology.ts` default-exports `topology({ <name>: { modules, adapter, servedBy?, storage?, shells?, caller?, origins?, styles? } })` (`@keel/server`), read statically; Adapters: `node` (serves the resume entry), `static` (prerendered HTML per route, k.hosting Static), `client` (loaders, actions in the browser; entry `mount(App, el)`, real `ctx`). Each module is in one deployable, where its routes, actions, live loaders and runners run. `styles` lists package specifiers whose export is a `.css` file (`['@keel/ui/fonts']`): each is imported by the deployable's entry, so its documents link it (k.head) in dev and build.

**Route table.** Generated entries merge each module's `routes` into `createApp({ routes })`: an app module's `modules/<id>/routes.ts`, a stdlib module's `./routes` export (none: no routes) from the `@keel/std-*` package in an app manifest's `deps` whose root manifest has that `id`.

**Runners.** A module's background work is the `runners` export of `modules/<id>/runners.server.ts`: `Runner`s `{ run(ctx, signal): Promise<void> }`. `createApp({ runners: { [moduleId]: Runner[] } })` calls each `run` of the served deployable's modules once after startup with the app `ctx`. A `run` that rejects before `signal` aborts is a `keel.unexpected` `diag` and runs again 1,000 ms later on `ctx.clock`. `app.close()` aborts each runner's `signal` and open event stream and resolves once every `run` settles.

**Calls and peers.** A module calls another's API entries through `service({ contract })` (k.services), encoded alike in every topology: a split adds latency and `api.network`/`api.timeout` outcomes, never another value. `createApp({ peers: { [deployable]: URL | ServerApp } })` names the other `node` deployables: URLs in production, apps in process. A `service` call is answered in process when its module is here or in an in-process peer, else by URL. A request for a path a peer serves (by `routes.json` in `artifacts`) is forwarded to the peer's origin: method, path, search, headers but `host` and hop-by-hop ones, body (`maxBodyBytes`); its response, a 3xx too, is returned less the same headers and `content-encoding` (unreachable: 502 `keel.unreachable` and a `diag` `peer unreachable: <name>`, the error's `name` only); one carrying `x-keel-forwarded` is not forwarded but answered where it arrived (a loop guard; 404 if no route there matches: through `x` to `y` to `z` no route of `z` is reached). Forwarding, a deployable's one relay of a client's request to a peer (pages, API routes, event streams: live loaders, std.channels), judges no route `local`: it marks each request `x-keel-forwarded: 1`, as a server's `service` call does (in process or by URL), and a peer's `local` route refuses it (k.contract Local routes). `keel dev` hands each request to the `createApp` whose route matches it, with its connection, unforwarded. The `node` deployables share one `KEEL_SECRET` (k.deploy): each accepts a caller or `user` (k.user) another signs.

**Local topology.** `keel dev` (its watcher: k.cli Dev watcher) serves every deployable in one process on one origin, on loopback alone (`localhost`, `127.0.0.1`, `::1`); any other Vite `server.host` (`true`, `0.0.0.0`) is E1560 naming `server.host`, and nothing listens. Only `keel dev --host <address>` listens wider (no environment value or committed file can): `<address>` is a machine IP address or `0.0.0.0` (else E1560 naming `--host`); it listens there and on loopback and prints one W1569 `keel dev listens on <addresses>: anyone on that network can reach it`, whose explanation names what that reaches (Vite's source modules, HMR, dev error texts, all the app serves in dev, a dev sign-in fixture's fixed secret). `/__keel/inspect` (k.inspect) answers only loopback connections, `--host` or not, whatever its `Host` or `Origin`. Every other server Keel starts in dev or tests listens on loopback alone, with no switch (k.e2e-run Reach). Vite serves `client` entries with HMR; each `node` and `static` deployable runs its dev `createApp` (real `ctx`, `.keel-dev/` storage) and runners, the others its in-process peers, and serves its paths; its documents resume its own islands. Its documents' entry: k.server Document.

**Rules.** W1569 `keel dev --host` listens beyond loopback · E1552 `topology.ts` not statically readable, a name not `[a-z][a-z0-9-]*`, a module unknown or in two deployables. A module is unknown when no `modules/<id>/module.ts` exists and no stdlib or library package in an app manifest's `deps` has root manifest `id` `<id>`: `keel check` and `keel build` report it at the id in `topology.ts`, `<name>: unknown module <id>`, so no build holds one; `createApp` refuses it at start (k.deploy Refusals at start). A deployable key the Declaration omits is E1552 too. A project root is the root or any folder without a `modules` or `node_modules` segment, outside every folder whose `package.json` marks it a library (k.library Kind), that holds a `.keel/` artifact or a `topology.ts` with a default export, readable or not; an unreadable one is E1552 at its path and the folder's files are checked as that project's · E1553 a `static` route with params or actions · E1559 one path in two deployables (names both) · E1558 a live loader, or a `loader` or `action` naming `stores`, in a `*.server.ts` of a module a `client` or `static` deployable serves (at the call in `keel check` and `keel build`; `createApp` throws it; fix: none), and there a `loader` or `action` call they cannot read: `decl` not an object literal, or with a spread or computed key; a loader `fn` neither inline nor a top-level function or `const` · E1587 a `styles` entry that is not a string literal or whose export is not a `.css` file (`keel check`, `keel build`) · E1586 a placed stdlib module whose `./contract` resolves and `./routes` does not (at its id) · E1511 (k.api) · E1560 (k.deploy).

**E1587's message.** `<name>: styles is not an array literal`, `<name>: a styles entry is not a string literal`, or `<name>: styles entry '<spec>' is ` then `a path`, `no package export` or `an export that is not a .css file`, `<spec>` shortened from its front past the bound (k.check Diagnostics); the remedy, a package export that is a `.css` file, is `keel explain`'s. `web: styles entry './x.css' is a path` is 37 units; `web: styles entry '@keel/ui/brand' is an export that is not a .css file`, 71.

**E1552's key message.** A deployable key the Declaration omits is E1552: `<name>: <key> is not a deployable key` (`web: cache is not a deployable key`, 34 units); the keys it may hold are `keel explain`'s.

**Conformance.**
- Fixture modules `a` (its loader calls `service({ contract: b })`) and `b` (a runner), served in one process as `{ one: [a, b] }` and as `{ x: [a], y: [b] }` under sim ctxs of one seed: a generated request script through `one` and through `x` gets equal statuses, bodies and final store states.
- `x` answers a path of `b` with `y`'s status, headers and body, or 502 `keel.unreachable` with `y` down; one carrying `x-keel-forwarded` is not forwarded.
- With `a` and `b` in one deployable a `service({ contract: b })` call makes no `ctx.net.fetch`; with `y` at `http://y.test` it makes one, to that URL.
- `createApp({ runners })` runs each runner of the served deployable once, none of another; `close()` aborts their signals and resolves once each `run` settles; a rejected `run` runs again 1,000 ms later on the sim clock.
- Two routes with path `/p` in modules of different deployables are one E1559 in `keel check` and in `keel build`.
- With `origin` `https://a.example`, a POST with that `Origin` to another host passes the same-site check, and the caller cookie is `__Host-keel-caller`.
- `keel dev` answers a `client` page and a path of each `node` deployable from one process on one origin.
- In a module a `client` deployable serves, a `loader` naming `stores`, an `action` naming `stores` and a loader whose `fn` is `async function*` are each one E1558 in `keel check` and `keel build`, and `createApp` for that deployable throws E1558; in a `node` deployable's module none is.
- In a `client` module's `*.server.ts`, `loader(c, 'a.feed', {}, feed)` with `const feed = async function* …`, `r.loader(c, 'a.home', { output, stores }, fn)` through `import * as r`, and `loader(c, 'a.home', { ...base, output }, fn)` are each one E1558 in `keel check` and `keel build`; `loader(c, 'a.home', { output }, load)` with `load` an `async function` of the file is none.
- A placed stdlib module whose `./contract` export resolves and `./routes` does not is one E1586 at its `topology.ts` id in `keel check` and `keel build`; both or neither is none.
- `keel dev` answers a `static` deployable's route with the document its `createApp` renders, its loader's text in it.
- With `styles: ['@keel/ui/fonts']`, a built `node` document's head and a built `client` `index.html` each link a stylesheet holding that file's `@font-face` rules; without it, neither does.
- `styles` entries `'./x.css'`, `'@keel/ui'` and a variable are each one E1587 in `keel check` and `keel build`.
- With `styles: ['@keel/ui/fonts']`, a `node` document served by `keel dev` links a stylesheet holding that file's `@font-face` rules, each `url()` answering 200; without it, the stylesheet holds none.
- Under `keel dev` of a `client` deployable `web` and a `node` deployable `api` whose page and app both serve section `x`, the inspect document's `sections.x` is `api`'s and `deployables.web.sections.x` and `deployables.api.sections.x` are each its own.
- In a fixture whose `vite.config.ts` sets `server.watch: { usePolling: false, interval: 1000 }` and holds a plugin that writes `config.server.watch` to a file in `configResolved`, `keel dev` with `KEEL_DEV_POLL=1` records `usePolling: true` and `interval: 100`; with `KEEL_DEV_POLL` unset, `''` or `0` it records `usePolling: false` and `interval: 1000`.
- `keel dev` with `KEEL_DEV_POLL=true`, and with `KEEL_DEV_POLL=2`, prints one E1560 line naming `KEEL_DEV_POLL` and not the value, listens on no port and exits 1.
- With `topology({ web: { modules: ['shop', 'ghost'], adapter: 'node' } })` and no `modules/ghost/`, `keel check` and `keel build` each report one E1552 at `'ghost'` in `topology.ts`, message `web: unknown module ghost`, and `keel build` writes no `dist/web/server.mjs`; with `modules/ghost/module.ts` present, or `ghost` the root manifest id of a library in `shop`'s `deps`, neither reports it.
