# k.test-run: Test end and results
status: implemented
From `@keel/testing`, under vitest: when a harness handle (k.testing) ends without `dispose()`, how `keel test` prints an error outside any test, and the run report the ledger reads.

**Disposal.** A `render`, `renderRoute` or `resumeDocument` handle made while a test runs, in its body or a `beforeEach` or `afterEach` hook, is disposed when that test ends, passed or failed, after its `afterEach` hooks: as `dispose()`, its elements leave the document, its scope is disposed and its seeded stores are restored. A route handle is disposed with every document it opened. A handle already disposed is not disposed again, so a write after a hand `dispose()` stays; a second `dispose()` does nothing, and a disposed handle's methods are E1705. A handle made outside a test (`beforeAll`, a `describe` body, module scope) is disposed only by `dispose()`, which an `afterAll` makes. With no vitest test running, nothing is registered.

**Results.** `testResults(files, errors, cwd)` turns a finished vitest run into OUTPUT.md diagnostics for `keel test` and the repository's reporter. An app frame is a stack frame whose file is an absolute path outside `node_modules`, not `node:`, and not vitest's own (`/vitest/`, `/@vitest/`); paths are relative to `cwd`. Each error outside any test's result, an unhandled error or rejection vitest reports or one `keel test` catches around the run, is one T0001 `uncaught: <first line>`, its string `code` before the line when it has one, its message clipped as k.check Diagnostics says. It is located at its first app frame, from vitest's parsed `stacks` when present, else its `stack` text; with none, at 1:1 of the file vitest names for it (`VITEST_TEST_PATH`); with neither, without a location. Both paths make it with `testResults`.

**Run report.** `writeTestReport(root, files, shard?)` writes a finished vitest run's report into `<root>/reports/tests/`, `files` the run's collected file tasks (`state.getFiles()`, as `testResults` reads them): `run.json`, or `<i>-of-<k>.json` given `shard` `{ index: i, count: k }` (vitest's `--shard=<i>/<k>`). Without `shard` it removes the folder's other files; with one, `run.json` and each `*-of-<m>.json` whose `m` is not `k`. `keel test` writes the project's report (`keel pack`'s `test` step writes none, k.library-pack Pack), and the repository's reporter each package's, both with `writeTestReport`; both runs set vitest's `includeTaskLocation`. The report is `{ v: 1, files: { [path]: { sha, tests: [{ line, state }] } } }`, as `JSON.stringify(value, null, 2)` and a line feed: one entry per test file the run collected, `path` relative to `root`, `sha` the SHA-256 hex of the file's source as the run read it, and per test case vitest ran or skipped, `line` its 1-based location line and `state` `passed`, `failed` or `skipped`, ordered by line, then as run. A file that failed to load, or holds no test, holds `tests: []`. Reports are under `reports/`, which a project does not commit.

**Summary.** The summary of `keel test` and of the repository's reporter counts `tests`, `failed` and `skipped` over the report: `tests` each test of a report entry, skipped ones among them, plus one per entry with `tests: []`; `failed` each `failed` test plus one per entry with `tests: []`, so `failed` never exceeds `tests`; `skipped` each `skipped` test. The run is not ok when `failed` or the T0001 count is above 0. With no test file and no vitest config, `keel test` runs nothing, writes no report and prints `ok test 0 tests`; with a config and no test file it is one T0001 `no test ran: vitest ended the run as failed`.

**Writes.** A test run writes under `reports/` only; a `.keel/` file the compiler writes during it (k.compiler) holds the bytes `keel build` writes. In a checkout where `keel build` has run, `keel test` changes no tracked file.

**Rules.** None of its own: a failed test and an uncaught error are T0001 (OUTPUT.md); a disposed handle's methods E1705 (k.testing).

**Conformance.**
- A test that `renderRoute`s a page with a `<main>` landmark and fails before `dispose()` leaves no element of it in the document once it ends, and the next test's `renderRoute` of that page passes its render checks.
- A `render` given `state: [[store, v]]` and never disposed: the next test reads the store's value from before the render. Disposed by hand and the store written after it in the same test: the next test reads the write, and a second `dispose()` throws nothing.
- An `afterEach` hook of the test that made a render finds it in the document; a render made in `beforeAll` is in the document in each test of its suite and is gone after an `afterAll` `dispose()`.
- A `renderRoute` with `app` whose `<Form>` submit is answered 303 leaves no element of either document after the test.
- `testResults([], [e], cwd)` for an error whose `stacks` are a `node_modules` frame, then `cwd/test/a.test.ts` 12:11, is one T0001 at `test/a.test.ts:12:11`, `uncaught: boom`; with `code` `ECONNRESET`, `uncaught: ECONNRESET boom`; with no app frame and `VITEST_TEST_PATH` `cwd/test/a.test.ts`, at `test/a.test.ts:1:1`; with neither, unlocated.
- `keel test` over a project whose test leaves a `setTimeout` that throws `new Error('late')` after the test ends prints `T0001 <file>:<line>:<col> uncaught: late` at the `throw`, and the run fails.
- `testResults([], [e], cwd)` for an error `e` whose `message` is 200 `a`s, with no `code`, `stacks` or `stack`, is one T0001 whose message is `uncaught: `, 76 `a`s and `...`; `testResults([f], [], cwd)` for a file `f` whose `result` is `{ state: 'fail', errors: [{ message: m }] }`, `m` 200 `a`s, and which has no test, is one T0001 whose message is 86 `a`s and `...`.
- `keel test` over a project whose `test/a.test.ts` holds a passing test at line 3, a failing one at line 6 and an `it.skip` at line 9 writes `reports/tests/run.json` holding `test/a.test.ts` with the SHA-256 of its source and the tests `{ line: 3, state: 'passed' }`, `{ line: 6, state: 'failed' }` and `{ line: 9, state: 'skipped' }`, and no other file in `reports/tests/`.
- `writeTestReport` with `shard` `{ index: 1, count: 2 }` over a `reports/tests/` holding `run.json` and `1-of-3.json` leaves the folder holding `1-of-2.json` alone; then without `shard`, `run.json` alone.
- In a git checkout of a project whose `.keel/` files `keel build` wrote, with `reports/` ignored, `git status --porcelain` prints nothing after `keel test`.
- `keel test` over a project whose `test/a.test.ts` holds one passing and one `it.skip` test and whose `test/b.test.ts` throws while loading has a summary with `tests` 3, `failed` 1 and `skipped` 1, and is not ok; `reports/tests/run.json` holds `test/b.test.ts` with `tests: []`.
