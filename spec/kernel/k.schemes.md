# k.schemes: Color schemes and themes
status: proposed

An app has a light scheme, a dark scheme or both, and themes (k.themes). A person's pick of either changes no class.

**Schemes.** `tokens.ts` takes an optional `schemes`: `['light']`, `['dark']` or `['light', 'dark']`; any other value is E1807 (k.ui). Without it, an app has both when one of its own color tokens (a name with no `.`, k.looks) is a `{ light, dark }` pair, else `['light']`. A pair gives one value per scheme and a string the same value in both; a pair's value for a scheme the app lacks is unused and never judged. In a library's own folder the schemes are both when a color its shipped object holds is a pair, whatever the root `tokens.ts` writes, else the root `tokens.ts`'s, so every scheme a default is written for is judged.

**CSS.** The compiled CSS (k.ui) opens with the custom properties in layers, each a selector `S` under a condition `M`: top-level tokens, `:root`; a `choice` theme, `:root[data-k-theme="<name>"]`; `contrast`, `:root` under `(prefers-contrast: more)`; `print`, `:root` under `print`. A layer's blocks, in order, each in an `@media` of its conditions joined by ` and ` (bare with none):
- `S` under `M`: each value the layer writes, a pair's light value (with one scheme, that scheme's); the top-level one declares `color-scheme` first (`light dark` with both, else the scheme), the `print` one `color-scheme:light;print-color-adjust:exact;-webkit-print-color-adjust:exact`.
- With both schemes, not in `print`: `S:not([data-k-scheme="light"])` under `screen`, `M` and `(prefers-color-scheme: dark)`, then `S[data-k-scheme="dark"]` under `screen` and `M` with `color-scheme:dark` first, each with the dark value of each pair the layer writes; the top-level layer then holds `:root[data-k-scheme="light"]{color-scheme:light}`.
- Once a `Box` writes `scheme` (k.aria Scheme), not in `print`: per scheme `<s>`, `S [data-k-scheme="<s>"]` under `screen` and `M`, with `color-scheme:<s>` and the `<s>` value of each pair the layer writes and, in a theme, of each color and overlay it writes.

With `themes`, the CSS opens `@layer keel.tokens,keel.theme,keel.contrast,keel.print;` and each layer's blocks sit in their `@layer`, so a later layer wins whatever the selector; with none, the top-level blocks are unlayered and no `data-k-theme` is written.

**Choice.** `SchemeSelect` from `@keel/ui` is the one control for a person's pick. It renders as `Select` (k.ui) does, with the options `system`, `light` and `dark` in that order, their words from `labels: { system, light, dark }`, named by exactly one of `label` and `labelledBy` (E1802), with `Select`'s style props and `styles`, role class `k-control` and `id`. Its value is `<html>`'s `data-k-scheme`, else `system`. Picking `light` or `dark` sets `data-k-scheme` to it and writes the cookie `keel-scheme=<value>; Path=/; Max-Age=31536000; SameSite=Lax`, with `; Secure` on https. Picking `system` removes the attribute and writes `keel-scheme=; Path=/; Max-Age=0; SameSite=Lax`. It is bound (`data-k`). It renders with `hidden` on the element it returns, the wrapper holding its label and its select, which the runtime removes at mount and at resume. The cookie holds one of two words and no identifier. `ThemeSelect` is the same control for a theme: options `default` then each `choice` theme `appearance(ctx)` knows, in `themes` order, each option's text (its announced name) the string `labels` holds under its name, else the name (with locales, loader text, std.messages); value `data-k-theme` when it names an option, else `default`; a pick sets `data-k-theme` and writes `keel-theme=<name>` likewise, and `default` removes both. Both go through `appearance(ctx)` (`@keel/ui`), the one way app code reads and sets the pick: reactive `scheme()` (`system`, `light`, `dark`) and `theme()` (`default` or a name), and `set({ scheme?, theme? })`, which writes as a pick does and returns `true`, or `false` with no change for a theme it does not know or with no document. It knows the `choice` themes of its deployable's tokens or, under a sim ctx, of the harness render given that ctx (k.testing, k.a11y Artifacts), whose document it uses; with no such render it knows none and has no document. On a server the reads give the request's cookies (First paint).

**First paint.** `keel build` and `keel dev` write `schemes.json` (`{ "schemes": [...], "themes": [...] }`, the `choice` themes) into each `node` deployable's artifacts folder (with `routes.json`), and `createApp` reads it once from `artifacts`; with no file the server takes `['light']` and no themes. In an app with both schemes, a `node` deployable's document writes `data-k-scheme="<value>"` on `<html>` when the request's `keel-scheme` cookie is `light` or `dark`, and none for any other value and, in any app, `data-k-theme="<name>"` when `keel-theme` names a listed theme. A `client` or `static` deployable in an app with both schemes or a `choice` theme holds in each document's head, before its first stylesheet link, `<script src="/assets/keel-scheme-<hash>.js"></script>`: a classic script of at most 300 bytes that sets the attributes from the cookies before the body is parsed, `data-k-theme` only to a theme name's form. `script-src 'self'` allows it and nothing is inline (k.security). An app with neither holds no scheme script. A `client` deployable builds to `dist/<name>/` with or without `servedBy` (k.hosting Artifact), its one document `index.html`.

**Checks.** Contrast (E1804) and the `base.focus` color (k.ui) are judged in each of the app's combinations (k.themes Combinations) and in no other. `SchemeSelect` in a project whose tokens have one scheme is E1814 at each element or call in an app or library file whose tag or callee the type pass resolves to `@keel/ui`'s `SchemeSelect`, through imports, re-exports and namespace members, and so is a `Box` writing `scheme` (k.aria), at the attribute. `ThemeSelect`, found the same way, is E1816 with no `choice` theme or with `labels` keys other than `default` and those themes.

**Rules.** E1814 `SchemeSelect` or `scheme` with one scheme (`SchemeSelect needs schemes light and dark; the tokens have <scheme> only`, `scheme="<value>" needs schemes light and dark; the tokens have <scheme> only`; fix: none) · E1816 `ThemeSelect` with no theme or other labels (`ThemeSelect needs a choice theme; the tokens have none`, `ThemeSelect labels lack <name>`, `ThemeSelect labels name no theme <key>`; fix: none).

**Conformance.**
- With color tokens `fg` `{ light: '#111111', dark: '#eeeeee' }` and `bg` `{ light: '#ffffff', dark: '#111111' }` and no `schemes`, the CSS's `:root` block declares `color-scheme:light dark` and `--k-color-fg:#111111`, a `@media screen and (prefers-color-scheme: dark)` block holds `:root:not([data-k-scheme="light"])` declaring `--k-color-fg:#eeeeee`, and a `@media screen` block holds a `:root[data-k-scheme="dark"]` rule declaring `color-scheme:dark` and `--k-color-fg:#eeeeee`.
- With those tokens and `schemes: ['light']`, the CSS's `:root` declares `color-scheme:light` and `--k-color-fg:#111111` and the CSS holds no `prefers-color-scheme` and no `data-k-scheme`; with `schemes: ['dark']`, `:root` declares `color-scheme:dark` and `--k-color-fg:#eeeeee`.
- `schemes: ['light', 'light']`, `schemes: ['sepia']` and `schemes: []` are each one E1807.
- With `brandTokens` composing a library's color `acme.x` `{ light: '#111111', dark: '#eeeeee' }` (k.looks) and no `schemes`, the CSS holds no `prefers-color-scheme`.
- With color tokens `fg` `{ light: '#111111', dark: '#787878' }` and `bg` `'#ffffff'`, `<Text fg="fg" bg="bg">x</Text>` is one E1804 with message `fg "fg" on bg "bg" is 4.42:1 in dark, needs 4.5:1`; with `schemes: ['light']` it is none.
- `<SchemeSelect id="scheme" label="Scheme" labels={{ system: 'System', light: 'Light', dark: 'Dark' }} />` renders a `select` with options of values `system`, `light`, `dark` and texts `System`, `Light`, `Dark`, value `system`, with no axe violations.
- After `fire('scheme', { type: 'change', value: 'dark' })`, `document.documentElement` has `data-k-scheme="dark"` and `document.cookie` holds `keel-scheme=dark`; after `fire('scheme', { type: 'change', value: 'system' })`, it has no `data-k-scheme` and `document.cookie` holds no `keel-scheme`.
- A `createApp` whose `artifacts` folder holds `schemes.json` `{ "schemes": ["light", "dark"] }` answers a document request sent with `Cookie: keel-scheme=dark` with `<html` carrying `data-k-scheme="dark"` and its `SchemeSelect` value `dark`; with `keel-scheme=blue`, with no cookie, with `{ "schemes": ["light"] }` or with no `schemes.json`, the document has no `data-k-scheme`.
- `keel build` of a `static` deployable, and of a `client` deployable, with both schemes and no `SchemeSelect` writes an `index.html` whose head holds a `<script src="/assets/keel-scheme-` before its first `<link rel="stylesheet"`, naming a file of at most 300 bytes; with one scheme and no theme to choose, no `keel-scheme` script.
- With `tokens.ts` exporting `brandTokens`, a page rendering a `SchemeSelect` is one E1814 at the element with message `SchemeSelect needs schemes light and dark; the tokens have light only`.
- In a library's own folder whose root `tokens.ts` is `brandTokens` composing a shipped `acme.x` `{ light: '#111111', dark: '#787878' }` on `acme.bg` `'#ffffff'`, a library `Text` with `fg="acme.x" bg="acme.bg"` is one E1804 whose message ends `in dark, needs 4.5:1`.
- With `brandTokens`, a `SchemeSelect` rendered as `<ui.SchemeSelect ... />` with `import * as ui from '@keel/ui'`, or through an app file re-exporting it, is one E1814, and one rendered in a listed library's file is one E1814 at `node_modules/<name>/<f>`.
- `SchemeSelect`'s server HTML has the `hidden` attribute, and after `resume` or `mount` it has none.
- With the first case's tokens and `themes: { slate: { color: { fg: '#222222' } } }`, the CSS opens with `@layer keel.tokens,keel.theme,keel.contrast,keel.print;`, the first case's blocks sit in `@layer keel.tokens`, and `@layer keel.theme` holds `:root[data-k-theme="slate"]` declaring `--k-color-fg:#222222`; with `slate`'s `fg` `{ light: '#222222', dark: '#dddddd' }`, it also holds `:root[data-k-theme="slate"]:not([data-k-scheme="light"])` declaring `--k-color-fg:#dddddd` under `@media screen and (prefers-color-scheme: dark)`.
- `themes: { hc: { when: 'contrast', color: { fg: '#000000' } } }` puts `:root` declaring `--k-color-fg:#000000` under `@media (prefers-contrast: more)` in `@layer keel.contrast`, and `themes: { paper: { when: 'print', color: { bg: '#ffffff' } } }` puts `:root` declaring `color-scheme:light`, `print-color-adjust:exact` and `--k-color-bg:#ffffff` under `@media print` in `@layer keel.print`; in each, every rule declaring `--k-color-fg:#eeeeee` is under an `@media` whose query starts `screen`, and no `data-k-theme` is written.
- `render` with `artifacts: { tokens }` holding `choice` themes `slate` and `forest`, of `<ThemeSelect id="theme" label="Theme" labels={{ default: 'Keel', slate: 'Slate' }} />` gives a `select` with option values `default`, `slate`, `forest`, texts `Keel`, `Slate`, `forest`, value `default` and no axe violations; after `fire('theme', { type: 'change', value: 'slate' })` `<html>` has `data-k-theme="slate"` and `document.cookie` holds `keel-theme=slate`, and after `value: 'default'` neither.
- With `brandTokens`, a `ThemeSelect` is one E1816 with message `ThemeSelect needs a choice theme; the tokens have none`; with a theme `slate` and `labels={{ default: 'Keel', forest: 'Forest' }}` it is two, `ThemeSelect labels lack slate` and `ThemeSelect labels name no theme forest`.
- With `ctx` a sim ctx given to a `render` whose tokens hold a theme `slate`, `appearance(ctx).set({ theme: 'slate' })` is `true`, then `theme()` is `slate`, `<html>` has `data-k-theme="slate"` and a computed reading `theme()` has run again; `set({ theme: 'nope' })` is `false` and changes neither; so is `set({ theme: 'slate' })` on a sim ctx given to no render.
- A `createApp` whose `schemes.json` is `{ "schemes": ["light"], "themes": ["slate"] }` answers `Cookie: keel-theme=slate` with `<html` carrying `data-k-theme="slate"`, and `keel-theme=nope` with none; a `static` build with one scheme and a `choice` theme has the `keel-scheme` script, and with only a `print` theme none.
