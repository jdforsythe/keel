# k.unsafe: Unsafe and negative type tests
status: implemented

**Unsafe.** `unsafe(reason, fn)` is the one named path around a check `keel check` makes: in a file under `unsafe/`, `fn` is a lifted range (k.check App code). A call stands for code that ships or runs and steps outside a guarantee. A claim that a call does not compile is a negative type test, never an `unsafe` call. In a kernel package, where of the lifted codes only E1757 is enforced (`tooling/structure-lint.mjs`), `unsafe/` holds type-system escapes: each call's function holds a cast, `!`, `any`, a ts-suppression comment or a type predicate E1762 reports. In a library's package (`"keel": "library"`, k.library), whose files the app's reading checks, each call's function holds a finding of a lifted code (a cast, a type predicate E1762 reports, a DOM global read); a throw is a defect and a catch is `attempt` (k.errors), never an `unsafe` call. A runtime technique with no such escape (a V8 flag, a `node:vm` context) is ordinary code in `src/`, its hazard stated in a comment where it lives.

**Type predicates.** A function whose return type is a type predicate (`x is T`) or an assertion (`asserts x is T`, `asserts x`) tells the type checker what its body has proven, and nothing checks the claim, so a predicate whose body does not establish `T` is a cast. That cannot be decided in general. `keel check` decides the shape it can: E1762 is a predicate or assertion whose claimed type, read through its properties, array elements and union members to any depth, holds a call or construct signature with a parameter or with a return type other than `void`, `unknown` or `any`, or holds a type parameter of the predicate itself, since `typeof v === 'function'` proves no signature and no value proves a type argument. A key guard is none: a predicate whose body's returned expression is, or is a `&&` chain ending in, `B.has(x)` or `Object.hasOwn(x, K)`, `B` a module-level `const` `WeakSet` the file does not export and `K` a `Symbol.for` key, `x` the predicate's parameter, proves membership in what the file marked. A predicate E1762 reports lives in an `unsafe(` call, where it is lifted and counted; `keel review` lists every other predicate and assertion in a range (R1015) for a person to read whether its body checks every property its type names.
**One path.** `unsafe` is the one path around a check, so no spelling is another: E1451, E1452, E1455 (k.errors) and E1207 (k.reactive) find their callee by its symbol in the type pass, not its spelling: an alias, a namespace member, a computed member with a literal key (`p['catch']`), `.call`, `.apply` or `.bind` of it (`Promise.prototype.catch.call(p, g)`), and `Reflect.apply` of it are each that call. The function used as a value any other way (stored, passed, returned, under a non-literal computed key) is that code at the use, message `<name> used other than as a call; check cannot follow it`, no fix. Under `check(files, { types: false })` they read spellings only. For E1455 the code argument is, by form: the second argument of a call of `defect` or an alias; the third of `defect.call(t, m, c)`; the second element of the array literal of `defect.apply(t, [m, c])` and of `Reflect.apply(defect, t, [m, c])`. E1455 is reported at that argument or element; an arguments value that is no array literal or holds a spread before the code, and a `defect.bind(...)`, is one E1455 at that value or at `bind`, message `defect code check cannot read`.
**Reason.** The justification string argues that the escape holds: the invariant that makes it safe and what keeps the invariant true. `keel check` judges its form: E1754 when there is none (k.check), E1760 when it holds fewer than 8 words. A word is a run of non-space characters holding a letter or digit, counted over the string literal's value or the template's cooked text. Whether the argument holds is judged in review: `keel review` lists every call with its reason (R1001, k.escapes), for a person or the `keel-escapes` skill.

**Negative type tests.** A negative type test is a file named `*.test-d.ts` or `*.test-d.tsx` under a `test/` or `conformance/` folder: test code, type-checked with its project (`keel check`; a package's `check`), never run and imported by no file. An expectation is a comment whose text, leading white space aside, starts `@ts-expect-error`, then white space, then a description holding a letter: what must not compile (`// @ts-expect-error a page guard needs a redirect`). When the line after it compiles, TypeScript reports TS2578: E1751 in `keel check`, a failed `check` in a package. A ts-suppression comment (E1757, R1050) is a comment with a line that starts, leading white space, `/` and `*` aside, with `@ts-ignore`, `@ts-expect-error` or `@ts-nocheck`; a comment that quotes one further on is none. In a negative type test an expectation is no E1757; a bare `@ts-expect-error`, `@ts-ignore`, `@ts-nocheck`, a cast, `!` and `any` are E1757 as in any file. Every other test file holds no `@ts-expect-error` (E1757). The run-time half of a claim, the same call made untyped, sits in a test or conformance file that runs.

**Ledger.** `keel ledger --write` writes two counts at the ledger file's top level (k.ledger File):
- `unsafe`: the `unsafe(` and `unsafe<T>(` calls, outside comments and strings, in the `src` and `unsafe` directories of `packages/*`, every file of `apps/*` and the root `modules/**` of an app; the declaration `function unsafe<T>(` is no call. E1706 reports a count above the committed one; with `--scope` the count is the apps' in scope and E1706 reports one above 0.
- `negativeTypes`, after `hostElements`: the expectations in the negative type tests of `packages/*`, `apps/*` and an app's root `test/**` and `modules/**`, none under `node_modules/` (a library's, k.library); with `--scope <prefix>`, those of the apps the prefix selects by item key (`golden-1:`) and of the negative type tests whose path starts with it (`apps/golden-1/`). It is written and never compared.

A negative type test gives no item evidence: the runner reports no test in it, so a clause it asserts takes its rung from its run-time half (k.ledger).

**Rules.** E1760 an `unsafe(` justification string of fewer than 8 words, in any code file (`src/` and test code too), at the string's first character · E1762 a type predicate or assertion function, its declaration or arrow function, whose claimed type Type predicates says no body can prove, at the return type, message `type predicate claims <what> no check proves; move it into unsafe()` (`<what>` `a call signature` or `a type parameter`), in app code and a library's files outside lifted ranges and, in this repository, in every package's `src/` (`tooling/structure-lint.mjs` S0019, same position and message), no fix · E1761 a `*.test-d.ts` or `*.test-d.tsx` file not under a `test/` or `conformance/` folder (at its first line), an `import`, `export ... from` or `import()` whose specifier names one, at the specifier's opening quote, or an `unsafe(` call in one, at the call's first character. In this repository `tooling/structure-lint.mjs` reports S0014: an `unsafe(` call in a file of `packages/*` (not `apps/*`) whose lifted range holds no finding E1757 makes (in a library's package, no finding of a lifted code the app's reading makes), or that has no lifted range. None carries a fix.
