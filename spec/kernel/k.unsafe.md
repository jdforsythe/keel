# k.unsafe: Unsafe and negative type tests
status: implemented

**Unsafe.** `unsafe(reason, fn)` is the one named path around a check `keel check` makes: in a file under `unsafe/`, `fn` is a lifted range (k.check App code). A call stands for code that ships or runs and steps outside a guarantee. A claim that a call does not compile is a negative type test, never an `unsafe` call. In a kernel package, where of the lifted codes only E1757 is enforced (`tooling/structure-lint.mjs`), `unsafe/` holds type-system escapes: each call's function holds a cast, `!`, `any`, a ts-suppression comment or a type predicate E1762 reports. In a library's package (`"keel": "library"`, k.library), whose files the app's reading checks, each call's function holds a finding of a lifted code (a cast, a type predicate E1762 reports, a DOM global read); a throw is a defect and a catch is `attempt` (k.errors), never an `unsafe` call. A runtime technique with no such escape (a V8 flag, a `node:vm` context) is ordinary code in `src/`, its hazard stated in a comment where it lives.

**Type predicates.** A function whose return type is a type predicate or an assertion tells the type checker what its body has proven. E1762 reports one whose body is none of the proofs k.identity Proven predicates lists; a claim no check establishes lives in an `unsafe(` call, where E1762 is lifted and the call is counted.
**One path.** `unsafe` is the one path around a check, so no spelling is another: E1451, E1452, E1455, E1457 to E1461 (k.errors, k.attempt, k.defects, k.expect, k.supervise) and E1207 (k.reactive) find their callee by its symbol in the type pass, not its spelling: an alias, a namespace member, a computed member with a literal key (`p['catch']`), `.call`, `.apply` or `.bind` of it (`Promise.prototype.catch.call(p, g)`), and `Reflect.apply` of it are each that call. The function used as a value any other way (stored, passed, returned, under a non-literal computed key) is that code at the use, message `<name> used other than as a call; check cannot follow it`, no fix. Under `check(files, { types: false })` they read spellings only. For E1455 the detail (k.defects) is the second argument of a call of `defect` or an alias; the third of `defect.call(t, m, d)`; the second element of the array literal of `defect.apply(t, [m, d])` and of `Reflect.apply(defect, t, [m, d])`. E1455 is reported at that argument or element, or at its `code` value; an arguments value that is no array literal or holds a spread at or before the detail, a spread argument there in a call, and a `defect.bind(...)`, is one E1455 at that value or at `bind`, message `defect code check cannot read`.

**Other spellings.** A catch or a throw under a spelling One path does not reach is reported too, in app code and a library's files, with no fix:
- E1452 at the element: a binding pattern that takes `then`, `catch` or `finally` out of a value typed `PromiseLike` (`const { then } = p`), message `<name> taken off a promise; check cannot follow it`.
- E1452 at the key: an element access whose key is no literal, on a value typed `PromiseLike` or on `Promise` (`p[k](g)`), message `promise member chosen at run time; check cannot follow it`.
- The `throw` rule's code and message (k.errors Rules), at the callee: a call of `throw` on a value typed `Generator`, `AsyncGenerator` or `Iterator` (`g.throw(x)`).
- E1452 at the call or the assignment: a listener for uncaught throws. `addEventListener`, bare or on `globalThis`, `window` or `self`, given the literal `'unhandledrejection'`, `'rejectionhandled'` or `'error'`; an assignment to `onunhandledrejection` or `onerror` of those; `process.on`, `once`, `addListener` or `prependListener` given `'uncaughtException'`, `'unhandledRejection'` or `'uncaughtExceptionMonitor'`. Message `listener for uncaught throws in app code: the Boundary and the server own them`. With an event name that is no literal those calls are R1020 in `keel review` (k.escapes): check cannot read the name.
**Reason.** The justification string argues that the escape holds: the invariant that makes it safe and what keeps the invariant true. `keel check` judges its form: E1754 when there is none (k.check), E1760 when it holds fewer than 8 words. A word is a run of non-space characters holding a letter or digit, counted over the string literal's value or the template's cooked text. Whether the argument holds is judged in review: `keel review` lists every call with its reason (R1001, k.escapes), for a person or the `keel-escapes` skill.

**Negative type tests.** A negative type test is a file named `*.test-d.ts` or `*.test-d.tsx` under a `test/` or `conformance/` folder: test code, type-checked with its project (`keel check`; a package's `check`), never run and imported by no file. An expectation is a comment whose text, leading white space aside, starts `@ts-expect-error`, then white space, then a description holding a letter: what must not compile (`// @ts-expect-error a page guard needs a redirect`). When the line after it compiles, TypeScript reports TS2578: E1751 in `keel check`, a failed `check` in a package. A ts-suppression comment (E1757, R1050) is a comment with a line that starts, leading white space, `/` and `*` aside, with `@ts-ignore`, `@ts-expect-error` or `@ts-nocheck`; a comment that quotes one further on is none. In a negative type test an expectation is no E1757; a bare `@ts-expect-error`, `@ts-ignore`, `@ts-nocheck`, a cast, `!` and `any` are E1757 as in any file. Every other test file holds no `@ts-expect-error` (E1757). The run-time half of a claim, the same call made untyped, sits in a test or conformance file that runs.

**Ledger.** `keel ledger --write` writes two counts at the ledger file's top level (k.ledger File):
- `unsafe`: the `unsafe(` and `unsafe<T>(` calls, outside comments and strings, in the `src` and `unsafe` directories of `packages/*`, every file of `apps/*` and the root `modules/**` of an app; the declaration `function unsafe<T>(` is no call. E1706 reports a count above the committed one; with `--scope` the count is the apps' in scope and E1706 reports one above 0.
- `negativeTypes`, after `hostElements`: the expectations in the negative type tests of `packages/*`, `apps/*` and an app's root `test/**` and `modules/**`, none under `node_modules/` (a library's, k.library); with `--scope <prefix>`, those of the apps the prefix selects by item key (`golden-1:`) and of the negative type tests whose path starts with it (`apps/golden-1/`). It is written and never compared.

A negative type test gives no item evidence: the runner reports no test in it, so a clause it asserts takes its rung from its run-time half (k.ledger).

**Rules.** E1760 an `unsafe(` justification string of fewer than 8 words, in any code file (`src/` and test code too), at the string's first character · E1762 a type predicate or assertion whose body does not prove its type (k.identity) · E1761 a `*.test-d.ts` or `*.test-d.tsx` file not under a `test/` or `conformance/` folder (at its first line), an `import`, `export ... from` or `import()` whose specifier names one, at the specifier's opening quote, or an `unsafe(` call in one, at the call's first character. In this repository `tooling/structure-lint.mjs` reports S0014: an `unsafe(` call in a file of `packages/*` (not `apps/*`) whose lifted range holds no finding E1757 makes (in a library's package, no finding of a lifted code the app's reading makes), or that has no lifted range. None carries a fix.
