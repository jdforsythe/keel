# k.unsafe: Unsafe and negative type tests
status: proposed

**Unsafe.** `unsafe(reason, fn)` is the one named path around a check `keel check` makes: in a file under `unsafe/`, `fn` is a lifted range (k.check App code). A call stands for code that ships or runs and steps outside a guarantee. A claim that a call does not compile is a negative type test, never an `unsafe` call. In a kernel or stdlib package, where of the lifted codes only E1757 is enforced (`tooling/structure-lint.mjs`), `unsafe/` holds type-system escapes: each call's function holds a cast, `!`, `any` or a ts-suppression comment. A runtime technique with no such escape (a V8 flag, a `node:vm` context) is ordinary code in `src/`, its hazard stated in a comment where it lives.

**Reason.** The justification string argues that the escape holds: the invariant that makes it safe and what keeps the invariant true. `keel check` judges its form: E1754 when there is none (k.check), E1760 when it holds fewer than 8 words. A word is a run of non-space characters holding a letter or digit, counted over the string literal's value or the template's cooked text. Whether the argument holds is judged in review: `keel review` lists every call with its reason (R1001, k.escapes), for a person or the `keel-escapes` skill.

**Negative type tests.** A negative type test is a file named `*.test-d.ts` or `*.test-d.tsx` under a `test/` or `conformance/` folder: test code, type-checked with its project (`keel check`; a package's `check`), never run and imported by no file. An expectation is a comment whose text, leading white space aside, starts `@ts-expect-error`, then white space, then a description holding a letter: what must not compile (`// @ts-expect-error a page guard needs a redirect`). When the line after it compiles, TypeScript reports TS2578: E1751 in `keel check`, a failed `check` in a package. In a negative type test an expectation is no E1757; a bare `@ts-expect-error`, `@ts-ignore`, `@ts-nocheck`, a cast, `!` and `any` are E1757 as in any file. Every other test file holds no `@ts-expect-error` (E1757). The run-time half of a claim, the same call made untyped, sits in a test or conformance file that runs.

**Ledger.** `keel ledger --write` writes two counts at the ledger file's top level (k.ledger File):
- `unsafe`: the `unsafe(` and `unsafe<T>(` calls, outside comments and strings, in the `src` and `unsafe` directories of `packages/*`, every file of `apps/*` and the root `modules/**` of an app; the declaration `function unsafe<T>(` is no call. E1706 reports a count above the committed one; with `--scope` the count is the apps' in scope and E1706 reports one above 0.
- `negativeTypes`, after `hostElements`: the expectations in the negative type tests of `packages/*`, `apps/*` and an app's root `test/**` and `modules/**`; with `--scope`, the apps' in scope. It is written and never compared.

A negative type test gives no item evidence: the runner reports no test in it, so a clause it asserts takes its rung from its run-time half (k.ledger).

**Rules.** E1760 an `unsafe(` justification string of fewer than 8 words, at the string · E1761 a `*.test-d.ts` or `*.test-d.tsx` file not under a `test/` or `conformance/` folder (at its first line), an `import`, `export ... from` or `import()` naming one, at the specifier, or an `unsafe(` call in one, at the call. In this repository `tooling/structure-lint.mjs` reports S0014: an `unsafe(` call in a file of `packages/*` whose lifted range holds no finding E1757 makes. None carries a fix.

**Conformance.**
- In `test/a.test-d.ts`, `// @ts-expect-error a number is no string` above `export const n: string = 1` gives `keel check` no diagnostic; with the line `export const n: string = "a"` instead, one E1751 whose message starts `TS2578`.
- In `test/a.test-d.ts`, `// @ts-expect-error` with nothing after it, `// @ts-ignore a number is no string`, `x as T`, `x!` and `let v: any` are one E1757 each; in `test/a.test.ts`, `// @ts-expect-error a number is no string` is one E1757.
- In `test/a.test-d.tsx`, `{/* @ts-expect-error text is no child of Match */}` is no E1757.
- `modules/m/a.test-d.ts` and `modules/m/unsafe/a.test-d.ts` are one E1761 each at line 1; `modules/m/test/a.test-d.ts` and `test/a.test-d.ts` are none; `import "./a.test-d.ts"` in `test/b.test.ts` is one E1761 at the specifier; `unsafe("one two three four five six seven eight", () => 1)` in `test/a.test-d.ts` is one E1761 at the call.
- In `modules/m/unsafe/a.ts`, `unsafe("one two three four five six seven", () => c as T)` is one E1760 at the string and no E1757; with `eight` added to the string, and with the same eight words as a template without substitutions, no E1760; `unsafe("a - b - c - d - e - f - g", () => c as T)` is one E1760.
- `keel ledger --write` of a fixture whose `packages/p/unsafe/a.ts` holds two `unsafe(` calls and one in a comment, whose `packages/p/unsafe/unsafe.ts` declares `function unsafe<T>(`, and whose `packages/p/test/a.test-d.ts` holds three expectations writes `unsafe: 2` and `negativeTypes: 3`; then a fourth expectation makes `--diff` report no E1706, and a third call makes it report E1706.
- A clause cited by the `// Spec:` header of `packages/p/conformance/a.test-d.ts` alone is `none` in `keel ledger`.
- `keel review` reports no R1050 for `// @ts-expect-error a page guard needs a redirect` in `test/a.test-d.ts` of a range adding it, and one R1050 for `// @ts-expect-error` with nothing after it there.
- In `tooling/structure-lint.mjs` over a root holding `packages/p/unsafe/a.ts` with `unsafe("one two three four five six seven eight", () => 1)`, one S0014; with `() => c as T` in place of `() => 1`, none.
