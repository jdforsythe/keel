# k.a11y-static: Static contrast
status: implemented
E1804 in `keel check` (k.a11y Contrast): the tokens it reads, the text it judges and what it leaves to the render check; and the token names E1801 judges (k.ui).

**Tokens.** Every command that runs the k.check pipeline over a project (`keel check`, the check `keel build` runs, `keel ledger`, `keel evidence`, `keel mcp`, `keel lsp`) gives each project the `tokens` export of its `tokens.ts`, the source `keel test` gives a render (k.a11y Artifacts). It is evaluated on every run, with the files it imports, and never cached: the next check judges a changed token. A `tokens.ts` that throws, exports no `tokens` or whose `tokens` fail `TokenSchema` is E1807 (k.ui), placed and worded as k.themes Token errors says, and that project gets no tokens. Without tokens no contrast is judged statically, no render runs E1804 (k.a11y Artifacts), and the project's 1.4.3 items stay `none`; with no `tokens.ts` each token a use names is E1801 (Token names).

**Token names.** A token prop's groups: `p`, `px`, `py`, `m`, `mx`, `my`, `gap`: `space`; `w`, `h`: `size`, then `space`; `bg`, `fg`: `color`, then `overlay`; `radius`, `font`, `fontSize`, `weight`, `shadow`, `border`: the group of its name. In an app file `keel check` reads each string literal given to a base element or `Part` as a token prop (directly, as a value of a responsive object or under `states`, or in a part style of `styles`), each key of a responsive object but `base` and `print`, and each `look` written as a string literal. A name in none of its prop's groups of the project's tokens, a key that is no `breakpoint` token, and a look that `look` lacks are each one E1801 at the literal or key, with no fix. Messages: `<prop>="<value>" is not a <groups> token` (`<groups>` joined by ` or `), `breakpoint "<value>" is not a breakpoint token`, `look="<value>" is not a look token`, `<value>` clipped at 20 units by k.check Diagnostics' clip. With no `tokens.ts` at the project root each such literal and key is E1801 and its message ends `: the project has no tokens.ts`. A project whose `tokens.ts` is E1807 has no name judged. A keyword prop (`direction`, `align`, `justify`, `wrap`, `textAlign`, `breakBefore`, `breakAfter`, `breakInside`) is judged by its type, not here.

**Values.** In an app file, an element's `fg`, `bg`, `fontSize` and `weight` are each, first found: its own prop written as a string literal; the set of its `look` written as a string literal; its role's `base` set (k.ui Base, the `base` breakpoint); its parent's, when the parent is a `@keel/ui` base element, `Part`, or one of `If`, `For`, `Match`, `Case` and `Boundary`, which add no markup. A later attribute replaces an earlier one and an element's own props replace its look's (k.ui). A value is unread when the prop is written any other way (an expression, a responsive object but its `print` key, k.themes Combinations), when a spread comes after it, when the element has a spread and does not write the prop, when the prop is not written and the `look` is not a string literal, or when it comes from an unread value. The chain ends at the component's outermost element and below any other component, whose markup another file holds: there `bg` is not found, and `fg`, `fontSize` and `weight` are `base.page`'s, else `#000000` and normal size.

**Judged.** A base element or `Part` holding text is judged: a JSX text child with a non-space character, or an expression child that is not JSX, a function, a `.map(...)` call, a string of spaces, or a conditional or logical expression with such a branch. It is not judged when its `fg` or `bg` is unread or not found, and it is exempt under a `hidden` or `disabled` attribute written bare or `{true}`, or `aria-disabled="true"`, on itself or on an element its values pass through, as at render. Its threshold is k.a11y's; with an unread `fontSize` or `weight` it is 3:1, which text of every size needs. The first failing combination is reported at the element. What is not judged statically is judged at render, and the ledger counts no 1.4.3 item without that: `example` needs E1804 among the `rules` of a passing `renderRoute` run of the route (k.a11y Claims), and that render judges every element holding text in the route's chain.

**Message.** `fg "<fg>" on bg "<bg>" is <ratio>:1 in <combination>, needs <need>:1`, with ` over "<backdrop>"` after `"<bg>"` for a `bg` overlay: the two tokens, the ratio to two decimals, the combination, and `7`, `4.5` or `3`. Each `base` set but `focus` (`page` among them) and each `look` that names an `fg` or a `bg` is judged where `tokens.ts` declares it: its `fg`, else `base.page`'s, else `#000000`, on its `bg`, else `base.page`'s, else `#FFFFFF`, at its own `fontSize` and `weight`; the finding is at the set's name in `tokens.ts`, its message prefixed `base.<name>: ` or `look.<name>: `. A message over 89 UTF-16 code units keeps its first 86 and ends `...`.

**Combinations.** E1804, the render check (k.a11y Contrast) and `base.focus` judge each combination (k.themes Combinations), `base.focus` none printing; with the `contrast` theme on, text needs 7:1, or 4.5:1 at a large size (WCAG 1.4.6). An element at or under a `Box scheme` its chain passes (k.aria Scheme) is judged in that scheme's combinations and the printing ones; one at or under `media="screen"` in none printing, one at or under `media="print"` only printing.

**Overlays.** An `fg` or `bg` naming an overlay (k.values Overlays) is judged on its composite. A `bg` overlay sits on the chain's `bg` of the element's parent when found, else on each of its `over`, and its text is judged against the composite over each; an `fg` overlay is composited over the element's `bg`, else over each of its `over`. A found backdrop missing from `over`, or itself an overlay, is E1817 at the overlay's literal: `<prop> "<overlay>" sits on "<backdrop>", not in its over`, or `<prop> "<overlay>" sits on overlay "<backdrop>"` (fix: k.themes Fixes).

**Library contrast.** In an app, an E1804 at an element of a library file, or at a library look (a key of the `look` group alone, whatever other groups hold the same name), is reported in `tokens.ts` and not at the library's file: at the opening quote of the app's key for its `fg` when the app writes one, else for its `bg`, else at the spread `...<id>Tokens.color`, else line 1, column 1, the app's key being the one in the latest layer on in that combination (k.themes Combinations) that writes it, in the order `print`, `contrast`, `choice`, top level; once per pair and combination however many elements and looks hold it, so with no `themes` once per pair and scheme; message `<fg> on <bg> is <ratio>:1 in <combination>, needs <need>:1; override in tokens.ts`.

**Build.** E1802, E1804, E1807 and E1820 are errors, so `keel build`, which runs `keel check` first, exits 1 on any of them and writes nothing (k.boundary Build gate).
