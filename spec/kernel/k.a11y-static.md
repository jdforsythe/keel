# k.a11y-static: Static contrast
status: implemented
E1804 in `keel check` (k.a11y Contrast): the tokens it reads, the text it judges and what it leaves to the render check.

**Tokens.** Every command that runs the k.check pipeline over a project (`keel check`, the check `keel build` runs, `keel ledger`, `keel evidence`, `keel mcp`, `keel lsp`) gives each project the `tokens` export of its `tokens.ts`, the source `keel test` gives a render (k.a11y Artifacts). It is evaluated on every run, with the files it imports, and never cached: the next check judges a changed token. A `tokens.ts` that throws, exports no `tokens` or whose `tokens` fail `TokenSchema` is E1807 (k.ui) at `tokens.ts` line 1, column 1, and that project gets no tokens. Without tokens nothing is judged statically, no render runs E1804 (k.a11y Artifacts), and the project's 1.4.3 items stay `none`.

**Values.** In an app file, an element's `fg`, `bg`, `fontSize` and `weight` are each, first found: its own prop written as a string literal; the set of its `look` written as a string literal; its role's `base` set (k.ui Base, the `base` breakpoint); its parent's, when the parent is a `@keel/ui` base element, `Part`, or one of `If`, `For`, `Match`, `Case` and `Boundary`, which add no markup. A value is unread when the prop is written any other way (an expression, a responsive object), when the `look` is not a string literal, when a spread follows the prop or the prop is not written beside a spread, or when it comes from an unread value. The chain ends at the component's outermost element and below any other component, whose markup another file holds: there `bg` is not found, and `fg`, `fontSize` and `weight` are `base.page`'s, else `#000000` and normal size.

**Judged.** A base element or `Part` holding text is judged: a JSX text child with a non-space character, or an expression child that is not JSX, a function, a `.map(...)` call, or a conditional or logical expression with such a branch. It is not judged when its `fg` or `bg` is unread or not found, and it is exempt under a `hidden` attribute, a `disabled` attribute written bare or `{true}`, or `aria-disabled="true"`, on itself or on an element its values pass through, as at render. Its threshold is k.a11y's; with an unread `fontSize` or `weight` it is 3:1, which text of every size needs. The first failing scheme is reported at the element. What is not judged statically is judged at render, and the ledger counts no 1.4.3 item without that: `example` needs E1804 among the `rules` of a passing `renderRoute` run of the route (k.a11y Claims), and that render judges every element holding text in the route's chain.

**Message.** `fg "<fg>" on bg "<bg>" is <ratio>:1 in <scheme>, needs <need>:1`: the two tokens, the ratio to two decimals, the scheme, and `4.5` or `3`. A `base` set or look, judged at `tokens.ts`, prefixes `<set>: ` (`base.link: `). A message over 89 UTF-16 code units keeps its first 86 and ends `...`.

**Build.** E1802, E1804, E1807 and E1820 are errors, so `keel build`, which runs `keel check` first, exits 1 on any of them and writes nothing (k.boundary Build gate).

**Conformance.**
- With `tokens.ts` exporting `brandTokens`, `keel check` reports one E1804 at the line of the `<Text` of `<Box fg="divider" bg="card"><Text>x</Text></Box>` and none at the `<Box`; for `<Box fg="text" bg="card"><Text>x</Text></Box>` it reports none.
- With `brandTokens`, `keel check` reports no E1804 for `<Box bg="card"><Text fg={tone}>x</Text></Box>`, `<Box bg={tone}><Text fg="divider">x</Text></Box>`, `<Box bg="card"><Text {...rest}>x</Text></Box>`, `<Box bg="card"><Panel><Text fg="divider">x</Text></Panel></Box>` with `Panel` an app component, or `<Box bg="card"><Text fg="divider" hidden>x</Text></Box>`, and one for `<Box bg="card"><If when={on}><Text fg="divider">x</Text></If></Box>` and for `<Box bg="card"><Text {...rest} fg="divider">x</Text></Box>`.
- With color tokens `low` `#787878` and `bg` `#ffffff` and `fontSize` `big` `24px`, `<Box bg="bg" fontSize="big"><Text fg="low">x</Text></Box>` reports no E1804 and `<Box bg="bg"><Text fg="low" fontSize={size}>x</Text></Box>` reports none, while `<Box bg="bg"><Text fg="low">x</Text></Box>` reports one.
- With color tokens named by 20 `a`s (`#ffffff`) and 20 `b`s (`#ffffff`), `<Text fg="<a>" bg="<b>">x</Text>` reports E1804 with the message `fg "<a>" on bg "<b>" is 1.00:1 in light, needs 4.5:1` (86 units); with names of 30 characters each the message is 89 units, the first 86 of the whole message and `...`.
- `keel check` in a project whose `tokens.ts` exports no `tokens`, throws, or exports `tokens` with `color: { fg: 5 }`, reports one E1807 at `tokens.ts` line 1, column 1, no E1804, and exits 1; in a project with no `tokens.ts` it reports neither for `<Box bg="bg"><Text fg="low">x</Text></Box>`.
- In a project with `node_modules`, after a `keel check` that reports no E1804 for `<Box bg="bg"><Text fg="low">x</Text></Box>` with `low` `#111111`, changing `low` in `tokens.ts` to `#787878` makes the next `keel check` report one E1804, the same stdout as a run with `node_modules/.cache/keel` deleted.
- `keel build` in a project where `keel check` reports only one E1802, only one E1804, or only one E1820 exits 1, prints that diagnostic and writes no `.keel/` folder and no `dist/` folder.
- `keel check`, `keel build`, MCP `check` and `keel lsp`'s published diagnostics report the same static E1804 for one project; after a passing `renderRoute` test of page `m.r` given `artifacts: {}` whose module holds that E1804, `keel ledger` gives `a11y:.:m.r#1.4.3` rung `none`.
