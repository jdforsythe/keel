# k.derived: Derived files
status: implemented
A derived file is one Keel computes from a project's tree: a `.keel/` view or a deploy file of Derivations. No command judges, tests or serves from a derived file's bytes on disk: each reader takes the derivation of the tree it runs over.

**Derivations.** Compiled: `a11y.json`, `deps.json`, `ids.json`, `std.json` and `styles.json`, from compiling the project's sources and its libraries' files (k.compiler Artifacts), and `schemes.json` (k.schemes), from the tokens each run evaluates (k.a11y-static Tokens). Evaluated: `routes.json` and `surface.json` (k.compat), both from one evaluation of the project's contracts, route tables and store factories (k.compiler Build-time evaluation). Deploy files (k.deploy): from `topology.ts` and the libraries' manifests. A derivation that fails reports its codes (E1000, E1006, E1048, E1049, E1807) at `keel check` as at `keel build`, and writes no view.

**Readers.** `keel check` takes every rule's `artifacts`, E1511's API entries and the current surface of E1562, E1563 and W1564 (k.compat Base) from the derivation. `keel test` gives each test process, before its first test file, the `a11y.json` derived from the tree (k.a11y Artifacts). `keel ledger` reads each project's derived `routes.json` (k.a11y Claims). The inspect document of `keel dev` holds the derivation of the tree it serves. Files Keel does not derive are read as their sections say: a `--base` surface, `ledger.json`, `monitored.json`.

**Derivation cache.** An evaluated derivation is kept in `<root>/node_modules/.cache/keel/derived/` when `<root>/node_modules` exists, in an entry named by the SHA-256 of the Keel version, the project's code file paths and the evaluation's inputs. Its inputs are each file the evaluation loads or its code reads, each `package.json` and `tsconfig.json` its resolver reads, and the `package.json` of each package holding one; its probes, each other question either asks (k.check-cache Evaluation probes), with the answer, a path found absent too, whose creation is a miss; a stat field only when read. k.evaluator bounds them and refuses the rest (E1050): the command answers each. An input is recorded by its path through the project and resolved again at every read, each symbolic link on it, and its `node_modules/<name>` entry, a real-path probe, so a link pointed elsewhere is a miss, to the same bytes too. Not keyed: what k.evaluator Not held lists (the clock and random values, which app code does not read; a file another process changes during the evaluation). An entry is one JSON file: its key, its `inputs` (each path, a project file's relative, a package file's `<package name>/<path in the package>`, another's absolute, with the SHA-256 of its bytes), its `probes` and the derivation; it is used only when every input and probe gets the same answer again (k.check-cache Entries). A cached derivation is the one a fresh evaluation gives: the cache changes a run's time and its json `evaluated` and `cached` counts, no other byte of its output, exit code, trailer or files written. Compiled derivations are computed on every run.

**In process.** `check()` (`@keel/check`) writes nothing; a compiled view among its files that differs from its compile is E1005, and an evaluated view is compared only with the evaluated derivation a caller passes as `derived`, else not at all.

**Refresh.** After it judges, `keel check` writes each view of each project it checked whose bytes differ from the derivation, beside an error too, but never the file its `--base` names (k.compat Base). `keel build` does so before its bundles, an applied `keel scaffold` operation after its edits in a project holding a view (k.scaffold Refresh), `keel test` before its first test file. `keel dev` does so, `surface.json` and deploy files too, after each change to any file a derivation read, a lone `*.contract.ts` edit included, or to the code file paths. `keel lsp`, and an MCP call given file texts, write no view. A write is a read-only temporary file `<name>.<pid>.tmp` beside the view renamed over it; no lock is taken, and a write is skipped when one of its inputs changed during the run. No source file, nothing in `dist/` and nothing outside the project is written; in a library's own folder (k.library-pack Own folder) no view is written. A view that cannot be written is W1018. The compact trailer counts the views written, `ok check 217 files, 2 refreshed, 0 errors`, with no `refreshed` when it is 0; the json summary's `counts` hold `refreshed`, `evaluated` (evaluations run) and `cached` (evaluated derivations taken from the cache) on every run, 0 included.

**Frozen.** A command runs frozen with `--frozen`, with `CI` set to a value other than empty, `0` or `false`, or with `KEEL_FROZEN=1`, which a frozen command sets for its children and the Vite plugin reads. Frozen, no view is written, and each view present that differs from its derivation is E1005 (for `surface.json` naming the first store, contract or entry that differs), with the fix k.compiler gives; an absent view is no diagnostic.

**Version control.** `keel scaffold project` writes a `.gitignore` holding one line per compiled view (`schemes.json` too) and `routes.json`; `surface.json` and the deploy files are committed.

**Work.** With no input of a project's cached derivation changed, a run evaluates nothing for it and reads one cache entry. An edit to a file that is no input evaluates nothing; an edit to an input runs exactly one evaluation of that project, whose new entry records exactly its inputs. Without `node_modules`, each run evaluates once per project with route tables. Durations are not part of the contract.

**Rules.** E1005 (k.compiler) frozen, a view that differs from its derivation; frozen or not, a file in `.keel/` that no derivation writes and no section names, never removed · W1018 a view not written: the reason and the path; the run judged from the derivation. W1018 is a command code (k.check Codes): `keel check`, `keel test`, `keel build`, `keel dev` and `keel scaffold` print it, `check()` never reports it, `reportedCodes()` does not list it, and clause 8 is its fixture.
