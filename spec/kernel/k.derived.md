# k.derived: Derived files
status: proposed
A derived file is one Keel computes from a project's tree: the k.compiler artifacts in `.keel/` (`a11y.json`, `deps.json`, `ids.json`, `routes.json`, `std.json`, `styles.json`), `.keel/surface.json` (k.compat) and the deploy files (k.deploy). No command judges, tests or serves from a derived file's bytes on disk. Each reader takes the derivation of the tree it runs over; the files on disk are views of it, for people, reviewers and tools.

**Derivations.** Compiled: `a11y.json`, `deps.json`, `ids.json`, `std.json` and `styles.json`, from compiling the project's sources and its libraries' files (k.compiler Artifacts). Evaluated: `routes.json` and `surface.json`, both from one evaluation of the project's contracts, route tables and store factories (k.compiler Build-time evaluation). Deploy files: from `topology.ts` and the libraries' manifests. A derivation that fails reports its codes (E1000, E1006, E1049, E1807) at `keel check` as at `keel build`, and writes no view.

**Readers.** `keel check` takes every rule's `artifacts`, E1511's API entries and the current surface of E1562, E1563 and W1564 (k.compat Base) from the derivation. `keel test` gives each test process, before its first test file, the `a11y.json` derived from the tree (k.a11y Artifacts). `keel ledger` reads each project's derived `routes.json` (k.a11y Claims). The inspect document of `keel dev` holds the derivation of the tree it serves. Other `.keel/` files are not derived and are read as their sections say: a `--base` surface, `ledger.json`, `monitored.json`.

**Derivation cache.** An evaluated derivation is kept in `<root>/node_modules/.cache/keel/derived/` when `<root>/node_modules` exists. An entry is named by the SHA-256 of the Keel version, the project's code file paths and the evaluation's inputs: each file it loaded, and the `package.json` of each package holding one. Each input is recorded with the SHA-256 of its bytes (a project code file: of its normal form, k.compat Sources), and an entry is used only when every recorded input gets the same answer again, as k.check-cache Probes and Entries say. A cached derivation is the one a fresh evaluation gives: the cache changes the time a run takes, never its output, exit code, trailer or the files it writes. Compiled derivations are computed on every run.

**Refresh.** After it judges, `keel check` writes each view of each project it checked whose bytes differ from the derivation. `keel build` does so before its bundles, an applied `keel scaffold` operation after its edits in a project holding a view (k.scaffold Refresh), `keel test` before its first test file, and `keel dev` after each change it applies. `keel lsp`, and an MCP call given file texts, write no view. A write is a temporary file `<name>.<pid>.tmp` beside the view, made read-only, then renamed over it, so a reader sees one whole file; no lock is taken, and a write is skipped when one of its inputs changed during the run. No source file, nothing in `dist/` and nothing outside the project is written; in a library's own folder (k.library-pack Own folder) no view is written. A view that cannot be written is W1018 and the run goes on with the derivation. The trailer counts the views written, `ok check 217 files, 2 refreshed, 0 errors`, with no `refreshed` when it is 0.

**Frozen.** A command runs frozen with `--frozen`, with `CI` set to a value other than empty, `0` or `false`, or with `KEEL_FROZEN=1`, which a frozen command sets for its children and the Vite plugin reads. Frozen, no view is written, and each view present that differs from its derivation is E1005 (for `surface.json` naming the first store, contract or entry that differs), with the fix k.compiler gives; an absent view is no diagnostic.

**Version control.** `keel scaffold project` writes a `.gitignore` holding one line per compiled view and `routes.json` (`.keel/a11y.json` and so on); `surface.json` and the deploy files are committed, so a reviewer reads a change to them in the diff and the generated CI compares against the base branch's surface.

**Time.** With the derivation cache holding the project's evaluated derivation and no input changed, the refresh adds at most 100 ms to a warm `keel check` of `apps/household`. After an edit to a file the evaluation loaded, a warm `keel check` of `apps/household` takes at most 1.5 s more than one after an edit to a file it did not load.

**Rules.** E1005 (k.compiler) frozen, a view that differs from its derivation; frozen or not, a file in `.keel/` that no derivation writes and no section names, never removed · W1018 a view not written: the reason (read-only file system, no permission) and the path; the run judged from the derivation.

**Conformance.**
1. In a copy of `examples/client-only-api` after `keel build`, adding an API entry to a contract and its binding, then `keel check`, reports no E1005, exits 0, prints `2 refreshed` in its trailer, and leaves `.keel/routes.json` and `.keel/surface.json` byte-identical to what `keel build` of that tree writes.
2. In that copy, after renaming an element id in a page component, `keel check` reports no E1005 and leaves `.keel/ids.json` and `.keel/a11y.json` byte-identical to what `keel build` writes.
3. A second `keel check` with no file changed writes no file, every `.keel/` file keeping its modification time, and its trailer holds no `refreshed`.
4. After the edit of clause 1, `keel check --frozen` exits 1 with one E1005 at `.keel/routes.json` and one at `.keel/surface.json`, each message naming the contract file, and no file in `.keel/` changes.
5. After the edit of clause 1, `keel check` with `CI=true` gives the output of clause 4, and with `CI=false` the output of clause 1.
6. Changing one byte of `.keel/ids.json` makes `keel check` rewrite it with `1 refreshed` and exit 0, and makes `keel check --frozen` report one E1005 at that file.
7. A file `.keel/x.json` is one E1005 under `keel check` and under `keel check --frozen`, and is still there after both.
8. With the copy's `.keel/` folder at mode 0555 and the edit of clause 1, `keel check` exits 0 with one W1018 per differing view and no E1005, and `keel test` runs every test with one W1018 per differing view and no T0001.
9. In a copy of `apps/household` whose `@keel/std-text` is a linked copy, after `keel build`, changing `line`'s default `min` from 1 to 2 in that copy makes `keel check --base <the surface keel build wrote>` report one E1563 at `modules/setup/Household.schema.ts`, and makes `keel check` without `--base` print `1 refreshed`.
10. In a copy of `apps/household` with `.keel/` deleted, giving the `setup.household` store's state a required field makes `keel check --base <the committed surface>` report one E1563 naming that field.
11. In a fixture whose page renders `<button id="p.b">` and whose test renders it with `renderRoute`, replacing `.keel/a11y.json` with one giving `p.b` role `link` leaves `keel test` passing.
12. In that fixture with `.keel/` deleted, a passing `renderRoute` under `keel test` records a run whose `rules` hold E1702.
13. `keel lsp` diagnostics for an unsaved buffer adding an API entry write no file in `.keel/`.
14. Two `keel check` processes started together after the edit of clause 1 both exit 0, and afterwards each `.keel/` file is byte-identical to what `keel build` writes and no `*.tmp` file is left.
15. After one `keel check`, replacing each entry in `node_modules/.cache/keel/derived/` with `{}` or its first 40 bytes leaves the next `keel check` printing the same stdout bytes and writing the same files as a run with the folder deleted.
16. After one `keel check` of the household copy, rewriting a file of the linked `@keel/std-text` copy that the evaluation loaded, with its old modification time, makes the next `keel check` evaluate again, as a run with `node_modules/.cache/keel` deleted does.
17. After one `keel check`, re-indenting a contract file and adding a comment to it makes the next `keel check` write no file.
18. While `keel dev` serves the copy of clause 1, within 2 s of the edit `.keel/routes.json` is byte-identical to what `keel build` writes, and a `keel check` run then writes no file.
19. In a copy of `apps/household` with `.keel/` deleted, `keel test` then `keel ledger` give one `a11y:` item per page route and criterion, as with `.keel/` present.
20. No fixture makes `keel check` report W1005.
21. `keel scaffold project p` writes a `.gitignore` holding the lines `.keel/a11y.json`, `.keel/deps.json`, `.keel/ids.json`, `.keel/routes.json`, `.keel/std.json` and `.keel/styles.json`, and no line matching `.keel/surface.json`.
22. On `apps/household`, 5 runs of each case of the Time paragraph, scaled as the repository's test times are (`docs/TESTING.md`), each stay within its bound.
