# k.evaluator: The evaluator
status: proposed
The evaluator is the process a build-time evaluation (k.compiler Build-time evaluation) runs in: a Node child the command starts for one bundle and ends when that bundle has answered. No evaluation runs in the process of `keel check`, `keel build`, `keel test`, `keel dev`, `keel ledger`, `keel lsp`, `keel mcp` or the Vite plugin. An evaluation's global object, intrinsics, module instances, timers and pending promises are its own and end with it; nothing the command's process holds (a dev server's globals, an earlier evaluation's write to `Math`) reaches it, and nothing it does reaches the command's process but its result.

**Start.** `evaluate({ kind: 'data', entry, deadlineMs })` of `@keel/compiler` is the one function that starts an evaluator, and it resolves to the entry's exports as JSON or to one failure (a code and a message). It starts Node on `entry`, a file in a folder holding nothing else, with `--permission`, `--allow-fs-read` naming that folder alone, `--disallow-code-generation-from-strings` and `--zero-fill-buffers`, in a new empty working folder, with an environment built from nothing: `TZ`, `LANG` and each `LC_*` name of the command's, and no other value of it. A build-time evaluation writes its bundle into such a folder and calls `evaluate`; both folders are removed when the evaluator ends. One evaluator runs one bundle: none is kept for a second. Node 22.13 is the least Keel runs on.

**Realm.** Before a bundle's first module runs, its banner prepares the evaluator's own global object from the allowlist (`HOST_VIEWS`, k.compiler Build-time evaluation): a pure member stays Node's own; an observed member is replaced by a view; every other own property, one Node adds too, by one that refuses (E1050). `globalThis` and `global` are that object. A write to it, to an intrinsic (`Math`, `Error.stackTraceLimit`) or to a pure built-in's defaults (`util.inspect.defaultOptions`) stays in that evaluation. A built-in the bundle imports or requires, by any name, comes from the same list. A view holds no object of Node's `node:fs`, `process` or `os`: what it returns (a stat result, a file handle, a read stream, a directory entry) is of the view's own classes, whose constructors ask as the view's functions do.

**Questions.** The evaluator holds no fact of the machine but its start. A view answers by asking the command, which reads the disk, the environment and its own process (the working folder is the command's), answers, and records the question as an input or probe (k.check-cache Evaluation probes). The evaluator waits for each answer, so `readFileSync` and a `process.env` read are synchronous as in Node. `console`, `process.stdout`, `process.stderr`, `process` listeners and `util` warnings write nowhere, and the command discards what the evaluator's own output streams carry, Node's warnings among it.

**Below the views.** Node and V8 refuse these in an evaluator whatever code asks and however it came by a name: reading a file outside the entry's folder; writing, renaming or removing one; starting a process or a worker; loading an addon or WASI; opening the inspector; making code from a string (`eval`, `new Function`, a function's `constructor`). Each is E1050 when it ends a file's evaluation. So a read of the file system that no view recorded cannot make a cached derivation differ from a fresh one: it fails in both.

**End.** An evaluation is its bundle's module top levels and the store factories its entry runs, up to the entry's result. When the result arrives the command ends the evaluator with a signal no code in it handles: a timer, interval, listener or handle the code left ends with it, runs nothing after the result, and is no diagnostic. The command also ends it, with no result: `deadlineMs` after its start by the command's monotonic clock (30,000 unless given; no `keel` command gives one), E1048; when Node ends it because a top-level await can never settle, E1048; when it exits or is killed any other way, E1049; when the command itself exits or is interrupted. `keel dev` ends an evaluator whose bundle a newer change made stale and starts the next. A failed evaluation writes no cache entry and no view.

**Placing.** A diagnostic crosses from the evaluator as a record of fields (its code, its message, the bundle positions of its frames, the entry file being evaluated), never as marks in text; the command maps positions through the bundle's source map, whatever the code did to `Error.stackTraceLimit` or `Error.prepareStackTrace`. A refusal reaches evaluated code as a thrown `Error` whose message starts with what was refused. E1050 is placed as k.compiler Rules says; a frame in a module that is no file on disk (a `data:` URL) is skipped. E1048 and E1049 lie at the entry file whose import had not finished (`tokens.ts`, a contract file or a `routes.ts`), with no line. No message from an evaluation holds a control character, the bundle's path or a line of Node's own output. `keel dev` prints each as `keel check` does and keeps serving.

**Not held.**
- Not keyed: the clock and random values, which app code does not read (E1601; a store factory runs on a sim ctx), and what moves with them (when a `WeakRef` empties); a file another process changes during the evaluation.
- Code written to get past a view to Node's own module objects (no route is known) is still held by Below the views. Past them it can read what Node gives without a file (the evaluator's process id, timings, memory, the host's name) and, on Node 22 and 24, reach the network. Node calls its permission model a seat belt for trusted code, no wall against code written to break it; Keel claims no more.
- A command killed outright (`SIGKILL`) while its evaluator runs a loop that never yields leaves that process running.
- The app `keel dev` serves and the tests `keel test` runs are in those commands' processes: only build-time evaluation is here.

**Rules.** E1048 a build-time evaluation that gave no result, message `<file> did not finish evaluating: a top-level await never settles` or `<file> did not finish evaluating in <n> ms`, `<n>` the deadline; fix: none · E1049 (k.compiler) from an evaluator that ended early, message `<file>: the evaluator ended with exit <code>` or `with signal <name>`. E1048 is a command code as E1050 is (k.compiler Rules): `check()` never reports it and `reportedCodes()` does not list it.

**Conformance.**
Let `G` be the fixture of k.compiler's E1050 clauses: a copy of `apps/household` whose `modules/setup/gate.guard.ts` imports a package `p` under `node_modules`, with `p`'s `index.mjs` as each clause gives; `<f>` and `<g>` are files in the copy. An entry given to `evaluate` is a file the test writes; each `evaluate` call below passes `kind: 'data'`.
- `evaluate`, called in a process whose `globalThis.document` is an object, with an entry holding `export const d = typeof document`, resolves to `{ d: 'undefined' }`.
- After `evaluate` of an entry holding `globalThis.keelMark = 1; Math.keelMark = 1; process.env.KEEL_MARK = '1'; export const n = 1`, the caller's `globalThis.keelMark`, `Math.keelMark` and `process.env.KEEL_MARK` are undefined, and a second `evaluate` of an entry holding `export const m = String(Math.keelMark)` resolves to `{ m: 'undefined' }`.
- `evaluate`, called with `KEEL_PROBE=1` in the caller's environment, with an entry holding `export const k = Object.keys(process.env)`, resolves to a `k` holding none of `KEEL_PROBE`, `PATH` and `HOME`; with an entry holding `export const z = Buffer.allocUnsafe(64).every((b) => b === 0)`, to `{ z: true }`.
- `evaluate` of an entry whose top level calls `process.getBuiltinModule('node:fs').readFileSync('/etc/hosts')`, `process.getBuiltinModule('node:fs').writeFileSync(<a path in the test's folder>, 'x')`, `process.getBuiltinModule('node:child_process').spawnSync(process.execPath, ['-v'])`, `new Function('return 1')` or `(() => 1).constructor('return 1')` resolves to a failure whose code is E1050, and the write leaves no file at its path.
- `evaluate` of an entry holding `setInterval(() => {}, 10); export const n = 1` resolves to `{ n: 1 }`, and the child has exited.
- `evaluate` of an entry whose top level is `await new Promise(() => {})` resolves within 5 s to a failure whose code is E1048 and whose message ends `a top-level await never settles`.
- `evaluate` given `deadlineMs: 200` and an entry whose top level is `for (;;) {}`, or `setInterval(() => {}, 10); await new Promise(() => {})`, resolves within 5 s to a failure whose code is E1048 and whose message ends `in 200 ms`, and the child has exited.
- `evaluate` of an entry whose top level calls `process.exit(3)` resolves to a failure whose code is E1049 and whose message ends `the evaluator ended with exit 3`; one calling `process.abort()`, to one ending `with signal SIGABRT`.
- In `G` with `index.mjs` holding `setInterval(() => {}, 1000); export default 1`, `keel check` exits with the code and stdout of the same tree without the `setInterval` call.
- In `G` with `index.mjs` holding `await new Promise(() => {}); export default 1`, `keel check` and `keel build` each exit 1 with one E1048 whose `path` is a contract file or `routes.ts` of `modules/setup` and no other error, and their output holds neither `unsettled` nor `Warning`; `keel dev` there prints that E1048 and answers a request.
- In `G` with `index.mjs` line 1 `import os from 'node:os'`, line 2 `Error.stackTraceLimit = 0` and line 3 `export default String(os.cpus())`, `keel check` reports one E1050 whose message starts `node:os.cpus at p/index.mjs:3`.
- In `G` with `index.mjs` the one line `import os from 'node:os'; export default String(os.cpus())`, `keel check` reports one E1050 whose message starts `node:os.cpus at p/index.mjs:1:` followed by a column greater than 26.
- In `G` with `index.mjs` line 1 `import os from 'node:os'` and line 2 `try { os.cpus() } catch (e) { throw new Error('wrapped: ' + e.message) }`, `keel check` reports one E1006 whose message holds `wrapped: node:os.cpus`, and no byte of its stdout is below 0x20 but the line feed; while `keel dev` serves `G` with line 2 `export default String(os.cpus())`, its output holds the E1050 line `keel check` prints for that tree.
- In `G` with `index.mjs` line 2 `await import('data:text/javascript,' + encodeURIComponent('export default 1'))`, `keel check` reports one E1050 with no `path` whose message holds ` at p/index.mjs:2`.
- In `G` with `index.mjs` holding `import { createReadStream } from 'node:fs'` and `const RS = createReadStream(<f>).constructor`, then `new RS(<g>, { flags: 'w' })`, `keel check` reports one E1050 and `<g>` keeps its bytes; with `export default (await new RS(<g>).toArray()).join('')` instead, after one `keel check`, changing `<g>`'s bytes makes the next `keel check` have `counts.evaluated` 1.
- In the copy of k.derived clause 9 whose linked `@keel/std-text` takes `line`'s default `min` from `Math.n = (Math.n ?? 0) + 1` at import time, while `keel dev` serves it, after each of three edits that add a comment line to a contract file, `.keel/surface.json` is within 2 s byte-identical to what `keel build` of that tree writes.
- While `keel dev` serves a copy of `apps/household`, after it has answered a `GET /`, changing the path `/api/household` to `/api/home` in the contract file that holds it makes, within 2 s, `.keel/routes.json` byte-identical to what `keel build` of that tree writes; after a second answered `GET /`, changing it back does so again; and its output holds no `E1050`.
