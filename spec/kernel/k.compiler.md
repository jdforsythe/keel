# k.compiler: Compiler and artifacts
status: implemented

**API.** One Vite plugin, no options (`@keel/compiler/vite`).

**Output.** JSX compiles to direct DOM operations (k.runtime). A component function runs once per instance. Each dynamic expression becomes one binding that updates only its own node. Static subtrees become templates built once and cloned. `If`, `For`, `Match`/`Case`, and `Boundary` are compiler intrinsics lowered to runtime ops, not component calls.

**Escaping by context.** Attributes and properties are set through the DOM. Server HTML escapes text and attribute contexts separately. **URL policy** (runtime ops, `Link`/`Image`): URL attributes are `href`, `src`, `action`, `formaction`, `xlink:href`, `poster`, `data`, `ping`/`srcset`/`imagesrcset` (each URL; split at spaces, commas), and `to`/`from`/`by`/`values` on any element (each `;` item). Navigation attributes (`href`, `action`, `formaction`, `Link to`) take an `Href` from a contract's `href()` or an absolute URL; a literal there starting with `/` or matching a `routes.json` path pattern is E1501. The rest are assets: relative literals pass. A value with a URL whose parsed scheme is not `http`, `https`, `mailto`, or `tel` renders as `about:blank`. Raw HTML has no API outside `unsafe`.

**Artifacts.** Derived files (k.derived), written to `.keel/` as views: sorted-key JSON, a content hash, read-only.
- `deps.json`: reactive graph (k.reactive).
- `ids.json`: `{ [elementId]: { file, line, col, component, tag, role } }` (k.component ids).
- `routes.json`: `{ [routeId]: { path, params, search, actions, layout, guard, module } }`, an API entry adding `api: true` and `method` (k.api); `layout` is the id of the layout that wraps the page or layout, else `null`; `module` the module that declares the route; schemas as JSON Schema. It is derived by evaluating the route tables, a placed stdlib module's from its package's `./contract` and `./routes`.
- `a11y.json`: per element id, expected `role` and the source of its accessible name (`label`, `alt`, `text`, `aria`). Its rules are one table, `@keel/compiler/a11y`, the harness applies to the DOM (WAI-ARIA 1.2, HTML-AAM): `img` with literal `alt=""` is `presentation`, unnamed; `section` without `aria-label(ledby)` is `generic`; name from content only for non-control roles ARIA 1.2 names from contents. A role, input `type`, or `select` `size`/`multiple` unknown statically is `null`, not compared.

**Build-time evaluation.** `tokens.ts` and each `routes.ts` run once in Node, bundled as the server build bundles: a package's CommonJS code may `require` Node built-ins and other packages (`pg` does). Only module top levels run; no handler or capability side does. A thrown E code is kept; else `tokens.ts` throwing or exporting no tokens is E1807 (k.ui), a `routes.ts` throwing or exporting no `routes` or a `routes` that is no route table, or a throwing contract file (k.compat), is E1006, with file and message. Any other failure is E1049 at the file and line it names (a bundling error's `<path>:<line>:<col>`), else unlocated, its message the failure's first line, with `see` k.compiler. It reads through its bundle's own views (k.derived Derivation cache), by any name (`globalThis.process`, `global`, an alias, `createRequire`, `process.getBuiltinModule`); each module's `import.meta` is its own. They record: each lookup of its resolver and of `require` (each candidate file, `node_modules/<name>`, `package.json` and `tsconfig.json` `paths` target tried up to the one that answers, all for a name resolving to nothing) and each loaded file's nearest `package.json` and `tsconfig.json` (and its `extends`); each `node:fs` read, existence test, stat (kind, size, mode), real path and listing, promised too; each `process.env` name; each fact of `process` (`cwd()` always) and `navigator` read; each call of `node:os` and `node:tty`, with its arguments. A `require` from `createRequire` takes a built-in, a `.json` file or a name resolving to nothing (Node's not-found error); a computed `import()` and another `require`, a built-in, an absolute path or a name bundling left unresolved. `console`, `process.stdout` and `process.stderr` write nowhere. The rest is refused with E1050: importing a `.node` addon, at the import; calling or constructing a function of `node:child_process`, `cluster`, `worker_threads`, `net`, `tls`, `dgram`, `dns`, `http`, `https`, `http2`, `vm`, `v8`, `inspector`, `wasi`, `sqlite`, `repl`, `readline` or `trace_events` (importing them is allowed); a `node:fs` write, watch or recursive listing; a read by a file descriptor the evaluation did not open; a code file named at run time; `node:module` but `createRequire`, `isBuiltin` and `builtinModules`; `process.dlopen`, `binding`, `mainModule`, `stdin`, `exit`, `chdir` or a property set; `import.meta.resolve`; `Function`, `eval`, `fetch`, `WebSocket` and `EventSource`. In `keel check`, `keel build` and `vite build` each of these is an error: the command exits 1; `keel dev` prints it and keeps serving.

**Rules.** E1000 source does not parse (at the parser's location, `syntax error: <parser message>`; nothing else runs on it) · E1001 `For` without `key`, or `key` not a field of the item · E1002 raw HTML (`innerHTML` family, `DOMParser`, `document.write`, `on*` strings, also spread; data in `script`/`style`) · E1003 any `srcdoc`, `<base>` `href` or `<meta>` `http-equiv`, or a literal the URL policy renders as `about:blank` in a URL attribute or `Link to`/`Image src`; fix removes the attribute, except a required prop · E1004 a server-only module (k.boundary) named by a value import, re-export or literal `import()` in client-reachable code (k.boundary Reach) · E1005 generated output that differs from what generates it: a view under k.derived Frozen, a file in `.keel/` no derivation writes, `turbo.json`, CI workflows, API schemas; when only the bytes differ, the fix restores them · W1005 reserved: no command reports it · E1049 internal compiler failure: message verbatim, no app location or code; from Build-time evaluation, at the file the failure names, with `see` k.compiler · E1050 a read the build-time evaluation cannot observe (Build-time evaluation), at the import for an addon, else with no location, its message starting with what it refused (`process.dlopen`).

**Conformance.**
- Compiling the same sources twice yields byte-identical JS and artifacts.
- Updating one signal changes only the DOM nodes bound to it; every other node keeps its identity.
- A string containing `<script>` or `"><img onerror=x>` rendered as a child or attribute value appears verbatim as text or attribute value and creates no element.
- A dynamic `href` whose value is `javascript:alert(1)` renders as `about:blank`.
- `ids.json` has exactly one entry per element in source, and each key is an id the harness `find(id)` resolves.
- Reordering a keyed `For` list preserves the DOM node identity of every row.
- Changing any byte of a file under `.keel/` makes `keel check --frozen` report E1005 on that file.
- A component with no dynamic expressions compiles to a single cloned template and no bindings.
- A literal `poster="javascript:alert(1)"` is E1003, and the same value bound dynamically renders as `about:blank`.
- Any `srcdoc`, and a `vbscript:` URL in any URL attribute, is E1003 as a literal and `about:blank` when bound.
- A literal `src="logo.png"` is not E1501; `href="/orders"` is.
- `<img alt="">`, an unnamed `<section>`, `<td>` and `<li>` with text render with no E1702.
- A file with a syntax error yields only E1000, also in `routes.ts` at build time.
- A `routes.ts` throwing a plain Error is E1006; throwing `{ code: 'E1502' }` keeps E1502.
- Under `keel check --frozen`, a `.keel/` artifact with changed `data` and recomputed `hash`, or older than its sources, is E1005.
- Beside a `routes.ts`, literal or with a computed `path`, `keel check --frozen` passes a genuine `routes.json` and is E1005 with a route added; `keel check`, `vite build` and a `node`-only `keel build` rewrite a differing one, reporting nothing for it.
- `javascript:` in `object data`, a `srcset` candidate, or a `<set>` `to`/`<animate>` `values` item is E1003 as a literal and `about:blank` bound; any `<base>` `href` or `<meta>` `http-equiv` is E1003, never rendered.
- `<script>{x}`, `<style>{x}` and `<script src={x}>` are E1002 and bind nothing.
- With `@keel/std-health` placed, `keel check --frozen` over its `routes.json`, its binding written whole or spread, gives no E1005.
- `export * from './a.server'` and `import('./a.server')` in client-reachable code are each E1004; `export type` from it is not.
- A `routes.ts` whose graph reaches a `*.server.ts` file importing a CommonJS package that `require`s `events` evaluates: `routes.json` lists its routes and no E1006 is printed.
- `keel build` of a project whose `modules/a/routes.ts` throws prints one E1006 naming that file, counts it among its summary's errors and exits 1, with a `client` deployable and with `node` ones only.
- A `routes.ts` whose first line imports `./missing.ts`, a file that does not exist, makes `keel check` report one E1049 at that `routes.ts` line 1, whose compact record is followed by the line `see: keel docs k.compiler`.
- A `routes.ts` whose graph reaches a `*.server.ts` file importing `node:child_process`, `node:net` and `node:dns` and calling none of their functions at import time evaluates with no E1050; that file calling `execSync('true')` at its top level makes `keel check` report one E1050 whose message starts `node:child_process.execSync` and exit 1, and `new Socket()` of `node:net` there one starting `node:net.Socket`.
- That `*.server.ts` file importing `./a.node` makes `keel check` report one E1050 at that file and the import's line, and exit 1.
- That `*.server.ts` file's top level calling `readFileSync(0)`, or `createRequire(import.meta.url)` with a name built at run time naming its sibling `c.cjs`, makes `keel check` report one E1050 and exit 1, and leaves no entry in `node_modules/.cache/keel/derived/`.
- In the copy of k.derived clause 9 whose linked `@keel/std-text` file `line.ts` is a symbolic link to `line.a.ts`, after one `keel check`, pointing that link at `line.b.ts`, a copy of `line.a.ts`, makes the next `keel check` have `counts.evaluated` 1 and `counts.cached` 0.
- In the copy of k.derived clause 30 with `line`'s default `min` read from `globalThis.process.env.LINE_MIN`, from `global.process.env.LINE_MIN`, from `env.LINE_MIN` after `const { env } = process`, or from `process.getBuiltinModule('node:process').env.LINE_MIN`, a `keel check` with `LINE_MIN=2` after one with `LINE_MIN=1` has `counts.evaluated` 1.
- In the copy of k.derived clause 30 with `min.txt` read through `openSync` and `readSync`, or `min.json` read by `createRequire(import.meta.url)` of a name built at run time, after one `keel check`, changing that file's bytes, its modification time kept, makes the next `keel check` have `counts.evaluated` 1.
- That `*.server.ts` file importing a package whose top level awaits `import()` of a name built at run time, the absolute path of a file `c.cjs`, makes `keel check` report one E1050 and exit 1; of a file `m.json`, after one `keel check`, changing `m.json`'s bytes makes the next `keel check` have `counts.evaluated` 1.
- That file importing a package whose top level calls `require('module')._load('./c.cjs')`, reads `process.mainModule.filename`, or calls `import.meta.resolve('./c.cjs')`, `Function('return 1')` or `process.dlopen({}, 'a.node')` makes `keel check` report one E1050 with no location, its message starting `node:module._load`, `process.mainModule`, `import.meta.resolve`, `Function` or `process.dlopen`, and exit 1.
- After one `keel check` of that file's project, the next has `counts.evaluated` 1 when one of these is created first: `bind.ts` beside the `bind/index.ts` it imports as `./bind`; `modules/setup/node_modules/<p>`, a copy of the project's package `<p>` it imports; `gen/h.ts`, its `@h/h` resolving to `src/h.ts` by `tsconfig.json` `baseUrl` `.` and `paths` `{"@h/*": ["gen/*", "src/*"]}`; `flag` in a package it imports, whose `existsSync(join(import.meta.dirname, 'flag'))` was false; `node_modules/absent-pkg/index.js`, for a package it imports whose top level is `try { module.exports = require('absent-pkg') } catch { module.exports = 0 }`.
