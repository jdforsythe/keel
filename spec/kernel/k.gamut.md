# k.gamut: Color gamut forms
status: proposed

Keel ships a color only in forms it computes and judges, each inside the gamut of the screen that shows it, so check judges exactly the colors a screen or a printer shows. Luminance, and when a color is inside sRGB or display-p3: k.values Contrast. Combinations: k.themes.

**Forms.** A color inside sRGB has one form, as written. One outside sRGB has two: its sRGB form `rgb(<r> <g> <b>)`, mapped into sRGB by CSS Color 4's gamut mapping (the OKLCH chroma search with JND 0.02 and epsilon 0.0001), each channel encoded by CSS Color 4's sRGB transfer function, times 255 and rounded to an integer; and its P3 form, the color as written when it is a `color(display-p3 ...)`, else `color(display-p3 <u> <u> <u>)` after the same mapping into display-p3 (no mapping when inside it), each channel encoded by the same function, rounded to 4 decimals and written as the shortest `<n>` of that value (`1`, `0.5055`). An `<alpha>` keeps its ` / <a>` as written in both. A color inside sRGB is its own P3 form.

**CSS.** A declaration of the compiled CSS writes each color in its sRGB form. Each block of k.schemes CSS that writes a color outside sRGB, but in the `print` layer, is followed at once by a block of the same selector in the same layer, under its conditions with `screen` and `(color-gamut: p3)` (`screen` once), declaring those properties again with each color in its P3 form. So a screen that matches `(color-gamut: p3)` shows P3 forms, any other screen sRGB forms, and printing sRGB forms only. Keel's declarations in the built CSS hold no other color value: each is kept as compiled, in its form and numbers, under no `@supports`. A browser build that sets no `cssMinify` and no `minify: false` minifies CSS with esbuild, which keeps each custom property's value as written whatever the `cssTarget`. Whatever the config, each browser build (`keel build`, or `vite build` alone) reads its emitted `.css` files after every plugin has run: each declaration of a `--k-color-*` or `--k-overlay-*` property, or of another `--k-*` one whose value there or in the compiled CSS holds a hex color or a color function, sits in a rule of the selector, `@layer` names and `@media` conditions of a compiled block declaring it, under no `@supports`, holding a value that block declares, numbers compared as numbers (`.5` is `0.5`), spaces beside `,`, `/` and parentheses ignored, all else as written; each P3 block follows at once its sRGB block; and, when the files declare any `--k-*` property, each compiled declaration of such a property is among them. No other declaration is read. The first difference, in file and declaration order with a missing one last, fails the build with E1819, one line, no position, and no `dist/<name>/` written: `<property> is <found> in the built CSS, expected <value>`, `<property> is missing from the built CSS, expected <value>`, `<property> is <found> under @supports in the built CSS, expected none`, `<property> is <found> in the built CSS where Keel declares none` or `<property>'s P3 block does not follow its sRGB block in the built CSS`, each value cut to an equal share ending `...` to keep the message within 89 units. Fix: unset the `build.cssMinify` (Lightning CSS rewrites colors and adds `@supports`), `css.transformer` or PostCSS plugin that rewrote it.

**Judging.** E1804, at check and at render, and `base.focus` judge each pair in each form, sRGB forms together and P3 forms together, in each combination, printing ones in sRGB forms only. The lower ratio stands, sRGB's on a tie, and E1804's message names its form when a color it judges is outside sRGB (k.a11y-static Message). An `<alpha>` over a backdrop is composited within each form: `a × c + (1 - a) × b` on each encoded channel, sRGB or display-p3, of the two colors' forms, times 255 rounded to an integer. `contrast(fg, bg)` (`@keel/ui/css`) gives the lower ratio. So `color(display-p3 0 0.52 0.5)` on `#000000` ships `rgb(0 133 127)`, 4.66:1, and itself, 4.56:1, and passes 4.5:1; `oklch(70% 0.48 290)` on it ships `rgb(160 131 255)`, 7.19:1, and `color(display-p3 0.6085 0.5055 1)`, 7.12:1; `color(display-p3 0 0.66 0 / 0.95)` over `#FFFFFF` composites to `rgb(13 171 17)` and to display-p3 channels 13, 173 and 13 of 255, 3.07:1 and 3.09:1 under `#FFFFFF` text.

**Conformance.**
- With color tokens `a` `color(display-p3 0 0.52 0.5)` and `b` `#000000`, `<Text fg="a" bg="b">x</Text>` reports no E1804; `contrast('color(display-p3 0 0.52 0.5)', '#000000')` from `@keel/ui/css` rounds to 4.56; the CSS compiled from those tokens declares `--k-color-a:rgb(0 133 127)` in its `:root` block and `--k-color-a:color(display-p3 0 0.52 0.5)` in a `:root` block under `screen and (color-gamut: p3)` that follows it at once, and `--k-color-a` nowhere else; with `a` `color(display-p3 0 0.51 0.5)` it reports one E1804 whose message holds `4.43:1 in light (P3)`, and with `themes: { paper: { when: 'print' } }` none inside `<Box media="print">` (4.55:1 in sRGB).
- With color tokens `card` and `on` `#FFFFFF`, `fontSize` `big` `24px` and `overlay: { scrim: { value: 'color(display-p3 0 0.66 0 / 0.95)', over: ['card'] } }`, `<Text fg="on" bg="scrim" fontSize="big">x</Text>` reports no E1804 (3.07:1 on the sRGB composite `rgb(13 171 17)`, 3.09:1 on the P3 one) and `<Text fg="on" bg="scrim">x</Text>` one with message `fg "on" on bg "scrim" over "card" is 3.07:1 in light (sRGB), needs 4.5:1`.
- With color tokens `a` `oklch(70% 0.48 290)` and `b` `#000000`, `contrast('oklch(70% 0.48 290)', '#000000')` rounds to 7.12 and the compiled CSS declares `--k-color-a` as `rgb(160 131 255)` and, in the block under `screen and (color-gamut: p3)`, as `color(display-p3 0.6085 0.5055 1)`; with `themes: { paper: { when: 'print', color: { a: 'color(display-p3 0 0.52 0.5)' } } }` the `keel.print` layer declares `--k-color-a:rgb(0 133 127)` and no block under `(color-gamut: p3)` holds `color(display-p3 0 0.52 0.5)`.
- After `keel build` of a `static` project with color tokens `a` `color(display-p3 0 0.52 0.5)`, `b` `#000000`, `c` `oklch(70% 0.48 290)` and `d` `hsl(19deg 87% 39%)` and `overlay: { s: { value: 'color(display-p3 0 0.66 0 / 0.95)', over: ['b'] } }`, the hex colors and color functions in `dist`'s CSS files, each compared as a color (the same form and equal numbers, letter case and a 3-digit hex's expansion aside), are exactly `rgb(0 133 127)`, `color(display-p3 0 0.52 0.5)`, `#000000`, `rgb(160 131 255)`, `color(display-p3 0.6085 0.5055 1)`, `hsl(19deg 87% 39%)`, `rgb(0 167 4 / 0.95)` and `color(display-p3 0 0.66 0 / 0.95)`, and no CSS file holds `@supports`.
- `keel build` of that project with `build: { cssMinify: 'lightningcss' }` in `vite.config.ts` exits 1 with one E1819 line and no `dist/<name>/`; with a `css.postcss` plugin writing each `rgb(<r> <g> <b>)` as lowercase 6-digit hex, it prints `E1819 --k-color-a is #00857f in the built CSS, expected rgb(0 133 127)`; with `build: { cssMinify: false }`, or none, it exits 0.
- In that project, a `styles` stylesheet holding `.x{--k-color-b:#000000}` makes `keel build` print `E1819 --k-color-b is #000000 in the built CSS where Keel declares none`; one holding `.x{color:#123ABC}` and `@supports (display:grid){.g{display:grid}}` builds.
