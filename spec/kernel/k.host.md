# k.host: Host reads
status: conformance-covered

App code reads no setting of the host it runs on: not the zone or locale (the server and the browser disagree, so a resumed page differs from the served one), and not a Node-only global in code the browser runs (it type-checks and fails there).

**Zone and locale.** E1758 (k.check) reports, in app code, by lexical scope and through `globalThis`/`window` and same-file aliases as for E1601:
- `navigator.language` or `languages`;
- an `Intl` `NumberFormat`, `DateTimeFormat`, `PluralRules`, `Collator`, `ListFormat`, `RelativeTimeFormat`, `DisplayNames` or `Segmenter`, called or constructed without a locale; an `Intl.DateTimeFormat` without `timeZone`;
- by method name on any receiver, also as `m.call(v, ...rest)`: `toLocaleString`, `toLocaleUpperCase` or `toLocaleLowerCase` without a locale, `localeCompare` without its second argument, `toLocaleDateString` or `toLocaleTimeString` without a locale or without `timeZone`;
- on a date: `getHours`, `getMinutes`, `getSeconds`, `getMilliseconds`, `getDate`, `getDay`, `getMonth`, `getFullYear`, `getYear`, `getTimezoneOffset`, `toString`, `toDateString`, `toTimeString`; `String(d)`; `d` in an untagged template;
- `new Date(y, m, ...)` with two or more arguments; `new Date(s)` or `Date.parse(s)` of a constant string that is not a date-only ISO date and does not end in `Z`, an offset, `GMT` or `UTC`.

A date is an expression whose TypeScript type is `Date`, found by the check's type pass (as E1453 is): a `new Date(...)`, a binding, a parameter, a member, a call result or an import. `any` and `unknown` are not dates; with the type pass off (`check(files, { types: false })`), a date is a `new Date(...)` or a `const` bound to one. No locale: absent, `undefined`, `void 0` or `[]`. An options argument that is not an object literal, or has a spread or a computed key, counts as giving `timeZone`. Not reported: `getUTC*`, `toISOString`, `toUTCString`, `Date.UTC`, `new Date(n)` of one argument, a string that is not constant, `.apply` and `.bind` forms, and `Date()` or `Date.now` (E1601). No fix.

**Node globals.** A browser file is an app file under `modules/<id>/` of a module a deployable lists that is not server-only (k.boundary), except the `routes.ts` of a module no `client` or `static` deployable lists; with no `topology.ts`, any app file that is not server-only. In a browser file E1759 reports a read of `process`, `Buffer`, `global`, `setImmediate`, `clearImmediate`, `__dirname`, `__filename`, `require`, `import.meta.dirname` or `import.meta.filename`, and a value import, re-export, literal `import()` or `require` of a Node built-in (`node:` or a bare name Node lists as built-in). In any app file, `*.server.*` included, `require`, `__dirname` and `__filename` are E1759: an ES module has none. Fix, outside a browser file: `__dirname` to `import.meta.dirname`, `__filename` to `import.meta.filename`; none otherwise. Not reported: a name the file declares; the operand of `typeof`, and a read under a `typeof x !== 'undefined'` test (`if`, `?:` or `&&`); members of `globalThis`; `import type`; tests, `*.config.*`, `unsafe/`, `.keel/` and `node_modules/`.

**Rules.** E1759 a Node-only global or built-in import in a browser file, or `require`, `__dirname` or `__filename` in an ES module (fix: `import.meta.dirname` or `import.meta.filename` outside a browser file).
