# k.scaffold-needs: What a generator needs from the project
status: implemented
What a k.scaffold generator's diagnostic prints when its input or the project lacks something, so that every line it prints runs, and the generators a library refuses.

**Lines.** A generator's E1052 for a missing input prints a line formed from the project that names only what the project holds: the first module in sorted order (`app` without one; `keel scaffold route app.about` in a fresh app) and a name it lacks (`about`, else `about2` to `about9`), for `transaction` that module's first store, for `service` `--base https://a.test`, with `--reason geo` where E1358 asks for one, for `shell` `--to` the first `client` deployable when there are several. Each line a generator's diagnostic prints, run as written in that project, exits 0.

**First.** A `first:` line only adds to the project: it never removes or converts a deployable, a module, a route or a file. Where a generator needs what the project lacks and such a line makes it, its diagnostic names that and prints the line after `first: `, in place of an example; where none does, it names the need in words and its `see`, with no line:
- `transaction` in a module with no store, and `transaction` naming a store its module lacks: E1052 `transaction needs a store first: keel scaffold store <module>.<store>` (`app.cart`, the first module's, with no id). A module the project lacks is E1052 `<module> is not a module of this project`, with no line.
- `shell` with no `client` deployable: no line adds one, since each module is in one deployable (k.topology) and `place` moves it. With no `<shell>`, E1052 `shell needs a client deployable, and this project has none`; with one, E1359 `no client deployable; a <shell> shell needs one`; each `see` k.topology.

**Refused.** A generator whose edit set k.check would reject writes nothing (k.scaffold E1353):
- `route --api` in a module a `client` or `static` deployable lists is E1353 naming E1511 (k.api), `aborted, would introduce E1511: an API route needs a node deployable; nothing written`.
- In a library (`package.json` `"keel": "library"`, k.library-pack), `module`, `route`, `component`, `store`, `transaction`, `service` and `shell` are E1052 `a library has no modules; write a component in src/ and export it from src/index.ts`, `see` k.library-pack, whatever their input: no line, nothing written. A library's components are files in `src/`, exported from `src/index.ts` and named in `module.ts` `public.exports`.

**Conformance.**
- In a fresh `client`, `static` and `node` app from `pnpm create @keel/app`, `keel scaffold <g>` with no argument, for `module`, `route`, `component`, `store` and `service`, is E1052 ending `keel scaffold module orders`, `route app.about`, `component app/OrderCard`, `store app.cart` and `service app --base https://a.test` (with ` --reason geo` in the `client` app alone, whose `client` deployable E1358 binds; the `static` and `node` apps' lines hold none); each line run as printed there exits 0.
- In a fresh app of each kind, `keel scaffold transaction` with no argument, and `transaction app.cart.addItem`, are E1052 `transaction needs a store first: keel scaffold store app.cart`; after that line exits 0, `transaction` with no argument ends `keel scaffold transaction app.cart.addItem`, which exits 0. `transaction orders.cart.addItem` there is E1052 `orders is not a module of this project`.
- In a fresh `client` app `keel scaffold shell` with no argument ends `keel scaffold shell tauri --id com.acme.shop`, which exits 0. In a fresh `static` and `node` app it is E1052 `shell needs a client deployable, and this project has none`, and `shell tauri --id com.acme.shop` is E1359 `no client deployable; a tauri shell needs one`, each `see` k.topology, holding no `keel scaffold` or `keel codemod` line, and writing nothing.
- In each of those apps, after each line a bullet above runs, every file and every `topology.ts` deployable the app held before is still there.
- In a project holding route `app.about`, `keel scaffold route` with no argument ends `keel scaffold route app.about2`.
- In a fresh `client` and `static` app, `keel scaffold route app.ping --api`, with and without `--method POST`, is E1353 naming E1511 whose message holds `an API route needs a node deployable`, and writes nothing; in a fresh `node` app each exits 0 and `keel check` is then clean.
- In a fresh library from `pnpm create @keel/app charts --library @acme/charts`, `keel scaffold <g>` for `module`, `route`, `component`, `store`, `transaction`, `service` and `shell`, with no argument and with the argument of the `client` app's line, is one E1052 `a library has no modules; write a component in src/ and export it from src/index.ts`, holding no `keel scaffold` or `keel codemod` line, and writes nothing.
